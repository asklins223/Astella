第 1 节

Tool 到底是什么

Tool 是模型可以调用的一段外部能力。模型自己只会生成文字：它能写出会读天气的那几行代码，但不会真的去读。Tool 就是把那几行代码接到一个真的会去执行的地方，模型才有办法动手。

第 2 节

为什么非得有它

  • 模型的知识停在训练数据里，昨天的新闻它不知道；
  • 它看不见此刻的界面、公司内部系统、你硬盘里的文件；
  • 它说什么都像在猜，因为它没有做过。
第 3 节

一件 Tool 有三件事

  • 描述：名字、说明、参数长什么样。模型只靠这段描述决定要不要用、怎么填参数。
  • 执行：一个真的会被调用的函数。它在模型外面，不在模型里面。
  • 回填：执行结果回到对话里，模型才接着往下说。

三件事缺一不可。描述写错了，模型挑错工具；结果不回填，模型只能装作做完了。

第 4 节

一次调用的完整链路

这是最容易忘的一段，所以单独拿出来。四步，顺序不能乱：

  • ① 用户说出想要什么；
  • ② 模型决定调用哪个工具、传什么参数；
  • ③ 运行时真的去执行那个函数；
  • ④ 结果回到对话里，模型据此写出回答。

第 5 节

三个常见误解

  • 「给模型接了 Tool，模型就学会新知识了」——不会。Tool 给的是做事的能力，不是知识。
  • 「Tool 就是插件市场」——插件是装东西，Tool 是让模型能调一个东西。
  • 「接得越多越强」——工具太多反而更容易挑错，描述质量比数量重要。
第 6 节

边界：谁说了算

模型只负责提议，运行时负责裁决。删文件、付款、发外部消息这类动作，运行时可以拒绝，也可以要求人确认。模型永远不是最后一道闸。
