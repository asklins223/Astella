# 启动问候的「重复、迟到、像旧消息」：判据与两个真窗口修法（2026-10-16）

用户反馈里除了「没声音」，还点名了送达问题：**重复、迟到、像旧消息**。这一篇记录在真窗口里
复现出来的形状、找到的两处调用链原因，以及修后同一场景的前后读数。声音那一条见
[companion-proactive-voice-redrive-2026-10-16.md](companion-proactive-voice-redrive-2026-10-16.md)。

## 现象（发行渲染包 + 本地栈，全程不点不敲）

一次窗口里**前后出现两句问候**：

| 修前 | 时间 | 气泡 |
| --- | --- | --- |
| 旧问候（上一次启动生成、没人看见） | t=4s | 「周五晚上好，来了。今天过得咋样？」 |
| 这次启动自己的问候 | t=12s | 「晚上好，来了。今天过得咋样？」 |

服务端那一刻的账：旧问候的投递在 12:29:42.539 被标成 `suppressed`（作废），
客户端却仍在 12:29:43.4 把同一句显示了出来——它手上是**作废之前**那次投影读取的负载。

## 原因一：没被看见的启动问候会顺延到下一次启动

启动问候是对**某一次启动**说的话（`app.started` 观察），而生成要十几秒。那次启动如果先关了
窗口（或网络慢），投递就停在 `queued`；下一次打开时它才被认领，用户看到的是「上一次启动的
问候」，紧接着这次启动自己的问候也到。上一次启动的问候在 11:40:48 生成、11:41:39 被下一个
窗口显示，就是这个形状。

## 原因二：那句没人听见的话还压着这次问候（2 分钟跨话题地板）

跨话题地板（2026-10-16 的用户口径：全局主动不节流太严重）量的是 `assistant_deliveries` 里
最近一条 `initiative:` / `run.completed:` 的时间。作废的旧问候**仍然算在里面**——于是快速重启
时，这次启动自己的问候被推迟整整两分钟（真栈实测：不修就是等满 2 分钟才产出）。

## 原因三：作废拦不住已经在路上的字（展示侧）

服务端的作废只是记账；投影负载已经发出去，客户端照旧显示。真窗口把这个顺序记得很清楚：
12:29:42.539 作废 → 12:29:43.4 仍然显示。所以展示这一侧也要判「这份负载是不是这次启动
登记之后读回来的」。

## 修法

1. **新启动作废旧问候**（`apps/api`）：`delivery-service.retireSupersededLaunchGreetings` 把
   仍处于 `queued`/`delivered` 的、来自更早一次 `app.started` 的主动投递按 `suppressed` 收掉；
   在 `/me/companion/awareness` 记录到一次**真实启动**（`recorded && topic === 'app.started'`）
   的同一事务里执行。只动 `app.started` 那一类：她自己的感想、她排的关注、用户约的提醒都不动。
   正文仍在连续历史与手记里读得到。
2. **地板读数排除用户永远看不到的行**（`packages/agent-host/proactive-floor.ts`）：
   `state NOT IN ('suppressed','expired')`。`queued`/`delivered` 仍然算——那一条随时会被看见，
   「刚说完又开口」正是这条闸要挡的。
3. **展示闸门**（`apps/desktop-client`）：这一次启动的 `app.started` 拿到成功回执之后
   （`companion-launch-gate.ts`）才允许显示投影里的主动气泡，并且要求这份投影是**登记之后**
   读回来的（`companionHomeProjection.projectionFetchedAt >= launchRegisteredAt`）。登记会触发
   投影重读一次，服务端那时已经收掉旧问候。被闸门挡下的气泡不回执也不丢：投递仍在 `queued`，
   重读回来的那一次照常交给它。窗口起在后台时闸门保持关闭（她不该对着没在看的人开口），
   用户真的把窗口调到前台时 `app.started` 补发、闸门随之开启。

## 真窗口前后对照（同一场景：先造一条没被看见的问候，再起窗口）

| 检查 | 修前 | 修后 |
| --- | --- | --- |
| 上次没被看见的问候 | 被作废，但 **t=4s 仍显示** | 被作废，**没有出现** |
| 这次启动自己的问候 | t=12s 出现 | **t=8s 出现（只有这一条）** |
| 窗口里收到的问候文本 | 两句 | **一句** |
| 两次启动的整体耗时（真栈脚本） | 旧问候把新问候压住 ≥2 分钟 | **14 秒** |

## 验证范围与边界

- API：`npm run typecheck` 干净；`proactive-run-completed-gate-guard` 4/4（新增一条钉住
  地板读数排除 `suppressed`/`expired`）；delivery 单测 11 通过 1 跳过。
- agent-host：`npm run typecheck` 干净；42/42。
- ai-worker：`npm run typecheck` 干净。
- Desktop：`npm run typecheck` 干净；伴星与 app 两目录 **108 文件 / 944 项**通过
  （新增 `companion-launch-gate` 5 项，含三条接线守卫：登记点、重读点、展示闸门）。
- 真窗口（发行渲染包）：上表；窗口跑的是工作区构建产物，安装包要重新发布才带得上。
- **没验到的**：多设备同时在线时的先后（另一台设备的 `app.started` 也会作废旧问候——这是
  想要的行为，但没有双端并跑过）；后台启动后一直不聚焦的那些窗口不会显示主动气泡
  （闸门不开，投递保留在队列里等下一次机会）。
