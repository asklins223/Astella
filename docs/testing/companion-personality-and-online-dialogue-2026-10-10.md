# 线上伴星人格与对话核对（2026-10-10）

## 结论与范围

用户提供的两张截图是真实线上对话。本次通过已登录桌面账号的产品 API 读取人格、关系、记忆、方法和两轮执行回放，并在安装版窗口核对显示。没有把开发库状态当成线上状态；原始私人回放留在被忽略的本地 `outputs/companion-persona-audit-20261010/`，不提交到仓库。

**这个账号没有产生过模型人格修订，用户感受不到变化有数据依据。** 已存在偏好记忆、自改工具、方法存储和记忆整理机制，但不能把这些基础设施等同于已发生或已验证的自主人格成长。本次修复了自改保存与生效的确定性缺陷；同模型合成对照仍复现招呼复述，不能宣称自然度已经解决。

本次修改在工作区，尚未部署线上。实际线上读取和窗口观察证明的是原问题；数据库测试证明的是修复后的存取行为；合成模型样本只说明有限情境中的表达与分类结果。

### 调查操作造成的版本记录

查看人格页时误用了旧的可访问性索引，误触“适度”，随后立即将“表达分量”恢复为原来的“活跃”。这留下第1、2版两条 `author=user` 的手动修改记录，并将这一字段来源标为用户。安装版窗口已再次核对“活跃”选中、无待生效、两条记录均显示“手动修改”。这不是她的自主成长，不能混入统计。原始第0版的结论取自误触前读取。没有删除历史来掩盖这次操作。

## 实现核对与修复

### 自改版本保存和下一轮采用

原来的 `companion_revise_own_style` / `companion_revise_own_tags` 描述承诺下一次对话生效，实际共用的 worker helper 直接改当前档案。API 有暂存和手动激活函数，创建新用户回合时却没有自动采用路径；持久手记不会因为发一句消息就另建 conversation。直接更新还没有清除旧的 `pending_revision`，当前版本前移后可能违反数据库的 `pending_revision > revision` CHECK。

修复后：

- 模型的语气和标签修订先写不可变版本，再设置待生效指针，当前档案保持原版本。
- 下一轮新的用户消息被服务接受时，在同一事务中采用模型待生效版本；页面读取、幂等重放、非法或被拒绝的请求不触发生效。
- 当前 run 已固定的人格版本继续使用原版本，历史产物不重写。
- 同一回合先改语气再改标签保留两项修改；首次并发写入先建立可锁定账号行，避免两个“第1版”相撞。
- 用调用固定的 revision 检查迟到提议；用户的新设置优先。模型不能覆盖用户暂存草稿，用户草稿也不会被新消息擅自激活。
- 用户明确修改表达分量或边界时清除被取代的待生效指针，新号排在历史队尾。修订记录保留作者、理由、模块范围和来源空间。
- 工具说明、回执和方案40同步到实际生效时点。

这接通了“提出修改后确实保存并在后续使用”的基础链路。它没有新增后台人格反思任务、反馈评分或定时改标签；没有证据就制造变化，不能算成长。

### 当前纠正与资料背景

分类器原来只接收最后5条消息的正文，没有与这些消息对应的服务器时间。此次补齐同一条消息的时间与冻结时钟；位置、角色或正文不匹配时日期保留未知。分类规则区分对刚才发言的纠正、明确查询外部记录、一次性表达要求和长期表达修订。普通纠正使用已有交流证据；真实日期查询保留读取能力。

`here_and_now` 不再每轮读取并注入最近3篇笔记清单。当前页面、用户本轮指称、真实资料读取和历史回放保留。线上样本确实带有这份清单，但它只是来源之一，移除它不能自动解决正文复述。

## 同模型合成对照

调用脚本：`workers/ai-worker/src/live-tests/companion-greeting-correction-probe.ts`。

四个表达样本、每个旧清单/当前版本各一次，共8次；另外4次分类调用。使用现役生产 builder、默认大肥鱼人格、DeepSeek v4.1 Flash、原有闲聊参数和原生合成历史；无线上用户资料、无数据库写入。表达阶段固定闲聊解释，因而不是完整 HTTP/队列回合。判据在调用前冻结，没有根据这批答案重新调候选后再把同一批当验收。

| 情境 | 结果 |
| --- | --- |
| `hi` | 旧版和移除清单后都复述笔记；当前样本甚至更长。未达标 |
| “早啊” | 两版都转回昨天的笔记。当前样本还出现“刚醒”等无记录的角色经历。未达标 |
| “这不是昨天的吗” | 两版均承认昨天，当前样本38个可见字符，无三篇标题清单、无下一步学习邀请；但“没有别的可分享的新记录”仍像系统汇报 |
| “我就是打声招呼……” | 两版能短句接回；当前样本27个可见字符。单例不能证明稳定改善 |

模型输出和请求收据保存在本地合成结果 `outputs/companion-persona-audit-20261010/synthetic-probe/results.json`。**本批不能证明移除清单使招呼自然，也不能证明本次改动带来长期人格变化。** 没有追加输出截断、固定招呼回复或关键词改写来掩盖失败。

## 验证与仍未闭合的部分

- worker相关7个测试文件共123项通过，覆盖人格、分类、当下信息、run固定、投机首步和运行时。
- API待生效规则单测7项、桌面待生效版本展示测试10项通过，新的生效条件能通过客户端契约并显示。
- API已有待生效人格集成与新增 worker写入→API创建回合采用集成共20项通过；受限API/worker角色、独立一次性Postgres库，包含首次并发与用户草稿保护。
- worker笔记可见性Postgres集成2项通过。
- shared、api、desktop-client、ai-worker各包的 `npm run typecheck` 通过。没有用桌面根references配置替代包检查。
- 安装版窗口核对了人格、待生效、版本作者、记忆和空方法列表；修改后的后台链路尚未通过线上发布后的窗口验证。

稳定触发人格反思、从经历提炼可用方法、在后续行为中采用并用用户反馈修订，仍需要各自的真实证据。当前实现的自改入口位于模型工具调用；经常采用的无工具闲聊投机首步本身没有自改机会，后台记忆整理也不调用人格自改。这个账号目前9次互动、少量记忆、空方法，不能据此证明所有成长机制永久失效，也不能向用户保证“再聊几天就会自然进化”。

下一步体验验收应直接检查普通招呼是否只接当前交流、纠正是否自然撤回误会、已记录偏好是否在后续行为中兑现，以及人格修订是否有来源并在下一轮产生可感知变化。增加版本数或不断改标签不是这些行为的替代证据。
