# Windows 安装写入拒绝、换目录与登录标题按钮修复（2026-10-12）

## 问题与接续基线

用户报告安装准备目录里的 `d3dcompiler_47.dll` 出现 Access denied，同时已有安装无法更换位置；登录页的最小化、最大化、关闭按钮消失，进入首页后恢复。

接续时的工作区已经包含 Qoder 的部分修改。实际执行层未能编译：`IsWriteRefusal` 被其他类调用但仍是 private，`HashSet` 把 `StringComparison` 当成 comparer；暂存目录的创建也在抽取中丢失。安装器界面仍将已有安装的位置输入框设为只读、禁用更改按钮，执行层测试仍断言禁止迁移。附件的安全软件归因缺少真机日志支持，只能作为可能性。

## 最终行为

- 文件创建、写入及校验作为一组重试，针对权限拒绝和共享冲突；损坏、越界和链接等包体错误直接拒绝。
- 写入持续被拒绝时尝试同卷的其他暂存目录，避开目标目录自身；原异常保留在诊断中，显示中文建议，不声称 ZIP 一定已成功写入或安全软件一定是原因。
- 校验错误、取消和准备失败清理暂存目录；提交失败恢复旧文件和真正的旧注册记录。
- 已有安装的位置输入框和更改按钮开放。新位置安装并登记成功后再清理旧程序，重叠目录被拒绝。更新保留桌面入口偏好，取消桌面入口时也清除仍指向旧位置的自有快捷方式。
- 清理旧程序失败不会把成功安装判为失败，完成页和 `setup-logs/*-leftover.log` 记录残留路径；资料目录等受保护位置仍拒绝清理。
- 标题按钮层级为 85，高于登录页的 80、低于带路浮层。按钮继续调用真实窗口 IPC。

## 真机范围

当前宿主是 macOS，未在 Windows 上运行 WPF 窗口、真实注册表、快捷方式或 Defender。代码里追加了 Windows DLL 短暂共享冲突及持久拒绝场景，随现有 Windows CI 执行；向导脚本现在要求已有安装的位置仍可编辑，并验证更改按钮可用。原始报错机器的拦截原因仍须由 Windows 真机与安装日志确定。

本地 `release/astella-1.6.0-win-x64.exe` 使用当前工作区构建，未签名、未上传，版本号保持 1.6.0。成品包含完整应用与卸载器；本机执行层的包体验证只模拟登记，不构成 Windows 安装窗口证据。
