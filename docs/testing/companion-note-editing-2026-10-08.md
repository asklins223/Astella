# 当前笔记编辑与段落锁定 · 2026-10-08

用户确认：伴星可以在当前笔记光标后插入、在末尾追加、删除选区或段落、把原文替换为新正文、表格或流程图。AI 处理期间锁住相关段落，并把相同反馈用于「发给伴星」和「原句解读」。

## 本次实现

- `companion_edit_note` 登记在唯一能力目录中。光标和选区来自当前纸面；发送前先保存本地改动，再冻结当前版本与原文。用户在正文点好位置后转到聊天框，仍保留笔记光标。选中阅读原文后新增「让伴星改这段」入口。
- API 从现有工具账本领取已授权的编辑，核对轮次、账号世代、空间权限、当前笔记及版本。通过现有 Hocuspocus 连接修改实时 Y.Doc，沿既有保存、投影和搜索链路落库；worker 获得实际保存回执后才宣告完成。没有增加另一条直接覆盖正文 SQL 的路径。
- 插入、选区替换、选区删除、整块替换和删除都核对目标原文；原文变化时拒绝覆盖。未修改块保留 CRDT 身份及来源属性。工具调用标记防止同一调用重复应用；恢复回执也带正文更新，阅读页与编辑器同步刷新。
- 锁定是局部、可读的整段流动光带与状态文字。富文本通过事务过滤阻止输入、粘贴、删除、格式转换和撤销触及锁定块；源码编辑器也过滤修改；阅读块暂时禁用内部交互。其他段落仍可编辑。失败、停止和完成解除锁定。工具实际执行时按冻结光标、选区或末尾提供范围，补足关键词反馈无法识别的说法。
- Off、Lite 和系统减少动态使用静态提示，不播放扫光。「发给伴星」继续解释原文；「让伴星改这段」交给用户输入编辑要求；「原句解读」沿原批注任务生成解读。

## 验证边界

没有进行全仓或打包产物回归。单次新正文上限 20,000 字符；阅读选区仍遵循现有锚点上限，过长或不可定位选区不能直接发起局部编辑。表格与 Mermaid 沿现有解析器呈现，不能等同任意图形内容编辑。真实模型样本证明上述请求可走通，不承诺所有口语措辞和知识内容质量。

测试中既有聊天引用浮层曾遮挡笔记工具栏，使用键盘完成对应操作；这不构成所有浮层、缩放与指针路径的验收。临时验证笔记在测试结束后放入回收站，窗口恢复到先前笔记，已有笔记正文未改动。

## 同日视觉返修

用户指出首版扫光几乎看不见，且不接受左侧颜色条。检查真实样式发现：编辑器段落规则的 `background: none` 覆盖了处理底色，低对比的白色覆盖层又使文字发灰。首版窗口验收没有发现这个视觉问题。

删除处理区左侧阴影，改用独立伪元素覆盖整段，以海盐蓝、浅紫和奶油亮带进行 1.8 秒连续横向流动。`multiply` 混合保留暗色字迹；右上状态文字改为清晰的深色纸签。已有批注与处理状态重叠时，处理期间隐藏批注边条，且批注伪元素不再抢占处理标签。Lite、Off 和系统减少动态保留整段静态蓝灰底色。

在真实 Electron 窗口用现有工作范围 store 驱动待处理状态，分别检查阅读、富文本和源码；这是视觉与锁定验证，未重复发起模型请求。原文及排版尺寸保留，边条为零，富文本 `contenteditable=false`、阅读区 `inert=true`；撤下状态后锁定清零。关闭、轻量与系统减少动态均为 `animationName=none` 且底色仍可见。富文本/源码编辑器 19 项回归再次通过，`git diff --check` 通过。
