# 从知识讨论生成笔记与库内链接 · 2026-10-08

用户确认：先讨论知识点，再要求伴星写成一篇笔记；直接保存，之后可以编辑，并自动寻找库内相关笔记生成链接。

## 实现与范围

- 唯一能力目录登记 `companion_create_note`，不要求已有笔记作为起点。当前请求明确要写成笔记时才能进入写工具面；普通问答、功能咨询与闲聊不创建。新笔记默认 private，沿既有阅读、CRDT 编辑和搜索链路继续使用。
- 手工新建与伴星新建共用 `createPrivateNoteRecords` 和 0395 的初始记录写入函数。worker 仅获得受作用域、既有空间 owner 权限和真实创建轮次约束的函数执行权，仍没有 notes 的通用 INSERT/UPDATE 权限；函数不改已有笔记，全局自动执行不扩大空间写权限。现有 API 保留标题/图像处理、文档初始化和 Journey 行为。
- 自动关联用关键词候选的 any 模式，按命中词数排序；精确找笔记的默认 all 模式保留。检索只读本人或已共享内容。创建前必须实际搜索；关联必须有本轮真实正文读取回执，并在保存事务中复核可见性与当前版本、锁住所选材料。正文内部链接也只允许核对过的 ID；额外附「相关笔记」及关联说明。没有相关内容可生成独立笔记。
- 新笔记有稳定的本轮身份、保存回执和可打开入口。成功回执恢复不重复创建；最后一句模型回复失败时，失败历史仍保留实际已保存笔记入口，聊天失败与笔记保存分别表达。
- 修复多步结束时的 Responses 流式历史：从原生 Agent 请求恢复 function_call、function_call_output、phase 和不透明 reasoning 句柄，不把工具回执发送为 role=tool 的普通 Responses 消息。原生历史仍经过同一外发/PII 治理和请求预算检查。工具进度展示取能力目录的人话标签。

## 真实窗口与真实模型

在开发账号 `companion-probe` 的当前空间，用原生窗口先问欧姆定律的适用条件，再说「把刚才这个知识点总结成一篇笔记给我」。问答轮 `32e1b34b-3f8e-45d6-9cdd-6da9904b0ef6` 0 工具；创建轮 `63999676-798e-4e54-a615-b55606b0ee54` 被识别为 task/act，实际搜索两次并创建一篇笔记 `0e4ef3b2-7b04-47ab-87cd-ba5c8f02ffe8`，版本 `d70cc45b-79e2-48e8-b41c-748db6165584`。没有命中旧笔记时没有虚构链接。

接着要求写电功率与电阻、固定电压与固定电流的关系，关联已有欧姆定律笔记。轮次 `e7391346-33d8-4357-afe8-a075107de3f0` 实际保存了笔记 `27af9007-a6da-400c-857b-b95bfbef5010`，版本 `f9b866c4-c70f-469d-a39d-62b3e055a1b9`，含指向前一篇的真实库内链接。**该轮最初的最后一句回复失败**：原生工具步骤成功，终答流式路径错误地发送普通工具角色，供应商返回 HTTP 422。保留这个负例，不把保存成功说成整轮交流成功。已补原生历史协议和保存后失败留档回归。

原生窗口操作核对：电功率笔记完整可读；点击「相关笔记」中的链接抵达欧姆定律笔记；「返回上一篇笔记」回到电功率笔记，全屏阅读状态保留。用户已有批注和正文没有被本任务改写。

修复后的真实模型验证使用独立数据库、合成讨论和相关笔记：`deepseek-v4.1-flash` 走完 4 步、4 次工具（2 次检索、1 次读笔记、1 次创建），最终 SSE 与落库笔记、链接身份一致，6 个实际 requester 调用包含分类及被丢弃的预生成。耗时约 23.3 秒，仅是这一小样本，非延迟承诺。原始产物：`outputs/audits/2026-10-07-live/note-authoring-live-20261008.json`。夹具随后清理；这项不包括 HTTP/队列和最终 assistant 消息提交，不能冒充修复后的完整 Electron 请求验收。

前一个合成样本漏掉库内关联，断言失败；当时脚本在保存输出前就断言并清理，只有本聊天的失败调用记录，未留下完整正文/工具输出。随后增加 any 候选检索，也补齐合成旧笔记中的符号定义，并把脚本改成先保存结果再断言。两个因素同时改变，没有单独归因的实验结论。

## 尚未解决的内容质量

真实首轮沿用旧回答，把 R=U/I 写成无条件成立，遗漏 I≠0；另一次把比较不同电阻的比例关系前提写成「R 为常数」。最后回复曾误报已完成的旧任务还在排队。已经增加知识条件和当前交付范围的生成指导；后续样本修正了固定量/变化量的区分，但仍出现交流功率条件与 I≠0 的适用对象不准确等问题。

当前没有把同一模型自我核对说成独立事实验证，没有增加在线审校模型、改模型或改写用户已经保存的笔记来伪造内容质量通过。这次能力、保存、编辑与真实链接验证通过；知识正确率和所有口语请求的稳定性没有通过承诺级验收。
