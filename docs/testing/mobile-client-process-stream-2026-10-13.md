# 手机思考流与工具过程接入 · 2026-10-13

本轮按用户要求接入桌面端已具备的真实思考内容流、工具执行与回看能力，同时修正与该流程直接相关的显示、滚动、消息归属和启动问候问题。代码现状以 `apps/mobile-client/src` 为准；没有调整后端协议或复制 Agent 执行逻辑。

## 发现与实现

| 原问题 | 修改后的行为 |
| --- | --- |
| WS 已接受 `assistant.thinking`，手机状态处理却没有该分支。 | 按 run 身份和思考 index 接收增量；思考独立于回答和语音，连续片段接续，缺片另起段，重放不重复。 |
| 界面只筛选不存在的 `running` 工具状态。 | 显示真实 `requested/executing/waiting_confirmation/succeeded/failed/outcome_unknown` 等状态、可读名称和摘要；一个调用的更新仍在原行，预备调用与实际调用合并。 |
| 终态后实时行移除，刷新不读取思考/工具档案。 | `run-nodes` 请求 `includeThinking`；按消息所属 run 补取最近 20 轮以外的档案。完成、失败、停止后仍保留一轮一份的过程。 |
| 实屏首次接入后，完成归档会擦掉实时工具、将两段思考合成一段。 | 归档 SQL 只保存展示字段，没有完整工具事件的 `riskClass/toolVersion`；改为展示字段校验，并将归档与实时已接收事件按 seq 合并重建。归档不能清掉真实收到的工具。 |
| 新回合尚未有回答时，场景仍显示上轮回复。 | 当前回合先显示自己的阶段/思考/工具；同轮自然分句接续，下一轮不能借用上轮回答。 |
| 流式回答和场景预览裸露 Markdown 标记。 | 与最终回答使用同一份安全 Markdown 展示。 |
| 思考与工具更新不会驱动记录跟随滚动；加载旧记录会移走可见内容。 | 监听实际内容高度；用户向上阅读时保持位置，提供“回到最新”；前插旧记录按消息锚点恢复。 |
| 旧笔记交付挂在新的最后一条回答；待确认入口被旧交付隐藏。 | 成功回执带 runId，交付按产生它的回合显示；待确认入口独立显示。 |
| 工具已经给了摘要时，提案可能没有确认指纹、永久无法确认。 | 缺指纹即读真实提案详情；取不到时可重新核对，不由摘要推断可确认。 |
| 后台自主补充失败被当作用户请求失败，形成徽标与输入区错误。 | 错误保留在所属过程；后台轮不会接管输入区；“待接手”只指向未完成且没有最终回复的用户轮。 |
| 每次文档刷新/HMR 都生成新启动身份并问候。 | 浏览器 tab 的启动身份存于 sessionStorage；同一用户只有启动观测成功后才标记，刷新、重连、换书房不重发。 |
| 展开工具详情后，面板仍使用折叠时的高度，后续思考行被挤出。 | 按独立内容内层的实际高度重新摆位；展开/收起改变尺寸，入场弹簧只在打开时执行一次。长内容超过可用高度时仍可在面板中滚动。 |

场景页采用一条紧凑过程摘要，点开自绘面板看完整时间线；记录页将过程放在本轮第一条回答之前，多句发言只保留一份。当前思考可展开追尾，过去的段默认收起；手动展开/收起在视图往返和完成接续后保留。显示追赶仅作用于已经收到的文本，不延迟 WS 或模型；减少动态时直接显示。各状态保留文字，逐字更新不整段反复触发读屏播报。

## 真实窗口核验

使用本机 probe 账号，在 `http://127.0.0.1:5174/` 真实发送两个只读问题：第一条查阅《导热与凝固点》，解释两个现象改变的物理量；第二条明确再次读取、仅用一句话对比，用于单独捕捉场景中的实时状态。两条都明确要求不创建或修改笔记。

- 发送后的窗口实际显示“思考 → 读取笔记已完成 → 继续思考”；工具摘要为已读第 1–20 块、共 20 块、1282 字。回答随后落入同一交流。
- 第一次归档覆盖问题在实屏中被发现并修复。修复后重新载入原会话，展开同一轮过程，仍能看到前后两段思考及读取工具回执；没有再次发送该问题。
- 第二条请求发送后，场景不再显示上一轮问候，先显示当前等待状态，随后显示持续更新的思考摘要与“1 项操作”。完成后点过程入口，自绘面板中保留“思考 → 读取笔记已完成 → 思考”三行。展开工具和长思考、再收起思考后，面板实际增高/缩回，三行及工具摘要仍可见。对话/伴星两种视图实际往返，历史中一轮过程只显示一次。向上读时“回到最新”可见；展开工具后保留来源阅读位置。
- 额外检查实际页面 320×740 CSS px：横向溢出为 0，过程行、输入与一级导航可见。浏览器缩放导致 viewport 工具参数和实际尺寸不同，因此尺寸取页面 `innerWidth/innerHeight`；随后恢复默认 viewport。

## 验证范围与仍存在的限制

手机包类型检查通过；最终生产构建通过，Vite 转换 614 个模块，主 JS 1,386.71 kB（gzip 377.02 kB）。本轮没有运行测试套件。真实验证会话中有一次后台模型错误消息，完整只读回答和工具回执仍保留；未改写该已持久化错误记录。开发期间也观察到 API 代理的间歇 `ECONNRESET`，客户端会进入恢复状态，不能将本次窗口核验当作长期连接稳定性结论。启动问候的 tab 身份与幂等逻辑已做源码和类型核对，没有在本轮另建用户、切换真实账号或长期运行计数。

真机触摸、输入法、前后台中断、小米 MiMo 录音与移动声音播放没有在本轮验证；待确认写操作、工具失败与结果待核对没有人为制造。本轮发送的读笔记问题不是资料修改或上传测试。共享依赖仍产生 Node 模块浏览器 externalize 提示，主 JS chunk 仍大于 500 kB；构建通过不等于包体与所有跨包依赖问题已解决。
