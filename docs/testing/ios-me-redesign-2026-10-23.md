# iOS「我的」与子页面重设计 — 2026-10-23

## 目标与范围

用户认为「我的」及子页面的产品组织和 UI 都有问题，要求先想清楚，再重新设计，仅改 iOS，使用中文沟通。本轮从实际调用与可用功能出发重做页面族，保留工作区已有的认证、对话、阅读、桌面及 Android 修改。

原首页把两个设置入口、基于日记的学习评价、重复的伴星头像和直接退出登录放在一起。伴星中心复制最近对话与日记／记忆入口；阅读设置同时重复外观、启动场景和动效。子页主要靠固定小字号与逐行圆角白卡堆叠，原有大字号开关实际上不放大这些文字。

新的层级围绕「本人 → 怎样相处 → 当前书房 → 偏好」组织。大角色与完整对话继续由相伴页承担；「我的」负责身份与可控偏好，减少对内容的重复陈列。蓝色用于主要行动、选择和少量标识，留白和文字层级承接其余信息。

## 页面地图

| 入口／页面 | 主要职责 | 关键行为 |
| --- | --- | --- |
| 我的 | 本人身份、伴星、当前书房、常用偏好 | 个人头像缺失时用昵称首字；设置只有右上入口；无学习评价与退出按钮 |
| 个人资料与账号 | 头像、昵称、登录邮箱、密码、退出 | 昵称修改后才显示保存；退出带后果说明；本人头像与伴星身份分开 |
| 我的伴星 | 相处设定与这台设备的声音呈现 | 名字／表达、相处约定、自动朗读、两类实时活动；关闭活动立即结束 |
| 名字与表达 | 账号范围的名字和说话方式 | 先读完整 persona 或生效预设，再保存完整合同和 revision；收到回执后更新全局名字 |
| 相处约定 | 自由文字的个人参与偏好 | 暂停保留文字；显式保存；空状态可直接编辑；CAS 冲突保留草稿并展示另一份内容 |
| 阅读字号 | 正文大小和即时预览 | 同一阅读缩放设置，滑块和增减按钮即时生效；不重复外观或动效 |
| 设置 | 外观、打开方式、减弱动效、本机工具 | 外观缩略选项；打开角色／记录二选一；系统减少动态优先；设备权限、缓存、关于、服务连接 |
| 设备权限 | 系统状态与具体需要 | 麦克风和通知按需请求；返回前台刷新；照片／文件说明按次选择；不虚构相机入口 |
| AI 与数据 | 账号授权、外发偏好与当前书房导出 | 失败可重试；完整协议；脏状态才保存；图片上传与模型读取分开；关闭外部服务不承诺本地接管 |
| 服务连接 | 私有部署地址与健康检查 | 输入不自动改变会话；测试不带登录凭据；保存前显示目标并确认重新登录 |
| 缓存管理 | 这台设备的可清理副本 | 按类统计；网页数据标明估算；部分清理失败如实显示；不删模型、资源与云端对象 |
| 关于 | 实际版本、资源状态、说明与许可索引 | 版本检查失败／未提供不显示「已是最新」；不把组件摘要写成完整许可或不成立的隐私承诺 |
| 书房管理 | 当前与其他可进入书房、创建／加入 | 先列表，再当前书房邀请与成员；保留改名、退出、解散计数与确认 |
| 邀请与成员 | 当前书房的邀请、名册与所有权 | 所有者、成员、个人书房各有真实边界；一次性回执、撤销、移除、转让保留 |

## 实现与真实调用

页面集中在 `apps/mobile-client/ios/Astella/Screens/Account/`。`AccountPage` / `AccountHeader` 统一页面骨架与紧凑返回栏；`AccountPanel` / `AccountGroup` / `AccountDestinationRow` 组织内容；反馈、按钮与头像共用组件。原 `HandAndAccountScreens.swift` 保留星轨与手边，不再承载账号页面；旧 `SettingsDetailScreens.swift` 的页面已转入功能目录，旧源文件和 Xcode 引用一起移除。

星轨仍在用的 `settingDestinationRow` 保持原实现并放到共享 `Design/Components.swift`；手边私有 label 保留，避免拆文件误删真实调用。`MainTabShell` 仍使用原来的 `NavigationStack` 与 `AccountScreenRoute`，只补齐 Debug 直达入口。没有新增后端路径或改动 Android。

| 对象 | 请求／状态归属 | 本轮修正 |
| --- | --- | --- |
| 昵称、头像、密码 | `AccountMethods` → `/auth/profile`、头像上传、`/auth/change-password` | 保留真实上传与认证流程；当前密码字段使用 `.password`，其余用 `.newPassword`；保存成功后全部会话重新登录 |
| 名字与表达 | GET/PATCH `/companion/pet-profile` | 首次无覆盖档案时读取 `activePreset` 和 `profileRevision`；完整回传文档，编辑字段标为 user；不提前乐观更新全局名字；409 保留 UI 草稿并提示核对 |
| 相处约定 | GET/PUT `/me/companion/participation` | 保留原文和 enabled，使用 expectedRevision；409 读取最新 revision／原文后供用户核对，不丢草稿 |
| AI 设置 | GET `/me/ai-settings`、PUT `/me/ai-data-policy`、PUT `/me/ai-consent` | 保存方法返回真实成功结果；无状态不当成已授权；协议与账号同意范围沿用桌面当前版本的说明 |
| 导出 | GET `/export/workspace` → 临时 JSON → 原生分享 | 名称与文案明确当前书房；请求持有书房与会话快照，切书房后清除旧分享入口、丢弃旧响应；失败保留重试，不宣称整个账号导出 |
| 本机偏好 | 原 `UserDefaults` / `AppStorage` 及 Store setters | 不变更已有 key；系统减少动态和本机手动选择合并呈现有效状态 |
| 权限 | `AVAudioApplication` / `UNUserNotificationCenter` / 系统设置 | 前台恢复刷新；已授权后的按钮叫「去系统设置」，不把跳设置写成即时撤销 |
| 服务连接 | 无鉴权 GET `/health` | 保存前确认目的服务；测试不修改当前会话 |
| 版本检查 | GET `/app/version` | 成功比较才报告结果；404／错误／无有效字段如实说明 |
| 书房与成员 | 原 `SpaceMethods` 的工作区／邀请／成员 API | 只调整组织与文字排版；保留 generation、token 隔离与破坏性操作确认 |

登出额外清空伴星名字、表达、完整档案、revision 和版本检查状态，避免下一账号短暂看到上一账号的设定。缓存清理保留真实错误，不再吞掉文件清理失败后统一显示成功。

## 验证边界

本轮没有修改真实账号的名字、AI 授权、密码、书房所有权或邀请。已有服务端合同按源代码核对；示例保存回执不能证明真实写入 API 成功。没有在实体 iPhone 上验证触感、语音、灵动岛或 60/120 Hz，也不把截图当成手势／流畅度证据。系统授权弹窗与真实口令提交不在本轮自动点按范围。

原生窗口中完成了首页进入资料／伴星、昵称编辑与本地保存的操作。原生开关的点按／拖动尝试未取得可靠状态变化证据，未计为通过；窗口曾在并行调试设备间变化，随后工具明确返回 `The Mac is locked and automatic unlock could not unlock it`。已请求用户手动解锁；锁屏后只继续 SDK 截图和编译检查。**软件键盘避让、原生侧滑取消、快速往返及开关完整交互仍未完成实测**，不能用 headless 截图补成通过。

未触及的消息历史代码仍有多余 `@discardableResult` 警告；缓存代码原有未使用变量、Cubism 静态库 26.2 与应用最低模拟器版本 18.0 不同的链接警告仍保留。未运行全仓回归：本轮不改共享类型、后端或 Android，主要构建依据为 iOS 应用目标和上述集中窗口检查。
