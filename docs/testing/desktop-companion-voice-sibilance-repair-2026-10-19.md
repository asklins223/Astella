# 桌面伴星气音、齿音刺耳的播放修复

2026-10-19，macOS 本地客户端。用户最终明确描述为声音变尖锐，尤其气音带有“呲滋”声，语速没有加快。

## 确认的问题

当前安装版为 v1.8.23，声音设置使用千问、龙华。实际缓存 MP3 为单声道 22050 Hz。最近从 `decodeAudioData` 改为 WebCodecs 后，解码器虽然连续保留了 MP3 状态，但每个 576 样本的输出都直接作为一个源采样率的 `AudioBufferSourceNode` 播放，约每 26 ms 新建一次节点。

这遗漏了解码之后的重采样。旧的整段 `decodeAudioData` 会先把整条 PCM 转到 AudioContext 采样率；直接播放源采样率的小 buffer 则经过播放节点自己的线性插值。高频镜像和片段边界的插值误差仍然存在。仅证明解码 PCM 相同、计划起播时刻没有空隙，不能证明最终播放波形相同。

Chromium 的两个路径可分别参见 [AudioBufferSource 的插值实现](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/modules/webaudio/audio_buffer_source_handler.cc) 和 [AudioBus 的整段重采样](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/platform/audio/audio_bus.cc)。本次结论以项目实际 Electron 运行时的离线渲染结果为依据。

## 修复

- 在 WebCodecs 与播放节点之间增加连续 PCM 重采样器，跨帧保留历史、前瞻与小数相位。常用升采样采用 32 点 Blackman 窗 sinc，参数与当前 Electron 整段转换的输出对齐；降采样按比例扩展窗口，抑制折回可闻频段的高频。
- AudioContext 收到的所有 buffer 已是设备采样率，播放节点不再逐帧独立重采样。起播时间使用整数设备样本序号，避免累积时长取整误差。
- 等解码器 flush 完成后交出重采样尾部，最后一个输出播完才完成。停止后的 flush 不再排出尾音。22050 Hz 输入只需约 0.73 ms 前瞻，继续支持边收边播。

此次播放修复没有额外增加均衡器、去齿音器、降噪、动态压缩、混响、变调或变速。重采样本身包含必要的抗混叠/抗镜像低通滤波，不能把它描述成“完全不做滤波”；参数与原有整段转换对齐。

## 补充复查：合成参数也需要一致

用户追问是否排除了其他问题、是否做了专门音频处理后，复查确认另一处参数分歧：预热/整段合成会读取账号引擎和音色，并合并基础声音描述、本轮语气与长期方言；缓存未命中的伴星流式分支却使用全局引擎/音色，并可能让本轮指令替换整个基础描述。这可能造成不同取音频路径的听感变化；尚不能据此断定用户那一段的刺耳声也来自合成参数。

已提取 `tts-synthesis-profile.ts`，两条合成路径共用同一套解析；伴星段的直接流式分支也读取账号选择。V1 文本流式接口保留请求参数优先、配置兜底的原有约定。增加仅含引擎、音色和指令来源分类的流式日志，不记录音频、正文或密钥。

合成端原本就会消费声音描述与情绪/拟声标签，目录包括 `asmr`、`whispers`、`gasp` 等，它们可以影响气声表现。这次未新增或开启这些效果，未核实用户所指录音是否用了这些标签。千问数字参数仍使用既有默认值：`volume=50`、`rate=1`、`pitch=1`。

本次改动范围为桌面播放器、API 合成参数解析、相关测试与本记录；未修改手机客户端。

## 补充复查：流式朗读漏接 Live2D 嘴型振幅

用户在修复版里发现伴星说话时嘴没有跟着动。整段缓冲播放经过 `HomeV2AudioController` 的 `AnalyserNode`，再逐帧写入 `setHomeV2VoiceLevel`；WebCodecs 流式播放绕过这段逻辑，直接连到扬声器，所以 Live2D 收到的嘴型振幅一直是 0。

流式音频现在也先经过同一类 `AnalyserNode` 再到扬声器，并复用现有 RMS、平滑和释放曲线更新嘴型。分析器不添加均衡、增益或其他声音效果。中断时会取消采样帧并断开节点，正常结束时嘴型平滑收回。

表情 cue 的链路仍在：签发片段附带 `cue`，播放阶段的 `speaking` 事件带上它，`useCompanionSpeechExpression` 接收后交给 `WindowLive2D`；本次额外加了流式播放 cue 的接线断言。若这一轮被判为 `neutral`，按设计不会显示明显的情绪脸。

本次补丁的 4 个相关测试文件共 54 项通过，覆盖流式振幅进入共用嘴型通道、音频自然结束后的分析器清理、流式段的情绪 cue 传递，以及现有 Live2D 情绪映射。`npm run typecheck` 与 `npm run build` 通过。真实窗口已重新编译，待用户试听确认实际模型的嘴型幅度与情绪观感。

## 最终输出波形验证

取当前客户端的一段实际缓存音频（295 帧、169920 个解码样本）。将相同源 PCM 打包为无损浮点 WAV，交给同一个 Electron 的 `decodeAudioData` 做整段转换，作为参考。分别把旧播放器与修复版的全部真实播放节点送入 `OfflineAudioContext`，比较最终渲染结果；不以节点排播时刻代替输出验证。

| 设备采样率 | 旧播放器 RMS 误差 | 修复版 RMS 误差 | 修复版最大绝对误差 |
| --- | ---: | ---: | ---: |
| 22050 Hz | 5.43 × 10⁻¹⁴ | 0 | 0 |
| 44100 Hz | 0.0100263 | 1.01 × 10⁻⁸ | 1.19 × 10⁻⁷ |
| 48000 Hz | 0.0102349 | 8.77 × 10⁻⁹ | 2.38 × 10⁻⁷ |

误差以归一化浮点 PCM 计。48000 Hz 总长度与源音频的差小于一个设备样本；44100 Hz 长度完全一致。这里的误差是相对同一份 PCM 整段转换的差值，不是语音合成器本身的信噪比。

诊断程序、输入副本、对照 WAV 和测量结果位于本地忽略目录 `outputs/voice-harshness-2026-10-19/`。真实语音不加入 Git。
