# 文档、随文图片与本机缓存交接验收（2026-10-09）

接续 Qoder 任务 `809f7da1-f8d9-46cd-8640-bf3adcc05591`、`6011f1e3-11c0-4e86-90ea-c05ac596a36a`。核对任务原始要求后完成 Word/PDF 图片提取、图片缓存，以及 Markdown 带图导入导出的剩余链路。用户随后指出多处 UI 问题，本次沿实际窗口继续修正。

## 完成范围

- DOCX：段落、标题、列表与表格转成 Markdown，段落和表格内图片上传并保留位置，同一文档的重复图片按内容去重。
- PDF：文字层、实际绘制的位图进入来源，图片位于前后文字之间；没有文字层的扫描页仍保留图片。覆盖普通 XObject、内联图像、重复绘制与组合绘制。
- TXT：沿现有解码入口处理 UTF-8、UTF-16 与 GBK，真实窗口使用 GBK 汉字文件核对。
- Markdown：文件夹与 ZIP 使用同一套路径解析、图片上传和正文改写。内联、引用式、HTML 图片、中文/空格/转义路径可用；HTML 尺寸保留。代码示例不改写，普通链接仍保留自己的引用定义，已展开图片不留下无用途的路径定义。
- 导出：图片落入 assets，正文使用本地相对路径，可再次带图导入。同标题多篇并发导出先保留文件名，写入使用独占创建，避免覆盖。
- 缓存：复用已有带身份验证的主进程字节通道，上传完成即写入本机缓存。按 API origin 与用户隔离，工作区由对象 key 隔离；原子写入、并发合并、256 MB 全目录 LRU。命中仍通过条件 HEAD 核对当前权限，不下载图片体。磁盘写入失败仍返回已取回的图片。
- 边界：ZIP 解压总量、文件夹符号链接与图片总量有明确限制；批次切空间后不继续把旧资料写入新空间。

## UI 修正

1. 带图导入不再借用重复材料提示的壳子。文件夹/ZIP 选择清楚分开，预览显示所选包名、正文与图片数量、总大小和收录去向。
2. 小标题墨色明确；预览关闭入口固定在滚动附页顶部。窄窗口下换行，提交可以滚动到达。
3. 缺图问题完整保留在可滚动清单中；图片警告不再计入“材料未收录”。批量超过 50 份时按实际超出份数汇报。
4. 取消重新选择保留之前的预览。检查中关闭后，迟到结果不重新展开，忙碌状态会结束；导入失败重开原预览并保留重试入口。
5. 文本/链接/带图模式支持方向键、Home/End，焦点接续当前选择。禁止并行发起另一轮读取；同帧反向开合使用函数式状态更新，最终状态遵循每次操作。
6. 无尺寸小图在笔记中按原大小显示；显式宽度、多图并排和点击查看器继续可用。来源阅读复用图片语法，保留 HTML 图片尺寸。

## 当前限制

- PDF 扫描页保留图像，不自动 OCR；矢量图不转成独立图片，图像掩膜保留明确提示。导入用于正文学习，不承诺复制原文档整页版式。
- 旧 .doc / .odt / .rtf 仍需先另存为 .docx 或 PDF。文档原文件本机解析上限 40 MB，来源正文上限 10 MB；单图上限 5 MB，单文档/包最多 600 张、本地图片总量 120 MB。
- 本轮未测试线上存储或 Windows/Linux 打包运行；其他并行任务的安装器、协作及伴星修改不属于本次 UI 验收。
