# 方案 57、58：继续收尾与复验

## 本次改造

- 学习卡在写入题目前增加整卡独立审题，核对答案依据、歧义和改写后的重复考点。选择、判断、排序和连线向审题者隐藏出题答案，由审题者独立解题，宿主再比较答案；选项携带明确的 0 起 ID。这样避免审题者把选项 1 理解成第一项、照着错误答案自圆其说。简答评分点与操作模板仍核对实际材料及目标。
- 结构与语义问题共用一轮内容修正，最多两次生成、两次审题。每次模型调用各自经过任务、租约、取消、治理、上下文计量与调用记账；生成和审题使用不同审计操作名。网络失败不转化成无限内容重试。审题中的额外解释字段被忽略，不能替代必需判据、来源或独立答案。
- 主动发言先查真实历史：相似度仅选择待核对材料，不直接判复读。存在相近旧话或最近失败／停止的用户请求时，才核对是否实质重复、是否把未交付内容推给“以后想听再说”。工具发言与最终正文都在可见文字及语音发布前执行。普通用户请求不增加这次核对；有事实纠正、新条件或新问题时保留发言。
- 总评由模型按题目身份返回逐题观察，宿主统一添加正确题号。缺项、未知题目或正文自带题号的结果不能覆盖有效总评。只更新总评时不采纳模型返回的任何新评分；必要时仅修正一次总评格式。
- 完成报告增加“重新生成总评”。更新期间保留旧文字，失败明确说明仍在显示旧总评；分数、星级、作答和完成时间均保留。同一命令重放或并发操作复用已有任务。
- 快速聊天入口的首输出／停流超时，未发布文字时可以使用正式配置且能容纳请求的备用服务接续一次。已发布正文、取消和不能容纳上下文时不重放；备用服务及调用次数进入运行记录。
- iOS、Android 的停止、核对与恢复动作移到过程折叠区域之外；失败原因直接显示，已结束任务不再沿用最后一个“正在……”阶段标题。
