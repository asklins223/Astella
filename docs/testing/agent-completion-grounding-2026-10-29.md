## 本轮结果

上一轮留下的反例是：模型没有读取私人笔记，却自行声明 `textOnly=true`，让编造答案通过结构 finish。本轮在用户请求的 work/未定资源档，以及已有实际写入或独立消息的回合中，增加来源与实际交付核对。核对直接使用原请求、宿主提供的材料、真实读取/执行回执和已发布消息，不依赖模型自己列出的 requirements，也不因 `textOnly` 跳过。

已补齐未发布草稿、实际消息和恢复状态之间的区别：被拒草稿作为宿主数据保留，不能伪造为已说出的助手历史；恢复时从数据库读取实际发布的正文，继续缺少的部分。已显示回复的修复仍透传原模型不透明续聊句柄。真实保存等已成功操作保留，修正答案不能重复执行。

这项核对只检查资料可得性、读取对象/版本、实际操作及用户明确要求的独立消息交付。它不评定计算、推理、普通解释或创作质量。关键词清理没有被新的中文意图词表取代。

## 实施与执行边界

| 环节 | 当前实现 |
| --- | --- |
| 输入依据 | 来源分为 request/context/material/receipt/published/provided_image；当前助手草稿和修复提示不成为外部依据，历史助手发言只作语境。只接收能关联实际调用的回执，使用最新结果。 |
| 核对结果 | release/revise/unavailable 严格 schema；逐字绑定本次请求、实际来源 ID/引文和候选片段；虚构引用、错误字段或格式不合格均算 unavailable。格式有效仍不等于语义正确。 |
| 待执行操作 | 执行当前批次前核对其授权、范围和材料；不要求这批同时完成后续目标。随后仍执行原有权限、确认、版本、取消、租约和幂等检查。 |
| 最终交付 | 在 finish、无工具收尾、已发消息后的裸收尾和附属产物收尾核对。独立消息按真实发布记录计数，编号正文不冒充多个气泡。 |
| 模型选择 | 优先使用现有配置副档，仅 unavailable 才尝试主档；负面结论不会换模型寻求放行。主档故障后若副档同时负责回答，两次调用可能是同一模型，不能声称总是跨模型独立判断。 |
| 失败处理 | 最多沿用现有两次修正机会；核对不可用或仍未核对通过时给出宿主未完成说明，保留真实结果，不公开未核对草稿，不把 unavailable 当成功。 |
| 流式输出 | 受保护的工作回复先缓冲，再核对公开；首次并行闲聊草稿仍由原资源判断释放。已知 chat/answer 且无实际操作/发布的普通回复不额外审查。 |
| 任务隔离 | 核对使用单独的 `companion_completion_grounding` AI 任务与政策哈希，不覆盖原生工具循环的模型结果检查点；记录实际 token 用量并沿用现有调用治理。 |
| 来源与中止 | 核对前后验证真实 job lease 和上下文来源；取消、来源修订/撤权和租约丢失不能被转换为可继续放行的 unavailable。最终提交仍经过原有执行边界。 |
| 图片 | 只把实际送达回答模型的内联原图作为 provided_image；结构化视觉观察保留实际 assetId。支持视觉或附件标题本身不证明图像已送达，也不证明识图结果正确。 |

主要实现位于 `companion-completion-audit.ts`、`companion-completion-guard.ts`、`companion-agent-runtime.ts` 和 `companion-delivery-draft.ts`。底层 finish 仍是结构校验器，不能单独承担上述语义核对。

## 真实原生循环验证

使用当前配置的 MiMo 主档、DeepSeek 副档、真实原生工具循环、真实资源分档、受限 Worker 角色和本次独立 PostgreSQL 实例；材料及账号全部为合成测试数据，私人笔记口令为每次随机值。以下五项均通过，逐条记录完整回答、实际操作和审查调用：

| 样本 | 观察到的交付 | 总耗时 | 来源/交付核对调用 |
| --- | --- | --- | --- |
| 私人笔记 | 实际读取指定笔记，回答随机口令 | 32.964 秒 | 最终 1 次 |
| 三条独立消息 | 数据库中恰有清晨、午后、入夜三条发布；没有额外收尾正文 | 26.801 秒 | 操作 1 次、最终 1 次 |
| 用户已经提供原文 | 回答“七只”，没有强制读取或多余工具 | 2.520 秒 | 0 次 |
| 引用“保存”台词分析 | 没有保存或写记忆，直接分析 | 44.696 秒 | 0 次 |
| 保存偏好后读取笔记 | 记忆实际保存 1 次；实际读出随机口令；结构 finish 修正后原稿复用，没有重复保存 | 22.135 秒 | 操作 1 次、最终 1 次 |

台词分析的耗时主要在回答模型，不能把零审查样本的耗时归给本次核对。保存加读取样本中，主档先给裸正文，原结构合同记录一次 `FINISH_CONTRACT_INCOMPLETE`，副档补结构 finish 后交付；保留这一过程，没有把中间失败藏起来。

这组定向夹具直接创建配置 provider 后运行原生循环，覆盖实际模型、工具、数据库与新核对接线；它没有走线上完整 handler/治理装配、客户端、SSE UI 或真实用户流程，不能替代生产及双端验收。[真实循环原始结果](./evidence/agent-completion-grounding-2026-10-29/runtime-live-results.json)。

## 当前仍有的限制与未确认部分

- 检索分词、停用词、中文 n-gram、向量/关键词降级和候选预算仍影响召回。协议枚举/标签、容量声明、原文引句精确匹配、动态去重、权限及版本校验仍在。它们的具体范围见[词表清理记录](./agent-lexical-cleanup-and-boundaries-2026-10-29.md#仍然存在的规则)，不能宣称整个仓库不存在关键词或正则。
- 资源档仍由模型判断。已知 chat/answer 且没有实际操作/发布的普通回复，以及主动参与路径，不增加本次核对；错误分档可能漏过本应核对的请求。主动参与继续沿用原有审查。当前实现没有确定性地证明每个请求都被正确分档。
- 审查器仍可能语义误放、误拦或不可用，引用绑定只能证明引文存在。有限中英文/日文样本不构成全语言保证；材料内注入也只覆盖了有限反例。
- 本次不解决计算、推理、知识事实、文章质量和所有图片识别错误。错误分母等范围外对照继续成立，不能把新增核对描述成通用真实性保证。
- 工作回复增加模型调用及等待，尚未测生产并发、长期费用分布和客户端流式体验。没有生产部署、迁移执行或双端验收结论。
