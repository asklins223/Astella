# 搜索后引文失败修复（2026-10-08）

用户截图中的自然追问为“还有吧，看看最新的”，前文讨论 Agent 的架构种类。

## 已确认的问题

原回合 `9c9469ce-5e9f-4d96-a071-ce3165c8e35a` 有三次真实搜索回执，结果依次为 0、0、8 个来源。模型提出第四次搜索，实际未请求接口。第三个模型步骤最终 `UNVERIFIED_QUOTE`，聊天保存为失败。

`planStepSteer` 要求本轮工具调用数为零，所以搜索完成后发现不匹配的引文不会进入纠正，直接报错。原错误的“after correction”描述不能证明纠正确实发生。旧模型草稿只保存了哈希、终态后 checkpoint 已清除；因此没有证据判定这一次具体引语究竟是模型改写，还是文本序列化导致的误判。

第四次搜索是本轮三次上限，原实现却把 `webSearchEnabled` 临时设为 false，生成“联网搜索已关闭或暂时不可用”的误导提示。

## 实现

- 给引文校验独立的一次纠正机会，读取工具后也可以触发。继续回答原问题，概括和翻译用普通段落；修正后的逐字引文仍须通过校验，不拿历史 assistant 或被拒草稿充当证据。
- 从实际工具 JSON 解码字符串后比较，避免换行、引号等转义打断真实引文；比较时忽略网页引用角标。
- 搜索次数上限与开关状态分开。超出本轮上限标记为 `not_executed`，提示根据已取得资料回答，不声称搜索功能被关闭。
- 原生复测发现模型把一个引用 ID 少写了一位。渲染、复制、预览和语音过滤现在隐藏此类无效标记；只有精确匹配保存来源的 ID 才成为可点击角标，代码示例保持字面内容。
