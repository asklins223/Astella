# Desktop history pressure and recovery — 2026-10-15

Scope remains the desktop client and its dependent Agent/backend chain. Mobile is excluded. This record continues `agent-complete-source-compaction-2026-10-15.md`; the audit goal remains active.

## Repairs

The first formal answer can now semantically compact unsummarized older exchanges when its measured full request crosses the selected model's pressure threshold. Source sequence identities come from the run's committed handoff, with text/hash/order checks. The latest answered exchange, later user additions, current request and current tool evidence remain intact. Summarization reads the complete bound source through measured parts; no old-message deletion or character cutoff is used. A speculative request rejected locally for context pressure, before any delivered text, yields to this formal recovery path.

Retries no longer combine newly read history indexes with an older committed replay. A complete compressed-message checkpoint is bound to the run, conversation and full request hash. It is saved before the compressed answer call, then can be reused without another summary call. Reuse precedes failed-compaction cooldown and the actual compressed request passes governance again. Changed policy, messages, tool declarations or output shaping miss the checkpoint. Fractional provider/tool parameters use stable JSON inside the private record so the integer-only handoff canonical format does not reject legitimate values.

Database testing exposed two existing persistence defects: worker lacked permission to update the private handoff table, and recovery selected only storage version 1. Migration `0438_handoff_compaction_append.sql` adds a narrow append function. It binds workspace/user/run, requires a live run and expected content hash, locks the run and snapshot, and forbids replacing the prior compaction prefix or frozen model context. API has no execution privilege; worker still has no direct UPDATE privilege. Concurrent append tests preserve both traces; cancellation, different scope, changed input and prior-prefix replacement are rejected. Recovery now reads advanced snapshots.

The old past-offer handling could replace an entire last paragraph based on a model-provided index. It now preserves the complete original reply and appends an idempotent status annotation. A classifier mistake cannot delete the explanation contained in that paragraph. Earlier invitation-suppression measurements describe the old replacement strategy, not proof that the new annotation has equivalent behavioral results.

Quote verification can consult the hash-verified retained original tool text while continuing to reject generated summary prose as quotation evidence.
