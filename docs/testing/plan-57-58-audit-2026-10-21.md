## Functional corrections

### Plan 57

- Removed the remaining `card_candidates` / old card-generation execution and result contracts, host receipt SQL, history fallbacks, and desktop navigation consumers. Current agent results must match the actual job capability and artifact kind. Removed obsolete renderer objective/review/run state; space switching now uses the actual navigation guard. Removed the always-null formal-answer/tutor stubs, their prompts, result metadata, task-queue projection and tests. Companion attention now uses current agent runs; temporary learning memory binds to the persisted note instead of retired learning runs/review pages.
- Card creation is serialized per note. Starting practice locks the card and resumes an existing unfinished attempt; saving an answer locks the attempt so it cannot race submission. Historical cards remain readable and practicable. Card and operation-artifact access also require a visible, undeleted note.
- Added the version selector and version metadata through API, shared IPC, main gateway, and renderer. Older scores remain attached to their original note version, including while a new card has failed to generate.
- Generation checks actual saved-version passages, supplied source provenance, answer shapes, question diversity, and duplicate stems. These checks now run **inside** the existing one-retry boundary. Corrected the model task route, nested option identifiers, interrogative validation, and prompt examples. This catches missing/invalid evidence; it does not automatically prove the semantic truth of every answer or detect every paraphrased duplicate.
- Multi-choice penalties use the number of incorrect options. Operation templates now support both parameter experiments and ordered-step repair, reject unreachable targets and malformed control state, and grade on the trusted host. Completed operation replay is read-only.
- Objective-only cards now receive the whole-card companion summary. Subjective results must cover every expected question exactly once; missing results fail grading instead of silently becoming zero. A summary failure retains earned scores/stars and offers a summary-only retry.
- History orders attempts by completion when available and keeps unfinished attempts accessible. Resuming an attempt created by another window reloads saved answers before practice.

### Plan 58

- Fixed desktop recovery when a successful terminal receipt has no message ID: the reply already matched by run is retained rather than discarded while looking up `undefined`.
- Visible-length checks exclude Markdown headings, link destinations and HTML tags. Note creation validates the actual final saved body, including appended reading-path text, rather than only the model's initial body. The hybrid entry now receives concrete length rules before generation; previously it could fail a rule it had not been given, then pay for another full answer.
- An explicit request to use the calculation tool requires a real successful tool receipt before a verified result can be delivered. Candidate reconciliation makes the authorized tool available; mental arithmetic cannot satisfy a requested tool check.
- The HTTP acceptance probe records saved-note lengths and successful tools, checks exact-version previews after save events, reconnects after the first saved note, and keeps timeout/cancellation failures in the evidence. An observation timeout belongs to the test harness and does not impose a product task deadline.
- The hybrid entry now forwards actual provider progress through the existing independent progress channel. It previously counted that activity for the provider watchdog but did not forward it to the client. This repairs a visibility gap; it is not evidence of an execution speed improvement.

## UI review

The current project window was inspected through native application controls, using real saved notes and attempts. The report's source action opens the existing preview at the exact note version and paragraph; Escape returns to the same expanded question and source-button focus.

| Before | After | Why |
| --- | --- | --- |
