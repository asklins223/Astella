## 结论

上一轮确认的主要语义词表拦截已清理：保存笔记不再猜字数，记忆范围不再按学科或指代词决定，输出不再因普通字段名或 UUID 被拒绝，主动静默也不再靠固定句子判断。当前实现仍有检索分词、协议格式、来源核验与动态重复检测，不能笼统宣称整个仓库“没有任何关键词或正则”。

本轮同时发现并修复了工具操作名转换后的确认规则遗漏、未审核的记忆连带删除、字符串包含关系冒充语义等价，以及普通模板语法被当成内部占位符误删的问题。

## 已落地的替代方案

| 范围 | 当前行为 | 保留的执行边界 |
| --- | --- | --- |
| 笔记长度 | 移除从用户原话猜字符数的保存闸；保留原稿和原问题 | 写入权限、租约、取消、实际笔记身份、关联来源和读取版本 |
| 划选提问 | 原样保留问题，不再给否定句追加“一句话回答” | 选中材料仍作为数据包裹，不能伪造宿主边界 |
| 记忆期限 | 不再因“今天”等词要求一个猜出来的期限；校验显式时间元数据 | 用户来源、原文引句、声明时间的来源与有效性 |
| 记忆范围 | 自动抽取使用明确的 portable/local 绑定与种类；手动账号级偏好尊重选定范围 | 非偏好不能升为账号级；缺绑定保持本地；任务身份、所有权和跨空间传播权限 |
| 自动记忆准入 | 移除“当前数字”词表；精确重复只按保留词语、标点、大小写的正文比较 | 原消息 ID、说话者、原文、置信度、敏感推断、用户忽略与来源抑制 |
| 统计、边界与对象预取 | 移除按中文问句、量词、标题或序号解析预取；模型使用当前页事实和读取工具 | 被选对象的可见性、稳定 ID 和版本由工具核验 |
| 主动静默 | 增加结构化 `companion_finish(silent=true)`；普通句子不再触发静默词表 | 限主动参与；已有正文、待发消息和真实写入结果不能被省略；普通用户请求不能静默完成 |
| 输出校验 | 保留实际宿主信封和工具语法的协议检查；普通技术名称、UUID 和代码示例可输出 | 真实协议标记、结构合同、容量及交付检查 |
| 日记 | 引文使用共享块合同，不按汉字连续长度、emoji、URL 或宣传词筛掉；移除报数、自贬词表和按措辞赋权 | 原始来源/图片身份、声明的块容量与嵌入数量、动态逐字重复检测 |
| 数据库维护 | 新增 `0462_companion_memory_maintenance_metadata` 并登记迁移 journal，覆盖旧函数中的正文词语条件 | 每日一次、候选等待时间、重要性、固定项和保留期限 |

旧的词表评测 CLI `companion-gate-eval.ts` 与 `companion-gate-counterfactual.py` 已退役；未发现包脚本或 CI 入口依赖它们。退役脚本与旧测试保存在本地工作快照中，历史迁移原样保留于仓库。

## 执行复查发现的问题

1. **内部操作名遗漏确认规则。** 模型使用领域工具名，但账本和执行器使用 `memory.write.forget` 等内部名。部分确认与自主操作判断只识别前者，导致 full 档删除无法准备确认，部分操作的权限语义也会漂移。共享规则现在先从内部操作恢复声明的领域动作，保持同一套确认/自主策略；额外传入的 action 不能改写已冻结操作。三档权限与实际确认续跑均有回归。
2. **遗忘越过审核范围。** 原实现删除指定记忆后，会凭正文包含关系删除其他记录，并可能凭八字重合关闭相处偏好。现在只删除用户确认的 ID/内容/修订，保留其他记录与偏好；选定记录的回收窗口、发现簿遮蔽、投递关闭、来源抑制和整理结论失效仍执行。
3. **包含关系冒充同义。** 查询命中多条记忆时，不再凭正文互相包含就自动选第一条。自动抽取也不再让带例外的长句“覆盖”无条件短句；只有完全相同的 active 正文可以作为精确重复，候选记录不能替代 active 记录。
4. **模板语法被误删。** 旧占位符逻辑把任何 `{{…` 都当成内部读数，可能删除正常模板说明或代码。现在只识别保留的 `{{f:…}}` 命名空间，代码范围保持字面内容；替换值必须是目录自己的字符串属性。已补普通模板、代码、混合正文及原型属性反例。

## 仍然存在的规则

- **检索分词与停用词。** `agent/relevant-methods.ts`、`memory/companion-memory-vector.ts` 的词元、中文 n-gram、停用词和候选预算仍影响召回。现有向量/关键词降级也有相似度阈值。这些机制需要单独用多语言召回集评估；检索没命中不能证明记录不存在。
- **协议和声明。** 工具名、动作枚举、页面类型、UUID/日期格式、真实宿主数据标签、`{{f:…}}`、日记 `图1/引1` 等仍有结构处理。schema 声明的内容容量和资源预算也保留。
- **动态原文检查。** 来源引句精确匹配、已发布正文去重、日记示例照抄/重复开头/跨篇重复说法检测仍在。重复意象提取仍偏向中文；它影响提示和风格重试，不能作为多语言质量保证。
- **未接入普通执行链的旧检测代码。** `companion-action-claims.ts`、`reviewCompanionStepCorrection`、数字/引用/算术等旧助手仍有词语匹配和测试。调用链复查未发现它们成为当前普通回合的结束或工具选择决策器；不能仅凭搜索命中就当作线上限制。
- **历史 SQL。** 已发布迁移里的旧词语条件保留不改。新部署必须执行 0462，数据库中的函数才会使用新逻辑。

## 完成度方案的实际边界

结构回执可以核对写入是否发生、引用的对象和版本是否真实，却不能证明模型理解了全部要求或推理正确。[本轮 14 个合成探针](./evidence/agent-lexical-cleanup-2026-10-29/cleanup-findings.json)仍保留一个明确负对照：模型把“读取私人笔记”自行声明为 textOnly 后，零读取回执的编造答案仍能通过结构 finish 校验。这个缺口没有被本轮词表清理解决，不能把它写成已修复。

完成度审查器继续作为离线方案：让它核对原请求、真实材料/版本、回执、实际发布状态与未发布草稿，分别检查目标覆盖、外部依据和推理。原审查器曾在两种思考模式下接受错误分母，尚不足以直接接入正常回复。后续比较需要冻结失败与新表达对照，统计漏放、误拦、不可用、额外调用、耗时和消息丢失；不可用不能算通过。此前[审计中的方案与一手来源](./agent-lexical-rules-and-recovery-audit-2026-10-29.md)继续适用，本轮没有新增审查器调用或性能结论。
