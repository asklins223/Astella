# Agent 桌面实机补验（2026-10-15）

结论：此前的源码、单测、数据库和模型网络测试不能证明桌面体验没有问题。本次真实窗口补验又发现了问题；不能给出“目前设计和逻辑都没有问题”的保证。

## 实际环境

- 当前工作区源码构建的 Electron 44.7.0 桌面窗口，macOS 本机运行，独立 userData。
- 当前源码 API（127.0.0.1:4015）与 worker；独立数据库 `astella_agent_review_20261015`，使用实际受限 API/worker 数据库角色。
- 独立合成验收账号、合成对话和偏好，调用现有配置的真实 MiMo。没有重启其他任务使用的开发服务。补验结束后停止本次独立运行的进程，保留测试库与证据。
- 窗口由原生 UI 操作，服务端事件与持久化结果单独核对。数据库夹具用于确定性回归，明确区别于模型实测。

## 本轮发现与改动

1. **安静机会可能无法上报。** 实际前台持续等待时心跳正常，但没有对应安静事件。`performance.now()` 的小数毫秒传入要求整数的合同，异常被客户端 catch 隐藏。共享计时器改为向下取整，保证不提前跨过门槛；增加小数时间戳与真实合同联合测试。
2. **答后主动通道重复发送刚才的结论。** 窗口和数据库同时复现：“改好了，小柚……”作为上一条回答末段，又在新的 `reply.finished` 运行里单独出现。普通最终回复和 `companion_publish_utterance` 两条发布路径现在共用父回答校验，拦住完全相同的全文或独立段落；新增内容仍允许发布，不按语义相似度删话。模型指引也明确答后考虑不是重新确认。
3. **主动停止被误判为发送失败。** 修复前，在手记中停止会跳回气泡并恢复已发送的问题。原因是本地取消让 generation 变化，发送 Promise 返回 false，触发失败恢复。现在单次发送区分主动取消与其他失效；窗口复测保持手记和下一条未发送草稿，后端记录 cancelled，数据库没有取消终态之后迟到的正文增量。
4. **闲聊无依据承诺提醒。** 原样复现“饭点再叫你”，但该轮没有安排提醒。新增当前闲聊策略版本，说明提醒、叫醒与持续监看必须有真实安排回执，未被要求时不擅自创建。相同输入复测没有再承诺定时提醒；这属于约束改进，不能保证模型以后永不生成类似话语。

## 已核对的窗口行为

- 首次登录、进入书房、气泡发送、对话手记保存。
- 保存“解释先举生活例子、称呼小杉”，更正称呼为“小柚”，数据库偏好 revision 1 → 2，旧称呼被替换，解释偏好保留。
- 退出重开桌面后，真实长回答仍称呼“小柚”，先给生活例子。
- 长回答生成中停止：修复版约 0.75 秒内恢复发送入口，手记保持打开，下一条未发送草稿保留；中止内容标识“你在这里停下了”。
- 语音：真实 MP3 已生成并缓存；点击手记音频按钮实际进入“停止播放这条消息的音频”状态。只核验播放链路和文件，未做听感验收、未测试麦克风识别。
- 安静在场观察：最新窗口实际前台等待约 101 秒后，服务端收到 `presence.quiet`，`quietForMs=101314`（整数），随后约 206 秒时收到 `quietForMs=206316`，两次安静片段身份相同，覆盖三分钟门槛。该账号此前的主动发言仍在 30 分钟节奏间隔内，本次没有产生新的安静主动运行；收到安静观察不能冒充实际主动开口通过。

内容质量也没有通过验收：被中止的贝叶斯推导草稿曾将分子误写为 `P(B|A)P(B)`，正确应为 `P(B|A)P(A)`；后续展开式又写对了。已核对持久化原文，属于模型实际输出错误，不能用代码回归通过掩盖，也不能把一条提示词约束说成可靠修复。

仍未覆盖：iOS/Android 实机、发行安装包、持续数小时使用、多设备同时在场、断网恢复、真实麦克风、长对话经过多次模型摘要后的整体验收。已看到的思考气泡中仍有内部工具术语；本轮未重做现有逐字思考呈现。
