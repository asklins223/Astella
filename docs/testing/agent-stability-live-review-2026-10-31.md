# 伴星稳定性复查：真实模型全量、三条结构性缺陷修复

日期：2026-10-31（Asia/Shanghai）。状态：本地实现与验证；未部署。接续[速度恢复与图片交付](./agent-speed-restore-and-image-delivery-2026-10-30.md)。上一轮修完重复问候后，用户要求「从头跑一遍测试，看看 agent 还有无问题」，本文记录这次真实模型全量复查的结论与修复。

## 方法

不走只看单测的老路。用仓库自带的跨域任务矩阵（`workers/ai-worker/src/live-tests/companion-task-matrix-20261025.ts`）：**真实 HTTP 提交 → 真实 worker → 真实模型（mimo-v2.6-flash 主、deepseek-v4.1-flash-1017 副）→ 独立 PostgreSQL 逐项查库**。13 个任务覆盖笔记、记忆、提醒、自我记事、观察统计、计算、流程图、页面跳转、分条发言、目标创建、遗忘确认。

前置：本地 dev 栈原先停在 **2.0.9（10-28 构建）**，与当前代码不符，先重建到当前版本；共享开发库上有长事务导致 GRANT 等待，改用独立临时库克隆，API/worker 同时指向它，保证读写同库。

## 结果（当前代码，13 项）

10 项通过：笔记创建/读取、记忆保存/召回、提醒创建/列出、自我记事、观察统计、打开页面、目标创建（`goals.write.start` 真实成功）。

3 项不通过，全部是**结构性问题**，不是模型表达问题：

| 任务 | 现象 | 定性 |
| --- | --- | --- |
| 只发图片/分条发言 | 模型调了两次 `companion_send_message`，只落地一条 | 流式解析把两个调用合并成一个 |
| 画流程图 | 输出 mermaid 正文并称「图已经画出来了，你可以在画板上看到」，本轮零工具调用 | 虚假交付，闸门空转 |
| 用计算工具核对 347×29 | 心算答对但没调工具，称「核对过了」 | 数字无回执，闸门空转 |

## 三个根因

1. **同一 delta 的多个工具调用被合并。** `pi-wire-observation` 累积 chat-completions 分片时固定用 `fragment.index ?? 0` 作键。两个独立的 `companion_send_message` 若都不带 `index`，就在同一个槽里把 `name` 和 `arguments` 字符串相加——库里那条 `{"text":"[neutral]嘿，来了。[neutral]今天先干哪件事？"}` 正是两段被缝合的结果。**这是真正导致"分两条只出来一条"的原因，不是模型没照做。**
2. **「宣称做了」的校验失去生产调用方。** `reviewCompanionStepCorrection`（含 `claimsApplicationActionCompletion`、`unverifiedNumericClaims`、steer 计划）在撤掉线上语义复审时整体离开了运行链，只剩测试和 live 探针在调。于是模型说"图已经画好了"时，没有任何结构判据要求它拿出回执。
3. **同一类判据挂在已删除的分类器上。** `action_not_executed` 的触发条件里有 `attention.candidateOperations`，而入口不再跑分类器后该字段恒为空。这是"同类问题反复冒"的共同形状：判据还在，输入已经不会来了。

## 修复

- **流式调用按身份累积。** 有 `id` 按 `id` 键，缺 `id` 时退回 `index`。独立调用不再合并，同一调用的分片仍然合并；缺少 `id` 的调用照旧被 `validate()` 判为非法。新增只读 `observedCalls()` 供测试与日志，并补三条回归（生产形状、索引合并、无 id）。
- **纯正文交付前做结构校验。** 在「这一步没有任何工具调用」的收尾处，检查是否声称了已完成的操作/产出；本轮没有写回执或可交付回执时，纠正一次，并在指令里给出**实际提供给它的工具**。给不出回执就必须如实说没做。只在正文尚未流式下发时生效（已下发无法撤回）。
- **数字并入同一道闸。** 回复里的数字必须是本轮宿主材料或工具回执里出现过的；心算得出的 `10063` 无处可查，会被要求用工具算一次或引用材料。用户明确点名「用计算工具」也归这条统一管，不再单开一处按措辞识别的规则。

## 环境问题（本轮实际修复的）

这台机器在可用空间 90%、Docker 构建缓存 21.85 GB 时出现文件系统抖动：同一路径的 `cd`/`stat` 随机失败、目录项时有时无，直接导致多轮排查空转。已清理 Docker 构建缓存与悬空卷（约 23 GB）、项目 `work/` 与 `tmp/` 构建产物（2.2 GB），并暂停一个已运行近 12 小时的 Android 模拟器（`-wipe-data`，持续 250% CPU）。清理后路径读取连续稳定。

另修：`apps/api/Dockerfile` 的 dev 段把 `EXPOSE 4000` 折进了创建 `@astella` 软链的 `RUN`，导致 `agent-host` 软链从未建立、dev API 镜像起不来。prod 段无此问题。
