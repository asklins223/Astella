# iOS note editing and collaboration — 2026-10-29–30

## Decision and implementation

The user requested direct editing of rendered notes, blank-note creation, native text selection, companion rewrites from a selection or caret paragraph, paragraph protection during rewrites, shared presence, last-editor metadata and an explicit read-only experience. Workspace owners can now write through mobile sessions; members remain read-only. The previous mobile-specific content-write prohibition is removed from authenticated routes and Hocuspocus. Existing visibility and workspace ownership checks remain authoritative.

The iOS client lives in the separate `astella-mobile` repository. Its WebKit surface uses the shared ProseMirror schema, Yjs updates and Hocuspocus provider. Native code owns authenticated HTTP, uploads, durable drafts and dialog presentation. It sends actual document deltas through `/v2/notes/:id/doc-update`, retaining edits made while a save is in flight. Read-only clients receive live updates and display no mutation controls.

`GET /v2/notes/:id/editing-state` returns permissions, share scope, authenticated presence, the last editor and active rewrite locks. Locks are acquired through `POST /v2/notes/:id/edit-locks`, bound to an owned run through PATCH and released through DELETE or terminal-run pruning. Acquisition validates the selected block contents against the live document. Relative Yjs positions protect the same block after preceding insertions; both HTTP and WebSocket manual deltas are checked. Version restore respects active locks. Internal companion transforms retain their existing canonical mutation path.

Migration 0463 adds nullable `notes.last_edited_by` and `last_edited_at`, populated by real document persistence rather than inferred from authorship. Migration 0464 adds `note_document_states.rewrite_locks`. Locks persist without advancing the content revision, rehydrate before manual writes in a new API process, and remain held for the lifetime of bound running jobs. Unbound preparation leases expire after two minutes; succeeded, failed, cancelled, superseded, stopped and completed runs release protection. Last-editor metadata and private-note collaboration details remain visibility scoped.

Rejected orphan CRDT updates are validated on a disposable document before changing the live document, preventing rejected pending structs from poisoning later valid saves. Shared safe reader projection moved to `@astella/shared/note-reader-projection`; API and iOS use the same renderer. The iOS reading view projects incoming CRDT changes immediately, then refreshes stored reader metadata after the server's idle-save interval. It does not display the stale HTTP snapshot as the live update.

Automatic titles and library snippets also use canonical rendered text: empty tables do not become Markdown-symbol titles, and rich text does not expose source markup as an excerpt. Existing automatic titles are recalculated on their next save; manual titles remain authoritative.

The final test counts above include these regressions. The last format-panel focus adjustment has automated and build coverage; its repeated window check was interrupted by manual device interaction and is not claimed as additional window validation. No new AI rewrite was sent during the window checks; live model output and physical-device input are not claimed as verified.

## Deployment and scope

Apply migrations 0463 and 0464 and deploy this API before installing the matching iOS build. Local verification used a disposable database and the existing development API; no production deployment, version bump or release tag was performed. The development database had an unrelated older migration conflict, so only these two additive migrations were applied there with their exact journal hashes; the full migration history was independently verified in the clean test database.

Hocuspocus still assigns each document to one API process; durable locks cover restart, not cross-replica document ownership. Android UI and companion-model changes are outside this batch. Physical iPhone, VoiceOver, Chinese IME composition and prolonged large-document collaboration remain unverified.
