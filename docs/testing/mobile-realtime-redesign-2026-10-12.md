对应[方案 55](../plans/learning-companion/55-mobile-redesign-and-companion-realtime-2026-10-12.md)。首轮记录真实 `apps/mobile-client/src` 的 UI 调整与示意验证。2026-10-12 后续又完成手机对话 WebSocket 与小米 MiMo 整段 ASR 接线；当前验证状态见文末，不能把旧语音示意当作真实语音链路。

## 发现与改动

1. 原交流页把固定 37vh 舞台与完整聊天记录同时摆放，没有实现用户已选择的“伴星／记录”切换。改为默认见伴星、完整记录独立占据中间空间；模型隐藏时暂停，切回保留同一画布。
2. screen-stack 已预留导航，composer 又重复扣一次导航与安全区，输入与正文被挤掉。移除 composer 的重复预留；visualViewport 适配可见高度，软键盘出现时导航收起。
3. 文字增量驱动口型与流光，实际没有播放器。移除这条接线，无音频时嘴部包络归零；状态从“在说”改为“正在回复”。
4. 回车未区分中文输入法选字。增加 isComposing/229 守卫；提交未收到回执时不能继续抢占。手机端明确停止当前回复后才可发下一条，输入中的草稿保留。
5. 原历史把所有带 text 的块拼接，把查阅原文混进伴星回答。对白只取 text 块，quote 独立展开；记录复用 shared 的已净化 Markdown 树显示标题、列表、代码与表格，保留图片、步骤、引用和可支持的笔记跳转。
6. 原 build 的 tsc 开启 composite，包外共享源码不在 include，产生已有导入路径的 TS6307；typecheck 明确 composite=false 却能通过。build 改为调用同一 npm run typecheck 再执行 Vite，避免两条类型结论不一致。

本轮只重做核心交流页，未重做登录、全部设置与阅读页；这些已有页面和原型中的能力不能凭本轮截图一并宣称完成。

## 手机 MiMo ASR 与 WebSocket 接线 · 2026-10-12

### 接线范围

- 对话 WebSocket：浏览器首帧传 session token，服务端鉴权后订阅现有持久事件；`turn.submit` 复用现役 `createCompanionTurn` 和幂等 `clientMessageId`。移动端 Vite 开发代理启用 WS。断线或回执超时会用同一 ID 回退到 HTTP；取消回合、图片上传和提案确认仍用 HTTP。
- 小米 MiMo ASR：用户点击麦克风后浏览器录音，转成 16 kHz 单声道 WAV，再经 `/voice/transcribe` multipart 整段上传。API 使用 `mimo-v2.5-asr`；结果先回填为可编辑草稿，只有未编辑的完整转写才带转写来源 artifact 提交。手机浏览器不持有 MiMo 凭据，也不上传实时音频帧。
- 服务端需设置 `COMPANION_VOICE_DIALOGUE_V1_ENABLED=true`，并满足语音识别同意与 MiMo provider 配置；示例环境默认关闭。ASR 容器、流式 partial、移动端 TTS/播放和桌面 WS 迁移均未完成。

### 代码验证

- 手机端类型检查与生产构建通过；删除未使用的手机 SSE 客户端后，手机测试为 8 个文件、30 项通过，覆盖 MiMo 上传合同与游标恢复顺序。
- API 类型检查通过；MiMo provider 与真实 WebSocket socket 定向测试共 8 项通过。socket 测试验证了路由升级后会拒绝未先鉴权的订阅。
- 用 `VITE_API_ORIGIN=https://api.example.test` 构建后核对 CSP，输出仅加入 `https://api.example.test` 与 `wss://api.example.test`；再执行默认构建恢复同源产物。
- 游标过期恢复现在等待快照与最新事件游标一起更新后再重新订阅，避免带旧游标形成重复失败循环。
- 手机端未使用的 SSE 客户端包装已移除；桌面 SSE 仍保留，等待桌面完成 WebSocket 迁移再清理。
- 本机 API 容器健康检查失败（`/health` 返回空响应），所以没有在已登录的真实对话里验证 WS 订阅、回合提交或真实 MiMo 上游音频识别。浏览器预览落在登录态，不能作为这三条链路的成功证据。

### 仍需真机或健康后端验证

录音权限拒绝、实体设备采集与转换、真实 MiMo 中文识别质量与耗时、授权会话下 WS 订阅/提交/断线重连、服务端开关关闭时的 UI 提示、系统来电与耳机中断、TTS 播放，以及桌面与手机共用 WS。当前语音识别为整段上传，不是流式 ASR；没有承诺它降低了端到端时延。

## 手机端实屏审计补充 · 2026-10-12

按用户反馈重新逐屏核对真实 React 页面，发现并修正了这些操作问题：

- 首屏此前把品牌星标 `star.svg` 误当成正式应用图标，虽然删掉了标题、标语和辉光，仍显示错图；后续按“开屏图标更正”记录改为桌面安装包使用的正式图标。
- “记录”模式此前仍显示大头像，头像压到第一条消息；顶栏模式切换也因只在“伴星”模式渲染而消失。现在主对话的两种视图都保留同一组切换按钮，历史正文从顶栏下方开始。
- 长书房名称在顶栏只剩不可辨认的截断文本。现在长名称显示为“当前书房”，完整名称保留在无障碍名称和选择列表中。
- 每条失败记录都放一个同样的恢复按钮会挤占正文。现在只有最近一条仍可恢复的用户消息提供“放回输入框”，旧记录仍保留失败/停止状态。
- 回复进行中仍可直接提交新问题，静默通过 `supersedesGeneration` 抢占当前回答。手机端改为明确停止当前回答后才允许发送；正在输入的草稿保留并说明下一步。
- 切换书房时旧会话可能在 React 清理 effect 前留在新空间界面一帧。现在在令牌切换成功后立即关闭旧实时流、清空旧会话和笔记状态，并保留笔记请求的 generation 防线。
- 冷启动 ensure inbox 与首轮历史/运行快照此前都可能无限等待。现在两段都设 20 秒超时并显示连接/同步状态与重试入口；同步快照完成前发送、录音和选图发送不可用，切换用户/空间时会中止旧 inbox 请求。

实屏核对：在 430px 手机窗口查看“伴星→记录→伴星”切换、顶栏空间弹层及真实历史。记录模式不再被头像覆盖，两个模式都可往返；空间弹层显示完整可选名称。页面重新加载后从登录态恢复并读取同一会话，客户端没有显示断线/重连提示（其状态只会在收到 WebSocket `subscribed` 后变为 open），可作为本次**鉴权订阅已连通**的证据；没有发送新回合，因此没有验证 `turn.submit` 与事件回流。`/health` 返回 HTTP 200。没有请求麦克风权限或录制音频，所以真实 MiMo 上游识别仍待有授权、语音开关已启用且 provider 已配置的环境验收。

## 手机端第二轮操作与状态审计 · 2026-10-12

继续沿真实页面和调用链检查后，修正了以下问题：

- 旧登录、旧书房的迟到 401 不再能注销新会话；实时连接的消息、连接状态和错误回调都校验书房及连接代次。重试请求、图片上传、语音识别和私有图片读取也忽略过期范围的响应；切换书房时会中止正在上传的图片和录音文件。
- 点下麦克风后尚未返回系统权限结果时离开聊天页，授权晚到会立即释放录音流；书房切换或页面转入后台会让这次录音请求失效。浏览器不支持启动录音时也会释放媒体轨道。
- 顶栏原来的三横线实际打开“我的”，图形和行为不一致；现改为与目的地相符的人像图标。

本轮 `npm run build`（含 web/node 类型检查）通过，Vite 构建 536 个模块成功；仍有约 1.15 MB 的主 JS chunk 警告。浏览器热更新短暂落在“正在接上…”，整页重载后登录态和同一聊天记录正常恢复，实屏确认顶栏人像图标与“打开我的”一致。没有请求麦克风、录音、发送聊天消息或修改笔记；MiMo 音质、设备后台中断、实时回合提交/事件回流仍未做端到端验收；本轮未运行测试套件。

## 手机笔记上下文接力更正 · 2026-10-12

继续逐屏审计发现，阅读页底部“问这篇笔记”原先只把笔记标题写进草稿；切到对话时阅读状态会关闭，最终 `turn.submit` 没有携带笔记身份和版本，模型只能按标题猜目标。现在将当前 `noteId` 与已读到的 `noteVersionId` 作为正式 `pageKind: "note"` 页面上下文随本轮提交，WebSocket 与 HTTP 幂等回退共用同一请求体；发送失败恢复草稿时也恢复这份上下文。笔记上下文草稿显示与笔记相关的快捷问题。尚未发送真实用户回合，端到端模型读取／修改结果仍待健康后端验收。

## 第三轮手机端真实窗口审计 · 2026-10-12

- 对照方案 51 §4.6a，个人中心此前缺少已确认的称呼/头像编辑能力。现在称呼通过 `PUT /auth/profile` 保存并即时更新当前会话资料；头像经现有 `POST /uploads/avatars` 上传，沿登录态读取私有对象，校验格式和 10 MB 限额。空称呼回退显示邮箱。选图上传、名称保存均未在当前真实账号上提交；只打开并取消了称呼编辑界面，未修改账号数据。
- 真实窗口热更新后曾停在“正在接上…”，没有错误和可操作的恢复入口。启动页现在始终提供“重新连接”，重新发起恢复会先取消过期请求；冷启动和登录后读取资料共用 12 秒上限，并取消超时的底层 `/auth/me` fetch。实际点击恢复后，页面回到已登录交流，能显示“我在”，没有发送回合。
- 在现有 430×900 浏览器手机框检查了个人中心和称呼编辑态：头像与资料行未互相挤压、编辑输入在卡片内，取消可回到展示态。页面保留在个人中心供后续检查。该窗口不等于实体手机；没有验证原生图片选择器、真实头像上传、修改资料服务端回执或 320px 宽度。
- `npm run build` 含 web/node 类型检查成功，Vite 生产构建成功；仍有主 JS chunk 大于 500 kB 的既有提示。本轮没有运行测试套件；没有请求麦克风、上传头像、发送对话或修改笔记。
