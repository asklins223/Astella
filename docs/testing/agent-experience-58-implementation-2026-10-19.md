### 2026-10-20 第三轮：右下角自动弹出、成果条、过期断言

**用户报的 UI 问题**：一打开笔记，右下角就冒出一张纸。真实窗口复现后确认，它不是"打开笔记"才出现——**每次启动就自动展开并挂着**，用户进到笔记页时自然还看见它。根因是通知中心的"已展示过"只记在组件 `useRef` 里，重启即清空，收件箱里任何未收下的后台提示每次启动都会重放一次。

修复：新增 `companion-notice-seen.ts`，按账号（`accountIdentity.email`）把已看过的提示身份持久化到本机（上限 200 条），键用 `id + revision`（不含只在本会话内递增的 `occurrence`）。后台提示（`delivery !== "immediate"`）展开过一次后，下次启动只留在收件箱；直接指引（`immediate`，如 AI 权限）仍会再露一次。补了三条测试：重启不重放、直接指引仍出现、两个账号互不影响。真实窗口重载验证：纸签不再自动展开，只剩"通知 1"角标。

**设计稿对照的缺口**：此前只核了交互语义，漏了设计稿里最显眼的一块——手记旁边常驻的"本次任务"面板（状态／已用时／资料已读待读／成果逐条预览与打开）。真实界面里成果只藏在每一步的展开详情里，要确认"刚那篇存下来没有"得先展开过程再逐条点。前一轮说"交互已落"是说得太满。

现在按项目自己的数据补上：`CompanionRunTraceView` 在过程**外层**（收起也可见）渲染一条成果条，逐篇列出带 `noteCreated` 真实回执的笔记，每篇一个「预览 / 打开笔记」；只列有回执的节点，无回执不渲染。同时把这条运行的已保存 noteId 传给回复渲染，正文里重复的「打开当前笔记」不再画第二遍（气泡侧本来就有这套 `representedNoteIds` 去重）。设计稿的右侧常驻栏、资料已读计数没有照搬——那需要一条真实"读了哪几份"的数据，当前协议没有。

真窗口验证：成果条落在所属运行的头部、收起过程时仍可见，点预览读到保存时的精确版本；去重后正文里不再重复出现入口。

**顺带清掉的过期断言**（都是 57 删链后没同步，且每处都先确认真实行为再改判据）：`ONBOARDING_STEPS` 5→4、搜索投影只索引 note/source（href、drift、批次数）、DomainError 快照 27→17、`worker-function-grant-guard` 的 DROP 豁免集。API 单测失败数从 196 降到 34。
