# 一轮回复的交付与查阅材料

日期：2026-10-09。触发反馈：生成一篇笔记后，同时出现两张长引用纸、一张去处纸、正文回复和工具过程，重叠并遮住书房。

## 调用链与语义

`companion_read_note` / `companion_read_source` 在 worker 工具执行链中附带正文前 1200 字的 `quote`。这只是本轮读取的快照，现有块没有笔记身份、来源版本或精确定位；它不能证明回答中的某句话用了哪段依据。

原 `CompanionReplyPapers` 把每个非文字块加入独立队列，各自显示和计时；成功过程和文字回复另外显示，导航纸又停在屏幕中央。一次回复被拆成多个通知，是本次堆叠的直接原因。

本次不改消息合同或工具的读取行为。快照称为「查阅的材料」，与已有联网回答的编号引用保持不同语义；「展开片段」只展开已返回内容，不宣称取得全文。真正的笔记目标继续使用已有 `nav` 路由。

## 最终行为

- 一次回复共用一张纸，完成说明和新笔记入口直接可见。成功过程在纸内默认折叠，运行中、失败、结果待核对和待确认仍明确表达。
- 材料默认折叠，展开后逐份查阅，同一时刻只打开一份。相同块去重，标题相同而正文不同的片段保留。
- 片段使用已有 Markdown 渲染，标题、表格、公式和代码不再显示为原始标记；长材料在纸内滚动。
- 当前交付使用一个 60 秒计时。正在展开阅读、朗读、逐字显示、被其他界面遮挡或窗口隐藏时暂停；交互沿用活动宽限。
- 关闭回复或成功打开目标，一并收起文字和附件；打开失败时保留入口与错误并允许重试。成功过程不在收起后再次变成独立气泡。
- 下一轮替换当前交付，不累积旧纸；已经自动打开且没有剩余附件时清除空交付，正文保留自己的阅读时间。
- 原始消息、材料与目标仍留在手记。待决定的动作不受短暂交付计时影响。

## 代码与回归

实现位于 `CompanionHud`、`CompanionReplyAttachments`、`CompanionReplyPapers`、`CompanionAgentRail` 和共用记录渲染。会话的轻聊正文只取 `text` 块，防止代码、出处标题重复混进正文与朗读。

桌面包执行 `npm run typecheck`（node 与 web），以及 `npm run build` 和书房资源构建前后校验。相关 8 个测试文件覆盖 108 项：交付、HUD 连续操作、旧纸队列移除、记录、过程、摆位和网页引用。边界修订后重新执行受影响的 2 文件 30 项。

计时回归验证展开阅读超过原期限仍在，折叠后继续原剩余时间；下一轮重置材料；导航成功/失败重试；关闭与到期同时清理；只剩已自动打开目标时不显示空交付。原有确认、网页引用、语音预览与焦点路径继续通过相关回归。

## 窗口证据与边界

本机隔离 Electron 窗口加载 `apps/desktop-client/demos/companion-reply-delivery.html`，使用生产附件、记录、过程组件、样式入口和实际浮动摆位 hook，提供截图场景相近的两份长材料与新笔记入口。

已操作：材料开合与切换、连续两轮、目标打开失败后重试、手记回看、键盘开合和分页滚动、完整/关闭动效、窗口放大与恢复默认缩放。放大时关闭按钮、目标入口、过程与手记操作仍可见，长材料在内部滚动，Markdown 表格可读。

示例使用本机合成消息、静态角色图片和演示路由，不调用模型、不写真实笔记，也没有测试麦克风、真实 Live2D 动作或真人朗读听感。本次未重新打包安装当前产品，也未通过真实账号重新生成截图中的笔记；生产 HUD 接入与真实路由调用由组件回归验证。

完整来源定位还需要消息合同携带来源身份和读取版本，当前快照仍是截短片段。已有笔记导航和联网编号引用保持各自的实际目标；本次没有把快照伪装成精确引用。

演示启动与复现步骤见 [本机验收说明](../../apps/desktop-client/demos/companion-reply-delivery.README.md)。
