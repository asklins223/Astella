# 手机端导航、面板与触摸动效修正（2026-10-13）

这份记录覆盖 `apps/mobile-client/src` 的页面过渡、导航高亮、边沿返回和共享面板。源码审查与类型检查不能证明真机手势和帧率已经验收；真实窗口覆盖由主任务另记。

## 可复现的实现问题与处理

| 问题 | 处理 |
| --- | --- |
| 导航高亮改变 `left` 后再读取带动画的边界，快反向时将上一次目标与当前视觉位置混在一起 | `left` 保持不变，每次先读取当前 transform，再取消旧动画，从当前 transform 接到新分区；缩放/转屏直接重新落位 |
| 一级分区和整张纸面都用同一条欠阻尼曲线，长距离移动在尾部回弹 | 纸面改为无回弹滑动，分区使用较短的位移；时长随未完成距离变化。小高亮保留低幅弹性 |
| 刚进入详情就返回时，目的页重新从预设偏移开始 | 捕获仍在退场的来源页位置，反向进入时接回其当前偏移 |
| 返回手势在 pointerdown 就 capture，会抢正文长按/选区和纵向滚动；mouseup 依赖旧 React 位移 | 返回只由独立 22px 页边触摸区接管；先判定方向，拖动位移和最终判断由实时 ref 持有；正文不被 capture |
| 每个 pointermove 更新壳的 React state，长笔记反复重绘 | 位移直接写入手势视口的 transform，完成或取消再清理；快速继续抓取弹回中的页面时读取其当前偏移 |
| 详情返回松手后，快照没有包含视口的跟手位移 | 捕获时合成视口与当前页的实际 transform，离场纸面接着手指释放位置滑走 |
| 离场副本在入 DOM 前恢复 scrollTop，浏览器把不存在的滚动范围夹到零 | 先插入 inert 副本，再恢复正文及内部气泡、代码/表格等滚动位置 |
| 整个视口和正文都限定 `touch-action: pan-y`，表格/公式横滑受限 | 正文恢复 `auto`，只在独立返回触摸区使用 `pan-y`；思维导图不加入返回触摸区，保留自身拖动 |
| 面板从很小图标拉伸成大纸面，正文也随宽高比例变形 | 短面板围绕来源做轻量统一缩放与短位移，长内容由下缘入场；内容维持比例 |
| 关闭回调或延迟焦点恢复能影响随后打开的面板 | 面板按 store 分配的实例序号挂载；完成回调检查当前实例，焦点恢复检查 store 版本；替换时取消旧动画 |
| 关闭中切换 Off 仍等待退出动画 | Off 和系统减少动态立即取消视觉动画，关闭立即提交，操作/焦点不等待动画 |
| 面板头部显示可拖动光标，实际没有拖动操作 | 只有长纸面给出拖动把手和向下关闭手势；短操作面板头部使用正常光标 |
| 软键盘遮挡面板或过程详情展开后尺寸不对 | 面板按可见视口重算边界；过程等普通面板按实际内容测量；内容旁交流面板取可见高度 90%，内部聊天区应按剩余空间 flex |
| 返回已有栈内详情无反应 | `push` 遇到栈内已存在的目的地时回到该层，处于顶层时保持不重复入栈 |

## 验证与待验收

- 执行移动包 `npm run typecheck` 通过；未运行测试。
- 本分工未操控浏览器，以免干扰主任务的真实窗口核验。
- 主任务需复核：连续快速切换三个一级分区；开笔记后立刻反向；边沿短拖取消、长拖与快甩返回；正文跨段长按拖选；表格/公式横滑；打开面板立即关闭、关闭中更改动效偏好；过程详情展开/折叠；内容旁交流在小屏软键盘展开时输入始终可达。
- 物理触摸手柄、浏览器系统边沿返回和真机帧率仍需在实际手机上核验。额外的返回按钮继续提供同一返回操作。
