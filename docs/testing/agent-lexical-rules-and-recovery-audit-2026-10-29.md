## Legacy code that is present but no longer decides normal delivery

`companion-action-claims.ts` contains an extensive Chinese action-completion/promise list. `claimsLookupThatNeverRan`, `looksLikeUnfulfilledActionNarration`, numeric/quote checks, and `companionClaimRepairTools` also remain in `companion-step-plan.ts` / `companion-dialogue-content.ts`. Their old aggregate `reviewCompanionStepCorrection` and correction-instruction builder have no current production caller. They are still tested and imported within that legacy helper family; their existence must not be reported as proof that the native loop still uses them.

Similarly, `reviewCompanionImageClaim`/`claimsImageContent` and the standalone arithmetic-language helper have no current production caller outside their helper family. The current image path supplies actual pixels/observations instead.

The old reminder/read candidate gates also remain in the runtime. Ordinary direct entry starts with an unclassified record and does not produce those old read candidates. Its `/提醒/` test against rendered ambient text is not a reliable receipt test and should be removed with the obsolete candidate gate, rather than reused as a new completion check.

Tool names, page destinations, supported actions, schema enums, access checks, source identity, revision checks, idempotency, and cancellation are separate contracts. A finite set of implemented operations/pages is legitimate; it does not require a natural-language trigger vocabulary. The current resource selector uses a model and fixed contextual examples, not runtime substring matching. Its decision still needs independent semantic evaluation.

## Implementation defects fixed locally

1. **The image hedge raced first settlement instead of first success.** `Promise.race` rejected as soon as either attempt failed, canceling a still-viable sibling. It now waits for a success, starts the second attempt immediately after an early primary failure, and reports both causes if both attempts fail. Normal fast success still makes one request.
2. **A malformed image observation could win.** Runtime now validates JSON and the full expected identity set inside each attempt before that attempt can win. Invalid content cannot cancel a valid sibling merely because its HTTP response arrived first.
3. **Returned image ordering was trusted.** The parser now reconstructs the result array using the host's input identity order and rejects duplicate expected identities. This prevents a model-returned permutation from changing the canonical observation order.
4. **Cancellation depended on provider cooperation.** The hedge now races a parent-cancellation promise and preserves the cancellation reason; the outer operation settles even if a test transport ignores its signal. Cleanup aborts the shared attempt scope and removes the timer/listener. Actual transport resource release still depends on the adapter honoring abort.
5. **Finish instructions contradicted runtime policy.** Direct-entry guidance and the shared finish-field descriptions still required a finish for every work resource label. They now use the runtime's actual condition: landed writes or unfinished independent messages. Read-only answers can deliver complete prose. The corresponding validation message was aligned. This avoids prescribing the extra round trip that the earlier implementation deliberately removed; no latency improvement is claimed without a new model run.

No new keyword, intent-to-tool sequence, model switch, thought timeout, or production guard was introduced. The [patch from the preserved working baseline](./evidence/agent-lexical-audit-2026-10-29/audit.patch) separates these edits from the existing uncommitted changes.

## Further solutions checked against primary sources

**Changing the MiMo endpoint does not provide forced tool choice.** Its current [Responses](https://mimo.mi.com/docs/en-US/api/chat/responses), [Chat Completions](https://mimo.mi.com/docs/en-US/api/chat/openai-api), and [Anthropic-compatible](https://mimo.mi.com/docs/en-US/api/chat/anthropic-api) documentation all specify automatic selection and state that other choices are removed/treated as automatic. A different compatibility endpoint is therefore not an established fix. The [official OpenAI documentation](https://developers.openai.com/api/docs/guides/function-calling) describes genuinely required/forced calls and strict argument schemas for supporting models. Inference: those features constrain a protocol; they do not establish that all user goals were understood or completed.

**A completion reviewer is a testable option, not a verified repair.** Claude Code documents [prompt-based Stop hooks](https://code.claude.com/docs/en/hooks#prompt-based-hooks) and [Stop continuation controls](https://code.claude.com/docs/en/hooks#stop), including repeat-continuation protection. That establishes a usable pattern for evaluating termination. It does not establish its accuracy or latency on MiMo or Astella. The existing local answer-review probe already records accepting a known wrong denominator in both tested thinking modes and is not connected to ordinary production replies. Reintroducing it unchanged would repeat that failed experiment.

**Claim-to-evidence binding is the stronger direction for externally grounded results.** The [Evidence-Carrying Termination paper](https://arxiv.org/abs/2608.23623) studies certificates that bind required claims to scoped trace evidence and replay; it explicitly limits its guarantee to trace support under declared assumptions. It is a research result on synthetic/controlled tasks, not a production quality guarantee for this application. Our current `textOnly` declaration can still mark a supposed private-note answer as complete with zero receipts; the synthetic findings demonstrate that validator boundary. An arbitrary model-declared requirement list cannot prove that it covers the user's entire request.

**Keep model-owned discovery; reduce avoidable round trips.** Anthropic describes [deferred tool discovery and programmatic orchestration](https://www.anthropic.com/research/advanced-tool-use). The current loader already implements the basic discovery idea. Further batching should be chosen by the model and use the same execution ledger, permissions, and cancellation, rather than installing a fixed search/read/write sequence. Provider features described for Claude cannot simply be assumed to exist on MiMo.

## Concrete next experiment

Use a frozen, offline replay of the existing failures plus independent held-out conversations before connecting another reviewer to production. Compare the native baseline with a narrow completion auditor. Give the auditor the original request, the exact provided materials/versions, receipts, the delivery ledger, and an explicitly unpublished draft. It returns structured findings tied to exact request/draft spans and actual source IDs; it has no write capabilities and does not choose a business workflow.

Separate three questions: whether every requested deliverable is covered, whether a claimed external fact/action has supporting evidence, and whether the reasoning itself is correct. A receipt can answer the second and still leave the third wrong. Conversely, an already-provided image or passage must not incur an unnecessary read just to manufacture a receipt.

Start in shadow evaluation. Record false acceptance, false blocking, extra calls, effective first text, completion time, cancellations, and any duplicate/missing message. Include negative controls: correct supplied-material answers, rhetorical quotes, negation, portable preferences mentioning a school subject, English text, ranges, hidden random note values, stale versions, partial writes, and multi-message requests. An auditor's unavailable result is unknown, not approval.

If this comparison earns adoption, feedback must remain a host observation carrying the draft as unpublished data. Do not insert the draft as an ordinary historical assistant message and thereby imply that it was sent; that was the cause of the previous split-message regression. Use actual write/publish events to track delivered work. Do not require every casual reply to pass another serial model call.

In parallel, replace the active lexical semantic rules in the table in small groups: selected-question wrapping and note-length inference first, memory provenance/binding next, then context/diary policies. Each replacement should preserve the associated permission/version/source checks and be tested against new wording rather than a longer exception list. These changes are proposed work, not part of this patch.
