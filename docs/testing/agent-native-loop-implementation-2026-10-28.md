# Agent 原生循环整改与真实链路验收

> 本文是 10 月 28 日阶段记录。10 月 29 日后续已实施三档并行资源调度并发布生产；当前状态、实测结果与保留反例见[发布及验收记录](./agent-completion-and-release-2026-10-29.md)。下文的“生产未部署／默认关闭”保留当时状态。

日期：2026-10-28。基线：`9ac7d098dd8ba2a4e82b49495f920bf3e99109d8` 加本轮开始时已有改动。用户在历史复盘和真实模型决策后要求开始实施；本文记录本地实现与实际验证，生产未部署。

## 当前决定

**执行架构确定为一个原生模型—工具—回执循环。模型理解当前目标并选择下一步；宿主负责权限、协议、对象版本、幂等、真实结果和交付恢复。**

代码已完成这一阶段的整改。快慢调度只保留严格 `chat/work` 的窄职责候选，默认关闭；不承担答案生成、工具选择、气泡数量、授权或完成判定。没有新增关键词路由、向量阈值或固定工具流程。

**生产模型与快慢配置仍未通过整体验收，不能宣称稳定达到 1–2 秒或任务成功率 ≥95%。** 主配置 `config/ai-platforms.json` 未切换。现有 SiliconFlow 凭据对应的 `deepseek-ai/DeepSeek-V4.1-Flash` 是本轮最有希望的文本候选，完整链路比 MiMo 的诊断批次快，但仍有聊天尾延迟、资源误判和内容质量反例。因此保存独立候选配置，保留原配置及默认关闭开关，而不是将小样本改善当成上线准入。

## 已实施的行为

| 问题 | 实现与边界 |
| --- | --- |
| 前置语义入口混合分类、回复、工具和消息数量 | 入口严格只解析 `{"path":"chat|work"}`；旧 `entryDecision` 在合同解析时丢弃。8 个语境示例沿用诊断版本，没有按失败句追加；包含对话、工具结果和材料身份。5 秒总截止，异常回工作档，父取消继续生效。 |
| 规则先决定工具顺序 | 删除标题／否定词驱动的笔记预读、强制编辑前置阶段、强制附件单独读取步骤。已有有效 ID 和版本可直接使用；搜索、阅读、编辑由模型决定。链接仍需要真实可见版本及读取依据。 |
| 模型拿不准编辑边界 | 参数直接说明含尾端的块范围、0 起算 `blockIndex`、完整 `expectedBlocks`、范围内替换及 Markdown 段落；共享工具目录复用权威 schema 描述，结构拒绝返回实际块数。权限、版本和结构保护保留。 |
| 内部纠正藏掉已成功的回执、重复要求模型交付 | 当前用户／主动观察有明确请求边界；内部修复不创建新边界。交付重试回放实际被拒绝的 assistant 草稿，继续使用本轮已成功结果。 |
| 把成功一项当成整件事完成 | `companion_finish` 申明 `outcome` 与逐项目标；宿主核验动作、读取、所有已成功写入及引用。未满足目标不能申报 completed；移除“一次写入就绑定整个目标完成”。这不能证明模型没有漏理解目标，也不能证明正文推理正确。 |
| 失败／未知结果被当成成功，或跨轮借用回执 | 统一真实成功回执收集，失败、阻止、等待、未知等状态不入账；同一调用的后续结果覆盖先前结果。被压缩的只读回合保留当前请求的精确、哈希核对来源，历史回合不能成为本轮成功依据。 |
| 两条独立气泡之后又多一条确认 | 实际 publication 回执可作为交付依据；修复扁平 `say.publish` 的工具映射。已独立发布时，finish 只关闭执行，不再附加确认气泡或泄露私有草稿。消息数量由模型理解，宿主不再扫描自然语言数量词。 |
| 正确完成计算后反复拼错长回执 ID | 工具结果给宿主分配的 `r1/r2` 短引用，协议原始 `toolCallId` 不变。引用保持到恢复／压缩；宿主精确映射，拒绝不存在、冲突、历史和失败引用，不做模糊匹配。 |
| 用户先陈述事实、下一轮同意记住，却因来源不是最后一句而被拒绝 | 记忆来源允许同一用户／空间／会话中、当前消息之前的唯一逐字原话，持久化真实原消息身份与时间。当前请求决定是否执行，历史原话只作事实依据；不增加确认词表。存在多个同文来源时拒绝猜测。移除 self-note 与用户事实分流中的自然语言正则。 |
| MiMo Responses 政策与材料位置混用 | 领先的政策写入协议的 `instructions`；后续 host 观察保持原位置，不能将资料提升成顶层政策。协议调整不等于证明模型质量已修复。 |

普通聊天继续自然流式输出；工作候选和实际写入通过结构化完成工具交付。没有中性开场白冒充有效首字、统一二次审稿调用或关闭全部工具的聊天支路。

## 真实模型试验与结果

本轮另有 100 次诊断试验：MiMo 原生／资源对照 32、已配置 TokenRhythm 对照 20、SiliconFlow 候选对照 14、备用端点资源判断 34。诊断包含真实 provider、完整提示和 schema、纯计算器与真实笔记变换；其中状态存储为隔离模拟器，不是实际 HTTP 工具执行。

完整执行共保留 **106 条已记录请求**，另有 4 条测试器中止记录；这些含重复与修复前后对照，不是独立场景。完整执行验证走 **HTTP→队列→当前源码 worker→实际工具→PostgreSQL／CRDT→持久化回复与事件**，使用独立数据库容器、API 4108、合成账户。原有 dev 容器、真实账户和生产部署未改。验收容器与自建 API／worker 已停止，凭据夹具已删除；早期在共享 dev PostgreSQL 创建的空测试库 `astella_agent_impl_20261028_c83f` 因残留会话仍无法删除，已记录到 `cleanup.json`，未为此重启共享实例或终止其他任务。每批原始失败、超时和测试器错误均保留，不能用后来的成功覆盖。

候选文本配置为 SiliconFlow `deepseek-ai/DeepSeek-V4.1-Flash`，Chat Completions、`enable_thinking=false/true`；档案只列实际使用的 `none/high`。出网记录确认 false 时的实测样本 `reasoningTokens=0`。配置 TokenRhythm 的 `none` 实际只能映射到 high，不将它计作真正关闭思考。候选没有未经验证的视觉声明；识图仍取现有辅助视觉能力。本轮没有完成真实图片、客户端屏幕或语音端到端验收。[SiliconFlow 参数文档](https://docs.siliconflow.cn/docs/api/chat-completions-post)、[DeepSeek 思考与工具回放说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

`firstVisibleMs` 来自首个 `assistant.delta/utterance` 的服务端时间，排除了队列外的测试节流，**没有客户端渲染、网络、音频或用户感知测量**。导出的逐条事件可复核实际首段；不能把标签、状态或礼貌开场当作有效正文 SLO。特别是工作档先缓冲到 finish，部分题目的首次公开正文接近总耗时。

## 人工内容核对发现的反例

本节由实施者阅读输出后核对，不是独立盲评；检查器结果保持原样。

- 资源判断仍会把移动参考系、贝叶斯或因果题分到 chat。MiMo 原生诊断中一条移动参考系输出标题为 6m/s，推导却为 5m/s。合格 JSON 不能保证档位策略正确。
- SiliconFlow 两批移动参考系得出乙向东 5m/s、质心 2m/s、动能 320→1040J，数值正确。最后一批却有一个分式缺括号，以及“非弹性式”的不精确术语；不能标为整篇质量满分。
- 2% 患病率、80% 敏感度、10% 误报题两次主要结果均为 `8/57≈14.04%`；其中一次被判 chat，不能用答对一次证明降档无风险。
- 冰淇淋与溺水题虽答“不能证明因果”，却把炎热天气这个合理混杂假设写成已知真实原因，并对控制变量后的结果作未经验证断言。旧关键词检查照样通过。
- 原生 high 对英文问候主动纠正时区、归因疲惫并劝睡；调度版本也过度纠正时间。`nonempty/noInternalLeak/noUnrequestedWrites` 无法检验这种自然度问题。
- sqrt(2) 两条证明的反证主链核对通过；不据此推广所有证明质量。没有统一语义成功率或已达到 95% 的结论。

这些问题是模型／提示／资源选择的能力准入问题。本轮没有把它们再转换成场景词表、禁止词或强制工具链。

## 本阶段交付与下一步

本地原生循环与合同修复可审阅，已有回归证据；窄资源判断和新文本端点均保留候选，不改生产默认配置。本轮没有发布、提交或新建 PR，也没有合并其他会话的声音改动。

后续只沿已确定的架构推进：在固定源码、模型、端点、提示和工具面上，以真实新样本检验自然交流、复杂推理与所有目标；达到聊天有效正文 p50≤2s、p95≤5s 及代表性任务达成率目标后再准入。当前还缺独立家族留出、长上下文／负载、多轮自然度、真实图片及设备链路证据。不能用更多关键词、误报正则修饰或反复挑最好结果填补这些缺口。

仓库仍有未被运行主循环调用的旧文本检查函数和测试，以及记忆时间元数据等领域规则。本轮移除了主决策链的这些依赖，不宣称清除了全仓所有正则或全部历史技术债。
