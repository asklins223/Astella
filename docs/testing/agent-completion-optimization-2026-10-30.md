## 本轮改进

1. **实际用过工具的 answer 回合也核对来源。** 原先的保护条件主要看资源分档、写入和消息发布；answer 档实际读取了笔记，仍可能绕过最终核对。新增数据库反例分别让读取成功、读取失败后给出编造口令：修改前两项都失败，编造正文直接交付；修改后两项均被拒绝并修正。现在已匹配的真实工具结果会启用后续来源核对，包括失败结果和同轮压缩保存的原始回执。未匹配的孤立 tool 消息、旧轮回执不触发这条条件。
2. **长材料只在来源中保留一份。** 旧输入同时在 tool 来源、成功清单和实际结果清单中重复携带正文。现在正文完整保留在原始回执来源，清单只保存调用身份、操作、风险类型、来源 ID 和实际发布数量。没有截断、摘要化或删除原文，审查器仍可逐字引用。
3. **新增材料不会切断本轮回执。** 原扫描把所有 role=user 消息都当成新请求，宿主补充的 user/hostObservation 材料会隐藏前面的真实读取或写入。现在忽略这类宿主材料，保留本轮边界；下一条真实用户消息仍开始新的作用域，不能借用上一轮的成功操作或来源。

新增条件使用请求边界、宿主身份和真实调用/结果的关联，没有增加按用户措辞匹配的意图关键词表。审查提示和严格引文解析没有改动，政策哈希仍为 `8ad1c3627638b87ce29cf712a52ad88c52c6d05255128ac1ee4b1beec0a5c882`；未放宽引用绑定或不可用判据。

这些是直接装配配置 provider 的定向循环夹具，账号、笔记、口令全部合成；不包含线上完整 handler/治理装配、客户端窗口或生产并发验收。[真实循环结果](./evidence/agent-completion-optimization-2026-10-30/runtime-live-results.json)、[运行日志](./evidence/agent-completion-optimization-2026-10-30/runtime-live.log)。

## 保留边界

- 已知 chat/answer 且没有实际工具结果、写入或发布的回复仍可直接交付；错误分档的零工具私人查询仍是剩余风险。本轮补的是实际工具调用后的路径，没有证明资源判断永远正确。
- answer 在首次工具调用之前可能已经流出前导正文；本轮新增条件会保护取得工具结果后的后续步骤，不能撤回已经显示的文字。主动参与继续沿用原有审查。
- 审查器仍可能误放、误拦或不可用；不保证计算、推理、知识事实或识图全部正确。合法工具使用后的 answer 会增加来源核对，资源判断超时也可能进入较慢路径。
- 检索分词、停用词、协议枚举/格式、来源逐字匹配、动态去重、权限和版本规则仍在，具体库存沿用[词表清理记录](./agent-lexical-cleanup-and-boundaries-2026-10-29.md#仍然存在的规则)。
