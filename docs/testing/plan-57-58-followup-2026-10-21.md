## 2. Plan 57 functional gap: failing questions must not kill the card

Plan 57 §3.3/§7.3 (line 146/368) says: validation failure retries once, then **discards** the failing question(s) and reports "有 N 道题未通过校验，没有收录"; only below 4 valid questions does the whole card fail. The implementation was all-or-nothing: one bad question aborted the whole card. Live evidence: a real generation failed after 46 s with "第 1 题引文与保存版本的对应段落不符" (`outputs/audits/plan57-58-2026-10-21/card-http-1792575029067.json`), and dev-DB jobs over 10 h were 7 succeeded / 4 dead, i.e. roughly 50–65 % generation success on the dev model.

Implemented now:

- Generation and review validation report per-question failures (question number, check, short excerpt) instead of one aggregated throw.
- One bounded retry with a correction naming the failed questions; after that, failing questions are discarded, one question per duplicate group (earliest kept). Fewer than 4 valid questions still fails the card. Provider/network errors are not turned into content retries.
- Host-side duplicate backstop: two questions with the same (essentially identical normalized) grounding quote **and** equal/nearly-equal review `knowledgePoint` are treated as duplicates; same-quote questions with genuinely different knowledge points are kept. This targets a live miss where a true/false question and an ordering question used the same quote to test the same experiment-order fact while the review returned `duplicateGroups: []`.
- `note_learning_cards.omitted_question_count` (migration `0453`, applied to the dev DB) is written by the worker, exposed additively in the shared card contract and API read route, and shown on the card front as "有 N 道题未通过校验，没有收录" (quiet paper-side note, wraps at 200 %).
- Rejected questions record question number/check/excerpt in the job error and worker audit log, so this class of failure is diagnosable without persisting raw model output.

One live probe after the change generated a clean 6/6 card in 43 s (`omittedQuestionCount = 0`) and completed grading and the operation-template checks (`tmp/verify/card-discard/card-http-1792577847936.json`). The discard path itself is proven by focused tests that reproduce the exact run-1 failure (question discarded, 5→? card kept with omitted=1, receipt names question/check/excerpt); the live run did not happen to need a discard.

## 3. Source guards that were red in the current tree

- `workers/ai-worker/package.json`: the new `journey-milestones-postgres.integration.ts` was not registered in any test script, failing the shared integration-registration ratchet. Added to `test:companion-integration:postgres`; shared suite 530/530.
- `memory-similarity-threshold` guard: the new proactive speech review used a literal `similarity(...) >= 0.18`. The threshold is now the named shared constant `COMPANION_SPEECH_REPEAT_CANDIDATE_SIMILARITY` (a retrieval prefilter, not the 0.85 memory-conflict threshold), and the guard now requires every `similarity()` site to use its own family's constant and forbids literal thresholds.
- `god-file-ratchet`: Plan 58's durability wiring (output watchdog, protocol fallback, request requirements, speech-review hook) added 15 live lines to `companion-agent-runtime.ts` after the 1553-line baseline was recorded. The baseline now records the true number (1568) with an explicit note that the next split still belongs to the turn/agent domain split; it is not treated as an acceptable final size.
- `renderer-style-dead-guard`: `lc-card-statistics` CSS rules had no emitter left after the card-front work; the dead rules were deleted (guard requires delete or an explicit exemption reason).

## 5. Remaining limits (not fixed by this round)

- **Generation reliability was not re-measured at scale.** The discard path converts some whole-card failures into smaller cards, but the observed ~50–65 % success rate on the dev model and the fixed cost of the two-attempt repair remain. p50/p95 and ≥95 % completeness are still unmeasured.
- **Semantic correctness and paraphrase duplicates are still partial.** The host duplicate backstop is deterministic and conservative; it does not detect every paraphrase. Question/answer semantic truth is still validated by an independent solving pass plus schema/quote checks, not by a proven semantic gate.
- **Content quality defects remain in real generated notes.** Existing user notes still contain, for example, the untranslated token "全国 initially 分为36郡" and previously observed "贞景之治"/"加强中央集盐铁官营". Length/schema gates pass; prose quality is not fully solved.
- **Native window pixel checks were limited this round.** The macOS screen was locked/occluded for part of the session, and the Electron zoom shortcut could not be driven reliably; DOM geometry and standalone Chromium probe renders (real components + full stylesheet order) carry the zoom/width evidence. System reduced-motion and the full native iOS/Android matrix were not re-checked; the mobile client is being changed by another work stream.
- **The jump chip still overlaps the bottom ~36 px band of the reading area while visible** (standard floating pattern). A zero-overlap variant would need a permanently reserved row; not chosen.
- Pre-existing low-contrast author/time metadata (2.77:1) and day divider (3.07:1) in the journal were not changed; that is a broader visual decision.
