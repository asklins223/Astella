# 手机端体验五轮源码走查（2026-10-14）

## 走查边界

五轮都从 `App` 的登录／导航／页面入口开始，沿真实调用关系跟到状态和控件。此记录是源码级走查，不把截图或构建当成视觉验收。当前回合未能访问本地浏览器窗口，因此布局、玻璃层次、动画观感和真机选图器仍须在可用窗口里确认；没有声称完成实屏验收。

## 第一轮：账号入口

- 路径：`App` 的 `signed_out` → `AuthScreen` → `authApi` 邮箱码、登录、注册、重置密码流程。
- 发现：原认证表单被包成一张大玻璃卡，人物与标题居中堆叠，缺少 Demo 的不对称识别。已改为伴星靠右、文案靠左；玻璃回到可操作的输入和切换控件，表单容器本身透明。注册／重置的双步骤进度继续跟真实状态走。
- 再查键盘与异常路径：保留输入法组合键保护、字段错误聚焦、验证码倒计时、请求超时／取消和状态切换清理。邮箱更换按钮命中高度从 42px 修到 44px。无玻璃与减少动态仍有单独样式。

## 第二轮：手记架与图片入口

- 路径：一级“手记” → 搜索／分页 → 打开当前笔记或从图片进入交流。
- 发现：列表有图片封面展示，但没有从手记架递图的入口。已在搜索工具旁增加相机／相册入口。选图校验和对话输入共用一处格式、10 MiB 限制；成功后带着图片和可编辑提问进入对话，仍由用户主动发送才上传。
- 再查列表状态：搜索请求会取消旧查询，清空条件可回完整书架；错误可重试，加载更多使用游标，返回时保留书架状态。

## 第三轮：笔记正文与派生页面

- 路径：手记架 → 连续正文 → 版本、讲解、思维图 → 返回原文。
- 发现：各页的结构职责不同，避免统一套卡片：正文是一张连续纸页；版本是保存时间线并带明确恢复确认；讲解由互动画面和章节原文组成；思维图是可拖缩画布，也提供提纲替代路径。页面携带真实 note/version 身份，选区提问与节点／章节回原文都用实际锚点。
- 再查变化状态：派生内容带来源版本，正文更新后不把旧讲解或旧图伪装成当前结果；读取失败、生成失败、恢复冲突和只读权限分别有原位反馈。

## 第四轮：伴星入口、连续交流与实时过程

- 路径：顶部伴星入口 → 当前页面旁交流 → 同一会话记录 → WebSocket 状态、思考与工具过程。
- 发现：旧顶部人物看起来像静态装饰。现在按钮带当前运行状态，可从笔记、设置、个人中心等页面打开就地交流；笔记上下文从当前可见页面读取 noteId/version，避免退出动画中的旧页面提供过期版本。上下文草稿按用户、书房、笔记版本和选区隔离。
- 再查消息表现：同一 run 的相邻伴星分句只在展示层合并成连续段落，服务端消息 ID、序号和工具事件仍各自保留。真实 `/companion/realtime` WebSocket 驱动 thinking、delta、utterance、tool 与归档恢复；`RunProcess` 展示实时思考和操作状态。

## 第五轮：触控、滚动、动效与边界

- 路径：从详情页返回、快速切换、键盘弹起、减少动态、思维图拖动／缩放。
- 发现：大思维图原先会先按整图缩小，节点和文字跟着缩成难以点按。现在大图以可读尺寸从主题节点开始，节点至少 68 CSS px 高；用户可主动缩小浏览整图，再点“主题”返回。窄屏使用阅读提纲时，分支操作和阅读操作仍各自有独立命中区。
- 再查动效：页面进退使用可取消的 WAAPI 过渡；面板可拖动、Escape 关闭并返回焦点；系统／账号／本机减少动态会停用过渡，批注定位也不再强制平滑滚动。键盘态会压缩账号插画区并保留当前输入。

## 继续复扫：弹层遮挡与就地输入

- 从设置／个人中心／伴星中心打开上下文交流时，复查模态背景发现 `.utility-header` 不在 inert 列表中。已补上，避免弹层打开后底下的返回按钮仍可点到。
- 对比主对话和页面旁交流输入：主对话回车发送、Shift+回车换行且保护中文输入法；页面旁交流此前只换行。现已统一发送行为和键盘 `send` 提示，输入法组词时不抢回车。
- 再查消息位置：记录页跟随用户是否贴近底部；阅读旧消息时保留锚点，补载历史不会把阅读位置拉走。伴星场景只在新一轮或用户仍停留在最新内容时跟随。

## 第六轮：会话失效与异步回包

- 从全局会话恢复入口重新走笔记架、正文、批注、讲解 HTML、伴星旧消息、停止回复、提议确认、权限资料和页面感知上报。发现多个状态层把 401 显示成普通网络错误，或在后台补全消息时静默吞掉；现在只在请求仍属于当前页面／回合／书房时清理登录态并回到登录恢复，旧书房的迟到回包不会影响新账号。
- 复核设置、个人中心、伴星中心的上下文交流弹层：打开时把工具页顶栏一并设为 inert；关闭后原触发按钮恢复焦点。主对话与页面旁输入都用 Enter 发送、Shift+Enter 换行，中文输入法组合态不会误发。
- 复核认证表单级联与步骤：手机窄屏／短屏、键盘态、验证码重发冷却、字段错误聚焦、密码显示、取消请求和减少动态都有独立状态；最终手机规则将表单容器保持透明，把液态玻璃留给输入与可操作控件。源码核对不能替代窗口中的布局观感确认。

## 本回合的五轮复扫（从入口重新开始）

这五轮重新从 `App` 的入口与页面状态开始，逐条沿当前 React、状态模块和 API 路由核对；前面的记录只作来历，不作本轮结论。成熟移动端基线参考了 [Apple 无障碍与触控指南](https://developer.apple.com/design/human-interface-guidelines/accessibility/)（常用 iOS 控件至少 44×44 pt，并给相邻控件留间距）和 [Apple 动效指南](https://developer.apple.com/design/human-interface-guidelines/motion/)（反馈短而明确、允许用户打断、减少动态时避免轴向位移）。本轮仍是源码、合同和构建证据，不代表窗口验收。

### 第一轮：启动、认证、书房和路由

- 从 `App` 状态分支走到 `AuthScreen`，再对照 `/auth/login`、`/auth/login-with-code`、`/auth/email-code`、`/auth/register-v2`、`/auth/reset-password` 的当前服务端合同。邮箱归一、六位验证码、登录密码 4–200 位、注册／重置密码 8–200 位、用途隔离和 `clientKind: mobile` 一致；没有在客户端暗示笔记正文可编辑。
- 书房切换沿 `/auth/workspaces` → `/auth/switch-workspace` → 会话范围更新 → 清空租户态数据 → 回到主对话。导航动作以 transitionId 隔离过期动画；弹层切屏会收起并处理焦点。
- 修复账号切换时设备偏好在首帧后才装载的问题：`loadFor` 从被动 effect 改为布局 effect，避免新账号短暂继承上一账号的字号和对话首页。
- 退出操作改为立即清除本机凭据并进入登录页；服务端撤销仍带原 Bearer 凭据后台执行，最多等待 8 秒，失败时反馈“本机已退出、服务端注销状态暂时无法确认”。旧请求不会覆盖后续新登录。

### 第二轮：对话、持久 WebSocket、思考/工具和语音

- 从 `openConversation` 的 inbox 恢复、快照游标开始，核对手机 `/companion/realtime` 首帧认证、订阅持久事件、服务端事件重放与 `turn.submit`。服务端将稳定 `clientMessageId` 用作幂等键；WS 回执不可用时客户端以同 ID 走 HTTP 兜底，不会重复创建消息。
- `assistant.thinking` 的增量、`agent.tool` 和终态进入 `companion-process`，再由 `RunProcess` 展示；快照恢复保留过程归档，事件序号缺口会重新取快照。相邻同 run 的伴星发言只在阅读投影合并成段落，底层消息身份仍分开。
- 修复快照恢复失败的连接竞态：旧 socket 现在按实例隔离迟到消息；恢复失败先关闭过期游标的连接再重连，避免双 socket 同时改写对话状态。同步回调即使同步抛错也会进入可恢复路径。
- 手机录音仍是用户主动录制、整段 WAV 交给服务端 MiMo 转写，文字先回到可编辑草稿；这不是流式 ASR，也不声称已接 TTS。页面旁问伴星共用会话与实时过程，草稿按上下文隔离。

### 第三轮：手记架、正文、历史和派生页

- 从手记架核对列表、正文搜索游标、取消旧请求、图片入口，再沿笔记 ID 到只读正文、批注选区、版本、速看、导图和讲解。生成任务均绑定来源版本，恢复版本使用 `baseVersionId` 乐观检查；权限、冲突和读取失败有各自状态。
- 修复图片入口覆盖主对话已有草稿的问题：选图时先保留现有文字；输入框原本为空时才放入图片提问提示，并清除与旧页面关联的草稿上下文。
- 修复版本分页在恰好 100 条时误显示永久“再往前看”按钮的问题：请求一条哨兵记录判断 `hasMore`，列表只呈现每页 100 条；计数改为“已载入”，不再把当前页冒充全量。当前正文版本改变时会重取首屏版本记录并标识当前版本。
- 讲解画框仍由带凭据的 API 取 HTML，隔离 iframe 不获同源权限；无法取画框时仍可读下方提纲和原文入口。

### 第四轮：伴星入口、手边、设置和弹层

- 从工具页顶栏伴星按钮核对它打开携带当前页面身份的就地对话；阅读页的 context 包含 noteId 和可见版本，离场 ghost 不会提供过时版本。手边显示待确认提案、运行中回合、掉线与中断恢复，入口返回唯一的共享对话。
- 设置中的字号和对话显示为自绘选择面板，减少动态响应系统／账号／本机三种来源。键盘方向键现在会像单选控件一样同步焦点和已选值，原生下拉菜单没有进入真实界面。
- 单一 sheet store 保证同一时刻一个面板；打开后背景设 inert、焦点留在面板、Escape／拖动可关闭、关闭回到触发点。页面切换时隐藏的工具顶栏一并设为 inert。
- 个人称呼、头像、权限、个人约定各走真实 API；偏好保存冲突会保留未保存文字。退出确认后本机即时退出，网络撤销有上限。

### 第五轮：触控尺寸、键盘、滚动和动效边界

- 核对安全区、`visualViewport` 键盘态、输入法组合保护、滚动锚点、历史自动补载、左沿返回手势、导图平移／双指缩放及短屏布局。WAAPI 页面转场有 transitionId，新的操作取消过期动画；减少动态同时覆盖 CSS 动画、程序化页面转场和面板动效。
- 按 44×44 pt 基线补齐消息重试、移除图片、语音录制取消／完成、录音入口、个人称呼输入、会话重连与若干行内重试按钮；其余关键主控原已有 44px 以上命中区。
- 真正的转场节奏、弹层是否挡住原文、窄屏内容是否拥挤、键盘遮挡、快速反向操作手感和 Live2D 性能，仍须在实际浏览器/手机窗口核对。本轮没有用源码推断截图观感。

## 继续复扫：思考流刷新与窗口状态

- 对 `assistant.thinking` 的展示路径重新从 WS 增量跟到 `RunProcess`。发现 `useStreamedText` 的 50ms 定时器会在每个文本增量到达时清理并重新开始；高频增量可能让思考文字停在旧片段，直到流暂停才追上。现改为单个 `requestAnimationFrame` 追赶循环，持续读取最新目标；新 run／截断窗口会重置到当前文本，减少动效或流结束时直接显示完整结果。
- 对断线重连的 `close` 回调做实例边界复核。旧 socket 迟到关闭时此前仍会清除新 socket 的全局订阅状态、拒绝全部待处理命令；现待处理回执记录所属 socket，关闭事件只结算该实例的命令，只有当前 socket 才能更改共享连接状态。
- 对照 `ThreadChat`、`SceneChat` 和页面旁交流的滚动状态：主记录在用户贴底时跟随流式正文与工具过程，离开底部时保留锚点并给“回到最新”；伴星场景只展示当前回复，并在读者仍停留底部时追随内容。需要真窗口连续发送、上滑读旧消息后新回复到达、再点回最新等动作确认手感。
- 本回合启动手机 Vite 预览于 `127.0.0.1:5174`，但当前可用的浏览器交互策略拒绝跳转到本地地址；已有标签指向桌面开发服务器 `5173`。没有用其他浏览器或原始请求绕过该限制，因此本回合没有视觉验收证据。
