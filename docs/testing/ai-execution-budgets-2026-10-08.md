用户决定：可以通过工具调用次数、重复平台错误和有限重试控制失控执行，正常长推理与生成不应经常被较低的时间或 token 上限截断。

## 已落地行为

| 层级 | 原实现 | 当前实现 |
| --- | --- | --- |
| 有档案模型的输出额度 | 后台任务的 500–24000 token 覆盖模型空间，包含推理 | 使用所选模型档案的 maxOutputTokens；当前默认 DeepSeek V4.1 Flash 为 384000 |
| 单次模型等待 | 默认 75 秒，多处额外 30/60/65/120 秒 | 公共默认 15 分钟，按父任务剩余时间收紧 |
| 普通后台任务 | 普遍 90–110 秒，被两分钟租约夹住 | 默认 30 分钟，运行中每 30 秒串行续租 |
| 多阶段制卡管道 | 20 分钟，模型子任务 120/240 秒 | 总管道默认 60 分钟，模型子任务复用 15/30 分钟公共预算 |
| 崩溃恢复 | started_at 同时承担起点与租约时间 | 两分钟回收窗口保留，新增 lease_renewed_at；续租不改开始时间 |
| 上下文治理 | 按请求里的小 maxTokens 预留 | 在计量之前解析有效输出上限，计量与实际请求一致 |

正文篇幅、引用、输入大小及输出结构仍由领域合同负责。模型档案缺少输出声明时保留既有 provider fallback；不会为未知模型伪造能力。正常的模型 high 思考设置保留。初始连接、数据库语句及纯数据读取有独立故障时限。

模型调用次数、自动重试次数、工具次数与幂等规则没有放宽。取消或续租失败立即中止任务信号；旧租约持有者不能继续保存。心跳不触发模型调用、不占 Agent 的调用额度，完成后停止续租。

获准的修复重试各自保留单次调用时间，并受父任务总时间限制，不再让第二次尝试只拿到第一次剩下的短窗口。历史预算回执仍能读取原有的 120 秒值，新默认不会使旧手记或诊断记录失效。

## 真实模型证据

与上一轮冻结的单摆精简提示一致，仍使用 DeepSeek V4.1 Flash / high / JSON 及相同合成素材。扩大额度后的请求真实下发 max_output_tokens=384000，约 152.4 秒后返回完整 JSON 和 17206 字符 HTML。

收据：prompt_tokens=821，output_tokens=37453，其中 reasoning_tokens=29757，最终正文约 7696 token。旧 24000 上限根本装不下这次推理与最终代码，旧 95 秒循环也早于最终结果。

输出通过 JSON schema 和页面安全检查，有 requestAnimationFrame 动画及 setLessonMotion 接口。但原文引用与“实测”声称没有通过既有完成判据，因此没有保存为业务成果，也未声称成品质量验收通过。这个样本验证的是扩大预算恢复了最终输出。

原始请求、返回、候选 HTML 与收据保存在 `outputs/audits/2026-10-08-html-motion/expanded-budget/`，没有保存明文推理或凭据。
