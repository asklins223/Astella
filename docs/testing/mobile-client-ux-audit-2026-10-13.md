## 设计参照

- 阅读选中文字时采用系统熟悉的触摸选择路径：长按文字后扩展选区，再对选中内容执行操作。Apple Books 的 iPhone 使用指南也采用长按文字、拖动选区手柄后高亮、添加笔记或复制的流程。本应用将同一选区交给伴星解释，而不要求逐段点引用图标。[Apple Books：Annotate books on iPhone](https://support.apple.com/en-gb/guide/iphone/iph17bf340c1/ios)
- 触控控件检查参考 Android Accessibility 对至少 48×48dp、相邻目标间至少 8dp 的建议；网页实现设置 48 CSS px 最小高度/宽度和 8px 控件间距。这是 CSS 预览中的尺寸基线，不等于真机的 48dp 验收。[Android Accessibility：Touch target size](https://support.google.com/accessibility/android/answer/7101858?hl=en)
- 信息分组、导航与手势的总体评估参考 [Apple HIG：Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 与 [Apple HIG：Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures)。实际内容层级仍按本项目移动学习流程与桌面共用数据约束来判断。

## 这轮确认的交互结果

在 `http://127.0.0.1:5174/` 的真实浏览器窗口，以手机预览宽度打开《导热与凝固点》，从“先看现象”段开头拖选到下一段“关键一步”结尾。选区面板完整显示两段文字；主要发送按钮和三项次要动作都在面板内可见；无须分别点每段旁的按钮。

发送动作复用现有 `sendTurn`。所选原文作为单个 `selection`，笔记 ID 和版本作为页面上下文；发送失败时选区仍留在面板供重试。面板会在对话尚未恢复、伴星仍在回复或附件仍在处理中时阻止重复提交并说明原因。窗口核验没有点发送，因此没有在真实账号中创建消息或触发 Agent。

其他相关改动：会话预览气泡在用户仍跟随最新内容时滚到新回复；用户主动向上阅读时保留位置。完整回复仍可在记录视图阅读。手记列表仅在 API 返回图片块时显示真实配图。个人中心权限和账号信息放进清晰分组；设置菜单由应用绘制，不依赖浏览器原生控件。

## 核验范围与限制

- 五轮均从根路由重载开始；实际窗口约 430 CSS px 宽，是桌面内嵌浏览器中的手机框，不是 Android 或 iPhone 真机。
- 已实际验证跨两段拖选及单一发送入口；没有提交选区、普通聊天、图片或语音，没有修改个人资料或笔记。
- 手记列表当前 11 项没有 API 返回图片块，因此这次没有可显示的缩略图样本；搜索结果对象也没有首图字段，搜索结果列表的图片展示未验证。
- 实际手机触摸手柄、中文输入法/软键盘、系统减少动态、真实新回复流式到达时的自动跟随，以及小米 MiMo 真机录音均未在设备上核验。样式 48px 是网页预览 CSS 值，不构成 Android dp 或 iOS pt 的测量结论。
- `npm run typecheck`：通过（web 与 node 两份 tsconfig）。
- `npm run build`：通过，Vite 转换 543 个模块；主 JS chunk 1,201.14 kB（gzip 322.02 kB），仍有超过 500 kB 的 chunk 提示。构建前的伴星素材同步没有改动文件。
