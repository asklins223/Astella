# 发现簿入口与收藏链路核对 · 2026-10-05

本记录保留首轮收藏链路的实现与验证经过。同日用户追加了查阅页和轻量书签要求，当前界面与入口以 [伴星记录阅读核对](companion-record-reading-2026-10-05.md) 为准；下文的一次提醒与正文下方按钮已移除。

用户决定：保留发现簿，补全对话、日记的收藏入口和返回原文。方案 40 §7 已同步这一决定。

## 本次行为

- 对话中已有的用户原话和伴星回答均有常驻收藏按钮，搜索结果、更早记录也使用同一入口。
- 最新回答的一次提醒仍可「先不留」；仅记录该原话身份，不关闭手动入口，旧版全局忽略记录也不会屏蔽入口。
- 日记正文按段落收藏，身份包含日期、版本、块序号和段落序号。同一天的不同摘录独立保存。
- 发现簿提供「去对话挑一句」「去日记挑一段」以及每条可定位记录的「回到原文」。取消收藏后两页同步，重新收藏保留已有批注。
- 移除当前客户端没有展示入口的「书房里放出的」筛选；收藏默认仍为私人内容。
- 收藏按钮有轮廓、图标、明确状态和键盘焦点。失败提示在对应原文旁单独展开，提供重试；不会把失败显示成已收藏。
- 返回日记时定位到原段落并交接焦点；版本不同则说明当前版本，不错误定位到新版同号段落。历史记录身份无法解析时如实说明。

## 实际错误与边界

桌面网关的收藏、取消收藏、批注 POST 原来只有 `request`，而 HTTP 路由要求 `{ meta, request }`，因此真实请求先在校验阶段失败。三个写请求现已补齐元信息。

公共桌面收藏状态契约的身份字段位于顶层，主进程 IPC 原来要求旧的嵌套 `query`；现按公共契约接收并转发。

日记摘录使用新身份后，删除日记、批量删除与材料撤权都按日期部分处理其全部段落，也兼容旧日期身份。收藏时校验日记是否仍存在、可读且版本一致，防止旧页面重新保存已失效日记；无效日期不会交给数据库解析。

## 真实桌面窗口

通过 CUA 操作独立的 Study Discovery QA 测试应用，连接实际本地 API。使用已有的全流程测试账户；该账户没有日记，因此仅在这一测试账户新增了一篇两段的日记夹具。

已操作并确认：

1. 收藏用户原话、查看发现簿、保存批注、返回对应消息、取消收藏、重新收藏后批注仍在。
2. 对话最新回答点「先不留」后，原话旁仍可手动收藏。
3. 同一篇日记两个段落分别收藏，发现簿出现两条独立摘录，返回原文定位到第二段。
4. 从发现簿取消日记摘录，日记按钮同步恢复可收藏；重收后返回发现簿没有上次「已取消收藏」提示。
5. 暂时将本次日记夹具置为不可收藏状态，通过实际接口产生失败。窗口出现清晰的「这段话还没存下」提示和「重试收藏」按钮；恢复夹具后重试成功。
6. 观察长回答末尾、日记纸面与发现簿的按钮、文字、滚动和伴星位置，操作区没有遮住阅读内容。

验证范围限于本次相关链路，未执行全项目回归。没有调用外部模型生成新日记；日记生成质量不在本次验证范围。测试应用的凭据注入仅存在于临时应用副本，仓库不含测试会话或凭据。
