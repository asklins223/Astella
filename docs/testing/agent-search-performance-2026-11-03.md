# Agent 联网与读取性能修复

2026-11-03。接用户“保持目前模型搭配、可独立读取与搜索全部并发”的授权，基于 s-v2.0.20 继续修改。MiMo 主模型与 DeepSeek 回退的配置、能力路由、推理档位映射保持原样。

## 实现

- 账号已开启联网且工具通过既有权限过滤时，首轮直接提供 `companion_web`，省去装载工具的模型往返；关闭开关仍不能执行搜索。
- 同批参数已确定的笔记、记忆、身份、提醒、目标、统计、历史和网页读取并发执行，每批最多四项在途；较大的批次继续排队，不截断任务。写入、工具装载、发布、确认和依赖前一项搜索结果的网页读取形成顺序边界。
- 参数验证与账本登记按顺序预留预算，I/O 才并行；回执仍按原调用顺序交给模型。取消停止排队并收束已开始的工作；同一持久操作回执只执行一次。后续同批失败不能覆盖其他已完成读取的实际结果。
- 搜索默认并读前两项，可显式选 0–8 项。每页仍通过真实搜索网址授权、当前账号开关、外发政策、SSRF 与重定向边界。回执分别保留来源身份、实际 URL、原文窗口、全文指纹、读取失败和续读位置；不是把搜索摘要标为原文。
- 并读原文按检索词在实际页面中选择约 3,000 字符的窗口，字面定位不会生成新的证据；显式 `findText` 和 `offset` 优先。只从模型上下文移除重复的已读摘要、压短未读摘要，完整搜索结果继续保存。
- 有来源的答复分为段落或顶层列表项，并发核验；每项都看到全文推理上下文和实际来源，本项的引用原文重点核对；全部实际读到的材料仍供交叉检查，不能因草稿未引用而隐藏矛盾证据。通过完整 JSON 判定后按原顺序交付，失败不能撤掉已交付部分，也不发布未核验草稿。没有来源的闲聊仍用原有单次交流核对；单段短答没有额外分段模型调用。
- 修复研究答复来源较多时历史接口 500：持久消息读合同原先限制 32 块，而真实答复可以含 32 个引用再加正文，形成 33 块。输出与输入附件限制分开，完整来源不丢弃。真实本地旧记录修复前 GET messages=500，修复后=200，33 块完整保留；数据库测试同时覆盖连续历史。
- 补齐显式“联网核对”即使涉及稳定事实也需要实际原文的前置义务，避免先生成一篇记忆答案又被要求补查。专名译名仍需依据；篇幅和要点数按用户原要求，不为展示查证而额外抄长引文。

## 验证口径

本地使用真实 API、Docker worker、原有生产同款配置与外部模型，独立临时 QA 账号。问题包括短问候、三次相同 NASA 月海查询、两次相同 NASA/ESA 月球火星比较，以及应用近期活动/统计/对话历史读取。每次保留正文首字、服务端完成、模型实际调用、来源读取和交付回执；轮询完成时间与正文首字不混算。

基线、过程中被淘汰的候选与最终验收分开保留。某候选虽运行状态为 succeeded，但交付回执为 partial 或答复只是“核对未完成”时，不能计为完整成功。外部服务超时和原有主线路转回退另行记录，不能归咎于网页下载或隐藏在平均数里。并发核验会增加多段长答的物理模型调用数，以输入更聚焦和等待重叠换取首段时间；不是所有任务都降低成本。

真实数据库测试用锁住的一项活动查询证明其余历史/页面读取仍完成，同时验证回执顺序、权限、恢复、确认、迟到结果与已交付部分保留。历史测试实际存入 49 块含 48 个来源的答复，再通过受限 API 角色读取。

本次没有同题实测千问或 DeepSeek 消费者 App，因此不声称比任何竞品快多少。官方机制比较仍只是定位参考，不是本系统验收数据。

最终实测和检查结果见 [验收数据](evidence/agent-search-performance-2026-11-03/acceptance.json)。发布状态以实际版本接口和部署 CI 为准。

## 最新修正与实际结果

2.0.21 已由 [41643791400](https://github.com/asklins223/Astella/actions/runs/41643791400) 成功部署，版本接口、API / worker 实际源码指纹和健康检查均吻合，模型配置指纹不变。线上简单查询 19.295 秒、复杂查询 36.016 秒完成；33 块研究答复 GET messages=200，引用都有实际读取。

但追加时序探针发现：一次 90.238 秒的复杂查询直到 90.003 秒才出现正文，主线路中途还等了 30 秒。这不能算逐段提前交付通过。根因是 `turnImagesSentDirectly` 表示主模型有看图能力及授权，却被当成本轮实际有图片，导致同配置的纯文字回合跳过表达与来源核验；最终交付工具也没有接上核验后的逐段回调。

2.0.22 修正依据：按当前及历史用户消息的实际图片输入判断回合，保留原图回放和治理开关；纯文字重新经过核验。已验证完成条件的只读 finish 可以交付核验通过的段落；写入、独立发布和已经可见正文仍保留原子收尾边界，避免重复或过早宣布操作完成。中途失败仍保存已核对前缀并标为 partial。

使用有看图能力的主模型配置，数据库回归覆盖 body / finish / publish / 不可用 / 流式 / 中断，以及 finish 流式和中断八条路径。后段核验主动等待前段落入持久 SSE，再返回判定，验证真实先后关系。图片回合、历史原图、恢复和确认边界另行回归。

| 实测任务 | s-v2.0.20 基线 | 2.0.22 本地真实样本 |
| --- | --- | --- |
| 简单 NASA 联网核对 | 三次完成 100.897 / 55.776 / 44.722 秒 | 完成 37.461 秒，首字 37.415 秒 |
| NASA / ESA 跨站比较 | 两次完成 93.423 / 98.409 秒 | 完成 84.354 秒，首段 68.046 秒 |
| 应用活动 / 统计 / 对话读取 | 完成 41.961 秒，首字 15.799 秒 | 完成 33.806 秒，首字 33.070 秒 |

这些是少量真实外部服务样本，不能推导稳定提速率或承诺每次耗时。2.0.21 及早期候选的来源读取验证仍有效，但因为实际线路曾跳过核验，其较快样本不能当成 2.0.22 完整核验路径的提速证明。核验恢复后也有额外等待；本次不将长期 Agent 速度、表达与知识质量审计标为“所有问题均已消失”，不声称复杂查询稳定秒回。

检查：worker 全量 1,997 项通过；本次相关真实数据库 70 项、独立图片与完成流程 10 项通过；worker 类型检查通过。shared 543 项、API 2,033 项（1 项既有跳过）及四端类型检查在前一版本通过，发布流水线将再覆盖所有包。completion 套件最初拒绝通用测试库，随后在其要求的独立数据库克隆中 10/10 通过；没有删除或绕过该保护。

2.0.22 当前处于发布准备阶段。最终线上状态、时序与清理以验收数据中的实际部署记录为准。
