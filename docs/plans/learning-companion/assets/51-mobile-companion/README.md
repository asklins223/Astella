# 方案 51 · 随身伴星交互设计与实施约束

日期：2026-10-10。当前交付是可操作的浏览器布局稿与真实截图，移动客户端及业务互通尚未实现。

## 当前方向

用户连续指出生成图的固定风景区占空间、玻璃不足、伴星被缩成图标；本轮又要求按 06、07 的玻璃图稿重做，接受常驻底部标签栏，并要求动效照 Telegram 的路子做。

现在界面底层是一张 CSS 画的天空与海面（不再复用房间底图，也不单独占一段高度）。顶栏不再是一条角色横幅，而是一行 58px 的控件；伴星用现有模型的静态取帧裁成肖像，从控件行下方挂进纸面 96px，姓名签压在她脚下——她站在纸上，不站在栏里。聊天与操作面是透色玻璃，长文与修改屏改用更实的暖色底把环境挡住。交流、键盘、阅读由同一个进度值连续插值：往上读、抬键盘、切到手边或手记，她都按同一条曲线收进控制行的 36px（取帧同时放大到脸部，是小一号的她，不是一个图标），纸面整块让出来。

![实际页面：对话首页、键盘抬起、长文阅读](08-layout-chat-keyboard-reading.png)

1. **对话首页**：伴星、"把想弄懂的，交给我。"、接着学接续行、拍一张问问与传文件，往下滑就是同一份交流记录。
2. **键盘抬起**：顶栏、角色和标签栏随同一个弹簧进度连续收拢，输入正常占位，不覆盖聊天。键盘为 292px 的布局占位。
3. **长文阅读**：分封制与郡县制各自成块，中央任免用图形说明，"听伴星讲这篇"就地换成播放条。

![实际页面：材料进展、修改对照、拍照圈问](09-layout-upload-edit-miniprogram.png)

4. **材料进展**：长文件名、解析进度、停止、图片引用与已存笔记在同一页；当前进展不假称已经读完。
5. **修改与对照**：修改后与原文可以真实切换，撤回仅作用于本机样例；正式能力须接保存版本与操作回执。
6. **拍照圈问**：圈选框压暗圈外，可清除与重选。首版圈选只作本机标注，区域引用进入跨端合同是第二批；图中宿主胶囊为上一轮小程序探索的占位，小程序本轮不做。

## 2026-10-10 设计走查后改了什么

方案 51 的走查落到这份稿子上四处，都是可以在浏览器里核对的：

- **一屏只留一个主操作**。首页的"继续看"大绿按钮删掉了，"接着学"改成一条带左侧竖线的接续行（整行可点，右侧一个箭头），卡片套卡片少了一层；首页那块产品小标也去掉，标题与空间胶囊两处标识就够。
- **阅读页的播放入口降级**。"听伴星讲这篇"从饱和绿实心 pill 改成行内文字行，不再与正文抢重心。
- **假百分比改成不确定态**。解析进度不再写死 46%，换成一条流动的短棒，配文说清"还没读完"。方案 51 §4.3 本来就不给未知生成进度编造百分比。
- **撤回标注为本机样例**。修改屏的撤回行加了"本机样例"小标；正式产品的局部撤回要先补版本与补丁合同，首版界面上不出现这个动作（方案 51 §6.3）。

同轮补上首屏的三种底色（截图板 board=3，图 10）：空书房、未签 AI 同意、只读与断网。三屏都是真实渲染，不是标注：未签同意时她不给答复、只递一句同意说明入口；只读与断网时提示落在材料上，草稿留在本机。错误与结果未知的逐条呈现仍未画。

键盘态可读性这条判据已经进检查脚本：抬键盘时正在被回复的那条必须留在纸面上，且正文窗口不小于 150px。实测最坏是 320×640 的 192px（上一版是 168px），390×844 是 409px。小字号下能同时看到两条，125% 与 150% 时一条长回答本身就高过窗口——那种情况只能看见你正在回的那条，脚本按这个事实判定，不假装能塞下两条。

## 动效

弹簧求解在 [mobile-companion-motion.js](../../../../../apps/desktop-client/demos/mobile-companion-motion.js)：把刚度／阻尼／质量积分成一条 CSS `linear()` 曲线和它真正需要的时长，所以过渡不是近似，而是那条弹簧本身。需要跨帧插值的量（顶栏收拢、标签滑块）由同一个求解器驱动，中途改方向会接着当前速度算，不回到起点重放。

- **顶栏只有一套收拢**。`--shrink` 取"键盘"和"往上读"里更大的那个值，所以往上滑时伴星和姓名签按同一条曲线缩小，和抬键盘是同一种变化，不是两套布局。实测滚 300px 过程中顶栏高度经过 13 个不同值，最后落到 44px。
- **换页横着走**。切标签按你去的方向推移，进来的那一屏从机身右沿外（x=390）滑入，走的那一屏向左让开并淡出；实测两屏不会同时可读，避免了上一版原地交叉淡入导致两页文字叠在一起。
- **标签滑块是液态玻璃**。左、右边缘各挂一条弹簧，右缘更软，所以滑块在路上被拉长到 175px、落定回到 121px，并且过冲 24px 再收回。镜面顶边、冷色底面、两端彩光和下方暖色焦散都是画在同一个元素上的。
- **面板从按它的那地方长出来**。左上角菜单是左侧抽屉；伴星和空间胶囊各自从自己下沿 8px 处放大展开；只有"递材料"从底部升起。
- 新气泡从尾巴那一角 0.7 弹出并回弹到 1.03 再落定；发送后先出现"正在想"的三点，再原地换成答复。
- 按压有回弹与以触点为圆心的涟漪；慢放 2.6× 与关闭档位同时作用于 CSS 与 JS 弹簧；系统要求减少动态时按关闭处理。

## 底部是一块玻璃，不是两层

输入区和标签栏现在同属一个 `.tray`，只有 `tray-glass` 这一层做背景模糊，中间不再有硬边，标签栏也不再被机身边缘切掉下圆角。短屏（高 ≤720）抬键盘时顶栏再多让 22px、托盘内边距收紧，把正文空间抢回来。

## 合成开销

上一版"卡卡的"不是 JS 慢（滚动 61 步只花 2ms，点击换页同步工作 2.2ms），而是合成层太多：七个屏都留在渲染树里，一屏叠了 29 层 `backdrop-filter`，换页时还给整屏加 `blur()`，逼出一次离屏合成。

三处改动：不可见且不在过渡中的屏直接 `display:none` 离场（同一页实测 29 层 → 14 层）；换页不再用整屏 blur；滚动路径只写不读，`measure()` 移出滚动事件。顶栏返回／菜单两个图标预先放在 DOM 里用属性切换，换页不再重建节点。

## 实际空间与交互

以 390×844 为参考，状态栏 44px。顶栏是 58px 的一行控件，往上读或抬键盘收到 44px；短屏（高 ≤720）再让 4px 到 40px。她挂在控件行下方 96px，这段挂入量随同一个进度收到 8px，所以静止时正文从 154px 起，收拢后从 52px 起。底部玻璃托盘 139px，含输入区、标签栏和主屏指示条，键盘抬起时标签栏与指示条让位、托盘收到 55px。输入框随草稿增长，短屏键盘态最高 62px，多余内容在输入框内滚动。

正文、顶栏、输入区和标签栏由 flex 正常布局划分，内容独立滚动。伴星入口、空间胶囊与"＋"、语音、发送的热区都不小于 44×44px；320px 宽时角色与名牌收小一档，避免和空间胶囊叠在一起。

已检查 90 组：390×844、360×720、320×640 × 正文字号 100%、125%、150% × 十种屏幕（含三种首屏底色）。最小正文空间是 320×640 键盘态的 192px。判据还包括：托盘不被机身底边裁切、标签栏要么整高要么完全让位、主操作热区不小于 44px 且互不重叠（她收进控制行后是 44×44 的可点区，脸只有 36px 但热区不小）、键盘态正在回复的那条不被整条挤出且正文窗口不小于 150px。其余几何与逐帧动效读数见 [几何与检查记录](layout-verification-2026-10-10.json)。输入草稿往返笔记保持，长文可滚到底，修改前后可切换，发消息会进入本机记录并收到一条演示答复，停止会改变本机任务状态。检查脚本连跑三次读数一致，其中标签过冲那条曾因弹簧太硬、采样刚好错过而时好时坏，已把左边缘阻尼调低并把判据改成"至少过冲 4px"。原型在 Chromium 自动检查中查看、操作。

## 从设计稿到移动组件

| 元素 | 实施依据 |
| --- | --- |
| 环境 | 天空、海面与暖色地面由 CSS 绘制，铺在全界面底层；不复用房间底图，也不需要 3D 渲染或独立风景栏 |
| 伴星 | 静态取帧来自已登记的 whale v3 模型，裁成肖像并渐隐下缘；布局先与动画解耦，正式 App／小程序运行时分别验证 |
| 玻璃 | 半透明浅底、亮边、内高光、短阴影和局部背景模糊；不依赖折射、液体模拟、物理消融 |
| 内容面 | 聊天面约七成白，阅读与修改面用更实的暖色底挡住环境；无模糊时改用更实的浅底 |
| 底部 | 输入区与标签栏同属一块 `.tray` 玻璃，只做一层背景模糊；不做两层各自模糊，那会在中间留一条硬边并把标签栏下圆角裁掉 |
| 标签栏 | 常驻三段（对话／手边／手记），键盘抬起时整条让位；这一条是 2026-10-10 用户改判，此前"不做常驻底部导航"的结论作废。选中块是液态玻璃，左右边缘各一条弹簧，靠快慢差拉伸出形变 |
| 面板 | 抽屉按触发源决定方向与原点：左上菜单走左侧，伴星与空间胶囊从自身位置放大，只有底部入口从底边升起 |
| 动效 | 弹簧曲线由求解器生成为 `linear()`；正式宿主需验证磨砂大面与角色动画的合成成本，必要时降低模糊与环境细节 |
| 输入与播放 | 同一底栏按状态切换，键盘高度与安全区来自宿主；草稿和上下文不因切页丢失 |
| 宿主胶囊 | 产品控件避让宿主真实边界，不重画系统胶囊 |
| 服务与数据 | 消息、任务、文件、版本均接方案 51 的同一业务身份；这份原型没有连接账号或业务服务 |

这些浏览器检查证明布局、本机交互和逐帧动效曲线能运行，不能证明软键盘、原生性能、Live2D、音频、文件解析、图片圈选或跨端实时聊天已接通。文件选择只读文件名，不上传；播放为显示状态，不发声音；演示答复是固定文案，不调模型。

完整行为与数据合同见 [产品方案 51](../../51-mobile-companion-full-agent-product-design-2026-10-10.md)。
