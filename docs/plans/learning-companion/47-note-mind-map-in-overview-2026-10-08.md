# 47 · 在笔记速看中生成思维导图

2026-10-08。用户希望 AI 为当前整篇笔记生成脑图，放在「速看」中。用户已于本轮要求开始实施。生成、独立存储、速看页面、只读原文、历史与 Agent 交付已接入；验收证据见文末。

## 1. 用户得到什么

把速看变成两种互补的阅读方式：**要点读懂意思，脑图看清结构**。保留页首「正文 / 速看 / 回想 / 往外学 / 记录」，在速看纸面内增加「要点 / 脑图」。

脑图是这篇笔记的一张学习附页：概念如何分组、哪个条件属于哪个结论、步骤如何展开，能一眼看清，也能逐层读下去。节点有短标题，详细解释和原文依据按需展开。主题分组由材料决定，不强制套进“定义 / 特点 / 用途”等模板，也不要求生成固定数量的分支。

## 3. 建议的页面与操作

### 3.1 入口与生成

1. 进入速看默认显示「要点」，记住用户在这篇笔记上最后使用的视图。
2. 点「脑图」先读已有结果。没有结果时，在同一纸面显示「把这篇整理成脑图」及「生成脑图」；浏览本身不调用模型。
3. 要点与脑图分别生成，不互相前置，不自动附送另一种产物。即使这篇从未生成要点，也能直接生成脑图。
4. 工作稿尚未存成版本时，沿用「保存版本并开始 / 使用已保存版本」；自动同步不等于冻结正式版本。
5. 排队、整理、保存和失败均在脑图入口表达；只展示真实阶段，不伪造百分比。离开页面后继续后台处理，重进可恢复。
6. 完成时更新结果和通知，不自动切换页面或抢焦点。用户仍停留在脑图页且主动等待时，可以展示结果，焦点仍留在有效控制上。

### 3.2 脑图阅读

- **推荐构图：中心主题向两侧生长。** 根节点是短主题，一级分支是材料的主要结构，后续节点承载概念、条件、步骤、例子与区别。空间关系表达组织与从属，不把父子连线画成因果箭头。
- 初次打开先呈现主题和主要分支，较深层按需展开。小笔记可以直接全部展开；不为凑形状补内容。
- 一级分支使用柔和的薄荷、桃色、暖黄等身份色，奶油纸面保持平整；节点像轻纸签，连线安静，避免让框和阴影压过知识。
- 节点标题可换行；点击节点打开短解释、逐字引用及「回到原文」。折叠控制与查看解释分开，避免一次点击做两件事。
- **按用户在实施中的最新决定，脑图页采用星图式固定画布。** 整块纸面承载地图，不设置外层页面滚动。要点/脑图、笔记工具、标题信息和缩放工具浮在地图上；普通滚轮缩放、拖动平移，与星图保持一致。
- 大纲与节点解释/依据在同一个可收起的浮动阅读页中打开，不排在画布下面，也不改变画布几何。大纲完整列出折叠后代，点选后展开祖先并定位真实节点；阅读页独立滚动，事件不进入画布。
- 适合画面不得把文字缩到不可读。大图先展示主干，保留可读字号，允许移动画布和展开查看。
- 展开查看沿用笔记的全屏纸面、伴星避让与返回语义，需要补上学习视图入口；退出恢复缩放、平移、展开状态和选中节点。不能另造脱离笔记的窗口。
- 窄画幅仍保留同一幅地图，可以平移、缩放或使用同数据的文字提纲。浮动阅读页按可用空间覆盖当前纸面，关闭恢复入口或原节点焦点；不把整篇宽图强制缩成一团。

设计示意提供「中心展开」与「向右梳理」两种构图用于比较，支持要点切换、分支折叠、节点解释及原文示例；不包含真实任务、画布缩放、全屏或业务回跳。

### 3.3 原文与历史

- 引用携带 `noteId + noteVersionId + blockOrdinal + quote`，返回的必须是当时版本的原文。
- 即使结果标为当前正式版本，工作稿也可能已改。只在工作稿与冻结依据一致时定位当前正文；不一致或来自旧版本时打开该不可变版本的只读原文，不静默跳到相同序号的当前段落。
- 从原文返回脑图恢复展开、选中及视口状态；原文阅读位置单独保存。
- 正文改版后提示「来自 v2，正文已到 v3」，允许查看旧图或生成新版。查看历史不会生成新任务。
- 「重新生成脑图」只重做脑图。旧结果在新任务运行或失败时仍可阅读；新结果与旧结果均有独立身份，学习记录能准确重开。
- 保留用户当前选中的历史结果；新任务完成不把它偷偷替换为最新图。
- 生成成功与用户查看分别记录；不据此推断掌握或安排复习。

## 4. 数据与生成合同

### 4.1 独立领域产物

建议增加 `note_mind_maps`，保存本人在该空间、该笔记版本上的不可变结果。它与 `note_overviews` 并列，同属速看体验；不把一张新图强行挂到某次要点结果上。

产物至少包括：`mindMapId`、空间/用户/笔记/版本身份、版本号、冻结内容哈希、冻结标题、结构 JSON、覆盖范围、`generationJobId`、模型与提示版本、创建时间。版本当前/旧版状态在读取时投影；布局坐标、折叠与视口属于客户端呈现状态，不写回 AI 原始产物。

建议结构使用扁平节点列表，父子边由 `parentId` 唯一确定：

```ts
type MindMapNode = {
  id: string;
  parentId: string | null;
  kind: "root" | "group" | "concept";
  label: string;
  explanation: string | null;
  references: Array<{ blockOrdinal: number; quote: string }>;
};

type MindMapContent = {
  schemaVersion: 1;
  rootId: string;
  nodes: MindMapNode[];
};
```

根和纯分组允许不直接引用原句；分组的出处可从后代汇总。承载事实的概念节点必须有至少一条可核对引用。不能借 `group` 类型放入没有依据的事实。

起始资源边界建议为最多 120 节点、六层；短标题上限约 48 字，详细解释独立存放。它们是执行与渲染上限，不是生成数量目标。真实样本验证后再调整。默认只生成有据的层级树，跨分支关系、人工编辑、自由拖拽重排和导出放在后续独立范围。

### 4.2 AI 负责结构，客户端负责画图

模型只返回受限 JSON，不生成可执行页面，也不负责坐标、颜色、SVG 或 Mermaid 语法。现有正文 Mermaid 继续承担正文里的图示；这里的脑图拥有自己的节点身份、引用和阅读状态。

短文：完整冻结正文一次生成。长文：按真实标题与段落边界分块，逐块提取有引用的局部结构，再进行整篇层级合并；合并使用稳定的证据身份，只可重组、合并已有依据，不能凭摘要补充事实。每个块成功生成后留检查点，失败重试不重复付费处理已完成块。

第一版按当前速看的量级设定清楚的全文输入边界。超限在调用前说明；图片未读必须标明，只有图片时不给出伪造脑图。覆盖合同至少保存：全部块、实际读取的文字块身份/范围、未读图片数量、全文文字是否读完。多块正文读完只证明输入覆盖，结构是否漏掉关键知识还需模型样本审阅。

码点上限不能代替模型上下文预算。每次请求还需按当前模型档案及统一预算核对完整提示、经验指令、来源和输出预留；放不下就进一步分块，合并阶段同样有界。输出额度跟随现役模型上限与任务内容合同，不另设包含推理的过小总 token 配额。

提交前检查：

1. JSON 结构和字符串长度有效；节点身份唯一。
2. 只有一个根，每个非根有有效父节点，树连通且无环，层级与节点数在上限内。
3. 每个事实节点的段落属于冻结版本、引用能映射回真实原句；跨块合并不丢失依据。
4. 覆盖信息来自读取过程，不由模型自行声明。
5. 任务未被取消、租约仍有效，用户仍可见笔记、冻结版本仍存在。

引用存在不等于解释正确。还要用真实样本检查概念混淆、条件丢失、错误层级与重复枝条。形状错误可有界修复一次并再次验证；依据修复仍失败时显示原因，保留旧结果。

## 5. 沿真实调用链实施

```text
速看 · 脑图 / 伴星「给这篇画脑图」
  → 同一 note_mind_map_generate 能力
  → startDomainAgentRequest / AgentRun + operation
  → jobs.note_mind_map_generate
  → runWorkerAiTask（完整执行预算、取消、续租、治理、检查点）
  → 读取冻结正文 → 生成结构 → 核对树与原文 → note_mind_maps
  → 权威结果回执 → IPC / 任务状态 / 手记成果
  → 速看 · 脑图
```

| 层 | 需要落到的职责与文件 |
| --- | --- |
| shared | 新增 `contracts/note-mind-map-contracts.ts`、DB schema 及包导出；登记 job 类型/payload、Agent manifest、直接请求联合类型、`note_mind_map` 产物引用；核对所有严格 schema |
| agent-host | `note-operation.ts` 复用唯一操作创建；`operation-receipt.ts` 与 `artifact-receipt.ts` 增加权威结果查询，检查权限、版本与 job 身份 |
| api | 新增 `modules/note-mind-maps` 的 start/list/get/latestTask/getTask；迁移注册、关联外键、RLS、API/Worker 最小必要读写授权；按本人和空间读取 |
| worker | handler 注册、provider task 路由与默认配置、输出错误分类、提示/结构验证、分块合并；调用 `runWorkerAiTask`，不能再造一套模型执行内核 |
| main / preload | 扩展 shared IPC 合同、`desktop-gateway-ns-note.ts`、实际注册的 `desktop-ipc-rest.ts` 与 preload；按真实调用方核对，不只改相似的历史文件 |
| renderer | 新增 `notebook-mind-map-paper.tsx`、`use-notebook-mind-map.ts`、独立布局/视口/依据模块与域内 CSS；CSS 从 `styles.ts` 接入 |
| 页面状态 | 在 `notebook-surface.tsx` 的速看主位加入模式分流；扩展版本选择、学习入口、后台通知、历史足迹、选中产物与原文返回，业务状态不塞进纯绘图组件 |
| 伴星交付 | 能力发现、任务成果标签、`use-notebook-goal-result.ts`、目标结果导航与手记按 `mindMapId` 打开脑图；聊天正文不成为正式存储 |

表/任务必须以本人及可见材料为边界。重复请求使用 requestId/operation/job 幂等；同版本重复点按钮复用正在进行的任务，主动重生成得到新产物。迟到响应按空间 epoch、笔记、版本和任务身份丢弃，不污染当前纸面。

画图建议第一版使用 **React DOM 节点 + SVG 连线 + 自有有界树布局**。这里是层级阅读器，需求集中在自动排布、节点交互、折叠、视口和原文定位；当前已有技术栈足以实现。先用真实节点上限验证长标题、动态测量和展开稳定性，再决定是否需要外部布局库。

## 6. 交付顺序与验证

### 第一段：打通真实生成与保存

合同、数据库/权限、统一能力、Worker、API、IPC 同步落地；短文及分块长文可以生成保存并重读，结构与依据都经过核对。用文字树读取真实结果，先证明保存、恢复与失败语义有效。

### 第二段：完成速看内的脑图体验

要点/脑图切换、画布、节点解释、折叠、缩放、展开查看、版本化原文回跳、历史、重生成与通知作为同一段完成。第一段不是对用户宣告功能完成的交付点。

### 第三段：模型与真实窗口验收

| 验证面 | 必须证明的行为 |
| --- | --- |
| 结构与依据测试 | 重复 id、多根、环、孤儿、过深、超限、假引用、合并丢依据会失败；合法简短笔记不被强行补成大树 |
| 领域/实库测试 | 空间隔离、本人产物、协作只读材料、权限撤回、版本改变、取消竞态、幂等、重新生成与旧结果留存 |
| 真实模型样本 | 无标题短文、长文多块、公式/代码/表格、章节相近但条件相反、图片混排；审阅结构是否贴合材料，不只检查 JSON 成功 |
| 页面测试 | 未生成要点可直接生成脑图；切页不触发模型；迟到完成不抢视图；旧产物选择不被覆盖；工作稿变动不能跳错原句 |
| 原生窗口交互 | 长中文节点、小窗口及缩放、伴星避让、连续切页、重复折叠/展开、拖动与捏合、原文往返、全屏进退、键盘焦点、Off 与系统减少动态 |
| 类型检查 | shared、agent-core、agent-host、api、desktop-client、ai-worker 对应包的 `npm run typecheck`；按变更运行相关测试并记既有失败基线 |

节点本身保留可操作 DOM 和可读提纲。展开/折叠先改变功能与可见状态，运动接续最新意图；不以动画完成回调释放焦点。折叠包含当前焦点的分支时，把焦点移回该分支控制。只平滑排布位置，不持续飘动，也不在生成中播放虚假的枝条生长。Off 和系统减少动态直接落到最终位置。

实施验证见下节，示意稿只用于追溯设计方向。

本轮设计检查：示意脚本语法、方案索引与差异空白检查通过；浏览器实际操作核对了两种构图、分支折叠、选择解释、原文示例往返、要点切换与方向键切换；窄画幅实际内容宽度约 306px 时文字重排且没有横向溢出，预览无 console 错误。设计阶段尚未修改业务源码，当时未运行业务类型检查或模型生成回归。


## 8. 实施与验收记录（2026-10-08）

- 独立 `note_mind_maps` 与 worker 私有 `note_mind_map_stages`，迁移 0398。角色 bootstrap 同步镜像授权，API 只读成品、无权读取分段检查点；worker 可读与追加，不能改写成品。
- `note_mind_map_generate` 经统一 Agent 请求、权限、租约、调用预算与治理 provider 执行；产物回执按真实表、job、用户、工作区、笔记版本联合核对。
- 全文最多 96,000 个码点、至多八个实际分段。每次外发按完整 system + 来源请求计量，不截取开头。分段经过结构与逐字原文校验后才存检查点，合并保留所有 concept 及其证据；格式最多修正一次。
- 默认先呈现中心与主要分支，按需展开。主要分支左右位置在折叠前后保持稳定；DOM 节点与 SVG 连线支持平移、缩放、触控双指、键盘、适应窗口和现有笔记全屏。按用户截图反馈改为整纸固定画布，取消页面滚动；大纲、详情、信息与分支操作均浮在地图上，只有阅读页内部滚动。
- 引用打开产物所属版本的只读正文，高亮对应段落，不恢复或覆盖正在编辑的正文。切换要点/脑图保持阅读视口，重新生成保留旧图，所有成品进入学习记录，伴星手记可精确打开旧结果。
