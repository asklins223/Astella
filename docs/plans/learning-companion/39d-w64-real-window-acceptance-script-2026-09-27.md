### A1 · 「停止本次评估」那颗按钮真的在、真的发得出去（§16.36）

**背景**：这条命令此前**四处各缺一半**，而每一处都合法地「看起来有」：action union 有、
`learning_assessments.status` 有、服务端 `case` 有、`allowedActions` 会宣告它——但
wire 的 zod 缺这一档（`parseBody` 直接拒）、`isV2ActionAllowed` 缺这一 case、
渲染层 `actionLinks` 是白名单式 `filter` 漏了这一档。四条旧判据全绿而命令发不出去。
现在四处都接上了。**这四处的判据是源码级的，量不到「屏上那颗按钮按下去会发生什么」。**

| | |
| --- | --- |
| **在哪** | 任一有进行中练习的笔记 → 开始一轮 → 作答提交 → 进入评估中（`phase` 是 `assessing`／`committing`） |
| **找什么** | 出口那一排（`skip_run`／`end` 所在的那一排） |
| **期望** | 同时出现两颗：**「停止本次评估」** 和 **「安全退出」**；且「停止本次评估」排在「安全退出」**左边** |
| **阳性对照** | 点「安全退出」→ 出现确认层（`confirmationRequired: true`）。**「停止本次评估」也必须出现确认层**——它收掉的是一次真实评估，不该一点就掉 |
| **再验一次** | 确认层取消后，屏上那颗按钮仍在、仍可点（不是取消一次就消失） |
| **不通过的症状** | 只有「安全退出」；或两颗都在但「停止」在「安全退出」右边；或按下去转圈后报「该 action 不在服务端签发的允许集合中」 |

**收尾**：这一轮请按「先到这里」结束。轮次行**留在库里**（轮次是历史，是产品合同），
清理方式见 A2。

### A2 · 取消评估之后，原回答还在（§16.36 / §5.5）

| | |
| --- | --- |
| **在哪** | 同 A1，评估中 |
| **做什么** | 点「停止本次评估」→ 确认 |

### A3 · 回忆模式等待页不泄题（§16.24 / §7.1）

**背景**：服务端那一半已落（迁移 0297 `reminder_kind`、两条命令、12/12 单测）。
**界面那一半没做**——`ReviewSurface.tsx` 上回忆模式进入后没有等待态。

| | |
| --- | --- |
| **在哪** | 今日复习 → 某一条**到期**的目标 → 进入回忆 |
| **期望** | 准备题目／等待生成期间，屏上**只有**：标题、提取线索、进度状态。**不出现**：笔记原文、正确结构、上次答案 |
| **阳性对照（这一条最重要）** | ① 先走一遍**初学**等待态：那一屏**允许**直接阅读相关材料。两种等待状态**不能共用会提前揭示答案的内容**——如果初学等待与回忆等待看起来一样，那回忆侧一定泄了 ② 用户主动点「先看笔记」→ 原文出现，且此后这一次按**暴露条件**记录（屏上或结果页要能看出这次带帮助） |
| **不通过的症状** | 等待期间闪出原文；或「先看笔记」是唯一入口（用户没有"不看"的选项）；或主动看笔记后这一次仍被记成独立表现 |
