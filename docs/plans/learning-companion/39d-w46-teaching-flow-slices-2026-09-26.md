## 0. 一句话结论

**教学流按"先解释、后练习、再动态"三段展开，共六刀：** 教学产物表与解释任务（刀一）→ 教学面（刀二）→ 轮次内练习接 LearningRun（刀三）→ 缺口帮助停止规则（刀四）→ 动态产物生成与 T6（刀五）→ §16.2/§16.3 案例收口（刀六）。解释不需要判分（A 否决案的直接推论），所以第一刀不碰 LearningRun；练习只有目标存在时才开 run。

## 1. 已定的边界（不做的事，先写下来）

1. **解释不判分**。W4-3 ⑥ 的 A 否决案继续成立：拿笔记原文当标准答案＝把复述当能力判定。第一刀的教学产物是解释与示例，**不产生** LearningRun、不产生能力证据、不进调度（§4.2："不是每个要点都必须评估"）。
2. **练习只在目标存在时开 run**，origin=`note_round`（W4-5 ② 已落的三条调度语义生效：有 pending 才 consume、从不 create_initial）。无目标的轮次只有解释；"先让我试一下"将来要判定时才需要 C 案（不判分任务形状），记下不排期。
3. **动态讲解不是第一刀**。§6.1 的表达选择按知识形态：第一刀只做"解释＋示例"的文字表达；动态产物（D4 隔离面）在刀五，且以"生成失败不冒充教学失败"（§6.2）为验收底线。
4. **产物绑定快照**：教学产物引用轮次的快照三件（0282 已有：note_version_id＋source_content_hash＋evidence_snapshot_ids），快照哈希变了就不复用旧产物（D3 §5 的冻结语义）。
5. **预算与停止规则是试用前冻结项**：每轮模型调用预算已在 0282 三项预算里（服务端签发，env 覆盖）；"同一关键缺口连续两次帮助"的"两次"起点值归 §18.4，不替它编数。

## 2. 刀一：教学产物表＋解释任务

**表**（迁移 0284，形状照 0282/0283 的全套：FK／RLS ENABLE+FORCE 无 worker 旁路／迁移内 GRANT）：
`note_learning_round_teachings`：`id, workspace_id, user_id, round_id (FK cascade), ordinal（轮内序号）, kind ('explanation')，content jsonb（结构化解释：正文＋示例＋依据块序号数组）, source_block_ordinals integer[]（依据在快照里的定位）, kernel_task_ref text（内核任务/job 引用，回放与审计用）, created_at`。只追加（触发器照 0283），不存"好不好/掌握度"（§6.7 同禁）。

**任务**（内核 `mode: structured`，照 W3-5 assess 任务的样子）：`note_teaching_explain_v1`——输入＝drivingQuestion＋最新计划（0283）＋快照正文块＋知识形态提示；输出＝`{ explanation, example?, sourceBlockOrdinals }`。**确定性 provider 先行**（离线可测），真模型归每波末尾那一次真跑。幂等键＝`round:{id}:explain:{snapshotHash}:{ordinal}`——同快照同序号复用，不重付模型钱（D5 §4.2 检查点四判据）。

**API**：`POST /v2/note-learning-rounds/:roundId/teaching`（幂等：同快照已有同驱动问题的解释 ⇒ 返回既有那条），`GET` 随轮次读合同带出。

**判据（确定性）**：集测双口径——解释落库且只追加；同快照重复请求返回同一条（不重付）；快照哈希变化后不复用；关卷后拒绝；预算缺额拒启动；跨用户不可见。

**落地记录（2026-09-26，刀一已落）**——实施时改了/定了下面这些，按本文件自己的规矩写回这里，不在任务里就地发明：

1. **表多了两列**：`snapshot_hash` 与 `driving_question_revision`。理由是"同快照同问题的解释"这条幂等判据**要能被查询**（生成时刻的凭据不能只活在任务的幂等键字符串里）；`kernel_task_ref` 保持可空——确定性 provider 这一天不走内核任务，"没有"与"走过没记"是两件事。两列都不是"好不好/掌握度"。
2. **没有把 (round, kind, driving_question_revision, snapshot_hash) 做成唯一索引**：§16.3 的「换解释」将来要在同一个问题下落第二条；"不重付"改由**服务层预读 + 轮内序号**承担（只追加的表里，同键只可能是重复请求造成的）。
3. **回信形状**：`{ version, round, teaching }`（生成与读取同一份），不往轮次合同里塞教学数组——"解释是按哪一版问题、哪一版正文生成的"只能由服务端一次说清，客户端拿两发去拼迟早错配。GET 只回与**当前**问题版本＋当前快照匹配的那一条：问题被改写之后如实回 `teaching: null`，不把上一版问题的解释摆在下一版问题下面。
4. **预算判据的形状**：`round.budgets.maxModelCalls − 已生成条数 < 1 ⇒ 409 round_budget_exhausted`（话术是 §6.2 那三句）。"已生成条数"今天等于"生成次数"；接真模型那一刀要把自动重试按内核回执加进来（内核 `maxAutoRetries` 今天允许每步一次）。
5. **检查点端口暂不挂**：重复请求在服务层就被拦下（根本走不到生成），所以没有可复用的检查点读写可测；接真模型那一刀再按内核回执定它的物理形状（W3-3 把那个形状定在 `jobs.payload`，而这条链今天没有 jobs 行）。
6. **内核任务身份**：`note_teaching_explain_v1@v1`，`mode: structured`、`resourceClass: interactive_ai`、预算 2 次调用／单步 55 s／整任务 110 s（与评估那一步同一把尺子）。provider 端口在路由层注入——换 provider（真模型）不动外壳。
7. **两档失败话术分开**：材料里没有可讲的 ⇒ `invalid_input` ⇒ 409 `teaching_material_missing`（"这一篇现在没有可以用来解释的正文"）；provider 那边没成 ⇒ 503 `teaching_failed`（"已经有的内容不受影响，可以稍后再试"）。
8. **确定性 provider 的取材规则**（都来自"材料里看得见的东西"）：问句点名的小节 → 第一个小节 → 第一块可读正文；例子只取同一节里含"例如／比如／举例／示例"的块；拼不出材料就是 `invalid_input`，不编一句盖过去。

## 3. 刀二：教学面

笔记页轮次块（W4-3 表单所在处）在轮次 active 时给出「开始这一轮」→ 教学视图：本轮问题＋解释＋依据引用（点开定位到笔记块）＋「先到这里」（已有）＋暂停（已有）。教学面是 `artifact-frame-host` 的**预留挂载点**（刀五之前不挂 iframe）。四法接线照 W4-3 的表单先例。判据：真窗口剧本（问题/解释/引用/收尾四步）；jsdom 状态机。

**落地记录（2026-09-26，刀二已落）**——实施时改了/定了下面这些：

1. **「暂停」这一版仍不接**（本文件上面那句"暂停（已有）"与代码不符，按本文件的规矩在这里改）：`desktop-ipc-contracts.ts` 的通道注释里那条先决条件没变——§5.5「没有其他活跃端才标可恢复暂停」要的**活跃度判据**还没有出处，接一颗点了就"暂停"的按钮等于把一段没有语义的状态摆到屏幕上。归 §16.39 那一刀的欠账，不在这里发明。
2. **教学面落在轮次块内部**（不是新开一屏）：轮次在时，问题那一行下面就是"讲没讲过"——没讲过只有一颗「先讲讲这一节」，讲过了摆解释＋例子＋依据。生成那一发成功后走 **silent 回读**，屏上那句解释来自服务端存下来的那一条（不是本发回执自己拼的，同 W4-3 表单那条纪律）。
3. **依据要能定位，就得先有锚点**：阅读正文每一块包一层 `.reading-block[data-block-ordinal]`，样式表里三条**直接子选择器**（`> p` / `> h3` / `> p.list-block`）跟着进一层——格线、标题字号、列表缩进一个字不变。点一颗依据：滚到那一段 ＋ 短暂高亮（2.4 s 自己过期，不留"上次点到哪"）；`scrollIntoView` **不用 smooth**（动效是产品设置里的一档，这里只负责"看得见"）。
4. **快照不是屏幕上这一版时不摆依据**：块序号已经不是同一份材料，照序号跳过去会点到别处；此时说一句如实话（`ROUND_COPY.teaching.staleVersion`），不假装定位得到。序号在屏幕这一版里对不上时同样不瞎画。
5. **依据标签与"从结构另选"的问句共用一份 `headingDisplayTextV1`**：真库里小节两种形状都有（实测 dev 库 6 条里 3 条是 `## 间隔重复`），顺手修掉 W4-3 那几颗标签会把 `#` 带上屏的同形缺陷（一处归一化，两个调用点）。
6. **挂载点先留在 DOM 里**：`<div className="notebook-round-teaching__artifact" data-artifact-slot="note-round-teaching">`，刀五往这里挂 `artifact-frame-host`（属性仍从 `shared/artifact-frame.ts` 取，不在这里另写一份）。

## 4. 刀三：轮次内练习接 LearningRun

有目标的轮次在教学面给出「练一道」→ 用 `note_round` origin 开 LearningRun（W4-5 ② 的调度语义原样生效）。run 结算回轮次：**轮次读合同增加"已做过的练习"一格**（经 origin→runId 反查，补上 W4-5 那笔"轮次 ↔ LearningRun 连接"的 producer 半边）。判据：集测——note_round run 的结果在轮次读侧可见；无目标轮次不出现「练一道」；run 结算不重开轮次、不重播奖励（§16.19 的轮侧）。

**落地记录（2026-09-26，刀三已落）**——实施时改了/定了下面这些：

1. **"已做过的练习"落在教学面那一份读里**（`roundTeachingViewV1Schema` 增 `practices`），不是加进 `noteLearningRoundV1Schema`：轮次行那一份读被 create／open／patch／revise／teaching **五处**装配共用，往它身上挂"练习"会让每一次读轮次都多一次 run 反查（而只有教学面需要这个数）。代价是"轮次读合同"的字面口径窄了一格，按本文件规矩记在这里。
2. **`practiceStart` 由服务端签发**（同一份读里）：`goal`／时长／怎么答三格**原样取自那一篇目标主行动的 `start`**，只有锚点换成 `note_round`——客户端不拼这几个值，服务端也不在第二处再签一份。
3. **起点只在"能开一场新的"时给**：目标必须是这一篇的 active 目标（`listObjectiveSurfacesV3` 的 `noteId` 收窄），且主行动是 `create_run` / `practice_only`。`resume_run`（这个目标已有一场开着）与 `create_review_run`（日程锚定的复习）都如实回 `null`——前者再开一场会同时两场进行中，后者把一次到期复习悄悄变成轮次练习。
4. **结算不推进轮次**：产物行的写入与 run 的结算都不碰轮次那一行（phase/revision 原样），也不重开轮次、不生成解释——三条都进了集测。
5. **`learningRunPhaseSchema` 收成具名合同**（`learning-run-contracts.ts` 里那段 12 值枚举此前是内联的），练习那一格与 run 快照共用它。
6. **`(origin->>'roundId')` 这一读暂不建索引**：dev 库上量到走 `(workspace_id, user_id, created_at)` 索引后过滤、**0.083 ms**（279 行），而这一读只在打开教学面时发一次。真要变热，按 0222 给 `objectiveId` 建的同一形状加表达索引。

## 5. 刀四：缺口帮助停止规则

§5.3 的默认触发："同一关键缺口**连续两次**帮助后仍没有改善"→ 停止自动加题，摆四选一（换解释／补前置／回材料核对／先结束）。落点：帮助计数挂在轮次的练习任务上（帮助暴露已在 D7 链路：W2-6 的 exposure 记账）；触发判据是**纯函数**（输入＝同目标的连续帮助次数与改善信号），单测钉死；"两次"读 §18.4 冻结值（env 覆盖，不硬编码）。判据：纯函数变异自证；集测——第二次帮助后不再自动出新题、四选一可走。

**落地记录（2026-09-26，刀四已落；判据与拦截见 §19 那一行）**——实施时定了下面这些：

1. **「改善」分三类不是两类**：七档结论各归一类，`demonstrated`＝改善；`partial`／`needs_repair`＝明说的没改善；`not_assessable`／`practice_completed`／`skipped`／`declared_unable`＝**不知道**（判不了不是没弄通，练习本来就不判分，自述"没想起来"也不是系统判出的缺口）。没改善的两类**不重置计数**（这一次确实没带来改善的证据），但也不因此说用户有缺口。
2. **停 = 计数 ≥ 阈值 且 最近一次不是改善**：阈值为真时"停"的是**自动加题**这件事，不是对用户下判断——所以 `unknown` 那一档也停（把选择权交回用户），但话术里不许出现"你没有改善"（屏上那句只说读数："帮了 N 次，还没有看到改善的证据"）。
3. **计数是现算的，不新表**：一次「帮助」=`learning_run_events` 的 `learning_task.hint_requested`（payload 里有 taskId），结论=`learning_runs.result->>'outcome'`，缺口身份=run 的 `origin->>'objectiveId'` ＋ `learning_tasks.intent`。判据（谁该停）在 `apps/api/src/modules/learning-runs/gap-help-policy.ts`（纯函数＋冻结值），落库那一半在 `gap-help-service.ts`。
4. **拦截在"签发加题"那一处**：`run-processing-tick.ts` 的 `supplementOffer` 在这一轮已停时不签发 followup（只对 `note_round` 的 run 生效，别的 origin 一律不受影响）；`activate_followup` 那一侧留防守层（按钮被绕过也拒）。
5. **四选一里三档今天真有去处**：换解释＝同一问题落第二条（`regenerate`：跳过复用、序号 +1、旧条保留——PRD §6「换解释才产生新版本」）；回材料核对＝客户端把依据那一段带到眼前（复用刀二那条定位）；先结束＝收尾这一轮（既有 close）。**「补一节前置」今天没有服务端语义**（PRD §16.3 那句"说明新增学习量"要先生成前置内容），面板上如实写出来，不摆一颗按不动的按钮装作能用——登记为欠账。
6. **`gapHelp` 那一格放在教学面读里**（与 `practices`／`practiceStart` 同一份回信）：它是"这一轮要不要继续自动加题"的读数，与"这一轮现在是什么样"同源。

## 6. 刀五：动态产物生成与 T6

D4 写入方（谁写 `artifacts/<id>.html`）：教学任务的动态产物经主进程写入（配额 512 KiB／20 000 标签已在 artifact-surface）；产物 id 回写进教学产物行（`artifact_id` 列，刀一预留或此刀加列）。宿主面挂进教学面；**T6 两条真窗口探针**（`while(true)` 产物、崩溃注入×2）与 §7.3 第三层在此跑。判据：§7.2 T6 原文两条＋"动态失败不冒充教学失败、不抹掉已有作答"。

**落地记录（2026-09-26，刀五已落）**——实施时定了下面这些：

1. **产物 HTML 不进渲染层**：教学面那一份读只带**引用**（`artifact: {artifactId, kind, createdAt}`）；HTML 由 main 按 id 去 `GET /v2/note-learning-round-artifacts/:artifactId` 取整份（不套 JSON 信封——消费方是主进程，它要字节原样落盘），过 D4 §8 的配额（**复用** `artifact-surface.ts` 已有的常量与口径，不另写一份数字）后写 `<userData>/artifacts/<id>.html`，frame 再从既定协议读。好处是三件事：HTML 只走一次网络与一次落盘、不额外穿过 IPC 的两层校验；渲染层拿不到 HTML，"顺手改一改再落盘"这条路不存在；落盘是**幂等**的（盘上已有就 `stored:false`，不重复下载）。
2. **HTML 本体在独立的新表**（`note_learning_round_artifacts`，只追加、FORCE RLS、同 0282–0284 的形状），`artifact_id` 落在教学产物行上（设计件说的那一格）——因为"恢复与历史回放读同一产物"要按 id 读整份 HTML，而教学产物行本身是"解释文本"那一份。`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`：`note_learning_round_teachings` 的只追加触发器是行级的，不挡 ALTER。
3. **确定性生产者先行**（`buildDeterministicArtifactHtmlV1`）：自包含 HTML（内联样式、不引用外部资源、不写脚本），把解释、例子与计划步骤渲染成分镜步骤；文本一律转义。真模型那一刀换的是这个函数。
4. **落盘成功才挂宿主**：落盘失败时挂上去只会画出浏览器自己的错误页——所以失败就"不挂 + 如实说一句（动态这一版没打开）"，文字解释与练习照旧（"动态失败不冒充教学失败"）。
5. **`motion` 接产品那一档设置**：`motionMode === "full"` 之外（lite／off）都当"减少动效"发给 frame，模板据此铺静态分镜。
6. **T6 两条探针自己种数据**：临时 userData 里写夹具产物 HTML（`while(true)` 一份、"先报到再崩"一份）＋库里插一轮/一条教学产物/一份产物（`artifact_id` 指过去，换产物时带绕行口子改），收尾删干净。§7.2 第二条的"两次"＝宿主自己的重建上限（`MAX_FRAME_ATTEMPTS`），探针按**元素身份**数"换没换过 frame"。
