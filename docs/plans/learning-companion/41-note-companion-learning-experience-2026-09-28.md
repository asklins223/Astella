## 0. 为什么重写

用户要做的事很朴素：第一次先看懂、隔久快速想起、弄懂眼前一句、从这篇往外学。上一版把四件事都接到伴星聊天，页面于是同时出现笔记、四个入口、聊天输入、回复、保存按钮和足迹。用户既不知道任务是否开始，也不知道结果会落在哪里。把这套东西换成暖色或缩短提示词，仍解决不了问题。

真实 Electron 窗口的初查已经给出反例：在 1440×810 下书房和 Live2D 可见，点击「先看懂这篇」后请求进入伴星对话；回复自己说明尚有 28 个正文块没读，却被保存并展示为整篇速览。它还以原始 Markdown 符号出现在纸面。这个结果说明**对话回复不是一份已完成速览的可靠完成条件**。此前的静态 Demo、类型检查和受控模型测试证明了局部能力，不能证明这条用户流程成立。

此后的唯一责任分配是：

| 谁负责 | 明确职责 |
| --- | --- |
| 笔记册页 | 让用户直接发起眼前的事，显示进行中、结果、失败恢复与返回原文的位置。 |
| 领域服务与后台任务 | 冻结材料、执行生成、校验覆盖与依据、保存结果、处理重试和版本变化。 |
| AI 模型 | 产出解释、问题、候选方向或整份互动页面；输出是待校验的候选，不宣布业务完成。 |
| 伴星 | 保持可见；用户点她时陪读、换种说法、给不泄题的线索或讨论候选方向。她可请求同一领域任务，但不拥有另一套任务状态和保存通道。 |

**没有打开伴星聊天，这四件事也必须能独立完成。** 陪伴是体验的一部分，任务可靠性属于页面和后台。

### 0.1 完整重构的范围

本方案不再只定义四个学习入口。**笔记架进入、正文预览、两种编辑方式、保存与版本、目录定位、批注、资料关系和学习回看是一套连续体验，必须一起设计、一起验收。** 能复用的底层能力可以保留，现有页面结构、按钮位置与操作顺序不构成必须保留的模板。

| 重构对象 | 必须覆盖的范围 |
| --- | --- |
| 笔记入口与笔记架 | 搜索、最近笔记、全部笔记、新建与打开；保留用户认可的彩色册本架外观，补齐状态标签、长标题、空态与返回位置，不换成表格后台 |
| 笔记主工作区 | 同一册页内的三种正文模式、标题与元信息、模式切换、格式工具、图片处理；重做主次和布局，不把旧预览页与旧编辑页拼在一起 |
| 编辑与持久化 | 同一工作稿、撤销/重做、自动同步、手动保存版本、草稿恢复、协作更新、失败与权限变化；不能只验收单窗口写几个字 |
| 目录与原文定位 | 可固定/隐藏的大小标题目录；在预览、可编辑预览和源码中定位同一小节，标题改动及时更新 |
| 原位批注与学习 | 默认合起的批注、悬停预览、旁侧详情，及册页页首可达的速看、回想、往外学页签；各自有任务、错误、恢复和回跳 |
| 来源与衍生关系 | 原始只读资料、补充资料、多个关联笔记，以及多篇拓展草稿的阅读、编辑、选择和正式收下 |
| 记录与版本回看 | 学习记录与版本历史分清，按当时版本回原文；回看后能回到当前工作稿，不覆盖正在编辑的内容 |
| 整体运行体验 | 首次加载、长内容、内部滚动、缩放、键盘、焦点、动效、伴星座位，以及真实的离开/返回与失败状态 |

笔记架标签只表达有依据的事实，例如空稿、未同步、有批注、有回想记录、有衍生笔记；用户自述与正式评估分别标明来源。不能从打开次数、速看次数或一句自述自动推断「已掌握」。未审核草稿不进入正式笔记架。列表交互属于重构范围，**保留笔记架不等于保留其高度留空、状态混乱或返回丢位置的问题**。

正式练习、长期复习、账号权限、来源不可编辑和 AI 外发同意的边界不变；本方案不授权重构其他功能的业务规则或把房间变成游戏操作。

### 0.2 当前实现与目标不能混写

2026-10-01 核对现行调用方：`notebook-surface.tsx` 已接入 `preview / live-preview / source` 三种正文模式。`note-document-editor.tsx` 保留 Milkdown 与 CodeMirror 实例，源码通过 `note-source-bridge.ts` 修改同一份共享文档；预览读取 `use-note-doc-live-view.ts` 的实时块投影。三者共用一份 `Y.Doc` 和撤销/重做历史，不各存一份正文。`use-notebook-body-mode.ts` 管理视图与块位置，并在输入法组合结束后切换；源码输入也会先映射组合输入期间的远端更新，再合入当前文档。**这证明第一批文档接线，不能代替完整 Markdown 往返、协作与失败状态的验收。**

`notebook-desk.tsx` 已替代原册页容器：正文、速看、回想、往外学与记录是页首的稳定页签，正文模式与目录、资料等工具独立组织。目录已有当前小节记号；目录和详细旁页在紧凑画幅中覆盖原纸面，原纸保留挂载和宽度并立即变为不可操作，关闭或按 Esc 后恢复有效焦点。`use-notebook-side-page.ts` 让版本、资料与单处批注互相替换，`use-notebook-learning-view.ts` 分开保存正文与学习主位的位置。关闭的资料袋不进入伴星可读视图。速看的回读与轮询由 `use-notebook-overview.ts` 管理，任务完成只更新结果，不自动抢走正文。

自动同步与手动保存版本仍是两条不同语义：前者提交文档增量，后者在同步成功后取得不可变版本回执。`use-notebook-learning-entry.ts` 将浏览已有结果与开始生成分开；只有用户明确开始时，才在工作稿有未版本化改动的情况下为速看、回想和往外学提供「保存版本并开始／使用已保存版本」选择。正文模式切换和自动同步本身不创建正式版本，也不发起 AI 任务。

回想每次打开从问题顶部开始，原文与线索默认合起，由用户展开；新问题的对照只取冻结版本的对应摘录。旧记录若保存了未定位的整篇长文，会再提供一次按需展开，不能将它冒充当前问题的精确依据。学习记录可以重开当时的回想，保留旧版本身份。

`notebook-expansion-drafts.tsx` 已用多篇彩色封面择一展开，逐篇保留三种模式、独立 `Y.Doc`、编辑缓冲和滚动位置。保存期间锁定提交内容，不强制切回预览。`use-notebook-expansion-task.ts` 去重初次任务读取，明确显示读取与保存失败，以笔记、版本、任务和本地修改序号挡住迟到回执；确认收下前先保存当前内容与选择快照，再提交已选候选，不以勾选代替创建回执。

## 1. 用户在笔记里看到什么

沿用 [DESIGN.md](../../../DESIGN.md#方向) 的温暖、有物件感的书房方向，V3.1 HUD 提供现有参考。具体构图、强调色与交互可按学习任务发展。Live2D 伴星在稳定座位，正文、角色和操作共同参与布局；安静指减少打断。布局参考见 [DESIGN.md §Layout](../../../DESIGN.md#layout)。

打开笔记时，**正文是正在阅读的主册页，不是功能总览**。册页页首有稳定、清楚的「正文」「速看」「回想」「往外学」「记录」页签，正文模式切换独立可见；目录、来源与历史是较轻的工具。不会依据是否有历史记录把熟悉的入口换位置、换名字。历史只提供明确的「接着上次」状态，不替用户决定这次该怎么学，更不推断掌握度。预览态的选区边按需出现「讲讲这句」与「写批注」，不需要先开启某种学习模式；编辑中的选区行为见 §1.1。

结果一次只占一个主位。速看从页首页签打开具体要点，可回到各处原句；不与回想、拓展内容一起压在正文前。回想只突出一个问题，答案合着，揭示由用户决定。主册页高度与位置保持稳定，不能切到回想就突然缩短整册、在下方留出大块无功能区域；内容较短时靠排版组织，不靠固定的小高度。批注与正文保持空间关联，但详情默认合起，只在点击后打开旁侧附页。往外学从页首页签进入可翻开的候选小册本，不埋在篇末。记录与来源按需拉出旁页，不同时铺满正文。进度、取消、失败和重试显示在触发位置，离开后回来可恢复。

页面不用说明文字教用户内部规则。用户只需看见当下一个有意义的动作和它的结果。面向用户的词用「先看懂」「想起来」「讲这句」「往外学」「收下这篇」；`job`、`round`、`artifact`、`grounding` 等只在内部。

### 1.1 三种正文模式

三种模式回答的是「这份正文怎样呈现、能否直接修改」，不代表笔记的三个生命周期，也不代表学习是否完成。下列内部标识已进入第一批现行代码；表中的完整行为仍是目标合同，不能仅凭模式枚举与编辑器接线宣称验收通过（现状见 §0.2）。

| 模式 | 正文与输入行为 | 工具与学习行为 |
| --- | --- | --- |
| **阅读** `preview` | 只读呈现 Markdown 的排版结果：标题、段落、列表、引用、表格、公式、代码和图片；点击或输入不改正文 | 不显示格式编辑工具。可复制、查找、目录跳转、查看批注与来源，发起速看、回想与往外学；有权限时可切到任一编辑态 |
| **编辑** `live-preview` | 正文仍以排版结果为主，但点击段落即可输入、删除与修改；支持 Markdown 快捷输入。正在编辑的结构可局部露出必要语法，其余内容仍呈现效果 | 显示轻量格式工具、撤销/重做、图片与链接编辑。已有批注记号保留；选字首先服务编辑，不自动弹出 AI 面板或夺走光标，用户明确调用才打开批注/讲解 |
| **源码** `source` | 单一 Markdown 源码编辑区，完整显示 `#`、列表标记、链接、图片地址、表格和代码围栏等语法；不把源码边输入边替换成渲染块 | 有语法高亮、撤销/重做、查找替换、缩进与编辑命令，行号可开关。图片在此是 Markdown 引用，预览到其他模式看；源码和用户写入的 HTML 不因光标进入而执行 |

**纯编辑不是左右分屏。** 本次核心是只读预览、实时渲染且可改、完整源码这三种；不能把「源码 + 预览并排」当成第三种，也不新增分屏作为必须经过的第四种模式。可编辑预览不是弹出一个表单或点「编辑」后仍只有纯源码，纯编辑也不是移除工具栏的同一个富文本框。

- 模式控制在正文页首的稳定工具位置，用一个明确的三段切换控件呈现「阅读 / 编辑 / 源码」，配可识别图标；不藏在篇末或与学习纸签混在一起。模式项是切换，不使用三颗同重主按钮。
- 从笔记架首次打开已有笔记默认预览；新建笔记有写权限时直接进入可编辑预览。离开学习结果或资料页再返回，恢复这篇笔记离开时的模式与位置，不强制回预览。
- 来源资料、不可变历史版本与无写权限身份仍然只读；不能因为选中某个模式就绕过权限。需要恢复旧版时，明确创建新的工作稿/版本，不在旧版上编辑。权限限制与加载失败各自说明，不伪装成空稿。
- 三种模式沿用同一册页、标题、目录和稳定伴星座位。纯编辑可按代码阅读需要使用等宽正文，但不因此切成普通 IDE、后台面板或隐藏伴星。

### 1.2 同一工作稿、模式切换与保存

**三种模式读取和修改同一篇笔记的同一份工作文档。** 沿用现行共享文档与权限边界；Markdown 源码、可编辑渲染和只读渲染是它的不同视图，不各存一份 Markdown/HTML 再轮流覆盖服务器。渲染结果不是另一份内容真相。

正文模式、当前打开的正文/学习结果和同步状态分别管理。打开资料袋、回想或学习记录不改写正文模式；切纯编辑不新建工作稿；自动同步失败不把整页切成错误画面。来源、历史版本和衍生草稿各自的身份不能因为共用册页而混到当前笔记里。

| 操作或状态 | 必须成立的行为 |
| --- | --- |
| 可编辑预览与纯编辑互切 | 同步输入事务后切换视图；正文、标题、未完成修改和本笔记撤销/重做记录保留。只切模式不产生正文修改、正式版本或 AI 调用 |
| 编辑切到预览 | 立即渲染同一工作稿的最新内容，最后一句和待同步修改也能看到；未同步状态继续保留，不能回读旧服务端快照造成「字丢了」 |
| 光标与阅读位置 | 按正文块/源码范围映射当前小节与光标；未变化内容保持位置。布局不同不能只复用滚动百分比，也不能每次切换回顶部；原位置已被删除时定位到邻近有效位置并明确反馈 |
| 中文输入、粘贴与撤销 | 切模式前安全完成输入法组合事务；更换编辑视图不重建工作文档，输入位置与撤销历史可恢复。打开旁页和后台回读不能靠重挂编辑器截断输入。撤销恢复用户修改，而不是把模式切换算一次文本编辑 |
| Markdown 往返 | 无编辑地反复切换不能悄悄改写原文；支持的语法、图片/链接引用、公式、表格和代码语义要能往返。不支持的结构保留原始内容或明确留在源码态，不丢弃或静默简化 |
| 图片粘贴、拖入与上传 | 两种编辑态都进入同一资产上传链；可编辑预览显示图片/占位，纯编辑写入对应引用。上传中、失败、重试与移除可辨认，不能提前当成功，也不能被一次模式切换抹掉 |
| 自动同步 | 两种编辑态都同步标题与正文的真实增量，预览态也不丢切换前排队的增量；就地表达待同步、同步中、已同步或同步失败。同步不等于产生一个不可变版本 |
| 手动保存版本 | 同一条提交链先确认工作稿增量，再定下不可变版本；回执前不显示成功。重复点击不重复创建，失败保留内容，版本冲突不能靠覆盖远端或伪造新版本解决 |
| 返回笔记架、换笔记与重开 | 保留当前工作稿、同步状态及返回位置；离开前的保护不依赖仍挂载的编辑器。断线、刷新或失败后可恢复本机未提交增量，不让本机旧拷贝覆盖协作端新内容 |
| 权限撤销或协作更新 | 服务端权限仍是权威。两种编辑态接入同一共享文档；远端更新不重置本机输入，失权后停止提交，未提交内容与错误分清，不能通过源码模式继续写入 |

标题只编辑同一个字段，不在模式间生成两份标题。保存状态在固定可见的位置表达，不能挡正文；两种编辑态共享一个「保存版本」动作，不再有语义不明的「预览此版本」充当保存。

学习产物仍绑定**不可变版本**，不是随工作稿漂移。工作稿与已保存版本不同、而用户要基于眼前改动发起生成或版本化批注时，在入口就地让用户明确选择「保存版本并开始」或「使用已保存版本」；不要静默使用旧正文，也不要把每次切模式都变成保存确认。返回学习结果不会丢失工作稿或编辑模式。

### 1.3 同一篇笔记的六个学习画面

以《Agent 里的 Tool 是什么》为例，下面是应当能直接画成真实页面的状态；每一幕仍是同一间书房、同一张笔记纸、同一位在旁边的 Live2D 伴星。

| 用户此刻看见 | 纸面上最显眼的事 | 接下来能做什么 |
| --- | --- | --- |
| 首次打开，正文正在眼前 | 标题、当前版本、页首学习页签；目录和来源可找到，批注只露记号 | 直接读，或用页首页签打开速看、回想、往外学 |
| 正在生成速看 | 原纸签变成「正在整理这篇」，正文仍可读；聊天面板不自动弹出 | 继续阅读、离开，回来接结果 |
| 速看完成 | 短册页写具体要点，每点有对应原句；不叠上回想与拓展 | 点原句，或返回原来的正文位置 |
| 框选了难懂的句子 | 选区附近有「讲讲这句／写批注」；点后打开旁页，原句仍可辨认 | 看解释或自己写想法；合起后只留轻量标记 |
| 隔久返回并点回想 | 纸面折页只露一个短问题，答案仍合着 | 心里想、点「给点线索」或自己「翻开对照」 |
| 从 Tool 往外学 | 页首页签打开多篇候选小册本，每篇有关系、来处和草稿状态 | 逐篇读与编辑、选择，最后明确收下；未选的保留为草稿 |

纸签、批注和折页一次只突出用户正在做的一件事。入口的可发现性来自它所依附的笔记位置和物件形态，不靠并排的六个按钮或大段操作说明。

### 1.4 目录、旁页与返回位置

- **标题目录**在正文旁，是可收起的索引纸，不是管理侧栏。基于 Markdown 结构识别正文实际的 H1–H6，不把代码围栏内的 `#` 当标题；按常用 H2/H3 等大小标题展示真实层级，笔记标题作为根入口不重复列出，当前小节有记号。三种模式中都能跳到同一小节：渲染态定位对应块，纯编辑定位标题所在的源码行。宽画幅可固定，取消固定后按需打开。两种编辑态改标题、增删小节或改变层级后目录及时更新；标题重名不能串位置。
- **旁页**一次只展开批注、来源、衍生关系或学习记录中的一种。打开另一种替换当前旁页，不继续套抽屉。正文与旁页各自滚动，关闭回到触发的原句或按钮，不重置正文到顶部。
- **紧凑窗口与缩放**不强挤三列。目录或详细附页可临时占主册页位置；保留关闭与返回，暂时让位的固定目录之后恢复。伴星座位不回收，隐藏内容不得仍参与焦点或挡住点击。
- **阅读不需要固定底栏**。保存新版本、确认收下等真实提交才有可达的动作条。三种正文模式与回想等主位切换保持册页外框、座位和关键控制的位置稳定，不用固定短高度留下大片房间空档，也不用无功能卡片补满纸面；短内容按当前任务集中组织。每个区域一个滚动所有者，标题和动作条不参与正文滚动；正文、源码、编辑草稿、展开的速看保留各自位置并可正确回原句。
- **批注与编辑分开**。预览中用原句标记及 hover/focus 预览；可编辑预览保留记号但不阻断输入；纯编辑可在对应源码行的侧边显示批注记号，点击打开同一旁页，不把批注文字或装饰标记写进 Markdown。改动使锚点不可靠时保留旧版本记录，不按相似文本猜一个新位置。

### 1.5 来源与多篇衍生笔记

来源不是只在正文末尾出现的一行字。标题附近可打开资料袋，分别查看**原始只读材料**与**补充外部资料**，
每项有标题、来源性质、地址和实际引用片段；笔记改动不改写材料。未关联、正在读取、失权和读取失败分别表达，
不能把失败画成「没有来源」。引用跨旧版时显示当时版本，不偷偷跳到新版相似句。

多篇衍生内容至少覆盖以下状态，不能只画一篇成功结果：

| 状态 | 可见表达与动作 |
| --- | --- |
| 生成中／失败／取消 | 入口原位显示；原文和已有草稿不消失；可恢复或重试 |
| 未读草稿／已读草稿 | 各自的小册本；关系与依据清楚，逐篇翻开，不默认勾选 |
| 已选待收下 | 复选框与数量明确；选择不是创建笔记，不使用「已收下」文案 |
| 正在提交／提交失败 | 冻结选择与内容；不重复提交，不丢编辑与选择，失败可重试 |
| 正式收下 | 以回执展示新笔记和关系；原笔记可开衍生笔记，新笔记可返回原笔记 |

草稿阅读页能改标题和正文、切上一篇／下一篇、看原句、返回全部草稿。
逐篇切换和暂时回正文不丢编辑缓冲；只有明确放弃或替换时才确认。已收下笔记不再使用同一草稿缓冲。
草稿同样可以预览、可编辑预览或纯编辑，但它的保存仍是候选缓冲；切换模式或编辑不等于正式收下。只有用户选择并收到提交回执，才创建正式笔记及关系。

### 1.6 触感与动效

页签轻抬与按压、册页短距离换页、目录从装订侧拉出、批注附页沿来路展开与收回，
都是显示位置和状态的短反馈；不旋转阅读文字，不搬动房间，不让内容持续漂浮。
快速开关以最新操作为准，进入与退出都可打断。键盘高频动作、输入和目录当前位置更新即时响应。
减弱／关闭动效及系统 reduced-motion 有完整终态，不能靠动画结束回调才能解锁。
真实生成不伪造百分比；收下的印记只在业务确认后出现，不代表理解或掌握。

## 2. 四件事各自怎么走

### 2.1 第一次看：先看懂这篇

1. 用户点「先看懂这篇」。当前笔记版本被冻结，一条后台任务读取**完整可读正文**及必要图片信息；长文按块继续读取，记录实际覆盖范围。纸签就地显示「正在整理这篇」。关闭纸签或切页不取消任务。
2. 校验通过后纸签给出：这篇主要讲什么、两三处关键意思、每处可点回的原文。先给具体知识，不给一串“目标、证据、阶段”栏目。看不懂某处就从对应原文接局部批注；确实适合操作演示时才给「看个演示」。
3. 用户看过后留下一次速看记录及当时版本。长文未完整读到、某块被截断或来源失权时，**不能叫整篇速看完成**；页面明示已覆盖到哪里，可继续处理或查看局部结果。生成失败时原文照常可读，同一纸签可重试。

后台任务负责分页、覆盖判定、模型输出检查与入库；伴星可在用户点她时指向关键句或朗读纸签，不承担生成完成条件。纸签上的「已保存」以领域服务回执为准。

### 2.2 隔久回忆：快速想起来

1. 用户点「回想」。先接回本篇未完成的回想；没有时，从当前不可变版本中选一处主题与依据清楚的可读片段准备问题，保存问题、依据和选择规则。不能永远取第一小节，也不根据浏览历史宣称掌握。常规短问题可由确定性规则从标题与原文组成；不适合的片段让用户换一处，需要模型时走 41a，不把泛泛的问题冒充整篇检验。用户不用等伴星回复才能进入。
2. 问题出现后，相关答案折起。用户可以心里想、口头说或自愿输入；**不要求打字才能继续**。先有「给点线索」，再由用户自己点「翻开对照」。线索必须在揭示前经过不泄题检查；揭示前不向伴星开放答案正文。
3. 揭示后显示原文和已有速看/批注，用户可选「想起来了」「再看一遍」或直接离开。记录实际发生的提示、揭示和用户自述；这些都不是自动评分，不自动安排复习。用户主动进入正式练习时，沿用其独立的作答和评分边界。

可见流程固定为「接回／生成问题 → 自己想 → 可选线索 → 自己揭示 → 可选自述」。问题从冻结版本的标题和原文块直接组成，原文块身份随问题一起保存；下一步由确定性的页面状态控制。伴星可以在用户求助时轻声陪想或换一种不泄题的提示，不负责生成默认问题、推进阶段、揭开答案或评分。

### 2.3 这一处看不懂：原位批注

1. 用户框选一句或选中可定位的段落，原句旁出现「讲讲这句」。系统保存选区在笔记版本中的块身份、起止、原文快照和前后文；图片区域若可框选，还需图片资产与坐标。定位不可靠时先明确告知，不能把解释贴到猜测的位置。
2. 用户主动点击后，**原句旁侧**展开详细批注附页；原句快照在顶部，对应正文选区有轻量记号。生成中与失败也在附页，正文不进入整页 loading。完成先给白话，再按需看比方、例子或演示；用户也可直接写自己的批注，不必先调用 AI。关闭附页不等于取消生成。追问与伴星对话是补充，不是生成和保存的唯一来源。
3. **默认收起所有详细批注。** 有批注的句段保留标记；精细指针 hover 和键盘 focus 可短预览，点击打开详情，再点原句或关闭可收起；触屏直接点击，不依赖 hover。重开不自动展开全部解释。改版后只有能可靠验证同一锚点才挂靠；否则留在旧版记录，显示原句与版本，不挪到相似的新句。

这条路径的完成条件是**有锚点、有可读解释、有保存回执**。用户离开时生成继续；失败、重试、旧版归档都在原句旁表达。

选文交给伴星讲解时，气泡内的短选文条显示原句与当前状态，点击打开原句解释附页，随气泡收起。正文选区有轻量虚线记号及「伴星正在解释」等状态入口；进度从发起时开始，完整生成后先显示保存中，收到回执才转成正式批注。重复点击同一句或重叠选区回到已有进度，不重复创建解释。自己的批注可同时写、独立保存，两条批注均可从原文打开，伴星回执不抢占输入附页。

停止包括发送前准备、提交回执在途和生成中的情况：界面立即停止，尚未提交的不再发送，迟到回执所属的 run 会被取消，旧增量或 final 不得复活解释或写批注。断流、失败或超时留下可读的未完成内容及恢复入口，不作为正式批注。完整解释保存失败保留原句与全文，可仅重试保存；保存成功后关闭气泡不丢批注。换选区、换笔记或换版本不把旧结果贴到新位置；旧版回执明确留在旧版记录，工作区切换后旧回执不进入新空间。

### 2.4 从这篇往外学：发现方向，再决定是否收下新笔记

1. 用户从本篇或某个概念点「往外学」。后台从冻结的笔记版本里找出少量相关知识，并直接写成 2–4 篇能独立读懂的短草稿。**草稿就是可先阅读的拓展内容，不会自动进入笔记架**；每篇都用人话说明与原文的关系，并带可点回去的原句。外部资料和没有原文支持的推断要各自标明来处。
2. 多篇草稿各有册本、状态和编辑缓冲，默认不勾选。逐篇读、改标题或正文、切上一篇/下一篇、对照来处，再选入待收下；返回列表保持位置与修改。替换未收下的编辑稿时先确认，不静默覆盖。伴星可陪比较，但不代用户选择，聊天回复不会直接写入笔记。
3. 用户点「收下 N 篇」后冻结选择与编辑快照，服务端在受控提交中只创建已勾选的笔记及双向关系。提交中不能修改该提交的内容或连点重建；失败保留草稿与选择、不留下缺关系的半成品，相同身份重试不重复创建。回执成功才显示「已收下」。原笔记能找到多篇衍生笔记，新笔记能返回本篇；未选草稿仍不在正式笔记架。

生成、阅读与编辑、审核、保存是可辨认的状态。候选草稿能先读后收；模型只能写候选内容，最终笔记与链接的权威状态只来自用户选择和业务提交回执。

## 3. 动态 HTML/SVG 怎样进入学习

「看个演示」可以从一处批注、速看重点或拓展解释发起，但不是每段必播。后台任务把冻结的知识片段、用户问题和可引用来源交给 AI，让它**自己设计有趣、生动的动态讲解动画网页**，由客户端嵌入展示。

**2026-10-02 用户裁决：生成提示只给学习内容与创作目标，不规定网页的版面、尺寸、配色、容器、图形形式、动作排布或动画方法。** 书房的 HUD 规范约束应用外壳，不作为模型网页的视觉模板。用于保存、文字说明与原文回查的返回字段不决定网页结构；嵌入侧负责高度适配、滚动与隔离，不强制重绘模型画面的布局和配色。

固定的只有边界：服务端核对引用确实落在材料中，限制脚本和资源；客户端在独立 origin 的隔离 frame 展示，不开放网络、存储、导航或业务写入。画面旁始终有文字等价和来源回跳。脚本失败、资源受限、用户减少动效时仍能看懂核心意思。任务保存不可变页面快照、生成器版本、输入版本、依据和校验回执；重新打开回放同一份，「换一个演示」才开启新任务。

`packages/shared/src/note-dynamic-artifact/` 中的整份文档生成和安全检查、独立 frame 宿主是复用的底层。笔记页可以为整篇速看或一条原位批注创建独立后台任务；Worker 根据冻结的笔记版本调用 AI 自主编写完整页面，再核对原文依据并经过安全检查。产物以 `note_learning_artifacts` 保存，不要求伴星先回复，也不使用固定画面模板。已用真实模型对三类合成知识拿到结构不同的 HTML，也通过了服务端引文和静态安全检查。2026-10-02 的提示版本 `note-dynamic-artifact-v5` 已用真实 IndexTTS 笔记生成并保存新页面；Electron 内已核对流程轮播、粒子与波形动画、卡片展开及原句回跳。嵌入时只投影模型场景的原节点，保留事件监听与网页自己的字体、配色、版面，不再继承保存快照外围纸面的样式。**学习效果、正文事实准确性、减少动效与完整失败矩阵仍未验收**；该局部样本将未展开的「四个升级点」补成了概括项，不能作为已核对的原文事实。

## 4. 伴星参与到哪里

伴星是身边的人，不是四个功能的总开关。她始终在书房里可见，用户主动点她或对话时才展开气泡；任务进行中只用低幅动作与必要的一次性回执，不主动打断阅读。以下是**可选增强**，用户不使用它也能完成各条路径。

| 场景 | 适当参与 | 流程权威仍属于 |
| --- | --- | --- |
| 速看已完成 | 指一处原文、读出短要点、回答追问 | 速看任务与纸签 |
| 回想中 | 用户求助时换一条不泄题线索、揭示后陪对照 | 回想折页的状态机与记录服务 |
| 原位批注 | 用户点「换种说法」时讲得更有趣，带当前选区对话 | 批注任务、锚点与保存回执 |
| 拓展审核 | 陪用户比较候选方向或解释一篇草稿 | 候选任务、用户勾选和原子保存 |
| 互动演示 | 邀请用户试一试、回答对演示的追问 | 动态页面任务和隔离宿主 |

伴星若通过工具帮用户发起其中一项，也调用**同一领域任务接口**，带 `noteId + noteVersionId + 选区`，返回同一 `taskId`，纸面出现同一份状态和结果。不能另造「伴星成功了但纸面没保存」的平行路径。伴星聊天消息可以作为补充来源记录，不能是速看、回想、批注、拓展和动态页面的必填外键。正式作答时角色可见但静默；用户主动关闭角色、减少动效或资源失败时按设置和真实失败状态处理。

## 5. 后台任务、状态与可追溯记录

四条路径共用最小任务语义，但各自有明确的业务状态，不要求用户看一套通用任务中心。一次请求保存 `taskId`、幂等请求身份、类型、工作区和发起者、`noteId`、**不可变的 `noteVersionId`**、必要的选区锚点/内容哈希、输入快照引用、任务定义版本、权限与外发同意快照、发起时间。对用户只显示「正在整理／已做好／没做好，可重试」等该纸签需要的状态；内部至少区分 `queued → running → ready`、`failed`、`cancelled`。队列重试、租约过期和模型提交失败都不得制造重复正式产物。离开页面再回来，从服务端按任务身份继续读状态和结果，不依赖某个仍打开的聊天窗口。

持久结果与运行状态分开：速看存覆盖范围和每个重点的原文依据；回想存题目、线索、是否揭示及自述；批注存原句锚点、解释版本和回跳；拓展存候选、草稿、用户审核与正式笔记关系；互动演示存不可变页面和文字等价。凡用户实际看过或主动做过的学习动作，足迹都能按时间找回；只生成未观看的后台候选不冒充「学过」。任何「看过」「求助过」「自己说想起来了」「正式测评通过」都是不同事实。

原文改版后旧结果保留在旧版册页，明确标记版本；不可确认的新位置不得自动重挂。权限变化时重新核对读取和提交权限；失权内容不因旧任务或伴星消息泄露。外部资料记录标题、地址、引用快照与获取时间；AI 的推断和可核对的原文引用分开显示。任何新笔记、关系或排期都要用户明确动作或既有独立业务规则，不能由模型文字或“任务完成”隐式写入。

当时还发现模块导入、Worker 权限与版本指纹约束的跨层问题。后续实施需按当前调用图复核，不能用历史“已修正”声明省略回归。**2026-09-30 独立 Demo 的生成、保存、资料与伴星形象均为明确标识的本机示例；不调用真实模型，不写服务端，不替代 Live2D 或业务验收。** 页面评估与真实数据闭环分开。

1. **先验证整套笔记的可操作 Demo。** 保留原笔记架身份，但一并评估列表返回、状态标签和空间使用；正文必须能实际切换预览、可编辑预览和纯编辑，不只换标签。评估目录、批注、资料、多篇草稿、记录及页首学习页签；离开/返回、滚动、失败/重试与动效也要能操作。Demo 不接真实数据，不作为最终认可或上线完成证明。
2. **先做三态正文与保存的真实闭环。** 共用工作文档、标题、撤销/重做与资产链；接入目录、焦点/源码映射、自动同步、版本提交、恢复、协作与只读权限。先通过 §7.1 中模式、输入、保存、权限与版面相关验收，再装载学习功能；学习、批注与多篇草稿联动在后续步骤完成后一起验收，不能把底座未完成的两态页面拿来继续堆新功能。
3. **建立独立任务合同并做速看闭环。** 请求创建、Worker 执行、覆盖检查、结果保存和重进恢复贯通；明确任务使用哪份不可变版本。真实长文必须完整或标出实际范围；重试不重复，旧版可回放。错误就地显示，不能用伴星聊天兜底掩盖。
4. **做确定性的快速回想。** 准备问题、可选线索、用户揭示和自述各有状态与记录；不要求输入、不提前泄题、不把自述当测评。主册页不突然缩短，重进能接回中断处。
5. **做三态下的原位批注与按需互动讲解。** 短选区、长段、代码、表格、引用、图片区域分别核对锚点；编辑与批注操作不冲突。解释和动态 HTML/SVG 走后台任务，验收真实 Electron frame、禁动效、脚本失败、来源回跳和改版归档。
6. **做资料关系与拓展审核提交。** 资料只读且能回原句，多篇草稿也能用三种模式逐篇读与改；候选选择、原子保存和双向引用独立验收。只收下一篇时其他草稿不进笔记库，正式笔记架标签随后按真实回执更新。
7. **接入伴星的可选动作并迁完旧链路。** 伴星工具发起相同任务、收到相同回执；默认的四条聊天流程和被替代的旧两态页面迁完后删除。列明调用图、旧路由/handler/类型/测试/配置，运行受影响的类型检查、测试、构建与真实窗口回归。

### 7.1 三种模式与完整编辑体验的验收

以下全部是目标验收，不是已完成声明。每种状态既要有自动化正控制，也要在真实窗口操作；测试里手工给 `scrollTop` 赋值或只断言 CSS 存在，不能证明真实内容能滚动或布局正确。

| 必测情境 | 通过条件 |
| --- | --- |
| 模式真实不同 | 预览输入不改文；可编辑预览直接改已排版正文；纯编辑完整显示 Markdown 源码且可编辑，不是同一个富文本框换名字 |
| 三态往返 | 在两种编辑态分别写入标题、中文、格式与最后一句，未经手动保存立即切其他模式也能看到；切换本身不创建版本，继续编辑和撤销/重做都有效 |
| 语法与图片 | 长文包含多级标题、列表、引用、表格、公式、代码围栏、链接和图片；切换不丢结构和引用。覆盖上传中/失败时切模式，以及不支持语法保留、原始 HTML 不执行 |
| 输入与定位 | 中文组合输入、选区、粘贴、查找替换、重名标题、增删标题和长源码行正确；目录在三个模式均可固定/隐藏并跳到对应段或行，返回不跳顶 |
| 保存与恢复 | 同步、版本保存和它们各自的失败可辨认；先输入再立刻换笔记/离开/重开不丢最后修改。重试不重建正式版本，保存过程中继续输入不被回执覆盖 |
| 权限与协作 | Member/历史版本/原始材料不能写；两窗交错编辑与模式切换不覆盖彼此，权限中途撤销不继续提交，也不伪造已保存 |
| 三态与批注 | 详情默认合起，hover/focus 仅预览，点击在旁侧开合；编辑不被自动 AI 弹层打断，源码批注记号不进入正文，改版后旧锚点不猜位置 |
| 学习与版本 | 未定稿与已保存版本的选择清楚；进入速看/回想/往外学再回来保留模式和工作稿，旧记录回当时版本而非当前近似文本 |
| 笔记架与多篇草稿 | 架子外观保留，开关笔记后恢复搜索/位置；标签不冒充掌握度。至少三篇草稿可分别用三态阅读和编辑，只收选中的，不丢剩余缓冲 |

### 7.2 笔记学习的端到端验收

最终用五次不加指导的实际操作判断：首次进入能看懂并回原文；隔久返回能自行回想；框选后解释留在原句；拓展只保存选中的新笔记；关闭再开仍能找到每次看过的内容。伴星一直在旁边，但不使用她也能完成全部操作。任何只在静态 Demo、受控模型或单测里成立的环节，都不能标成真实用户流程已验收。

布局与操作还需逐项通过：开篇不用下滚就能速看与往外学；没有展开详情时正文不被批注挤碎；
hover 预览完整、点击旁页可合回且焦点恢复；大小标题目录固定/隐藏及两种编辑态定位均正确；
来源失败不变空态；三篇以上草稿可独立阅读、编辑、取消选择与只提交一篇；
提交中冻结快照，失败不丢缓冲；旧版回跳不篡改新版；所有影不被滚区裁断；
短内容不靠缩短主册页制造大片底部空档，也不靠内容卡片填屏，200% 缩放不遮操作或伴星；动画打断、Off 和系统减少动效都立即得到正确终态。
