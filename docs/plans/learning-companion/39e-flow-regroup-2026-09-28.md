## 1. 一句话结论

**卡片没有被替换掉，它被留下了；笔记学习被倒进卡片留下的骨架里，于是两套 IA 挤在同一张纸面上。**

方案 39 的主张是「一篇笔记就是一个完整学习对象，**不用制卡就能学**」。实现里，学习轮的**主体页面不存在**——轮次住在笔记详情页的一个 tab 里，而那个 tab 与正文互斥；轮次里唯一真正的「学一下」动作会跳去另一张全屏页面，那张页面是**为一张卡的三分钟单题旅程写的状态机**。复习队列、候选审核、生成进度、结果页、底部主操作条，也全都还站在"卡"这一侧。

所以用户看到的不是"一条学习流程"，而是"笔记 + 卡片 + 一堆学习零件被摞在一起"。

## 2. 证据：骨架还站在卡这一侧

### 2.1 页面注册表里没有「学习页」

`apps/desktop-client/src/renderer/src/components/hud/hud-pages.ts` 注册 20 屏。与学习相关的六屏：

| # | id | 标题 | 站在哪一侧 |
| --- | --- | --- | --- |
| 10 | `goals` | **学习卡** | 卡 |
| 11 | `goal-detail` | **学习卡详情** | 卡 |
| 12 | `generating` | **学习卡生成中** | 卡 |
| 13 | `candidate` | **候选卡审核** | 卡 |
| 16 | `assessment` | 理解练习 | **卡机**（见 2.2） |
| 17 | `result` | 练习结果 | **卡机** |

PRD §13.1 点名的九个页面里，**「学习页」「回忆页」在实现里不存在**，因为轮次没有自己的屏；「笔记详情」（08）是唯一承载学习入口的一屏。

### 2.2 练习页是卡片的单题状态机

`surfaces/learning-run-surface.tsx`（3211 行）：

- 屏头三格是 `正式挑战 / 暂不计入掌握 / 练习关`（:2673-2677），题目是 `问题 ${sequence} · ${interactionLabel}`（:2882），配一个 `专注时间` 计时器（:2884）。
- 作答区有 **11 种题型编辑器**（:716-1367）：单选、判断、匹配、排序、多段结构包、关系画布、修补编辑器……这些是"一张卡的正面可以长什么样"的枚举。
- 复习队列开 run 时写死 `requestedTimeBudgetSeconds: 180`（`ReviewSurface.tsx:773`）——**三分钟单次预算**是卡片时代的遗产。
- 结果页的骨架是「本次挑战记录 / 本次掌握 / 还差什么 / 学习状态变化 / **本次学习发现卡**」（:2688-2774），其中「发现卡」是明确的游戏化抽取物（:2720-2744，注释写着"每轮从真实评分里抽一张"）。
- 学习轮次在这里**不是一个状态**：它只作为 `originV2.kind === "note_round"`（:618）和 `returnTargetV2`（:395）出现在边缘，决定"回到这一轮"那颗返回按钮。轮次本身对这一页是不可见的。

也就是说：笔记轮次点「练一道」，用户掉进的是**一张卡的单题挑战页**，跑完回到笔记页的一堵墙里。

### 2.3 复习队列是卡叠

`surfaces/ReviewSurface.tsx`：`.card-deck` / `.deck-card`（:997, :1061），卡面位置写「第 N 张 / 共 M 张」，操作提示是**「把最上面那张拖走，或按 ← → 抽下一张」**（:1246）。这个隐喻假定"到期的东西 = 一叠卡"，而 PRD §9.4 要的是"**有限的一批任务**"，任务来自目标与维度，不只来自卡。

### 2.4 笔记详情页本身是三个互斥 tab + 一条常驻底栏

`surfaces/notebook-surface.tsx`：

- 三个册页按钮 `笔记正文 / 本轮学习 / 学习记录`（:2541-2543）用 `hidden` 属性互斥（`note-hud.css:89`）。**正文与学习区永远不同屏**——而 PRD §3.2 的前提是"正文是视觉主体，学习区只放一个主要动作和一句理由"。
- `本轮学习` 那一页（:2628-3102，475 行）是一个**平铺的竖直长墙**，从上到下依次是：目标主动作 → 暂不安排 → 开启笔记订阅 → 本轮问题 → 这次一起走的小路线 → 换一个问题/先到这里 → 讲解 → 待核对块 → 例子 → 依据定位 → 私有来源 → 先讲讲这一节 → 这一轮练过 → **练一道** → 缺口停止四选一 → 动态产物 →（接页面底部）**留下这次的理解**。没有"现在该做什么"的引导。
- `NoteReflectionShelf`「留下这次的理解」渲染在**三个 section 之外**（:3185-3198），因此**在正文页、练习页、记录页都常驻**。截图中在"笔记正文"页看到「留下这次的理解 · 私有备注 1 / AI 整理建议 · 2 / 修改自己的批注」，就是这个原因——它与正在读正文毫无关系，却压在正文下面。
- 底部操作条（:3250-3265）五颗：`学这一篇 / 编辑这篇笔记 / 查看关联来源 / 版本历史 /` **`规划学习卡`**。PRD §8.2 把制卡列为**次级、主动选择**的入口；现在它与"编辑正文"平级，出现在每一屏。

### 2.5 动态讲解是一叠"步"

`artifact-frame-host.tsx:181` 渲染「共 N 步」，`main/artifact-template.ts:37` 在 iframe 里渲染「第 N 步」。动态讲解本身是 PRD §6 要的，但当前它挂在长墙的最末端、读起来像一叠卡，而不是"这一节讲清楚了"。

## 3. 方案要的那条流程

PRD §2 的职责表与 §13.1 的页面合同，画出来是这样：

```
笔记详情（正文是主角）
  └─ 一个主动作 + 一句理由
       开始学习 / 继续学习 / 接着弄懂… / 复习这篇 / 继续探索
       ↓
     学习页（这一轮）——线性四段
       ① 这一轮的问题（它在笔记的哪一段）
       ② 讲解：解释 · 例子 · 依据（可定位回正文）
       ③ 一次参与：预测 / 指出条件 / 用新情境解释
       ④ 本轮收获：今天能更好地做什么 · 还卡在哪里 · 下次建议做什么
       ↓
     完成并返回笔记
  └─ 次级动作（不打断）：留在笔记里 / 值得记住→学习卡 / 安排以后复习
  └─ 次级入口：学习记录 · 快速回顾 · 完整走一遍 · 本篇卡组 · 未来安排
```

四个关键点，正是现在缺的：

1. **学习页是一张屏**，不是笔记页的一个 tab。正文不该为了学习而消失。
2. **一次参与属于这一轮**，不是另一张屏上的单题挑战。轮次要有自己的第 ③ 段。
3. **结果回答三个问题**（收获 / 缺口 / 下一步），不是"本次掌握 + 抽一张发现卡"。
4. **卡片是支线**：值得反复提取的具体知识才制卡；不制卡不影响初学与复习。

## 5. 收拢顺序

每一刀都留下可验收的状态，不做大爆炸重写。

| 刀 | 做什么 | 退出条件 |
| --- | --- | --- |
| **A** | 新增「学习页」这一屏，把 `notebook-learning-leaf` 整块搬进去，改成线性四段（问题 → 讲解 → 一次参与 → 收获）。笔记详情页只留：正文 + 一条「下一步」纸签 + 学习记录入口。 | 真窗口里：笔记详情只看到正文和一个动作；点动作进学习页，四段顺序读下来不跳。 |
| **B** | 「练一道」不再跳 `invoke("validate")`；轮次第 ③ 段自己做一次参与，结果回到轮次而不是掉进单题挑战页。 | 一轮内「讲解 → 参与 → 收获」不离开学习页；练习记录仍写同一份 round practice。 |
| **C** | 结果页改成 PRD §5.6 的三问（收获 / 缺口 / 下一次建议），主按钮「完成并返回笔记」。撤掉「本次掌握」账本措辞与「本次学习发现卡」。 | 结果页三问都有内容，且不出现"抽卡"。 |
| **D** | 卡片降级：`规划学习卡` 移出笔记页主操作条，收进结果页的可选建议与本篇卡组入口；`hud-pages` 10–13 保留但不再是笔记页的邻居。 | 不制卡能走完初学与复习全流程；制卡入口仍在结果页与卡组可达。 |
| **E** | 复习队列从「卡叠」改成「今天这一批任务」，按目标/维度组织，理由仍可展开。 | 队列里同时能出现笔记级回访与卡片级回访，且不出现"抽下一张"。 |
| **F** | `NoteReflectionShelf` 只在**这一轮真的产生了讲解或作答**时出现，且只在学习页与结果页；正文页不再常驻。 | 在纯阅读一篇笔记时，页面上没有任何学习写入控件。 |

顺序不能换：**A 是所有其他刀的地基**；B、C 依赖 A；D、E 可以在 A 之后并行；F 依赖 A。
