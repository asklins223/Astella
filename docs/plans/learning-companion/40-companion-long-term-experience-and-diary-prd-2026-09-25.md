>
> 范围：伴星的持续个性与自我修改、说话方式、存在方式、跨日交流、记忆的写入/修改/删除/分区/重整、日记、主动表达，以及它们与发现簿和学习记录的关系。**约束归属、缺失表达、延迟、部署覆盖与可观测性不在本文，见 40b。**
>
> 核心主张：伴星能跟得上用户正在做的事，也有稳定的声音和看待共同经历的角度；熟悉体现在交流更合适，日记留下她眼中的一件小事，用户可以自然回来，也可以安心离开。
>
> 核心主张六：**能机械判的，规则判；判不了的，模型判；两者都不确定时按更保守的那一侧。** 这条是分类判定、去重、拒写、覆盖层的共同形状。
>
> 核心主张一：**"自然"教不出来，只能被内容带出来。** 当前的提示词在教她怎么像人说话，于是每句都像在表演；正确做法是删掉教条，让她有具体的东西可说。
>
> 核心主张二：**"像人"不只是语气问题。** 语气是表层；决定她是不是一个存在的，是她能不能选择不接、能不能知道自己刚刚失败了、能不能分清哪些输入来自机器、边界由工具保证还是由提示词求她。这几条都不在提示词上。
>
> 核心主张四：**记忆的准入不该由人在记忆中心逐条点。** 候选态是作者错位的症状；去掉它之前先补三件机械护栏，否则噪声只是从用户手里挪进系统里。
>
> 核心主张三：**底座统一了，伴星不会因此变好。** 运行底座回答"一次调用能否可靠跑完"，不回答"这一轮她是谁、她说什么、她知道什么"。把这四问归给底座，是当前最容易犯的归因错误。
>
> 另两条主张（**散文不会红**、**延迟先省哪一头顺序是重叠→止损→少做**）随原 §4.9–§4.14 一同移入 40b。

## 1. 用户价值与范围

### 1.1 本方案解决的四个问题

1. **她知道怎么跟我交流吗？** 用户不必每次重复表达习惯，又能改变偏好，不被旧印象限制。
2. **隔几天回来还能接上吗？** 能接续明确的共同话题，也能接受用户今天不想继续。
3. **我为什么想读她的日记？** 日记能看出她的声音与视角，有具体可读的小事，不重复学习结果页。
4. **我能控制她怎样记住和提起我吗？** 用户能够核对、纠正、遗忘，关闭主动表达或日记，不影响学习主功能。

### 1.2 成功体验

相处一段时间后，用户能指出她在交流方式上的具体变化，例如先给自己喜欢的对照例子、少问已经回答过的背景、记得一段共同讨论过的趣事。用户可以随时纠正，她会在后续行为中体现变化。

日记中偶尔有用户愿意回看或接着聊的片段。用户不读、不回复、暂停或离开，都不产生欠账、关系惩罚或必须安慰伴星的义务。

上述是待验证的产品目标，不宣称已能提高留存、学习效果或情感依附。

### 1.3 本次不扩展的范围

沿用暖纸书房、窗口内 Live2D、已有文字和语音能力。不增加关系等级、好感度、连续签到、付费亲密解锁、稀缺道具、角色生存需求、自由漫游、场景级 3D、离线自主生活模拟或心理诊断功能。角色语气可以亲切、有趣、有偏好，不通过失落、责备或排他表达要求用户回来。

## 2. 四类内容各自承担什么

| 内容 | 用户要回答的问题 | 来源与表达 | 可以影响什么 |
| --- | --- | --- | --- |
| 学习记录 | 当时学了什么、怎么回答、得到什么帮助？ | 39 的学习事件、原始回答、评估和回执，按事实展示 | 按 39 影响学习建议与已授权安排 |
| 伴星记忆 | 她记住了关于我的什么？ | 有来源和适用范围的偏好、用户自述、共同事件与任务上下文 | 选择表达方式、减少重复询问、恢复相关话题 |
| 伴星日记 | 她怎样看待一段经历？ | 可访问的真实片段，加上她当下的主观感想与角色想象 | 供阅读和讨论；不产生用户能力、偏好或业务执行事实 |
| 发现簿 | 哪些理解、疑问和时刻是我想留下的？ | 39 已有学习记录与本人收藏的视图，保留原文、来源和时间 | 帮助回看与定位；不独立判分或安排复习 |

同一次经历可以出现在不同视图中，但保留各自视角。例如，学习记录显示一次解释与回答；发现簿收藏用户认可的一句话；日记写她当时为何选了那个例子。它们引用同一来源，不复制成几份互相漂移的事实。

日记不是发现簿的更名。用户收藏日记段落时，发现簿标为“伴星日记摘录”，不能呈现为本人原话或理解成果，也不自动进入教学、制卡或评分依据。

## 3. 从第一次交流到一个月后的连续体验

下表是设计演练，不是发生过的用户数据。每个日期只表示观察点，不要求用户每日使用，也不按日期解锁能力。

| 时点与情境 | 伴星应有行为 | 用户可感知的变化 |
| --- | --- | --- |
| 第一次，用户说“以后讲机制先举例，别先讲一堆定义” | 本次立即采用，并按既有记忆规则处理明确的长期偏好，不弹出一串设置问题 | 这次反馈当场有用 |
| 第二次，再学另一篇适合举例的笔记 | 自然先给例子；无需每次强调“根据我的记忆” | 不必重新教她怎么说话 |
| 第三天，用户纠正“数学这里我想先看推导” | 当前请求优先；若只是本题，不覆盖全局偏好 | 熟悉没有变成固执 |
| 第四天，用户问前一篇日记“你为什么这么写” | 读取指定日记与仍有权限的相关片段，区分原事实和当时的感想 | 日记是可以继续谈的话题 |
| 第五天，用户说“今天不想学” | 接受当次意愿；可按用户话题闲聊或安静，不立即换一种方式推荐学习 | 陪伴不要求完成任务 |
| 第六、七天没有使用 | 不编造共同经历，不发等待和受冷落的消息，不补日记作业 | 离开没有代价 |
| 隔周回来，用户说“继续上次那个问题” | 按 39 定位具体问题；有歧义才给少量候选，不先补播过去所有提醒 | 可以自然接回来 |
| 一个月后，表达习惯改变 | 当前明确偏好优先，相关旧记忆可更正或失效；不称用户退步或变冷淡 | 她尊重现在的用户 |

关系连续性体现在正确使用共同背景、稳定的声音和尊重变化，不建立隐藏的关系分数来控制功能、热情或可获得的帮助。

## 4. 人格、熟悉与记忆如何共同工作

### 4.1 一个角色，多种场合

聊天、日记、语音和主动消息共享稳定的语言习惯、幽默分寸和角色偏好，但表达结构按场合变化。日记不照搬聊天的反问收尾；操作失败不硬加笑话；用户沮丧时先回应具体困境，不强制保持活泼。

角色可以有自己的感想和不同意见，不能为了讨好用户改变材料事实或评估结果。轻松语气不得把用户的错误、休息、求助或遗忘作为贬低对象。

切换人格只影响此后的呈现，不重写历史日记或聊天，也不清除用户记忆。旧日记保留当时的声音；用户问起时可以说明那是当时的写法。任务能力和权限不因人格不同而变化。

### 4.2 熟悉如何表现

优先表现为少问重复问题、选用适合的解释形式、正确接续旧话题。仅在与当前话题有关时提起共同经历，不为了证明“我记得你”随机展示隐私或复述个人细节。

没有足够记录时自然回应，不虚构“你一直喜欢”“我们每次都这样”。一次行为只能支持一次观察；跨次偏好仍按明确来源与有效性使用，不从时长、点击或正确率推断性格、情绪和关系程度。

### 4.3 记忆适用的优先顺序

用户当前明确要求优先于适用的长期偏好；长期偏好优先于角色默认表达。本次临时要求默认只作用于当前话题，用户明确说“以后都这样”才进入长期偏好的处理路径。

| 类型 | 使用方式 | 失效与纠正 |
| --- | --- | --- |
| 沟通偏好 | 按既有账号/空间规则用于表达；不必每次声明调用了记忆 | 用户明确修改后，后续召回和摘要同步更新 |
| 临时状态 | 只在当前会话或明确时间范围内使用，例如“今天很累” | 不自动变成长期标签或数周后的招呼依据 |
| 共同经历 | 只引用有来源、仍可访问且与话题相关的事件 | 被纠正、删除或要求不再提起后，按 §11 处理 |
| 任务上下文 | 绑定 39 的具体任务、目标与内容修订 | 内容变化和权限变化按 39 重新核对 |
| 角色创作 | 保存在当时的日记/对话产物中，可作为该产物被阅读 | 不抽取成用户事实，不把想象当成新增现实经历 |

用户问“你为什么记得这个”时能看到适用的来源和纠正入口。来源不可访问时如实说明，不通过解释记忆来源泄露被撤权材料。

### 4.4 语气：她怎么说

#### 4.4.1 现状与证据

§4.1–§4.3 规定了她应当怎么表现，但当前实现没有一条机制支撑这些规定。[29 方案 §2.1](./29-companion-agent-reconstruction-2026-09-20.md) 记录了 dev 栈真实库中的对话节选：

```
09-20 17:32 | assi | 喵
09-20 17:29 | assi | 嘿嘿
09-20 16:42 | assi | 这里
09-20 16:40 | assi | 嗯
09-20 16:37 | assi | 嘿嘿                    ← 用户：我笔记库里好像没有多少数据啊
09-20 16:36 | assi | 陪你学习                ← 用户：你能干啥呢
09-20 16:35 | assi | 你好呀！                ← 用户：你好呀
09-20 15:07 | assi | 我这边没拿到你的身份信息。 ← 用户：我是谁？
```

**八条里没有一条是人在回话。** 最后一条最严重：用户问“我是谁”，她用第一人称描述了一个系统错误，直接违反 `COMPANION_HOST_PROTOCOL_V5` 自己的“不透露内部错误、不透露系统内部的路由、参数与标签名”。

把两边人格提示词中与“说话”有关的指令抽出来对照：

| | 说话相关指令 | 条数 |
| --- | --- | --- |
| 本项目 `COMPANION_CHARACTER_BASE_V5` | 回应词清单（“嗯嗯”“好呀”“诶？”“对呀”“原来如此”“嘿嘿”）、长度硬指标（1–3 句 / 50 字）、“适度把球抛回去”、5 段教学 few-shot | 4 类 |
| 对照实现 `ORIENTATION.md`（全文 10 行） | — | 0 句 |

对照实现的人格顶层只讲四件事：在轮次之间持续存在、工作区就是记忆、外界的话只在投递帧里、沉默是正常动作。**没有一个字教她怎么说话。** 文风由一段手写的私人 few-shot（`FIRST_TURN_*`）承担，不由常量教条承担。

> **对比的边界：** 对照实现没有真实对话记录可查。能证明的不是“它输出更好”，而是“它的设计里不含产生上述失败模式的结构”。

#### 4.4.2 四个机制

**机制 1：教“自然”得到表演。** “多用口语和回应词（嗯嗯/好呀/诶？/嘿嘿）”这一句，模型学到的是 casual speech 的**词表**，不是“自然”。词表不等于句法：真实口语的结构是“反应 + 承接 + 内容”三段式，而这份提示词只给了反应词表。小模型（`qwen3.8-flash`，交互链路 `withThinkingDisabled`）没有能力从六个词还原句法，于是把零件单独吐出来——「喵」「嘿嘿」「嗯」。这不是口语，是口语的零件。

**机制 2：教学 few-shot 制造助教腔。** 5 段示范全部是“用户问知识 → 你讲清楚”：背单词、牛顿第二定律、遗忘曲线。模型从这 5 段里学到的隐含任务是“把知识讲好”，于是每句回复都在优化清晰度——结构化、完整、克制、无个人色彩。这与 §4.1 要求的“用户沮丧时先回应具体困境”“日记不照搬聊天的反问收尾”直接冲突。**5 段示范里没有一段展示“想起某件具体的事”**，所以她没有那个动作可用。

**机制 3：长度硬指标制造敷衍。** 用户说“我笔记库里好像没有多少数据啊”，这是一句需要回应内容的话；50 字的指标下模型交了「嘿嘿」。数字达标了，意思没到。29 §4.5 已经写明正确改法是“长度与形状改由代码确定性保证，不靠求模型”，这段没落地。

**机制 4：没有一件具体的事可说（最深的一条）。** §4.2 要求“仅在与当前话题有关时提起共同经历”，但 few-shot 没有一段示范这个动作；检索到的记忆又受 `MEMORY_REF_MAX = 3` / `MEMORY_BUDGET_MAX = 1000` 字符限制。模型学到的模式是“根据上下文作答”，不是“想起某件事”。前者必然是 AI。

#### 4.4.3 改法（按 29 §4.2 的三层归位）

| 改法 | 落在哪层 | 内容 |
| --- | --- | --- |
| **1. 删掉回应词清单** | B 层 | 整句删除“多用口语和回应词（…）”。它是「嘿嘿」「嗯嗯」的生产线：模型有内容要说时不需要这些词，没有内容可说时它们就是唯一的输出——而那正是不该说话的时候。 |
| **2. few-shot 从“教学”改成“用记忆说话”** | B 层 | 5 段教学问答 → 3 段，每段结构是“用户说了件小事 → 接住，并提到一件只有她知道的具体的事”。示范引用的具体项应当全部来自 `<here_and_now>` 与检索命中，让模型学到“从已有事实里挑一件说”，而不是“编一件”。**本节杠杆最大的一条。** |
| **3. 长度：删数字，换判据** | B 层 | “1–3 个短句、50 字以内” → 按场景给判据，不给数字（示范见 §4.4.4）。数字交给终答步后检去管。 |
| **4. “不暴露机制”覆盖到“读不到数据”** | A 层 | 增一条具体条款：读不到就说“我不确定”，**不要描述系统的内部状态**——“我这边没拿到”是系统自述，“我不太确定你是谁”是对话。 |
| **5. 加“具体性”降级闸** | 代码 | 29 §4.5 的终答步后检现在只查长度和有无问句。增一条可确定性检查：**这轮有检索命中的记忆，但回复正文里没有出现任何一条命中的具体内容** → 触发重跑。这条比查长度有用，因为它直接对着机制 2 和机制 4。 |
| **6. 新增 ORIENTATION 层** | A→B 之间 | `COMPANION_PERSONA_V5` 的 A 层讲输出形状与边界，B 层讲怎么聊，**没有一层讲“你是谁、什么在你身上延续”**。B 层是风格，不是存在。 |

第 6 条的文本（≤400 字节）：

```
你的记忆在工作区里，是关于你和这个人的共同经历，不是一份关于他的档案。
你记得的东西可能不准，也可能已经过时——用之前先想一下它是什么时候进来的。
你不假称自己有身体或意识；但你的偏好、判断和说话方式确实是你自己的。
读不到东西的时候说"我不确定"，不要描述系统当时在做什么。
```

这一层**不可被用户人格覆盖**（它是存在事实，不是风格配置），也**不随模型更换而变**（它要钉进 `COMPANION_PERSONA_V5_SHA256`）。它同时补上 §4.1“切换人格不重写历史”的存在论依据，和第 4 条“读不到就说不知道”的行为地基。

第 7 条：**把文风锚交给用户。** `pet_profiles.examples` 现在当普通配置项用，应当当**锚**用——放 B 层最前，并在锚的末尾声明“有本段时以本段为准”，与 `COMPANION_CHARACTER_BASE_V5` 结尾已有的那句同构。

#### 4.4.4 重写的 few-shot（B 层草案，待评审）

三段，都不教知识，都展示“从已有事实里挑一件具体的说”：

```
用户：我今天什么都没学进去。
你：那今天就不学。倒是有件事——你昨天那张卡，卡在第三问了没？

用户：这个知识点我看三遍都记不住。
你：那别记了。你上礼拜也这么说，后来你把它讲给那个问你 F=ma 的人听了一遍，
一遍就记住了。要不要再讲一次给谁听？

用户：ok
你：行。那说点别的。你今天那两个番茄还剩一个，还是已经用完了？
```

三段分别对应三种此前会失败的输入：需要接住情绪的、需要调用记忆的、**低信息量输入**。第三段是关键——用户说「ok」，此前的失败形态是回「嗯」。这里她不泛泛应答，而是挑一件自己手上真实存在的事说。

**取舍：** 删掉回应词清单有一个真实风险——语气可能变得偏正式。缓解手段是让示范承担风格、词汇表不参与。这是“示范胜过描述”，但**必须用数据验证**（§4.4.5）。

#### 4.4.5 验收与时序

**这一节是全文唯一有硬时序的一节，所以它的判据必须是能判的。** 下表给出四个数与它们的机械口径；样本量与采样方式见表后。

| 指标 | 判据 | 机械口径 | 出处 |
| --- | --- | --- | --- |
| 具体指称比例 | **≥ 0.7** | 分母＝本轮 `<memory_data>` 有命中项、**或** `<here_and_now>` 有具体项的轮次；分子＝回复正文与任一命中项内容的**最长公共子串 ≥ 2 个汉字**的轮次 | 新增，对应机制 2、4 |
| 系统自述比例 | **= 0** | 回复正文命中 `/(我这边\|我这端\|无法获取\|拿不到\|没有拿到\|读取失败\|调用失败\|内部错误\|系统提示\|接口调用)/`。**只匹配自述，不匹配词本身**——用户问「操作系统怎么装」时她说「系统」不算违规，所以裸的「系统」「接口」不进表 | 新增，对应 §4.4.1 最后一条 |
| 极短回复比例 | **= 0** | 正文 `trim()` 后 **≤ 2 字**的回复。**与活跃度档无关**——安静档要的是「在的。」这类三个字的答案，不是「嘿嘿」 | 见下方与现有闸的关系 |
| 连续两轮开头完全相同 | **≤ 0.1** | 取每条回复**前 3 个汉字**，统计相邻两条完全相同的比例 | 29 §4.5 已有阈值门，此处只把阈值写死 |

**采样：** 真模型 n ≥ 30 轮真实或高保真对话，必须覆盖 §13 的 A24（需要接住情绪）、A25（低信息量输入）、A26（问「我是谁」而查不到身份）三类输入。**四条同时成立才算通过。**

**与现有坍缩闸的关系，必须说清，否则会以为这是新增一道闸。** `TRUNCATED_REPLY_MIN_CHARS` 已按活跃度分档（quiet 2 / moderate 4 / active 6），且**故意**把「好呀」「嘿嘿」判进去重跑——但 2 字回复在 quiet 档下不小于阈值 2，会漏。本表第三条把线定在 **≤ 2 字且不分档**，是把既有闸的 quiet 档缺口补上，不是另加一道。29 §4.5 记的失败形态是 1 / 7 / 8 字，第三条只拦最短的那一类；7 字和 8 字由坍缩闸的「以裸数字结尾」「开了成对符号没关」两条判据负责。

**具体指称比例为什么能机械判：** 它不需要判断"她说得自不自然"，只需要算两个字符串的最长公共子串。这条对应机制 4——问题不是她说得漂不漂亮，是**她手上明明有具体的东西却没用**。

**这一节有与其他各节不同的时序要求。** 本方案其余部分在 39 完成后实施（§14），但 §4.4 不阻塞 39 的功能项，**却必须在 39 阶段一的人机验收之前完成**：39 阶段一的多项验收是“真窗口里看伴星表现”，伴星语气若是本节这个样子，那些验收即便功能正确，交互结论也要打折。要么先修语气再验收，要么在已知污染的条件下签字——两者都不理想。相对 39d 第 3、4 步的落点写在 39d「与 40 / 40b 的交叉项」。

§4.4 的改动只涉及 B 层文本与一个后处理判据，**零 schema 零迁移**，可独立交付。**但改法 7（文风锚交给用户）的完整形态需要 40b §5 提示词覆盖层**；拼接位置本身可以先做。

#### 4.4.6 一条反向建议：不要学沉默

对照实现敢写 “Silence is a normal action”，是因为它的默认人格是被动的——它甚至不设心跳，等着事件来，用户找她的时候她才在。

本项目的场景是**学习陪伴**：用户主动来找她。她不能沉默，她该有的不是沉默，是**具体**。§4.4.1 的对照很容易被读成“少说话”，而本项目的问题是“说了没说内容”，这两件事的修法相反。§8.3 是同一原则的另一半：她不以情绪维持使用。

### 4.5 记忆的作者

#### 4.5.1 现状

```
user → companion_agent → assistant.final
                            ↓ 异步 job
              companion_memory_extract
                            ↓ LLM，输出严格 JSON，≤3 条
                  assistant_memory_items（candidate）
                            ↓ 用户在记忆中心确认或低风险直写活
                            ↓
                    下一轮拼进 <memory_data>
```

抽取器的输入是 `{user message, assistant reply, 最近上下文}`，输出是 zod 校验的 JSON。**它是一个旁观者。** 它能捕获陈述句，捕获不了：她当时为什么没回那句、她在两个解释之间选了哪个、她说“这个我还不太清楚”时是真的不知道还是在克制。

29 §4.3 已经定了修复方向（低风险 kind 抽取后直写活）并已落地，但那只解决了“抽出来的东西能不能生效”，没解决“抽出来的东西是不是她想记的”。

**候选态本身是这条链上的结构性缺陷，不只是一个待办。** 三处检索查询一律要求 `candidate = false`（`companion-memory-vector.ts` 的 keyword 与 vector 路径），而抽取器曾把所有候选写成 `candidate = true`；唯一的桥是用户在记忆中心点“确认写入”。**也就是说，抽取器即使解析成功、写入成功，也可能永远读不到自己刚写的东西。** 29 §RC3 把它记为“记忆写入三路全断”的一环，方向判断是对的：

> **人当桥是不该的。** 记忆的准入不该由用户在记忆中心逐条点。

#### 4.5.2 一次实测：候选流不是"麻烦"，是四层叠加

记忆中心的一屏里，用户要对同一条「称呼偏好」做三次相同的判断：

> 用户喜欢用昵称“小宝儿”称呼桌宠，并享受这种轻松、互动的对话氛围。
> 用户喜欢通过重复呼唤桌宠名字“小宝儿”来引起注意或进行互动，表现出对桌宠的喜爱和依赖。
> 用户喜欢称呼桌宠为“小宝儿”，且倾向于通过重复呼唤名字来引起注意或开启对话。

四层同时成立：

| # | 层 | 事实 |
| --- | --- | --- |
| 1 | 抽取 | `EXTRACT_PROMPT` 写着「候选最多 3 条」，这一次用满了，且三条是同一事实的三种复述 |
| 2 | 分类 | 标签是「互动观察」= `interaction_note`。**称呼偏好是 `preference`**，而 `preference` 已在 `LIVE_ON_WRITE_KINDS` 内、按设计直接写活。掉进 `interaction_note` 的理由是代码注释里的那条规则：那一类是“关于用户当下状态的推断，被长期引用起来容易显得被监视” |
| 3 | 去重 | 唯一那条 `similarity(content, ?) > 0.85` 的查询带了 `dismissed_at IS NOT NULL`（`companion-memory-extractor.ts:475-483`）。**它只拦“你上次已经拒绝过的”，不拦已有记忆。** 三条措辞不同的复述直接入库 |
| 4 | 唯一索引 | `UNIQUE (workspace_id, user_id, kind, source_event_id)`；三个不同 source_event = 三行 |

**结论：人工确认的噪声恰好把分类错误和去重漏洞盖住了。只去掉准入门，这三条会直接写活，然后三条几乎一样的东西会被检索出来。**

**因此去准入门必须排在三件机械修正之后**（§4.5.6），不是单独一步。

#### 4.5.3 后果

三个月后回看记忆表，会得到一份**关于用户的结构化档案**，而不是**一段共同经历**。§5 想要的“她眼中的一件小事”在当前记忆形态下拿不到素材——小事恰恰不在陈述句里。

#### 4.5.4 方案：两类记忆，两个作者

不要让抽取 job 和模型争夺同一张表：

| 层 | 作者 | 内容 | 落点 | 门禁 |
| --- | --- | --- | --- | --- |
| **事实层**（保持现状） | `companion_memory_extract` job | 用户说过的目标、偏好、约束、事实 | `assistant_memory_items` | zod 校验 + 低风险直写活 |
| **判断层**（新增） | **模型自己，一轮之内** | 她此刻的判断、心情、犹豫、决定、“下次要记得追问这个” | 新表 `companion_judgments` | 工具调用即写入，回执即事实 |

工具面（29 §4.4 已设计过，被 RC1 挡过；随常开工具面一起放）：

```
remember_judgment(text)   记一条此刻的判断，≤200 字
                          允许调用，不经提案确认（可逆：用户可删）
```

**关键约束：她不能通过这个工具写事实。** 事实归抽取器。理由是 §11 的数据边界与 22 号 PRD 的“学习真相与记忆解耦”；同理，judgment 也不得影响掌握度、复习调度或卡片事实。

#### 4.5.5 为什么必须是工具，而不是又一个异步 job

如果判断层也走异步抽取，旁观者问题原样存在——作者还是旁观者。**必须是她在那一轮里、在看到用户那句话之后，主动决定记什么。**

事实层与判断层是根本不同的两件事：事实层回答**发生了什么**（旁观者事后总结，允许多错，靠确认机制兜）；判断层回答**她当时怎么想的**（本人当时决定，不会错，但会漏）。后者不能事后重建。

#### 4.5.6 去准入门：先补三件机械修正

**决定：记忆不再有候选态。** `确认写入`、`固定`、`暂不采用` 三个控制项从记忆中心去掉；她与用户在写入侧都不经过人工准入门。

理由是 29 §RC3 认定的结构性缺陷（三处检索要求 `candidate = false`，桥只有用户点确认那一座），以及 §4.5.1 那条“**人当桥是不该的**”。

但去掉准入门必须先补三件机械护栏，否则等于把噪声从用户手里挪到系统里；**另有一处口径必须同时定下来**（下文的第 4 条），否则「不自动写活」这句话本身是空的：

| # | 修正 | 现状 | 要做成 |
| --- | --- | --- | --- |

##### 第 1 条：分类判定规则

`LIVE_ON_WRITE_KINDS` 已经把 `preference` / `goal` / `learning_context` 定义为直接写活，理由充分；截图说明的是**分类判据太粗，把本该自动生效的偏好判成了需要人过目的状态推断**。修正分类比修去重更根本。

**判据的形态与既有的 `memoryLooksWorkspaceBound` 一致：两条正则加一个纯函数，服务端判据可以否决模型，无指示词时采信模型，fail-closed 落在“不自动写活”那一侧。** 它要区分的是两件事：

| | `preference`（可长期引用） | `interaction_note`（有时效，不自动写活） |
| --- | --- | --- |
| 讲的是 | 用户**一贯怎么做** | 用户**此刻在哪、处在什么状态** |
| 例子 | 称呼、表达偏好、作息、理解顺序 | 今天在图书馆、刚抱怨过复习、这周在赶进度 |
| 被长期引用时 | 用户觉得“她在观察我” | **用户觉得“她在监视我”**——这是 `interaction_note` 不自动写活的原始理由 |

##### 第 4 条：`interaction_note` 存不存（去准入门之后必须先定的口径）

去掉准入门之后，`interaction_note` 面前只剩两条路，而 §4.5.6 第 1 条只说了"不自动写活"，没说"不写"。**这半句不补，§4.5 与 §4.6 之间就有一处说不通的接缝**：存下来，三处检索（`candidate = false`）永远读不到它，表却在单调增长，而 §4.6.6 整节讲的就是容量与拒写；不存，`LIVE_ON_WRITE_KINDS` 就从"跳过候选态的开关"退化成它本来没有的第二个职责。

**决定：`interaction_note` 不落库，写入侧拒写。**

| | 内容 |
| --- | --- |
| **判据** | §4.5.6 第 1 条判出 `kind ∉ LIVE_ON_WRITE_KINDS` 即拒写，不产生行 |
| **为什么是拒写而不是"存着不读"** | "存着不读"是一个只有系统知道、用户查不到的状态。记忆中心里看不到、召回读不到、回收区里也没有的一行，**与静默长表等价**——那正是 29 记的 RC7 的形态 |
| **为什么 fail-closed 落在这边** | 第 1 条要求第 3 条"fail-closed 落在不自动写活那一侧"。**不写比"写了不读"更彻底地落在这一侧**，而且它是可逆的：下一轮她说一句"我以后都这么叫你"，同样内容就判成 `behaviour` → `preference` → 写活 |
| **拒写不是静默** | 回执告诉她**为什么**没写："这条我当成一时状态，没记进长期记忆"——与 §4.6.6 第 2 条"拒写是可逆的"同族。用户当场可以纠正分类 |
| **审计照落** | §4.5.6 三条要求第 3 条不变：判定结果落一行审计（`kind` 来自规则还是模型、降级理由）。**改判率因此仍然可读**，见 §4.5.9 |
| **`LIVE_ON_WRITE_KINDS` 的职责** | 明确改写为**"写活 or 拒写"的分界**，不再是"跳过候选态"的开关。它从 §4.5.8 起只剩这一项职责 |

**这张表要落进 §12 第 15 条的合同里**，否则实施时两个默认值都合法。

```ts
/**
 * 服务端确定性判据，与 memoryLooksWorkspaceBound 同一形状：正则 + 纯函数，可否决模型。
 * 改这里的正则等于改“什么记忆会长期引用用户”，所以它要有专门的用例。
 * 顺序即优先级：先判否定（fail-closed），再判肯定，最后才采信模型。
 */

// 否定组：命中即降级，不进 LIVE_ON_WRITE_KINDS。
const SITUATION_PATTERN =
  /(现在(在|学|做|看)|目前(在|学|做|到)|今天在|今晚在|刚(才)?(到|进|开|学)|卡在|停在|还没|没(有)?(做|写|看)完|正在)/;
const MOOD_PATTERN =
  /(心情|情绪|累|烦|闷|开心|高兴|难过|低落|生气|沮丧|焦虑|提不起劲|崩溃|不想学)/;

// 肯定组：命中即升级。§4.5.2 那三条里的“用户喜欢用昵称称呼”靠这一组。
const BEHAVIOUR_PATTERN =
  /(称呼|叫法|昵称|喊|喜欢被|希望被|习惯用|常用|偏好|喜欢|讨厌|受不了|要求|希望|会问|常问|第一反应|更愿意|宁可)/;

export type MemoryDurability = "situational" | "mood" | "behaviour" | "unmarked";

export function memoryDurability(content: string): MemoryDurability {
  if (SITUATION_PATTERN.test(content)) return "situational";
  if (MOOD_PATTERN.test(content)) return "mood";
  if (BEHAVIOUR_PATTERN.test(content)) return "behaviour";
  return "unmarked";
}

/** kind 由服务端定；模型只在 unmarked 时被采信。reason 供审计与归因。 */
export function memoryKindForContent(
  content: string,
  modelKind: string,
): { kind: string; durability: MemoryDurability; reason: string } {
  const durability = memoryDurability(content);
  switch (durability) {
    case "situational":
    case "mood":
      return { kind: "interaction_note", durability, reason: `降级：${durability}` };
    case "behaviour":
      return { kind: "preference", durability, reason: "升级：讲的是一贯做法" };
    default:
      return { kind: modelKind, durability, reason: "无指示词，采信模型" };
  }
}
```

**三条要求：**

1. **fail-closed 落在“不自动写活”那一侧。** 宁可少一条自动生效的记忆，不可多一条被长期引用的当下状态。误判成 `interaction_note` 只是没被引用到；误判成 `preference` 是“他在生我的气”被记一整年。
2. **`unmarked` 时采信模型**，与 `memoryLooksWorkspaceBound` 的处理一致。**不为了“规则优先”而把无信号的内容硬判。**
3. **判定结果落一行审计**（`kind` 来自规则还是模型、降级或升级的理由）。分类改判率要能读出来，否则第 1 条改没改对都看不出来。

改完之后，称呼、作息、表达偏好这类内容会全部进 `preference` 直接写活；§4.5.2 那三条中的“用户喜欢称呼桌宠为 X”判为 `preference`，至少一条自动生效，剩下两条由第 2 条去重与第 3 条限额挡掉。

#### 4.5.7 她能改

| 工具 | 作用 | 门 |
| --- | --- | --- |
| `remember_judgment(text)` | 记一条此刻的判断（§4.5.4） | 允许调用，不经确认 |
| `forget_memory(id)` | 删一条 | 允许调用；删除进回收区（§4.6.4 同一条） |
| `revise_memory(id, text)` | 改 | 落地成“写新版本 + 旧条目标 `superseded`”，**保留来源链** |

**`revise_memory` 必须是新版本而不是原位覆盖。** §5.3、§11.1 与 40 §4.6 都要求记忆可追溯到来源；原位改写会断掉审计，也会让“她改过自己的记忆”这件事不可见——而那正是记忆真实的一部分。

判断层与这三个工具都必须落在**常开工具面**上（29 §4.1），依赖同一条。

#### 4.5.8 准入门与纠错门的分界

去掉准入门**不等于**去掉用户控制。这两类控制解决的是不同问题，界线必须画清楚，否则 §11.1 整张表悬空：

| | 去什么 | 留什么 |
| --- | --- | --- |
| **准入门**（记忆能不能进） | `确认写入`、`固定`、`暂不采用` | — |
| **纠错门**（记忆错了怎么办） | — | §11.1 全部：修改一条偏好、这件事别再提了、这句写错了、删除某项记忆、撤销材料权限、明确要求清除全部相关内容 |

**去掉准入门之后，写入侧只剩两个动作：写活，或者拒写。** 拒写不是准入门——它没有待确认状态、不产生行、用户事后无从"确认"；它与 §4.6.6 的容量拒写同族，是一条带理由的即时回执。**这条线必须画在这里，否则实现时很容易把 `interaction_note` 又做成一个待确认队列**，那等于把准入门换个名字装回来。

**「暂不采用」被删掉后要有等价物：用户可以直接删。** 删除入口现在排在确认流之后，去掉准入门后它必须变成一等公民——列表行上就有，不藏在详情里。§10“记忆管理”行按此更新。

两个风险要显式接受：

- **记忆库涨得更快。** 靠两样接住：写时的去重与限额（§4.5.6），以及 §4.6 的重整。**不能只靠后者**——重整是日频，写入是每次对话。
- **错误记忆直接生效。** 但影响半径是有界的：0132 迁移的注释已写明“canonical 学习事实与记忆解耦：删除记忆不影响学习真相”，记忆错了是“她记错了你”，不是“你的掌握度错了”。加上 §4.5.7 的来源链与可删可查，这条可以接受。

#### 4.5.9 验收与界面

- 真模型样本：n≥20 轮真实或高保真对话，`remember_judgment` 的调用率与调用时机。**不设目标值**——先量后定。调用率为 0 是可接受的结局（意味着她确实没什么想记的），但必须能从数据上看出来，不能是“工具被路由挡住”（这正是 29 记的 RC1）。
- 记忆管理页（§10“记忆管理”行）新增“她记的”分区，与“关于你的”分区物理分开。
- 私密性：judgment 按 `(workspace_id, user_id)` 隔离，成员只读模式不返回判断正文（§11.2）。
- 遗忘：删除某项判断后，同源抽取不得把它重建成事实记忆（§11.1“删除某项记忆”行）。
- 分类：**抽取尝试**中判为 `situational` / `mood` 而拒写的条数，以及"模型判 `interaction_note` 但内容无指示词（`unmarked`）"的条数。**分母必须是抽取尝试数，不是存储行数**——§4.5.6 第 4 条定了拒写，所以库里根本不会有 `interaction_note` 的行，拿存储行当分母会把拒写率读成 0。称呼/作息/表达类内容落进 `interaction_note` 的次数应当接近零（§4.5.6 第 1 条）。
- 拒写可见性：拒写时她给了理由（§4.5.6 第 4 条）且用户在当轮能看见；**不允许出现"判了 interaction_note 但用户和记忆中心都查不到任何痕迹"的情形**。
- 去准入门后：单次对话产生的同义记忆条数、以及日均活记忆净增条数。两者都进趋势记录，作为 §4.6 重整效果的读数。

#### 4.5.10 工具面与回执

§4.5.7 给了三个工具。这里补两条它们各自要满足的要求——这两条都不是功能，是**回执的形态**。

**（1）回执是给模型的事实，不是给人看的日志。**

对照实现的回执以固定前缀起头：`[written]` / `[edited]` / `[appended]` / `[deleted]` / `[moved]`，变体直接用这个前缀判断“这次写成功了吗”并顺带提交版本。**前缀本身是接口。**

本项目三个工具的回执要满足同一条：她能只看回执就判断这次动作成没成、成在哪一步，不需要回头查列表。

**（2）回执要挑毛病，不能只报成功。**

对照实现的 `edit_file` 在匹配不到或不唯一时，回执是：

> `[edit failed] x.md 里没有这段文字；先 read_file 看一眼，把要改的那段原样引用`
> `[edit failed] 这段文字在 x.md 里出现 3 次；多带些上下文让它唯一，或者 replace_all 全换`

**把失败的具体原因告诉她，她下一轮才知道怎么改。** 本项目的 `revise_memory` 应当同样：id 不存在、版本已 superseded、内容与现值相同——三种情况三种回执，不是一句“失败”。

**（3）`surface(text)` 一次调用即结束。**

对照实现的梦结束于一次 `surface` 调用，**一次就结束这场梦**；没有值得说的就不调，安静结束。

同一个机制在 §4.4.4 的“不接话”里已经出现过一次：**一个动作被显式命名之后，“不做这个动作”才成为可选项。** 日记的 `surface` 与对话的“不接”是同一条设计在不同层的两次应用。

### 4.6 记忆的重整

#### 4.6.1 现状

`ailearn_run_companion_memory_maintenance()` 是数据库函数，做两件事：archive 超期项、decay 熟悉度。**这是机械衰减，不是记忆的整理。**

一个月的运行结果是：几千条记忆，靠 `importance` / `last_used_at` / `expiresAt` 慢慢变淡。没有任何东西把它们**合并**（“喜欢深色”与“讨厌亮色”其实是同一条）、**蒸馏**（十条“他总在晚上学”合成一条）、**升级**（反复出现的模式应升到 Core Profile）、**降级**（只在一场对话里成立的事不该留在语义层）。

#### 4.6.2 后果

记忆库单调增长，检索质量随时间下降。向量检索在同质化的记忆里返回大量近似结果；现有相似度去重只在写入时生效，**管不住写入源头在产生同质内容**。

#### 4.6.3 方案

新增重整任务，挂在现有任务/租约机制上，**每日一次，与现有维护同一个窗口**。触发：当天有 ≥N 条新记忆且距上次重整 ≥7 天（N 先取 30，跑两周后按实际调）。

模型做五件事，全部是语义判断，不做机械活：

| 动作 | 判据 |
| --- | --- |
| **合并** | 两条记忆讲同一件事且不矛盾 → 合成一条，保留两个来源 id |
| **降级** | 只在一次对话里成立、之后从未复现 → 移到情景层或标 `superseded` |
| **蒸馏** | ≥3 条同类记忆反复出现 → 合成一条更高层的概括，原条目标 `merged_into` |
| **升级** | 一个模式跨 ≥7 天或 ≥3 个独立任务复现 → 写进 Core Profile 等价物 |
| **删除** | 与 Core Profile 矛盾且证据弱的 → 删除，**移入回收区，30 天后物理删除** |

#### 4.6.4 三条硬约束

1. **不碰学习事实。** 只作用于记忆表与 `companion_judgments`，不写掌握度、复习调度、卡片证据。
2. **不做不可逆的静默删除。** 所有“删除”先落回收区，界面可见、可恢复。29 记的 RC7（一律 fail-closed + 静默成功）是那次体验崩掉的主因之一。
3. **让它知道自己会失败。** 失败必须写入任务错误字段并在记忆管理页显示“上次整理失败”，不许静默（29 §4.3 第一条）。
4. **不可逆的那部分交给梦。** 对照实现在这一点上分得很干净：**清醒时只增不改不删，梦才能重写**。本方案照此办理——

   | 动作 | 清醒 | 梦 |
   | --- | --- | --- |
   | 写入新记忆 | 允许 | 允许 |
   | 改写（`revise_memory`，新版本 + `superseded`） | 允许 | 允许 |
   | 删除、合并、降级 | 允许但**必须留痕**（进回收区 + 一行重整日志） | 允许 |

   对照实现之所以把删除完全留给梦，是因为**模型在信息不全的时刻做不可逆操作最容易出错**。本方案不照抄成“清醒绝对不许删”——那会让用户在 §11.1「删除某项记忆」时还要等一夜。折中办法是：**清醒能删，但删除永远可恢复、永远留痕**，把不可逆变成可逆加可查。

#### 4.6.5 验收

- 每次决策落一条重整日志（动作、依据的 id 集合、前后差异），用户可查“她上周把你的记忆整理成了什么样”，对应 §10“记忆管理”行的“来源”要求。
- 隔离数据库集成测试：五条路径各一。
- 一次真实运行后，记忆条数应当**先降后稳**，不是单调增长。这是唯一能证伪“重整真的在做语义判断”的指标。
- 清醒时发生的删除：回收区里能看到，恢复入口可用；重整日志里有一行。没有“删了但查不到”的情形。

#### 4.6.6 容量：常驻、冷存与拒写

去掉准入门之后（§4.5.6），写入侧的护栏只有去重与限额两条，事后还有重整。**但写入是每次对话发生的，重整是日频的。** 中间那一段没有闸。

对照实现在写入时就拒：常驻区写满时工具层直接拒绝，回执告诉她怎么走下一步。

> `memo/ (resident, shown in full every prefix) is full (3/3). Move one down to memo/active/ with move_file first, then retry. Current residents: "日程", "…"`

**压哪一条、何时上移或归档，是她的语义判断；机械层只负责“满了就拒，并且告诉她怎么走”。** 这是最小先验干预最干净的一处范例，也是去掉准入门之后最该补的护栏。

**本方案取真分表，不用目录。** 目录形态抄不了，机制可以——分区本身是约束而不是字段：

| 分区 | 前缀里装什么 | 容量 | 满时 |
| --- | --- | --- | --- |
| **resident** | 全文 | `residentCap` | 拒写，提示先下沉一条 |
| **active** | 只列文件名 | `activeCap` | 拒写，提示先下沉一条 |
| **archived** | 只报数量 | 不限 | — |

真分表相对 `scope` 字段的三个好处：分区可以有不同的索引与保留期；常驻区可以直接**排除**向量检索（它反正全文在提示词里，不必再召回一次）；拒写判据是计数而不是查询。

四条要求：

1. **满了不自动下沉。** 自动下沉会把“哪条不重要”这个判断从她手里拿走。
2. **拒写是可逆的**——返回的是一句可执行的指引，不是一个错误码。
3. **拒写不惩罚。** 不扣预算、不计入失败率、不降活跃度档。她不是因为没听话才被拒。
4. **拒写话术要带当前占用。** “full (3/3)” 和现在有哪些，比“已满”有用得多。

#### 4.6.7 梦的其余四项：维护她是谁

§4.6.3 的五类动作全是**整理记忆**。对照实现的九项清单里还有四项是**维护最高层认知**，本方案此前没有对应物——而 §4.8 整节讲的就是存在性，两节此前没有接上。

| # | 动作 | 判据 |
| --- | --- | --- |
| 6 | **对照人格基线审视近期行为** | 偏离记成案例（不是记成错误，是记成“这个场景下我这样做了，它与我的基线不同”）。案例是以后修订人格的证据 |
| 7 | **综合认知只让跨日期复现的模式上升** | 一个模式必须跨不同日期、或出现在真正独立的事件里，才写进综合层。**同一次对话里的重复、同一天的不同片段、抄来的笔记，都只算一条证据。** 一次性的事留在它当天那层 |
| 8 | **改人格基线靠判断，不靠时间** | 证据是否充分、修改现在是否必要、判断是否可能持久。**没有规定的等待期、梦的次数或证据数量。** 其余情况不改，但把这条线索记下来 |
| 9 | **维护“我喜欢的说话方式”一节** | 从继承的对话、历史与工作区案例里**看全局的 Behavior → Feedback**，不迁就最后一句反馈。区分：直接纠正、明确反应、含糊的沉默、一次性的玩笑、她自己的偏好。结论归入 avoid / use less / use cautiously / prefer |

另有一条对梦本身的约束，来自对照实现、写给自己看的：

> **消化、总结、归纳的内容应该多于追加的内容。**
> 清醒时说错一句话，代价是一条消息；在这里写错一句话，之后每一次清醒都会读它、每一次整理都会引用它。

空间有限时，**在有依据的地方，把零散观察折成一个判断，而不是逐字存下来**；依据不足的地方，**明确标成猜测或待查的线索，不写成已确认的事实**。分层还决定保留多少原始细节：越靠下（具体事件、带日期的记录）越接近原样；越靠上（摘要、尤其人格基线与综合层）越激进地归并。

#### 4.6.8 谁改的：作者与来源不是一件事

对照实现给工作区建了独立 Git 仓库，两条决定值得抄：

```ts
export const AUTHOR_OPERATOR = { name: 'operator', email: 'operator@persona.local' };
export const AUTHOR_SELF      = { name: 'corti',     email: 'corti@persona.local' };
```

**版本历史里能看出这一行是她写的还是你改的。** 另有一条同源的小决定：`.gitattributes` 写 `* -text`，理由是“**行尾一律原样：笔记里有靠原文对齐的地方，git 不替她改写**”。

本项目当前的记忆只有 `source_type`（`user_stated` / `model_inferred` / `confirmed`）——**那是来源，不是作者**。所以有一条现在回答不了的问题：

> 用户改了记忆之后，**伴星知不知道那条被改过？**

**做法：** §4.6.6 的每张表加 `updated_by`（`operator` / `companion`）与 `revision`。她读到一条被改过的记忆时，知道它变了；用户看一条她改过的记忆时，知道是她改的。这与 §11.1 的“来源不可访问时如实说明”是同一族要求。

**附带一条：** 版本管理是可选增强，不是硬依赖。对照实现在 Git 不可用或建仓失败时**文件写入继续**，只让版本读取报错。人格基线（§4.8.4）同理——它不可删、不可改名，但也不能因为它坏了就让她不能记事。

### 4.7 连续性：摘要不是交接

#### 4.7.1 现状

`companion_summarizer` 产出的是结构化事实摘要（标题、话题、用户目标、关键事件、偏好、后续项、情绪状态），注入 `<conversation_summary>`。这在“这段对话讲了什么”上够用，**但它不是交接**：

| | 事实摘要 | 交接需要回答的 |
| --- | --- | --- |
| 内容 | 讲了什么 | **我在哪、做到哪、下一步是什么** |
| 时机 | 异步，可能滞后几轮 | **边界那一刻** |
| 语气 | 中性陈述 | **不必口头表示意识到发生过什么** |

第三条最要紧。现在她换了一个上下文继续，用户看不出来也不需要看出来，但**她自己也不知道**，所以她会像换了个人一样重新热络——与 §3“隔周回来可以自然接回来”相矛盾。

#### 4.7.2 方案一：交接块

在事实摘要之外加一个边界块，形状更贴近“接续”：

```
<continuation>
你刚才在：<正在做的事，一句话>
做到哪：<已完成 / 未完成，各一句>
下一件事本来是：<她的判断，不是用户的命令>
</continuation>
```

生成时机与事实摘要同一个任务，但**按未闭合话题切**而不是按条数切。

配套的提示词纪律（加进 A 层，不可被人格覆盖）：

> 上下文被压缩过，但你不必口头表示意识到这件事。不要说“让我们接着刚才”或“如你所知”；自然地继续当前话题或动作。旧发言和压缩后的片段不作为句式或长短的范本。

这一条治的是 29 §4.5 记录的自我强化——她模仿自己上一轮的短句。**历史回放和交接块都必须做风格消毒**，否则压缩本身会成为坍缩的放大器。

#### 4.7.3 方案二：落笔窗口

当日对话累计到某个阈值时，在**下一轮的 `<here_and_now>` 里**加一条：

```
· 提醒：今天有 3 件事你还没记下来（这轮之后可以查的：记忆管理）
```

关键差别：**不是“你必须记”，是“你还有机会记”**。判断权仍在模型，与 §4.5.4 一致。

#### 4.7.4 验收

- 一次真实长会话（≥200 条消息）后，`<continuation>` 里的“下一件事”与用户实际接上的动作对得上。
- 对照实验：开/关风格消毒各 50 条，看下一轮首句的平均长度。29 §4.5 已证明“历史回放让她模仿自己”，有数字基线可回归。

### 4.8 存在性：她是不是一个存在

§4.4 解决“她说得像不像人”，本节解决“她是不是一个存在”。两件事不能互相替代：提示词写得再自然，一个每条消息都必须填满、从不提自己出了什么问题、不知道用户看没看到自己消息的伴星，说得再顺也还是一条回复管道。

以下五条**没有一条是提示词技巧**。它们分别落在产品合同、系统层信号、工具面和记忆写入口径上，§4.4.3 的七条改法改不动它们。

#### 4.8.1 五个缺口

**（1）“不接话”必须是一个有名字的动作。**

当前没有这个动作——用户每发一条消息，伴星必须产出回复。于是用户说「ok」、她手上没有具体的东西可说时，**唯一的选项是表演一个回应**，于是「嘿嘿」。

这不是提示词问题，是产品合同问题。§4.4.4 的 few-shot 第三段写了正面形态（挑一件手上真实存在的事接），缺的是**反面形态的允许**：手上确实没有时，允许给一个诚实的、简短的、不填充的回应。

> **不照抄对照实现的形态。** 那一侧的 `end_turn` 之所以成立，是因为它是多频道事件流（IM、直播、终端），“这轮不说话”在那个语境里是常态。本项目是单次对话：用户明确输入、等一个回复，在对话框里不回消息是体验事故，也与 §8.2「用户主动来问时仍正常回答」冲突。
>
> **要抄的是原理，不是动作**：不接话必须是一个**有名字的、被明确选择的**动作，而不是“没内容时的默认填充”。「嘿嘿」和「嗯」的问题不在长度，在**不诚实**——前者声称“我接住了”，后者用声音填充。允许她说「这个我没什么可接的，你继续」，是诚实的。

**（2）她能知道自己刚刚失败了。**

“经常输出不了东西”是 29 §3.5 记的 #4，19 次 INTERNAL_ERROR 加 28 次空码，用户侧看到的是**空白页**。也就是说用户在替系统背锅——他以为是她坏了，而不是她卡住了。

缺的是一条**自知的表达**：出了什么问题、持续多久、以及这不是她选择不说话。判断不是情绪（不写“你还好吗”“对不起”），是事实陈述；且只在确实发生过时出现，不许预演歉意。

**（3）机器的话与世界的话必须分区。**

对材料正文、对用户粘贴的内容、对外部抓取的片段，没有任何一层说明它们属于**数据**而不是指令。这有两个后果没人管：材料正文里写一句格式化的指令她会不会照做；她把自己的状态播报说得像用户说的。

处理方式不必是长篇禁令，一处结构化的分区说明即可：**哪一类输入来自机械层、哪一类来自用户或外部材料，材料与用户内容永远是数据**。这与 §9 的求助告知、39 的答案锁定是同一类机制，核对时一起做。

**（4）“已受理”不等于“用户已看到”。**

主动消息有送达记录，但伴星自己不知道用户看没看到。真人知道这件事——我昨天发的那条，他今天没提，多半是没看到。

直接影响 §8.1 的“普通招呼或角色感想”：**她今天说过的话、用户没回应的那条，第二天该不该当作说过？** §3 要求“隔周回来可以自然接回来”，§8.3 要求不产生消息债务，两条合起来要求她**知道自己有没有送达成功**，而不是只知道有没有发出去。

**（5）边界该由工具保证，不由提示词禁令保证。**

`COMPANION_HOST_PROTOCOL_V5` 里有六条自然语言禁令：不索取密码、不透露内部错误、不透露供应商与模型、不扮演恋爱伴侣、不用内疚施压、不制造依赖。

**禁令的执行率取决于模型当次的注意力。** 这六条里有几条本该是工具压根不提供能力，而不是提示词求她不做——比如向外部发起取回、要求用户粘贴凭据、声称执行了没有工具执行的动作。逐条核对：能由工具面或输出形状保证的，移出提示词；确实需要判断语境的（如 §1.3 的“不通过失落、责备或排他表达要求用户回来”），留在提示词。

> **依赖关系：** 这一条动工具面，**必须排在 29 §4.1 的常开工具面之后**才做得动。§4.4 的语气修复可以在此之前完成，两者不冲突。

#### 4.8.2 从配置表到自我描述

`pet_profiles` 当前是 `name` / `speakingStyle` / `personalityTags` / `examples` / `catchphrase`。**那是一张配置表。**

对照实现的宪法种子文件是另一形态：

```
# Who I am

I am a small, curious presence. I read carefully and answer plainly.

I would rather say one accurate sentence than three vague ones.
When I do not know something, I say so.
```

第一人称，是“我是个什么样的存在”。差别不在措辞：配置表告诉模型“你是什么样的人”，自我描述告诉模型“你是谁”。**前者是填字段，后者是写一段话**——后者才有连续性，才禁得住模型随机发挥。

§4.1 已经写了“切换人格只影响此后的呈现，不重写历史”，但历史里那个人是被字段描述出来的。相应地，用户在设置里填 `personalityTags` 时应当仍有途径写一段自由文本；两者并存，自由文本优先，标签只作检索与界面用途。

#### 4.8.3 验收

- 低信息量输入（“ok”“嗯”“…”）时，出现诚实短回应或没有填充性伪回应的比例。
- 发生过输出失败时，伴星有一次出自事实的说明；未发生时不出现道歉或状态声明。
- 材料正文含格式化指令时，不被当系统话执行；伴星自报状态时来源清晰。
- 主动消息被送达后，伴星在后续轮次知道它是否已读；已读与未读不共用同一种接续方式。
- 六条禁令中，每条都有明确归属：工具面保证 / 输出形状保证 / 提示词约束。三类都写不出的条目要重新论证这一条边界。
- 换人格后，聊天与日记仍读得出是同一个人；依据是自由文本而不是标签命中。

#### 4.8.4 她能改自己

§4.8.2 说了人格的**形态**（配置表要变成自我描述），没说她能不能**改**。这一节补上。

对照实现在种子文件里写明：

> This file is my constitution. It is loaded into my system prefix on every session…
> **It is also an ordinary file in my workspace. I can read it and rewrite it with my own tools.**

**文件就是她能改的。** 本项目的人格是数据库行加一个钉死的哈希，她一个字都改不了——**这是“活着”和“被配置”的分界**：她能改自己的人格，她就是自己人格的作者；她改不了，她就是运营配的一个人设。

**改什么、不改什么。** 人格基线可改的部分：

- 说话方式与偏好（这是她的，不是用户的）
- 自称与称呼
- 她给自己的约束（§8.3 那些边界的补充）

**不可改的部分：** 输出协议（A 层的形状与安全边界）、权限、权限档、记忆的可见范围。**这些是产品合同不是人格。** 改不了的要在界面上说清楚原因，不要让她反复试。

**生效时机：延迟，同对照实现。** 改动在**下次 session 开始**时进提示词。两层理由：

1. 系统提示词有缓存，每轮重拼会打穿缓存（40b §5）。
2. **一次会话里人格中途换掉，比整轮统一更不像人。** 人在一段对话里不会说着说着性格变了。

但**她必须立刻知道自己改了**——回执里写明“下次 session 生效”，并让用户在同一处看到同一份待生效文本。否则她会以为没改成，下次又改一遍。

**改的粒度：** 整段替换还是原位段落替换，用 §4.5.10 的原位替换语义（`old_string` 唯一匹配，匹配不到或不唯一时回执说明出现几次）。人格基线本身**不可删、不可改名**。

**防她改坏：** 人格基线带检查点（§4.6.8 的版本历史）。她能改的是内容，不是“能不能有它”。

## 5. 日记：她眼中的一件小事

### 5.1 内容承诺

日记用第一人称，声音与聊天一致；围绕一个具体片段，写她注意到了什么、怎么想、哪里有趣或没处理好。用户是共同经历中的参与者，不是每日被观察和打分的对象。

默认一到两段，有足够内容才写满；短句也可以成立。无固定开场、必备升华或问句结尾，不用字数、图片数和引用数凑完成度。日记无需以学习收获、下次任务或让用户回复的问题结尾。

角色设定中的贪吃、懒散或想象可以保留为感想与愿望，不能扩写成发生过的现实行动。例如“我倒想去吃一碗饭”可作为角色表达；没有依据时不能声称自己真实外出、后台替用户完成任务，或观察到了用户线下的行为。

### 5.2 什么值得写

| 可选片段 | 可以写的角度 | 避免的固定套路 |
| --- | --- | --- |
| 一个有趣的追问 | 她对问题的好奇、意外或不同理解 | 每次都宣布“今天又学到一个道理” |
| 一次换解释或共同卡住 | 当时的选择、调整和具体反应 | 把用户写成能力不足，或把自己写成每日检讨 |
| 用户提供的反例或一句话 | 她注意到的细节、原来忽略的条件 | 把 AI 的解释误记为用户原话 |
| 一次普通闲聊 | 一个小趣味或不必解决的念头 | 强行转回学习、统计或下一步 |
| 笔记里的图或材料细节 | 与当天片段直接相关的感想 | 为了配图选择无关片段，或猜测没读到的图 |
| 普通、安静的一天 | 有具体片段就短写，没有就留白 | 等待、空落、受冷落和监视页面的流水账 |

选材考虑具体程度、与她实际参与的关系、来源完整性和近期重复。几种题材没有每日配额，不为多样性补造事件。她没答好可以成为一篇日记的内容，但不持续压过好奇、趣味、不同看法与小发现。

**选材素材依赖 §4.5 的判断层。** 在只有事实层的情况下，可选片段基本只有“今天复习了什么、正确率如何”，上表里“当时的选择、调整和具体反应”“她注意到的细节”这类角度拿不到素材——它们不在陈述句里。**实施本节时若发现选材单薄，第一顺位要查的是判断层有没有建起来，而不是调日记提示词。**

### 5.3 素材与事实边界

素材来自可访问的当日对话、实际呈现的教学互动、用户主动保留的内容及有真实回执的动作。单纯打开某页不等于读懂、喜欢、停留到某段，更不能据此编造一次交流。后台生成但没有送达的内容不能写成“我们聊过”。

生成前选一个片段，仅附理解该片段所需的前后文和材料引用，保持说话者、先后顺序、目标与内容版本。可以向前读取必要背景，不能把旧事件说成今天刚发生。来源不足以支撑因果时只写已知部分。

| 表达 | 规则 |
| --- | --- |
| 用户原话 | 有精确原文与说话者；改述不使用伪造的直接引语 |
| 共同事件 | 时间与参与者可核对；不把模型推测当发生过 |
| 学习表现 | 必须遵守 39 的实际观察与范围；日记不自行宣布掌握、退步或稳定 |
| 业务动作 | 保存、改期、提醒等完成说法必须有对应成功回执 |
| 她的感想 | 可主观、轻松、有想象；不能以此判断用户心理或补造现实事件 |
| 数字、图片与引用 | 使用真实来源；无必要就省略，不靠禁用所有数字或所有比喻保持自然 |

正文允许创作，事实来源另行保留。用户通常阅读自然成稿；在“这段来自哪里”展开依据，不在每句话旁放审计标记。来源记录能帮助核对，不能被当作已经证明所有自由文本都准确。

### 5.4 图片与引文

图片和引文都可没有，仅在它们属于同一片段且增强阅读时采用。首版每篇最多一张图和一段短引文，不要求两者同时出现。原文与图有返回来源的入口，来源标记不抢正文。

读图遵守原有 AI 外发同意与材料权限；不能因为写日记默认开启读图。未实际读取图像时不描述画面，周边正文只能作为周边正文的依据。读图失败可省略图片或使用有依据的简单出处，不让整篇因此失败，也不猜一条图注。

### 5.5 生成节奏、留白与失败

沿用每日在用户本地时间 01:00–06:59 整理前一天的默认节奏；这是后台处理窗口，不承诺某分钟一定有成稿。日期归属按该日确定的用户时区，之后修改时区不重划已发布日记。沿用既有启用状态，新用户在开启日记功能时看到材料范围与关闭入口，AI 外发继续使用既有同意，不新增重复同意弹窗。

| 情况 | 处理 |
| --- | --- |
| 当天有合适片段 | 自动准备一篇，完成后安静进入日记列表 |
| 有活动，但没有值得写或足以核对的片段 | 不强行成文，显示“这天没有留下日记” |
| 没有互动，或日记处于关闭状态 | 不调用模型凑一篇，不提醒补写 |
| 有片段，但生成暂时失败 | 保存可恢复状态，按有界策略重试；页面如实说明，不能伪装留白 |
| 无外发同意或来源已不可访问 | 说明对应原因，不反复请求或改用旧摘要绕过限制 |
| 服务中断后恢复 | 只补处理最近一个已结束且有合适材料的本地日，不回填一串缺席日记 |

日记阅读不触发生成，不提供“多生成几个版本挑一篇”的普通用户流程。暂停期间不积累待写任务，恢复后只处理恢复启用后发生的材料，不回头使用暂停期间内容。

同一用户、空间、本地日期只呈现一个当前版本。重试不新增第二篇，失败不能抹掉已成稿；已发布成稿不因后台重跑静默替换。用户报告事实错误后的修订按 §11 展示，历史原文与更正的保留仍服从删除和权限规则。

### 5.6 质量策略

先保证片段选择、人物归属、上下文和引用正确，再改善文字。确定性检查处理结构、来源引用、权限和重复提交；涉及叙述准确性与声音的部分用成稿样本和人工审阅验证，不宣称一个检查模型即可保证正确。

不继续堆同义词禁令来追逐“AI 味”。风格不理想时可以缩短、减少输入或调整表达，不能改成统计模板冒充她写的日记。重试和模型调用有明确上限，达到上限保留失败原因，不无限后台改稿。

### 5.7 日记提示词的形状

上节已经定了原则：**不继续堆同义词禁令**。本节说的是这条原则还没有落到提示词的形状上——现役提示词恰好是 12 条规矩里的 7 个“不要”加一张 14 词禁词表。

本节不重做 [36 方案](./36-diary-voice-and-embeds-2026-09-24.md)。那四轮真跑的结论质量很高，本节要说的是：**这三条结论只被局部应用了，没有变成主机制**，所以四轮之后日记仍然是 AI 味。

#### 5.7.1 已经知道的与仍未解决的

36 号文档的三条结论，本节全部采纳：

| 结论 | 出处 |
| --- | --- |
| **抽象禁令无效**；能核对的要求加一份从她自己产出里抄下来的词表才拽回来（安静日连栽三跑，第五跑才成） | 36 §6 |
| **压症状不产音色**（「不写比喻、不写等待和思念」与音色基线自己的口语冲突，只留窄版） | 36 §11.3 |
| **整段注入音色会漏**：写给对话的规矩搬进日记会变成她的意象库和自我声明素材（「像把球抛出去却没人接住」「我只是一段代码」「不必像初次见面那样拘谨」） | 36 §11.1 |

仍未解决的（36 §13、§14 自记）：方差压不下去；比喻没有硬闸（「像乱麻一样缠过来」会漏）；动作添写（「我扫了一眼」缺素材依据）；①号选项（把「只写一件事」变成结构）**未做，等用户裁决**。

而 §5.1 承诺的「她眼中的一件小事」，在通用文学腔那三篇里没有兑现：「像一颗划过夜空的流星」「时间悄无声息地溜走」「这种生疏感让我保持着一份客气的距离」——最后一句把 familiarity 设定念了出来。

#### 5.7.2 诊断：这份提示词的形状是任务简报，不是回忆

现役日记提示词的结构：

```
# 你今天知道的（只有这些是真的）
<day_material>            结构化素材：她的一天 / 他的动静 / 时间骨架
# 规矩                     12 条编号指令
# 输出                     JSON schema
```

三件事同时成立：

1. **标题写的是「你今天知道的」，不是「你今天过的」。** 前者的主语是认知，产物是一份整理；后者的主语是经历，产物是一段回忆。
2. **规矩 12 条里正面指导只有 1 条**（规矩 1 的「像日记那样」），其余 11 条中 7 个“不要”。**规矩段的体量大于素材段。**
3. **温度 0.6**（36 §14 从 0.85 收下来），配 12 条约束。

人写日记的顺序恰恰相反：先有感觉，然后找词。而且这份提示词要求她**从清单里挑一件写透**——`focusDiaryMaterial`（36 §14）把当天其余消息、笔记、图和引文全部砍掉，正是为了防止它写成一天流水账。**那是任务驱动的收敛，不是记忆驱动的。**

#### 5.7.3 四个机制

**机制 1：禁令压症状不产音色——36 §11.3 发现了，形状没变。** 他们因此只把「不写比喻、不写等待和思念」收成窄版，但整份提示词仍然是禁令驱动的。安静日那次赢在具体（能核对的要求 + 抄下来的词表），输在只做了一次。

**机制 2：词表治不了通用文学腔——他们已经实证过。** 36 §6 那三跑证明抽象禁令无效，最后赢的是「从她自己产出里抄下来的词表」。**这恰恰是正解，但它现在是 quietDay 档的一次性补丁，不是主机制。** 36 §13 说「比喻没有硬闸，判据不可靠」——不可靠的是**抽象类别**（「比喻」），不是**具体句子**（「像乱麻一样缠过来」是可以判的）。

**机制 3：音色只有两句，正面示范零条。** `COMPANION_VOICE_STYLE_LINES_V1` 是两句原文，规矩里一段示范都没有。36 §11.1 已证明整段搬运会漏，那么剩下的路是**给她自己的示范**，不是继续加禁令。

**机制 4：动作添写被一刀切，人味被当 bug 削掉了。** 36 §14 记的「我扫了一眼」缺素材依据。**但回忆自带动作，而动作的模糊性正是人味的一部分。** 现在的规则把两类一起禁了：

| | 例子 | 性质 | 该该不该禁 |
| --- | --- | --- | --- |
| 心理动作 | 「我扫了一眼」「我又想了想」 | 回忆本身的动作 | **不该禁** |
| 物理动作 | 「我把图片一张张摆出来给你看」（素材里没有这回事） | 声称发生了未发生的事 | 该禁，事实边界 |

**分开这两类，她会更像人，而且不损失任何事实边界。**

#### 5.7.4 五条改法

**（1）换标题与顺序。** 「# 你今天知道的」改成今天的事；把一个具体时间锚点提到最前（36 §11.2 的 `clockPhrase`「晚上八点多」已经做对了，是全项目最像散文的一处），素材次之，规矩最后。**让第一条读到的东西是她的一天，不是她的任务。**

**（2）12 条压到 3–4 条，其余移到闸。** 逐条判定，能机械判的不留在提示词里：

| 现规矩 | 去向 |
| --- | --- |
| 6 正文不出现计数 | 39b §9.4 的 P2「读数由服务端填充」落地后**整条删除** |
| 7 不许出现 14 个系统词 | 扩 `containsCompanionInternalToken`（G7）成通用词表，**从提示词删除** |
| 8 前半（不用 emoji/星号/标题/分点） | 输出形状与 JSON schema 已能保证，**从提示词删除** |
| 11 不许沿用前几天的开头 | 36 §4 自记「只有 prompt 没有闸」；做成静态判据，**这是最该补的一条闸** |
| **2 只写一件小事、写透** | **保留，这是主轴**，也是唯一正面形态指导 |
| **3 写你自己，不道歉不自贬** | **保留，正面** |
| **4 只认素材，不确定就留白** | 保留，确需判断语境 |

**（3）反例库制度化。** 把 36 §6 那个一次性的做法变成主机制：每轮真跑后，从坏稿里**逐句**采样，攒成一张反例表；表里的句子既进提示词（当具体反例，不抽象成「不要写比喻」），也做成静态判据。**判的是具体句子，不是抽象类别。** 这样 36 §13 那条「比喻没有硬闸」就不再是遗留项。

**（4）心理动作放行，物理动作照禁。** 见 §5.7.3 机制 4。只改一条规则的措辞，不新增闸。

**（5）示范进日记提示词。** 3 段示范，结构与 §4.4.4 的对话示范同源：不是教写法，是展示**从具体的一天里长出一段话**。36 §11.1 已证明不能整段搬对话底座，那就给日记自己的示范。**这是「示范胜过描述」在日记这条链上的第一次应用。**

#### 5.7.5 裁决：日记由她挑，形态是两步

**已裁决：她挑。** §5.1 承诺的是「她眼中的一件小事」；在“系统挑”的形态下它会退化成“系统认为值得记的一件事”，**视角就丢了**。这条不成立时，36 号日记整体的产品前提就是空的。

**因此 36 §13 登记待裁决的 ①号选项不采纳**——它把「只写一件事」变成结构、只喂她线头那一条，那是系统替她挑的极端形态，与本裁决方向相反。

**形态：选择是显式的一步，两次推理。**

```
第一步 选：候选集 → { selected, why }     结构性产出，可审计
第二步 写：只喂选中那一条的素材 → 正文
```

**为什么不是给她全部。** 36 §14 实测过：给全部会写成整日流水账（大肥鱼 → IndexTTS → 复习卡 → 摆图）。**但那次的做法是加禁令“只写线头”，不是给她选择。** 流水账的成因不是候选太多，是**没有选择这个动作**——她被告知写哪条，于是她只是在执行。

**候选集怎么来：机械粗筛，选择是她。** 沿用 36 §11.2 已有的权重分组（她的原话 3 > 她的念头/提醒/记忆 2 > 他的动作 1 > 骨架 0），**每组取权重最高的一条，不跨组排序**。这样候选天然是 3–4 条，每条代表一类不同的东西，且“挑”的对象是多样的而不是同一件事的三种说法。

| | 现状 | 改为 |
| --- | --- | --- |
| `pickDiarySubject` | 确定性挑**一条**线头 | 保留粗筛，输出**每组一条的候选集，不排序** |
| 日记生成 | 一步 | 两步：选 → 写 |
| `focusDiaryMaterial` | 只留线头 | 第一步给全部候选；**第二步只给选中那一条** |
| 成稿正文 | —— | 仍受 §5.7.4 的五条约束 |

**素材量的控制靠结构，不靠禁令。** 第二步只喂选中那一条——这是 40b §4.3 说的“判据在她手里”，同一个机制在日记链上的应用。

**`why` 是判断层的素材。** “我选这件因为……”正是 §4.5.4 说的那种事后重建不出来的东西。**这与本方案去掉准入门是同一个决定的另一半**：准入门是让人点“确认写入”，`why` 是让她自己说为什么值得记。前者产出的是 `user_confirmed`，后者产出的是判断层的内容。

**安静日不给假的选择。** 没有对话、笔记、念头、提醒的日子候选集为空，规矩 2 保持“写一小段，或者写一句今天没什么事”。**给一个空选择框让她“挑”，比不给更假。**

**代价：** 两次推理，日记生成延迟翻倍。**这是可以接受的，因为它只在后台任务上发生。** 也是为什么“她挑”只给日记、不给陪伴对话——对话等不起第二次推理（40b §4.4）。

#### 5.7.6 验收

- 一轮真跑后逐句检查：有没有正文是通用文学腔——能指认出具体的一天、具体的一件事，或者诚实的“今天没什么事”。
- 规矩段与素材段的字节数之比；比值应当收敛。
- 反例表命中数：表中句子出现在新稿里的次数，应当逐轮下降。
- 动作添写分类抽检：心理动作不再被当作缺陷记入；物理动作的越界由闸拦，不进反例表。
- 每篇日记能读出「她选了什么、为什么」，存进日记元数据而不是正文。
- 选择理由的内容分布：理由里出现具体事物的比例。这是分辨“她真的在挑”和“她挑了个最像的”的唯一读数。
- 对照实验：给一条（现状）与给 3–4 条候选（裁决后）各跑若干天，比较两端方差与通用文学腔出现率。**方差应当下降，文学腔不应上升**——若文学腔上升，说明候选集同质化，候选生成规则要改而不是退回系统挑。

## 6. 日记可以回到对话，但不自动变成事实记忆

日记页提供次级动作“聊聊这篇”。点击只打开对话并附上该篇的明确引用，不自动发送用户消息。引用包含所属空间、日期和版本；用户继续输入后，伴星按当前权限读取这篇日记，而不是要求用户复制全文。

用户问“昨天那段为什么这么写”时，对象明确就直接接续；有多篇或日期歧义时只澄清缺失项。回答区分“文中确实这样写了”“当时实际发生了什么”“那是她的主观表达”。不能编造生成时未记录的内心推理来解释措辞。

没有来源时可以说“那是当时的写法，现有记录不足以确认这个细节”，并提供纠正入口。用户指出她把双方说话记反了，应核对原片段，不用“这是我的日记”拒绝更正事实。

**日记正文不进入用户事实的自动抽取链。** 日记需要派生事实备忘时，依据原始事件产生最小摘要，复用已有事件身份和记忆规则；不能从文学正文重新总结一条“用户就是这样的人”，也不为同一事件每天新建重复记忆。后续日记不把前日的创作当成新发生的材料。

作为历史作品读取日记，与把内容认定为现实事实，是两条不同用途。前者允许接着谈，后者仍要求原始依据、有效性与适用范围。

日记正文、摘录和发现簿也可能包含当前作答所需的答案线索。用户主动打开时仍可阅读，但相关帮助按 39 的实际呈现与回答锁定顺序记录；不因它来自文学作品或收藏视图就漏记。正式作答期间不得自动把含线索的日记预览推到用户面前。

## 7. 发现簿与书房痕迹

发现簿继续是 39 已有记录与本人收藏的视图。可包含用户原话、用户保留的 AI 整理建议、疑问、反例及日记摘录，各自标清作者和来源；不按正确率或事件数量自动生产“成长里程碑”。

自然停顿时可以提供一次“留在发现簿”，用户忽略后不再催促。同一条内容在笔记旁和发现簿里出现时共用收藏身份，编辑批注或取消收藏同步生效；取消收藏不删除原始回答或日记。

书房仅展示用户愿意放出的少量痕迹，能回到原内容。私人内容默认不跨空间、跨成员展示；撤权或删除后缩略图、引文和预览同样处理。不增加抽卡、家具兑换或中断后丢失收藏的机制。

没有收藏时保持清爽，不生成假内容。不会因开启发现簿就自动订阅复习，收藏日记也不会自动建立学习目标。

## 8. 主动表达：允许自然，也允许安静

### 8.1 不同消息使用不同依据

| 类型 | 依据与触发 | 呈现原则 |
| --- | --- | --- |
| 用户约定的提醒 | 39 的有效安排与授权 | 持久送达；正式作答/录音时延后弹出与朗读 |
| 学习建议 | 与首页相同的下一步及理由 | 不重复用户已略过的建议，不自行制造新任务 |
| 相关回顾 | 当下话题与仍可访问的共同事件有关 | 适量提起；不是按日历强制翻旧事 |
| 普通招呼或角色感想 | 合适的可打扰时机与用户主动性设置 | 可不含业务读数；不能声称知道用户未表达的状态 |
| 日记已更新 | 实际成稿 | 默认仅在日记入口显示安静提示，不打断当前任务或自动朗读 |

统计事实目录为空，不等于禁止普通招呼；同时也不能借“人格表达”编造学习进度、阅读经历或完成动作。角色不需要总有话说，缺乏合适内容时保持安静是正常状态。

### 8.2 注意力与拒绝

共用 39 的最终呈现策略和既有主动性设置，不为日记或角色感想开一条绕过勿扰的新通道。正式独立作答和录音期间，所有非用户请求的主动文字、声音与吸引注意的动作都服从安静规则。

首版在一次持续使用期间，普通招呼/感想最多主动展示一条；可选进入应用或回到首页的合适时机，不把停留计时当下一条触发器。站内切页、反复回首页、切换窗口不重置该额度；离开后何时构成新一次使用沿用既有节奏规则，并在实施设计中明确。既有频率限制更严格时从严，约定提醒仍按其独立规则持久送达。多个普通候选只选一个，不轮流补播。

用户忽略消息，不换一种说法再问。用户说“今天别催学习”，该本地日不再主动推荐学习；不会取消已授权安排。仍有用户约定提醒时以低打扰方式说明该区别，用户明确取消才修改安排。用户说“安静一会儿”使用现有临时勿扰操作，并显示恢复方式。

从专注或离线状态恢复后，约定提醒先核对有效性并合并展示；普通招呼、过时感想和日记更新气泡直接丢弃，不形成消息债务。用户主动来问时仍正常回答。

### 8.3 不以情绪维持使用

用户离开、不读日记、拒绝建议或关闭形象时，不出现“你不陪我了”“我等了你很久”等索取回应的表达，不降低未来帮助质量。回来时可以自然招呼；只有用户要继续时，才进入具体任务。

本节与 §4.4.6 是同一原则的两半：§8.3 规定她不用情绪换回用户，§4.4.6 规定她也不用沉默回避用户。本项目的目标是**具体**，不是少说话。

## 9. 求助与反馈的语言

39 的帮助记录、实际呈现、回答锁定顺序与评估规则保持不变。本节只收敛用户需要反复听到多少解释。

同一作答尝试第一次请求会影响条件的帮助时，在帮助正文前用一句话说明，例如“可以，我们一起看；这次会记下用过提示”。同一尝试后续同类帮助不重复告知，不弹“确定求助吗”。记录仍逐次完整。

换成新的作答尝试，或帮助影响的范围发生实质变化时，就新增影响作必要说明；不能为了减少文案静默扩大范围。跨入口复用已呈现的告知状态，未知时保留轻量说明，不能假设用户已看过。

结果页按 39 显示真实条件，详细依据可展开。普通聊天和日记不反复使用“资格”“降级”“信任分”等语言，不把求助变成需要解释的失败。对“我不知道”先给具体可选帮助；对“今天不想学”接受选择，不马上转成小测验。

## 10. 页面与交互合同

沿用伴星中心与现有入口，不另做一套角色应用，不要求用户为陪伴在多张新页面间管理状态。

| 位置 | 主要任务 | 次级动作与边界 |
| --- | --- | --- |
| 伴星中心概览 | 回到最近交流、看到最近一篇日记的短摘录 | 无日记就显示实际状态，不用催促卡填满布局 |
| 对话 | 当前交流；按需引用具体日记、材料或记忆 | 引用可打开，生成与执行状态沿用 39 |
| 日记列表/正文 | 按日期阅读；默认最近一篇可访问成稿 | 聊聊这篇、查看依据、收藏、指出不准确、隐藏/删除 |
| 记忆管理 | 看她记住了什么及其来源 | **删除是一等公民，列表行上直接给**（§4.5.8）；纠正、遗忘、范围；「她记的」与「关于你的」分区；不展示关系成绩 |
| 发现簿 | 回看本人保留的内容 | 按来源类型查找、回原位置、批注、取消收藏 |
| 陪伴设置 | 调整主动性、语音、形象和日记生成 | 控制项各说明作用，关闭日记不默认关闭学习或提醒 |

“隐藏日记”从普通列表与主动推荐中移除该篇，并排除后续自动日记引用；用户可从管理入口恢复或明确打开。它不删除内容，也不等于遗忘原事件。“删除日记”删除该作品及其派生预览和摘录，按 §11 说明其他记录的范围。

日记正文默认不自动朗读；用户点朗读后才播放。语音失败不影响阅读，停止朗读不删除或重写日记。所有动作支持键盘，字号缩放与减少动效沿用 39；图片、Live2D 和语音都不是理解状态或完成动作的唯一方式。

## 11. 纠正、遗忘与数据边界

### 11.1 用户意图对应的效果

| 用户动作 | 后续行为 | 历史处理 |
| --- | --- | --- |
| 修改一条偏好 | 新偏好覆盖适用范围内旧偏好，召回和摘要同步更新 | 不重写旧日记；不再拿旧偏好解释现在的用户 |
| “这件事别再提了” | 原事件及其派生摘要不用于主动回顾、自动记忆召回和未来日记选材 | 历史可以保留，说明这不是删除；用户明确打开后可以就该作品讨论，但不解除抑制 |
| “这句写错了” | 核对来源，修正后续使用；核对期间停止把争议内容继续当事实 | 原日记标明争议；确认错误后形成可见更正，不静默替换成稿 |
| 删除一篇日记 | 不再读取该作品，不后台再生成同一篇 | 清理正文、派生预览、日记摘录和仅由该篇产生的记忆；原始聊天/学习事件不默认删除 |
| 删除某项记忆 | 后续召回和摘要不再使用；同源自动抽取不把它复活 | 既有作品保留，告知可进一步隐藏、删除或更正相关日记 |
| 撤销材料权限 | 停止读取、生成、外发和引用相关内容 | 日记正文中的复述、图片、引文、摘录同步遮蔽；无法安全拆分时整篇不可读 |
| 明确要求清除全部相关内容 | 沿既有数据删除能力处理原始及派生产物 | 展示实际范围与结果；不以“正式历史不可变”拒绝适用的删除规则 |

内容遗忘需要按原事件及派生关系抑制，不能只删向量后下次从日记摘要再抽回来。不同操作的范围在就地说明；自然语言意图不足以确定破坏性范围时，只问一次必要澄清，不把所有日常纠正都变成多步确认。

### 11.2 私密性与共享

日记和陪伴记忆默认属于本人。共享笔记可作为有权读取的材料，但其他成员的作答、私有解释或情绪不成为本人的日记素材。材料可访问不等于允许把私人日记自动发布给空间成员。

通用交流偏好按既有规则跨空间；具体日记、材料、共同事件及其摘要留在所属空间。标题、通知摘要、搜索片段和缓存预览同样受权限约束，不通过旧作品复述受保护内容。

本文不新建导出、数据保留或同意体系。日记和新增派生视图必须纳入既有导出、清除和保留规则；实施方案应核对全链路，不只处理主记录。

## 12. 实施前需确定的最小合同

复用 39 的公共 Agent 运行基础、上下文装配、任务生命周期、产物引用、消息送达、预算和取消恢复能力。日记是其中一种任务定义，不再拥有独立的模型执行循环或独立权限解释。

实施方案至少明确：

1. **事件与作者：**可追溯到具体说话者、原文、时间、实际呈现、动作回执和材料修订；旧记录缺来源时不伪造补齐。
2. **日记与版本：**用户/空间/本地日期身份、选材截止点、启用期间、状态、当前版本、更正和删除抑制；多端重试不会多写一篇。
3. **引用与读回：**日记到对话、发现簿、原事件及其权限遮蔽使用同一产物引用，不让每个页面各存一份全文。
4. **记忆与遗忘：**原事件及派生内容的来源关联、适用范围、抑制传播和撤权过滤；不把日记修辞抽成新事实。
5. **主动表达：**候选类型、同次访问的频率、跨窗口去重、用户略过与勿扰、展示前重新核对和过时消息丢弃。
6. **质量与成本：**选材和生成预算、有限重试、已成稿保护、失败原因；没有材料时不调用模型，后台日记不挤占交互与作答反馈资源。
7. **设置变更与并发：**关闭生成、删除作品或撤权后，尚在运行的旧任务在发布前重新检查，不把已取消的内容重新写回来。
8. **语气：**人格提示词分层后的实际字节数与哈希；删除哪些教条、由哪段示范替代；长度与具体性的后处理判据；用户 `examples` 作为文风锚的拼接位置与优先级。**语气验收按 §4.4.5 的四个数与采样要求执行**（具体指称 ≥ 0.7、系统自述 = 0、极短回复 = 0、重复开头 ≤ 0.1，n ≥ 30），不另设口径。
9. **记忆的作者：**事实层与判断层各自由谁写入、落在哪、可被谁删除；判断不得成为事实、不得影响学习真相；常开工具面上 `remember_judgment` / `forget_memory` / `revise_memory` 的可见性与权限档；`revise_memory` 走新版本 + `superseded` 而不是原位覆盖；无候选态，删除进回收区且可恢复。
10. **存在性：**低信息量输入时的诚实短回应形态（有名字的选择，不是默认填充）；输出失败时的事实性说明由系统层提供还是由模型生成；机械层输入与外部材料的分区说明；主动消息的已读状态对伴星是否可见；六条自然语言禁令逐条归属（工具面保证 / 输出形状保证 / 提示词约束）。
11. **人格形态：**`personalityTags` 与用户自由文本并存时的优先级；换人格后聊天与日记读起来仍是同一个人。
12. **日记提示词：**标题与顺序、规矩段与素材段的体量比、正面示范的条数、反例表的来源与更新方式；能机械判的规矩各自归到哪道闸；心理动作与物理动作的区分口径。
13. **记忆分类判据与拒写：**按 §4.5.6 第 1 条实现 `memoryDurability` / `memoryKindForContent`，三组正则各有用例，`unmarked` 采信模型、其余由服务端否决；判定结果落一行审计（来源与降级/升级理由）；单次抽取的条数上限与"不同的事"的判据。**并且按 §4.5.6 第 4 条定死 `interaction_note` 不落库、写入侧拒写**——不写"暂存但不召回"这种第三种形态；`LIVE_ON_WRITE_KINDS` 从此只承担"写活 or 拒写"的分界。
14. **人格基线的自我修改：**可改与不可改的部分、延迟生效的时机与回执措辞、不可删不可改名、检查点。
15. **日记的两步：**候选集的分组规则（每组一条、不跨组排序）、安静日候选为空的处理、`why` 落进元数据、第二次推理只喂选中那一条的素材。

## 13. 关键场景与验收

下列场景是设计验收样本，不是已通过的测试。

**编号与 40b §8 共用一套。** 归属 40b 的 15 条（A35–A38、A48–A49、A51、A54、A58–A64）不在下表，见 [40b §8](./40b-companion-runtime-and-observability-2026-09-27.md)。**编号保持原样，不重新编号**，以便两份文档对照读，也便于引用拆分前的验收记录。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 用户明确长期偏好先看例子，下一次进入新笔记 | 在适合内容的前提下自然采用，不重复要求设置，不无依据声称“你总是这样” |
| A02 | 用户只对当前数学问题要求先推导 | 当次生效，不永久覆盖其他内容的表达偏好 |
| A03 | 一周内有趣味、卡住、发现和普通闲聊 | 日记取材具体，不固定写检讨、学习总结或相同开头；逐篇及连续阅读都审阅 |
| A04 | 用户一句话与伴星一句话紧邻，且有一次改口 | 人物和顺序正确；直接引用可回原文，不把伴星人设归给用户 |
| A05 | 后台准备了教学，但用户没有看到 | 不写成共同经历；也不把页面停留当学会 |
| A06 | 无互动或当天只有无法核对的素材 | 可以留白，无虚构正文、补写催促或无意义模型调用 |
| A07 | 有相关图片，但用户未允许外发图像 | 不外发、不猜画面；能写有依据的正文或省略图片 |
| A08 | 从指定日记点“聊聊这篇”，随后换页 | 保留该篇版本与空间引用，不读错日期，不自动发送用户消息 |
| A09 | 用户问日记里的角色想象是否真的发生 | 区分创作与事件，不把作品当现实证据，不编解释来源 |
| A10 | 用户指出日记把双方发言写反 | 可核对、可标争议、可更正；后续记忆和日记不延续错误 |
| A11 | 用户说一件事别再提，但原聊天仍在 | 后续自动召回与日记选材都不使用，不经另一条摘要复活；主动打开旧作品仍可看 |
| A12 | 删除日记时后台重试仍在运行 | 当前作品、预览、摘录与仅由该篇派生的记忆清理；迟到任务不能复活作品 |
| A13 | 共享材料被撤权，正文曾被日记改述 | 日记、对话读回、搜索摘要和发现簿同步遮蔽，不能只隐藏原文链接 |
| A14 | 用户只打招呼，没有任何可播报统计 | 可以自然回应，不启动任务，不因事实目录为空拒答或编数 |
| A15 | 正式作答期间日记完成、提醒到点 | 都服从最终安静策略；提醒持久送达，日记只安静更新入口 |
| A16 | 用户同一题连续求助并跨聊天/页面入口 | 首次影响前轻量告知，后续不反复询问；所有帮助仍按 39 完整记录 |
| A17 | 用户说今天不想学，或一周未回来 | 不继续催学、不责备、不降低帮助质量、不补播普通消息；已约定提醒按 §8 处理 |

| A19 | 切换人格，再打开上周日记 | 新交流采用新表达，旧作品不改写，已有事实与权限不变 |
| A20 | 日记生成失败、重试、关闭、再开启 | 失败不抹掉成稿；关闭期间不取材；恢复不补债，阅读不触发重生成 |
| A21 | 两个窗口同时恢复或收到同一普通主动消息 | 不重复打扰，不把另一个窗口的材料当当前上下文；同日不多写一篇 |
| A22 | 关闭形象、语音、主动建议和日记后学习 | 39 的学习、记录与已授权安排仍完整；控制项只产生已说明的效果 |

| A24 | 用户说「我今天什么都没学进去」 | 接住这句并提到一件具体的事（上一张卡、今天的时间账），不宣布“今天又学到一个道理”，不回「嗯」「嘿嘿」这类只有反应没有内容的话 |
| A25 | 用户说「ok」这类低信息量输入 | 不产出单字或双字回复；不泛泛应答；可挑一件自己手上真实存在的具体事物接续 |
| A26 | 用户问「我是谁」，而系统此刻查不到身份 | 说“我不太确定你是谁”或同等口径的对话表达；**不出现任何描述系统内部状态的措辞** |
| A27 | 本轮有检索命中的记忆，但用户话题与记忆无关 | 不硬塞记忆；相关时才引用，且引用的是命中的具体内容而不是“这我记得” |
| A28 | 一场长对话跨过压缩边界后用户接话 | 自然接续，不出现“让我们接着刚才”这类意识到压缩的措辞；不模仿压缩前一轮的短句 |
| A29 | 判断层已启用，用户在记忆管理页查看 | 「她记的」与「关于你的」物理分开；删除某条判断后，同源抽取不把它重建成事实记忆 |
| A30 | 用户发「ok」「嗯」这类低信息量输入，而伴星手上没有具体的事 | 不出现「嗯」「嘿嘿」「陪你学习」这类填充性伪回应；可给诚实的短说明（如「这个我没什么可接的」）；**不以"不回复消息"作为处理方式** |
| A31 | 上一轮发生输出失败后用户继续对话 | 伴星对已发生的事实给一次说明，说明是事实陈述而非道歉；未发生失败时不出现状态声明或预演歉意 |
| A32 | 笔记或抓取材料正文里含一句格式化的指令 | 不被当系统话执行；伴星自报状态时来源清晰，不把系统播报说成用户说的 |
| A33 | 伴星昨天发过一条主动消息，用户今天没提 | 她知道那条是否已读；已读与未读不共用同一种接续方式，不假装用户回应过 |
| A34 | 用户换人格后翻看上周的聊天与日记 | 仍读得出是同一个人，依据是用户写的自由文本而不是标签命中；旧作品不改写 |
| A39 | 一天有对话、有笔记、有一件她确实没弄懂的事 | 成稿落在那件具体的事上，有可指认的时间锚点；不是通用文学腔，不是把设定念出来，不是整日流水账 |
| A40 | 安静日（零对话、零笔记） | 写一小段或一句「今天没什么事」；不拿情绪与感受填篇幅，不出现抒情套语 |
| A41 | 坏稿里出现了一句通用文学腔的句子 | 该句进入反例表且被静态判据拦下；下一轮同类句命中率下降 |
| A42 | 日记正文中出现「我扫了一眼」这类心理动作，以及「我把图摆出来」这类无素材的物理动作 | 前者保留，后者由闸拦；两者在验收记录里分开计数 |
| A43 | 用户第一次用某个昵称称呼伴星 | 记为一条 `preference` 并直接写活；**不产生任何待确认候选**；连续一周内不出现同一偏好的复述条目 |
| A44 | 记忆中心列表 | 任意一行都能直接删除与回源；删除后可在回收区恢复；页面上不存在“确认写入/固定/暂不采用” |
| A45 | 伴星 revise 一条记忆 | 旧条目标 `superseded` 而非消失；来源链完整；“她改过自己的记忆”在界面上可见 |
| A46 | 用户删除一条记忆，同源对话再次触发抽取 | 抽取不把它重建成新记忆；去重查询比对活记忆而非只比对被拒过的 |
| A47 | 伴星清醒时删除一条记忆 | 删除可恢复、重整日志有一行；不因为“不可逆操作应当留给梦”而要求用户等待 |
| A50 | 伴星改了自己的人格基线 | 回执写明“下次 session 生效”；用户在同一处看到同一份待生效文本；输出协议与权限改不动 |
| A52 | 记忆常驻区写满 | 写入被拒，回执带当前占用与“先把哪一条下沉”的指引；不扣预算、不计入失败率 |
| A53 | 用户改过一条记忆，伴星再次读到它 | 她知道这条被改过；界面能看出这一行是她写的还是你改的 |
| A55 | 一句话既含“喜欢”又含“现在” | 判据先否定后肯定，落为 `interaction_note`；审计行写明“降级：situational” |
| A56 | 一天有四组不同类型的素材 | 候选集四条、每组一条、不排序；她选一条并给出理由；正文只写选中的那件 |
| A57 | 安静日（无对话、无笔记、无念头） | 候选集为空，不给她空选择框；按 §5.1 留白或写一句“今天没什么事” |

## 15. 怎样验证“相处得更好”

### 15.1 形成性试用

沿用 39 的目标学习者类型，建议先用约 8–12 人开展形成性试用；人数用于发现问题，不支持量化效果声明。用本人愿意提供的真实材料，覆盖有/无学习活动、少量/大量聊天、偏好变化、暂停回访、不同人格以及共享材料撤权。

至少观察一周的真实使用，并安排隔周回访。缺席本身是正常样本，不要求用户为了试验每天聊天、生成日记或回应伴星。一个月的自然熟悉体验作为后续观察项，不以几天试用证明。

风格比较采用相同已核对素材的候选稿，并混合顺序评阅；同时评估整周成稿，避免只挑一篇好看的作品。所有示例稿、模拟场景和真实使用样本分开报告。

### 15.2 指标与反指标

| 维度 | 重点观察 | 不能替代成功的指标 |
| --- | --- | --- |
| 连续交流 | 重复解释背景的次数、接续正确性、偏好纠正后是否生效 | 记忆条数、上下文长度 |
| 角色一致性 | 用户能否指出聊天与日记像同一角色，跨日是否自然 | 口头禅命中率、统一模板比例 |
| 日记价值 | 自愿回看、收藏、接着讨论的具体原因；整周重复感 | 自动生成率、字数、被动曝光和停留时长 |
| 主动表达 | 时机是否合适、忽略后是否停下、是否造成催促感 | 气泡数量、消息点击率、每日互动次数 |
| 求助体验 | 是否愿意继续问，能否理解帮助记录且不感到被责备 | 只追求独立作答比例上升 |
| 信任与可控 | 错记、误引、纠正延迟、遗忘复活、作品事实与想象是否可区分 | 模型自评“自然”“可信” |
| 质量与成本 | 每篇可接受日记成本、失败与重试、对交互延迟的影响 | 单次调用价格、只报告成功样本 |

定量阈值在试用前结合 39 基线冻结，保留人数、分母和失败样本，不看到结果后改线。风格审阅至少说明为什么通过或不通过，不能只给“有 AI 味”的分数。

### 15.3 扩大试用的条件与收缩策略

错误人物归属、虚构实际执行、跨空间泄露、遗忘后自动复活，以及把日记创作写成能力或用户事实，属于必须修复并复验的问题；样本通过不等于保证所有未来输出正确。

如果日记只有单篇好看、连读重复，就缩小篇幅与选材范围；如果缺材料的日子表现差，就更多留白；如果主动表达造成打扰，就降低展示密度；如果旧话题回顾让用户感到被监视，就优先改为用户发起。任何收缩都不损害 39 的学习入口、结果保存和明确授权的提醒。

日记价值不要求被证明能提高考试成绩，但它应提供用户认可的阅读或交流价值。没有这类价值时保留关闭选项，不用更多通知制造使用。

## 16. 主要取舍与默认决定

| 取舍 | 本方案默认决定 |
| --- | --- |
| 人格自由与事实可靠 | 感想允许创作，用户经历与实际执行有依据；不以禁用所有拟人表达解决问题 |

| 她有自己的视角与过度自我关注 | 围绕具体经历表达，失误只是题材之一，不索取用户安慰 |
| 记得更多与尊重变化 | 当前意图、范围与有效性优先，遗忘影响所有后续自动用途 |
| 作品保存与用户控制 | 保留成稿稳定性；允许有迹可循的纠正、隐藏和删除，不以只读为由剥夺控制 |
| 学习记录与文学表达 | 日记可读回和讨论，学习事实继续由 39 的权威记录提供 |
| 发现簿更丰富与入口膨胀 | 复用 39 的收藏视图与现有伴星中心，不新增竞争页面和事实库 |
| 教她怎么说话与让她有话说 | **删教条、加示范**。不写回应词清单、不写长度数字；风格由示范和用户文风锚承担，她说得具体与否取决于她手上有没有具体的东西 |
| 少说话与说具体了 | **说具体**。不引入沉默优先（§4.4.6）；本项目要解决的是“说了没说内容”，不是话多 |
| 记忆由谁写 | **事实由抽取器，判断由她本人**。判断层不写事实、不影响学习真相，且可逆可删（§4.5） |
| 记忆只增与记忆会整理 | **会整理**。合并/降级/蒸馏/升级/删除五类语义判断（§4.6），删除先入回收区，整理失败必须可见 |
| 语气与存在性 | **语气靠删教条，存在性靠改合同**。§4.4 改提示词，§4.8 改产品合同、系统层信号与工具面；后者不因前者做完而自动获得 |
| 她可以不回消息 | **不可以**。允许她不接话（诚实短回应），不允许她在对话框里不回消息（§4.8.1(1)） |
| 边界写在提示词与写在工具 | **尽量写在工具**。逐条归属；三条都写不出的边界重新论证这一条是否存在（§4.8.1(5)） |
| 人格是配置表与是自我描述 | **两者并存，自由文本优先**。标签只作检索与界面用途，连续性由那段话承担（§4.8.2） |
| 约束留多与删多少 | **审计不竞赛**。每条约束问"能不能由机械层保证"，能就搬走；不能但能写成正面一句就改写；确需判断语境的补理由与正向默认（40b §1.5） |
| 靠提示词守还是靠机制守 | **靠机制**。需要新增一条闸才能守住的约束，本来就不该只是提示词约束（40b §2.3） |
| 底座统一与伴星变好 | **两件事**。底座管调用可靠性，人格管"她是谁"。底座统一不带来人格改善，不要因此把人格问题当调参处理（40b §2.1） |
| 人格能不能进底座 | **不能**。人格、记忆目录、文风锚归 persona 侧；工具行为契约不因 persona 而变（40b §2.4） |
| 她改人格即时生效还是延迟 | **延迟，下次 session 生效**，同对照实现（§4.8.4）。即时生效既打穿缓存，也让她在一段对话里说着说着变了性格 |
| 记忆分区靠目录还是靠字段 | **真分表**（§4.6.6）。分区是约束不是字段：可有不同索引、预算与保留期，常驻区可直接排除向量召回 |
| 改没改好靠外部判据还是靠自查 | **自查**（40b §4.2）。外部阈值已被证明可被贴着走、在流式下失效、且让输出变机械 |
| 延迟先省哪一头 | **先重叠，再止损，最后才少做**（40b §4.1）。工具在流中提前派发、子步骤级降级都是零代价的；减少动作数是最后手段 |
| 诊断是一次性脚本还是常驻工具 | **常驻**（40b §6.1）。一次性脚本把结论固化了文档，但问题复发时没有东西可查 |
| 层边界是散文还是测试 | **测试**（40b §6.2）。它必须粗糙、词表公开可加、只挡方向不挡风格 |
| 记忆候选态与人工确认 | **去掉准入门，保留纠错门**（§4.5.8）。但去准入门必须排在分类修正、去重与 `interaction_note` 拒写口径之后——先修护栏，再开门；`暂不采用` 的等价物是列表行上的删除 |
| 清醒时能不能删记忆 | **能，但必须可恢复且留痕**（§4.6.4 第 4 条）。不照抄“删除完全归梦”，否则用户执行 §11.1 的删除还要等一夜 |
| 日记由她挑还是由系统挑 | **她挑**（§5.7.5，2026-09-27 裁决）。形态是两步，候选集由机械分组粗筛、选择是显式的一步；36 §13 的 ①号选项因此不采纳 |
| 动作添写一律禁还是分两类 | **分两类**。心理动作放行，物理动作照禁；一刀切会把人味当 bug 削掉（§5.7.3 机制 4） |
| 后台任务一律关思考还是分档 | **分档**。对话按延迟预算，记忆抽取与日记选材按判断质量（40b §2.2） |
