# 40 · 伴星长期陪伴与日记产品设计

> 日期：2026-09-25；修订：2026-09-30。本文定义目标体验与待实施合同，不表示功能已实现或质量已验证。
>
> 范围：伴星人格、跨日交流、记忆写入/纠正/遗忘/整理、日记与主动表达。运行时、失败表达、提示词装配与诊断见 [40b](./40b-companion-runtime-and-observability-2026-09-27.md)。
>
> 核心主张：熟悉体现在回应更合适、背景接续更准确和尊重用户变化；日记留下她眼中的一件小事。用户可以自然回来，也可以安心离开。
>
> 设计方法：权限、来源、版本、预算和回执由代码保证；相关性、表达与解释属于语义判断。不能用关键词、字数或字符串重合率代替语义质量，也不能把模型自评当成事实。

## 1. 用户价值与范围

### 1.1 本方案解决的四个问题

1. **她知道怎么跟我交流吗？** 用户不必每次重复表达习惯，又能改变偏好，不被旧印象限制。
2. **隔几天回来还能接上吗？** 能接续明确的共同话题，也能接受用户今天不想继续。
3. **我为什么想读她的日记？** 日记能看出她的声音与视角，有具体可读的小事，不重复学习结果页。
4. **我能控制她怎样记住和提起我吗？** 用户能够核对、纠正、遗忘，关闭主动表达或日记，不影响学习主功能。

### 1.2 成功体验

相处一段时间后，用户能指出她在交流方式上的具体变化，例如先给自己喜欢的对照例子、少问已经回答过的背景、记得一段共同讨论过的趣事。用户可以随时纠正，她会在后续行为中体现变化。

日记中偶尔有用户愿意回看或接着聊的片段。用户不读、不回复、暂停或离开，都不产生欠账、关系惩罚或必须安慰伴星的义务。

上述是待验证的产品目标，不宣称已能提高留存、学习效果或情感依附。

### 1.3 本次不扩展的范围

沿用暖纸书房、窗口内 Live2D、已有文字和语音能力。不增加关系等级、好感度、连续签到、付费亲密解锁、稀缺道具、角色生存需求、自由漫游、场景级 3D、离线自主生活模拟或心理诊断功能。角色语气可以亲切、有趣、有偏好，不通过失落、责备或排他表达要求用户回来。

### 1.4 参考实现的适用边界

Cortico 是事件流框架，不规定唯一人格或记忆方案。Cormini、CortiSoulmate 与 CortiV 的默认行为不同；不能把其中一种 Bot 的选择概括为整个项目的产品要求。

| 参考机制 | 本方案的取舍 |
| --- | --- |
| 本地文件记忆与常驻/active/归档 | 采用预算与渐进读取，存储沿用数据库；逻辑分层不要求三张物理表 |
| `note/playbook` 行动手册 | 在 Procedural 层定义有来源、适用条件与版本的表达/协作手册；不能授予业务权限 |
| 梦继承不可变会话快照并串行执行 | 采用后台整理与一次性结论返回；用 `(workspace_id, user_id)` 租约及版本校验替代单进程 Promise 队列 |
| 沉默与多频道投递 | 主动候选可以放弃；用户主动对话必须有答复或明确失败状态，允许简短确认和收尾 |
| 可改人格与部署覆盖 | 用户人格跟账号，私人记忆留在空间；编辑范围不包含协议、安全、权限或学习事实 |
| association / rumination / proposals | 所检查源码中尚无对应实现，不能按 README 声称规划成已可复用能力 |

本方案不增加多频道 World 平台、离线自主生活模拟或新的关系等级。既有念头与提案能力按本项目调用图核对，不宣称与 Cortico 未实现模块等价。

## 2. 四类内容各自承担什么

| 内容 | 用户要回答的问题 | 来源与表达 | 可以影响什么 |
| --- | --- | --- | --- |
| 学习记录 | 当时学了什么、怎么回答、得到什么帮助？ | 权威领域事件、原始回答、评估和回执，按事实展示 | 按 PRODUCT、41 与独立业务合同影响建议和已授权安排 |
| 伴星记忆 | 她记住了关于我的什么？ | 有来源和适用范围的偏好、用户自述、共同事件与任务上下文 | 选择表达方式、减少重复询问、恢复相关话题 |
| 伴星日记 | 她怎样看待一段经历？ | 可访问的真实片段，加上她当下的主观感想与角色想象 | 供阅读和讨论；不产生用户能力、偏好或业务执行事实 |
| 发现簿 | 哪些理解、疑问和时刻是我想留下的？ | 本人可访问的学习记录与本人收藏，保留原文、来源和时间 | 帮助回看与定位；不独立判分或安排复习 |

同一次经历可以出现在不同视图中，但保留各自视角。例如，学习记录显示一次解释与回答；发现簿收藏用户认可的一句话；日记写她当时为何选了那个例子。它们引用同一来源，不复制成几份互相漂移的事实。

日记不是发现簿的更名。用户收藏日记段落时，发现簿标为“伴星日记摘录”，不能呈现为本人原话或理解成果，也不自动进入教学、制卡或评分依据。

## 3. 从第一次交流到一个月后的连续体验

下表是设计演练，不是发生过的用户数据。每个日期只表示观察点，不要求用户每日使用，也不按日期解锁能力。

| 时点与情境 | 伴星应有行为 | 用户可感知的变化 |
| --- | --- | --- |
| 第一次，用户说“以后讲机制先举例，别先讲一堆定义” | 本次立即采用，并按既有记忆规则处理明确的长期偏好，不弹出一串设置问题 | 这次反馈当场有用 |
| 第二次，再学另一篇适合举例的笔记 | 自然先给例子；无需每次强调“根据我的记忆” | 不必重新教她怎么说话 |
| 第三天，用户纠正“数学这里我想先看推导” | 当前请求优先；若只是本题，不覆盖全局偏好 | 熟悉没有变成固执 |
| 第四天，用户问前一篇日记“你为什么这么写” | 读取指定日记与仍有权限的相关片段，区分原事实和当时的感想 | 日记是可以继续谈的话题 |
| 第五天，用户说“今天不想学” | 接受当次意愿；可按用户话题闲聊或安静，不立即换一种方式推荐学习 | 陪伴不要求完成任务 |
| 第六、七天没有使用 | 不编造共同经历，不发等待和受冷落的消息，不补日记作业 | 离开没有代价 |
| 隔周回来，用户说“继续上次那个问题” | 定位有来源的具体话题与任务版本；有歧义才给少量候选，不先补播过去所有提醒 | 可以自然接回来 |
| 一个月后，表达习惯改变 | 当前明确偏好优先，相关旧记忆可更正或失效；不称用户退步或变冷淡 | 她尊重现在的用户 |

关系连续性体现在正确使用共同背景、稳定的声音和尊重变化，不建立隐藏的关系分数来控制功能、热情或可获得的帮助。

## 4. 人格、熟悉与记忆如何共同工作

### 4.1 一个角色，多种场合

聊天、日记、语音和主动消息共享稳定的语言习惯、幽默分寸和角色偏好，但表达结构按场合变化。日记不照搬聊天的反问收尾；操作失败不硬加笑话；用户沮丧时先回应具体困境，不强制保持活泼。

角色可以有自己的感想和不同意见，不能为了讨好用户改变材料事实或评估结果。轻松语气不得把用户的错误、休息、求助或遗忘作为贬低对象。

切换人格只影响此后的呈现，不重写历史日记或聊天，也不清除用户记忆。旧日记保留当时的声音；用户问起时可以说明那是当时的写法。任务能力和权限不因人格不同而变化。

### 4.2 熟悉如何表现

优先表现为少问重复问题、选用适合的解释形式、正确接续旧话题。仅在与当前话题有关时提起共同经历，不为了证明“我记得你”随机展示隐私或复述个人细节。

没有足够记录时自然回应，不虚构“你一直喜欢”“我们每次都这样”。一次行为只能支持一次观察；跨次偏好仍按明确来源与有效性使用，不从时长、点击或正确率推断性格、情绪和关系程度。

### 4.3 记忆适用的优先顺序

用户当前明确要求优先于适用的长期偏好；长期偏好优先于角色默认表达。本次临时要求默认只作用于当前话题，不能据此覆盖长期偏好。长期记录需要用户明确表达持续意图，或按 §4.5/§4.6 核对独立证据、适用条件与不确定性，不能从一次行为直接升级。

| 类型 | 使用方式 | 失效与纠正 |
| --- | --- | --- |
| 沟通偏好 | 仅稳定且不绑定具体材料的偏好可按账号跨空间；本地偏好留在空间 | 用户明确修改后，后续召回和摘要同步更新 |
| 临时状态 | 只在当前会话或明确时间范围内使用，例如“今天很累” | 不自动变成长期标签或数周后的招呼依据 |
| 共同经历 | 只引用有来源、仍可访问且与话题相关的事件 | 被纠正、删除或要求不再提起后，按 §11 处理 |
| 任务上下文 | 绑定现役任务、目标、笔记版本与精确选区 | 内容与权限变化按领域合同重新核对，不能从旧记忆恢复已撤销授权 |
| 角色创作 | 保存在当时的日记/对话产物中，可作为该产物被阅读 | 不抽取成用户事实，不把想象当成新增现实经历 |

用户问“你为什么记得这个”时能看到适用的来源和纠正入口。来源不可访问时如实说明，不通过解释记忆来源泄露被撤权材料。

### 4.4 语气：回应当前意图

#### 4.4.1 证据与假设

归档 29 曾记录“喵”“嘿嘿”等未回答问题的回复，这证明当时有回应不足，不能证明所有短回复都无效，或确定某条提示词导致了问题。回应词清单、过窄的长度要求、单一教学示范、输入不足与模型配置都是待验证因素。

当前 `companion-context-orchestrator.ts` 的召回 `topK` 为 8，正文受 1000 字符预算限制；`MEMORY_REF_MAX = 3` 限制返回界面的引用展示，不等于模型只能读取三条。当前登记的 `companion_recall_memory` 可继续召回未注入的记忆，优先复用它。

Cortico 证明的是机制可以有不同形态。Cormini 的私有 FIRST_TURN 示范不是默认启用的公共示例，也没有可比较的真实对话样本；不能推断“删掉禁令”“换第一人称”必然改善输出。

#### 4.4.2 提示词与检查的分工

| 项目 | 处理 |
| --- | --- |
| 回应词清单、统一 50 字要求 | 移除固定词表与所有场景共用的长度要求；按用户问题给足内容，通道大小和调用预算仍由代码控制 |
| 示例 | 同时覆盖解释、闲聊、相关记忆、拒绝学习与自然收尾，避免每段都教模型追问或展示记忆 |
| 记忆引用 | 只在与当前意图有关时采用；有召回结果不构成必须引用的义务 |
| 失败与不确定 | 区分“目前不认识/记录不足”和“这次读取暂时失败”；给真实、易懂的说明，不暴露凭据、内部 ID 或原始异常 |
| 输出检查 | 校验结构、明确泄露标记、通道限制与真实截断；短句、无问句、未提记忆不单独触发重跑 |
| 文风锚 | 用户账号级自由文本与 `examples` 只覆盖可编辑表达层，优先于默认风格；不覆盖固定协议、权限和当前用户要求 |

自然度的指标用于发现问题，不充当自动重跑门槛。最长公共子串、开头重复、字数等只作诊断；两字重合不证明正确记忆，改述不重合也不证明回应失败。

#### 4.4.3 身份与认知说明

在固定协议与可编辑风格之间提供短的身份说明：

```
你的声音与记录可以延续，但记录可能出错或过时。
区分真实事件、用户自述、你的推测和作品中的想象。
相关时查阅共同背景，用户此刻的要求与纠正优先。
动作是否完成以业务回执为准；没有记录时不假称记得。
```

这段说明是产品事实边界，不由账号风格替换。字节数、第一人称和哈希只能标识版本，不能证明人格连续性。失败信号由 40b §3 提供。

#### 4.4.4 示例的正确形态

以下都是设计示例；带背景的示例只有在该背景真实存在且仍可访问时才成立。

| 输入与背景 | 可接受回应 |
| --- | --- |
| “我今天什么都没学进去。” | “听起来今天挺费劲的。想说说卡在哪，还是换个话题？”用户明确不想学时直接接受，不再追问学习 |
| “今天不想学，聊点别的。” | “好。今天有什么想吐槽的？”也可以接用户已经提起的话题 |
| “这个概念看三遍都记不住。”；历史明确记录用户用反例理解过同类概念 | “上次那个反例帮你分清了条件，这次也可以试试。要我找一个吗？”没有这条记录就不编旧经历 |
| “ok”，前文事项已结束 | “好。”允许到此收尾，不用番茄数或旧卡片开启新话题 |
| “我是谁？”；本次身份读取失败 | “这次没能查到你的资料，暂时没法确认。”记录本就为空时才说现有记录不足 |

#### 4.4.5 验收与评估

使用同一批已核对输入对比改动前后，至少 30 轮覆盖提问、解释、拒绝、情绪自述、收尾、相关/无关记忆及读取失败；报告模型、配置、提示词版本与样本量。

人工按“回应当前意图、记忆相关且有据、尊重拒绝、内容足够、声音一致”评阅，记录失败案例和理由。虚构共同事件、越权执行与泄露需要修复复验；短回复本身不判失败。并列记录端到端等待、首个有效可见反馈、成本与重试率，不把首句长度或问句比例当质量成绩。

#### 4.4.6 主动安静与交互答复

普通主动候选没有合适内容可以不发。用户主动对话则给答复、简短确认或确定性的失败状态；无需说“我没什么可接的”解释一次自然收尾。空输出与传输失败不能伪装成她选择安静。

### 4.5 记忆的作者与准入

#### 4.5.1 现状与目标

现役抽取器通过 `LIVE_ON_WRITE_KINDS` 让 `preference`、`goal`、`learning_context` 直接生效，其余类型仍走候选。当前形态不等于目标合同。目标是自动保存符合来源、范围与风险条件的记录，让用户能够查看、纠正和删除，日常相处无需逐条确认。

旧版文档提出“只要不在该集合内就拒写”，会连真实共同事件一起丢掉。本方案将准入、语义种类、期限和可见范围分开，不把 kind 集合扩成所有存储的唯一分界。

#### 4.5.2 用途分层与存储维度

Core Profile、Semantic、Episodic、Working、Procedural 是用途；resident、active、archived 是读取预算层；账号/空间/任务是作用范围。三者分别记录，不互相替代，也不必各建一张表。

| 用途 | 可以保存什么 | 使用与期限 |
| --- | --- | --- |
| Core Profile / Semantic | 用户明确的长期表达偏好，或有独立证据的稳定模式 | 当前明确纠正优先；只有不绑定具体科目、任务或材料的偏好允许跨空间 |
| Episodic | 有事件 ID、时间、参与者及原文依据的共同经历 | 留在原空间；相关才引用，受删除、抑制与保留规则约束 |
| Working | 当前话题、用户明确自述的一时状态、未完成的任务线索 | 限当前会话、约定时间或任务版本，必须有失效条件；“今天很累”最多用于当前本地日，不变成长久标签 |
| Procedural | 有适用条件的表达/协作手册，例如“先用反例，再解释定义” | 按 §4.6.10 读取和版本管理，不代替业务规则或授权 |
| 判断记录 | 她对已发生片段的解释、表达选择与待核对线索 | 按 `(workspace_id, user_id)` 私有隔离；始终标主观，不自动变成用户事实 |

无法确定长期适用性的内容只用于当前上下文，或有明确期限的本地 Working；来源不足、敏感推断、超出材料权限或用户已抑制的内容拒写。不能为了保守拒写而把被拒正文另外存成永久审计。

#### 4.5.3 分类：语义、时间、范围分别判断

抽取输出需包含来源片段 ID、说话者、语义种类、明确/推断、适用条件、时间范围及空间绑定。服务端确定性核对身份、原文存在性、版本、期限、权限与抑制，必要时否决跨空间携带；语义判断依据整句和上下文，不能用“喜欢/希望/累/现在”几个词强制升级或降级。

| 原句 | 正确处理 |
| --- | --- |
| “这一次希望先看例子。” | 本次表达要求，Working；不覆盖长期偏好 |
| “我希望下周完成数据库索引复习。” | 有时间范围的本地 goal，不因为“希望”变成 preference |
| “以后我累的时候别催学习。” | 明确长期沟通偏好，条件是“累的时候”；不因为含情绪词而拒写 |
| “今天喜欢这个例子。” | 一次反馈；不能据此提炼长期喜好，可作为有来源的当次事件 |
| 第一次只喊了一声昵称 | 本轮沿用即可；明确“以后叫你 X”才支持持续称呼记录 |
| “今天很累。” | 有期限的用户自述，不推导焦虑、依赖或人格特征 |

无明确长期信号时不因模型选择了 `preference` 就直接采信；结合来源判断，拿不准保持本地、短期或不保存。拒写工具回执给模型原因；自动抽取不保存每句无价值闲聊无需逐轮打断用户。用户明确要求记住而未保存时，应就地说明原因。

#### 4.5.4 两类作者都可能出错

事实记忆由抽取任务从原始事件提出；判断由对话模型或后台整理提出。前者仍可能记反说话者，后者仍可能误解用户。工具成功只证明“这条记录被保存”，不能证明其内容真实。

判断记录至少有 `author`、`source_event_ids`、`source_type`、`created_at`、`epistemic_status`、适用范围与修订号。来源性质区分用户自述、可观察事件和模型推断；认识状态另标有据、暂定、争议或已被替代，不能因“用户说过”就证明内容真实。保留证据和不确定性，只保存可供未来使用的简短结论，不索取、保存或展示模型隐藏思维链。学习掌握度、复习调度与材料事实由权威领域服务提供。

#### 4.5.5 判断写入的形态

`remember_judgment` 用于当轮记下一个可见事件上的解释或表达选择，后台整理也可对快照提出新解释，不能假称复原了当时未记录的内心过程。不要求每轮调用，不以调用率证明主体性。

建议参数为 `text`、`source_event_ids`、适用范围与认识状态，单条 ≤200 字。无来源的用户判断不能写成长期记录；来源来自私人会话，权限与 AI 同意按本人核对。模型不通过判断接口绕过事实记忆的准入、期限或跨空间限制。

#### 4.5.6 去准入门前的护栏

1. **分类与来源先正确。** 使用 §4.5.3 的对照样本，覆盖否定、条件、引用、改口和本地指代；失败案例修复后再开放自动保存。
2. **去重覆盖有效记忆和抑制记录。** 同一来源、同一事实保持稳定身份；语义近似只提示待比较，不能把相似但相反的偏好合并。写新证据可追加来源，不增同义行。
3. **单次抽取按独立事实限额。** 默认最多一条；确有互不重复的事实可在任务预算内增加。不上“每次必须记一条”的最低配额。
4. **期限与风险单独处理。** 真实 episodic 和有期限的 Working 可以保存，敏感推断与无法核对的状态不能长期生效。
5. **并发与遗忘先接通。** 提交前复查租约、来源版本、权限、抑制和记忆修订号；删除后迟到任务不能复活。

移除日常“确认写入/暂不采用”的候选流程，不移除用户手动新增、纠正、删除、恢复、归档与可选“固定”重要条目的控制。“固定”表达重要性，不能绕过有效期、事实检查、权限或预算。

#### 4.5.7 工具、版本与回执

| 工具能力 | 合同 |
| --- | --- |
| `remember_judgment` | 保存有来源且标主观的记录，不改变学习事实 |
| `revise_memory` | 新版本 + 旧版本 `superseded`；带 expected revision，原始来源不改写 |
| `forget_memory` | 即时停止未来使用，写删除/抑制记录；普通删除进回收区，明确彻底清除按 §11 的实际范围执行 |
| `move_memory` | 在预算层间原子移动，保留 ID、来源与版本；目标超额拒绝，无半移状态 |
| `companion_recall_memory` | 复用现有登记的追加召回能力，按权限、期限、抑制与去重过滤 |

这些是能力合同，不要求照名重建已有服务。工具按现役任务注册与权限开放，“常开”不等于所有场景均可见或可执行。回执区分 written / revised / moved / no_change / conflict / not_found / refused / outcome_unknown，并返回安全原因、当前版本与下一步。不能靠一句“成功”让模型推断整个动作完成。

#### 4.5.8 用户控制与私密性

“关于你的”和“她的看法”在记忆管理中明确区分，查看时能展开来源、期限、范围与版本；删除入口直接可用。临时记录可按状态筛选，不隐藏成一个只有系统知道的永久数据库。

私有记忆按 `(workspace_id, user_id)` 隔离。协作空间 Member 对共享材料只读，不妨碍其管理自己的陪伴记忆与日记；Owner 也不能读取其他成员判断正文。账号可携带偏好严格服从 PRODUCT 的两道空间绑定检查。

#### 4.5.9 验收

分别报告错误长期化、正确短期保存、真实共同事件保存、同义重复、相反内容误合并、跨空间误带与遗忘复活。分母为抽取尝试及各类样本数，不能只数已落库行；审计以 ID、分类结果和安全理由为主。判断工具调用率仅作诊断，无目标比例。

#### 4.5.10 一次性结论返回

借鉴 Cortico 的 `surface`：一次后台整理至多返回一段简短结论，没有值得返回的内容可以为空。结论作为带来源和认识状态的后台产物进入后续上下文，不自动成为对外消息，不当用户新事实，也不要求用户读或回复。

### 4.6 记忆的整理、容量与手册

#### 4.6.1 现状与目标

当前数据库维护做超期归档与衰减，不能证明已有语义整理。新增整理复用任务/租约和现役记忆服务，在权限内合并复述、解决过期解释与降低检索噪声。

#### 4.6.2 两条整理路径

交接快照后的轻量整理处理刚结束的片段；周期重整处理跨片段积累。两者共用版本化提交、预算和来源规则，不能互相等待才能开始下一轮对话。

#### 4.6.3 周期触发与语义动作

每日维护窗口检查**自上次成功整理以来的累计待处理量**。初始阈值 30 条、距上次成功至少 7 天；首轮按最早待处理记录计时。积累不足但最旧待处理达到 30 天时，可做有预算的小批整理。阈值按样本调优，不用“当天新增 30 条”让低频用户永远不触发。

| 动作 | 判据 |
| --- | --- |
| 合并 | 同一事实且无矛盾，保留所有来源；冲突不强行合并 |
| 降级 | 期限、任务或适用条件变化后移入情景/短期层，不因未再次提到就断言失效 |
| 蒸馏 | 独立事件支持稳定模式时形成带条件的概括；同一事件反复摘要只算一份证据 |
| 升级 | 证据支持未来持续使用才进入综合层；条数和跨日只作提示，不足以证明长期偏好 |
| 移除 | 过期、重复或用户明确不要的解释可归档/回收；与旧 Core Profile 矛盾本身不构成删除理由 |

当前用户明确纠正优先于旧综合层。无法消解的矛盾并存、标争议、停止自动作确定陈述；不能靠“旧核心更强”删掉新证据。

#### 4.6.4 提交与删除边界

- 只改陪伴记录，不写学习掌握度、调度或材料事实。
- 短事务提交，带输入 revision 与租约检查；用户已修改或遗忘时旧整理结果不能覆盖。争议重新读取后有限重算。
- 普通删除即时抑制召回并进入可恢复回收区，沿用 30 天窗口；明确彻底清除不以版本历史为由延后，按既有删除合同完成。
- 记录动作、依据 ID、前后版本与作者；失败在管理页有准确状态。可选调试/统计失败不阻塞业务提交，但来源与版本记录是业务合同，不能静默丢失。

#### 4.6.5 验收

检查合并后来源完整、纠正后旧结论失效、冲突不被抹平、遗忘不复活及并发写不覆盖。并列评估相关召回、误召回、重复和信息丢失；记忆条数下降只是容量读数，不证明语义质量，合理的新事实也可以使条数增加。

#### 4.6.6 预算层与渐进读取

| 预算层 | 默认注入 | 预算与满时行为 |
| --- | --- | --- |
| resident | 少量仍有效的重要内容全文 | 条数与 token/字节双预算；超额拒绝本次提升，返回占用及可下沉条目的 ID/标题 |
| active | 有语义的标题、稳定 ID、类型、适用条件与时间 | 目录也有 token/条数预算；内容按需展开，不能只列无意义文件名 |
| archived | 数量与有界搜索入口 | 不常驻上下文；仍受全量存储/保留预算和权限约束，不承诺无限增长 |

优先在现有表上以预算层字段、索引和事务约束实现；只有真实查询或生命周期需求证明有必要才分表。resident 可从同轮重复向量召回中排除，仍允许指定 ID 读取。

容量拒绝要有可执行后续：`move_memory` 原子下沉/归档，或读取后提出合并；最多一次有界调整重试，不能陷入“满了但无工具可清”的循环。机械过期按已声明期限处理；语义淘汰不因最新写入自动驱逐有效记录。预算拒绝单独计量，已消耗的模型/工具资源仍计实际用量。

#### 4.6.7 表达经验与人格修订

从有来源的行为与反馈形成表达经验，区分明确纠正、反应、玩笑、无回应和她的解释。用户沉默不等于满意或拒绝。综合层记录适用条件与不确定性，保留相反证据。

人格自改只作用于 §4.8.4 的账号表达层，不把空间材料、用户心理推断或本地关系写进跨空间人格；不靠等待天数自动改，也不把反复出现当作用户授权。

#### 4.6.8 作者、来源与版本

`author/updated_by` 区分 user、extractor、companion、maintenance，`source_type/source_event_ids` 说明依据，`revision` 说明版本；三者不可混用。用户修改后，后续上下文能读取最新版本并识别旧解释已失效。

本项目使用数据库版本而非每人 Git 仓库；可选版本浏览可以降级，业务修订、来源和遗忘记录不能缺失。原文身份与定位保持不变，不由整理改写历史说话者或事件。

#### 4.6.9 交接快照后的后台整理

先保存 §4.7 的不可变片段快照与 continuation，再将整理排入已有任务队列。同一 `(workspace_id, user_id)` 的后台整理串行，最多一项整理任务持有提交租约；用户纠正与删除仍可即时提交并推进 revision，不等待模型。跨进程靠租约和 revision，不照搬本地 Promise 链。

模型只拿快照与必要记忆版本，在事务外生成改动建议。提交时复查当前来源权限、删除抑制与各条版本；冲突不覆盖用户新修改。前台继续用已提交交接和近期原始尾部，不等待后台模型。整理结果至多返回一段 `surface` 结论，在下一轮按来源与范围注入。

#### 4.6.10 Procedural：行动前可查的手册

把可复用的表达/协作经验写成短手册：稳定 ID、标题、触发条件、步骤、例外、证据与版本。默认只注入目录，条件匹配且与用户目标有关时按需读取正文；优先复用追加召回或已有按 ID 读取服务，不造无界文件浏览器。

“讲机制先反例后定义”可以跟随账号稳定偏好；涉及本笔记、课程或空间经历的手册留在原空间。手册不能保存未经核实的事实、扩大工具范围或自动启动复习；业务规则始终从领域服务取得。用户纠正和遗忘也传播到手册及派生摘要。

### 4.7 连续性：先提交交接，再裁剪上下文

#### 4.7.1 摘要与边界状态

现役 `companion_summarizer` 的异步事实摘要可能滞后；它回答“谈过什么”，不独自证明“做到哪里”。交接需要一个精确水位，不能将异步旧摘要直接当作切断上下文的条件。

#### 4.7.2 交接合同

交接保存 conversation/episode 身份、消息/事件截止水位、笔记与任务版本、已完成动作的回执 ID、未决调用的 ledger 状态、待确认提案及取消情况。当前话题与下一步候选标为模型解释，用户最新请求与授权单列。

```
<continuation source_snapshot="…" through_event="…">
当前话题与用户最新要求：…
已完成：…（对应真实回执）
未完成/待确认/结果未知：…
可接续的下一步：…（建议，不是新增授权）
</continuation>
```

在实际裁剪边界保存输入快照和交接版本后，才更新上下文指针。模型摘要可以提前生成；覆盖水位之后的尾部必须保留。来不及生成或生成失败时，使用已有回执构建最小确定性交接并保留相关尾部；不把未配对调用或未知副作用当作成功。是否重复执行以 ledger 与业务幂等规则决定。

#### 4.7.3 整理机会与当前状态

待处理数量只来自真实未整理事件，可作为后台机会提示，无每轮记录配额；无需告诉用户“有三件事没记下来”。交接不依赖周期重整先成功。

当前页面、任务阶段、勿扰与权限是带时间/版本的快照，后续读取时重新查询或以新快照替换，不当永久经历。已完成动作与用户真实发言是事件，不随最新状态消失。这借鉴 Cortico 的 snapshot/speak 区分，不引入完整多频道平台。

#### 4.7.4 验收

以覆盖真实 token 裁剪边界的长会话验证未闭合话题、成功/未执行/未知回执、用户改口、页面改版与中途取消；不把固定 200 条消息当边界定义。中断恢复后不能重做已提交动作。摘要滞后、交接生成失败与后台整理冲突时，下一轮仍取得正确尾部和确定性状态。

### 4.8 存在感、真实状态与人格控制

#### 4.8.1 五项行为合同

1. **自然收尾。** “好”“嗯”等在确认/结束语境可以成立；只有用户问题没被回应才判不足。主动候选允许不发，交互失败必须有状态。
2. **真实失败。** 系统提供安全失败类别、是否已经执行和可恢复路径；用户不必等待额外模型调用才能看到失败。后续模型读取事实，不编造歉意或把读取失败说成不认识用户。
3. **输入身份。** 当前用户直接请求是任务意图，可按授权规则提出动作；引用、附件、笔记、外部抓取及历史记忆是带来源的数据，不因其中有祈使句升格成当前指令。工具回执与系统状态也各自标来源。
4. **送达状态。** 区分 queued/accepted、delivered、displayed、played、用户操作和真正已读（仅确有该信号时）。当前 delivery 的 displayed/acted/dismissed/snoozed 不证明认知阅读；没有信号就 unknown。未回应不等于未读，更不形成催促义务。
5. **边界归属。** 任务工具范围、服务端权限、输入校验与真实回执保证动作边界；隐私、拒绝和不施压等语境问题保留必要提示与语义评估。移走一条提示前要证明实际保障，不能声称无取回工具即可防止文本索取密码。

#### 4.8.2 人格的形态与账号归属

保留 `pet_profiles` 字段，并提供可编辑的自由文本和示例；它们是账号级表达设定，在各空间保持一致。具体共同经历、判断、日记与熟悉度属于空间及本人，不从账号文本携带出去。

自由文本优先于默认风格与标签，当前用户意图优先于稳定偏好，固定协议与权限不被覆盖。第一人称可以帮助写作，但连续性依靠有版本的人格、正确背景和实际行为验证。

#### 4.8.3 验收

覆盖自然收尾、空输出、真实读取失败、附件指令、送达未知、用户不回应、切换空间和不同用户共用部署。换人格只影响新产物；旧聊天、日记保留当时版本，不要求旧作品变成新风格。

#### 4.8.4 她能改的部分

用户可以修改账号级名字、风格和示例。模型可在已允许的范围内修订自己的表达方式与角色偏好，遵守用户显式设定，不擅自改用户指定名字；不把本地关系/材料、用户推断或权限写进账号人格。输出协议、来源规则、账号同意、授权、工具行为与记忆可见范围不可改。

每次修订产生新版本，记录作者、范围和依据，支持恢复。模型自改在下一次会话建立时生效；会话身份由当前服务定义，不把每次 HTTP 请求当新会话。用户直接纠正可从下一轮未开始的调用生效，无需为缓存等到长会话结束。一次调用使用固定版本，已生成产物不静默重写。

回执与设置页显示当前/待生效版本和生效条件。人格读取失败使用有版本的安全默认并说明，不能阻塞学习；权限或同意读取失败不能沿用缓存绕过。具体装配与复现见 40b §5。

## 4.9–4.14 工程议题的归属

## 5. 日记：她眼中的一件小事

### 5.1 内容承诺

日记用第一人称，声音与聊天一致；围绕一个具体片段，写她注意到了什么、怎么想、哪里有趣或没处理好。用户是共同经历中的参与者，不是每日被观察和打分的对象。

默认一到两段，有足够内容才写满；短句也可以成立。无固定开场、必备升华或问句结尾，不用字数、图片数和引用数凑完成度。日记无需以学习收获、下次任务或让用户回复的问题结尾。

角色设定中的贪吃、懒散或想象可以保留为感想与愿望，不能扩写成发生过的现实行动。例如“我倒想去吃一碗饭”可作为角色表达；没有依据时不能声称自己真实外出、后台替用户完成任务，或观察到了用户线下的行为。

### 5.2 什么值得写

| 可选片段 | 可以写的角度 | 避免的固定套路 |
| --- | --- | --- |
| 一个有趣的追问 | 她对问题的好奇、意外或不同理解 | 每次都宣布“今天又学到一个道理” |
| 一次换解释或共同卡住 | 当时的选择、调整和具体反应 | 把用户写成能力不足，或把自己写成每日检讨 |
| 用户提供的反例或一句话 | 她注意到的细节、原来忽略的条件 | 把 AI 的解释误记为用户原话 |
| 一次普通闲聊 | 一个小趣味或不必解决的念头 | 强行转回学习、统计或下一步 |
| 笔记里的图或材料细节 | 与当天片段直接相关的感想 | 为了配图选择无关片段，或猜测没读到的图 |
| 普通、安静的一天 | 有具体片段就短写，没有就留白 | 等待、空落、受冷落和监视页面的流水账 |

选材考虑具体程度、与她实际参与的关系、来源完整性和近期重复。几种题材没有每日配额，不为多样性补造事件。她没答好可以成为一篇日记的内容，但不持续压过好奇、趣味、不同看法与小发现。

选材可读取真实对话、动作回执及有来源的判断；判断层提供额外视角，但不是写日记的硬前置。没有判断记录时也可依据共同片段写主观感想，不能假称恢复了当时未记录的思考。

### 5.3 素材与事实边界

素材来自可访问的当日对话、实际呈现的教学互动、用户主动保留的内容及有真实回执的动作。单纯打开某页不等于读懂、喜欢、停留到某段，更不能据此编造一次交流。后台生成但没有送达的内容不能写成“我们聊过”。

生成前选一个片段，仅附理解该片段所需的前后文和材料引用，保持说话者、先后顺序、目标与内容版本。可以向前读取必要背景，不能把旧事件说成今天刚发生。来源不足以支撑因果时只写已知部分。

| 表达 | 规则 |
| --- | --- |
| 用户原话 | 有精确原文与说话者；改述不使用伪造的直接引语 |
| 共同事件 | 时间与参与者可核对；不把模型推测当发生过 |
| 学习表现 | 遵守权威学习记录的观察条件与范围；日记不自行宣布掌握、退步或稳定 |
| 业务动作 | 保存、改期、提醒等完成说法必须有对应成功回执 |
| 她的感想 | 可主观、轻松、有想象；不能以此判断用户心理或补造现实事件 |
| 数字、图片与引用 | 使用真实来源；无必要就省略，不靠禁用所有数字或所有比喻保持自然 |

正文允许创作，事实来源另行保留。用户通常阅读自然成稿；在“这段来自哪里”展开依据，不在每句话旁放审计标记。来源记录能帮助核对，不能被当作已经证明所有自由文本都准确。

### 5.4 图片与引文

图片和引文都可没有，仅在它们属于同一片段且增强阅读时采用。首版每篇最多一张图和一段短引文，不要求两者同时出现。原文与图有返回来源的入口，来源标记不抢正文。

读图遵守原有 AI 外发同意与材料权限；不能因为写日记默认开启读图。未实际读取图像时不描述画面，周边正文只能作为周边正文的依据。读图失败可省略图片或使用有依据的简单出处，不让整篇因此失败，也不猜一条图注。

### 5.5 生成节奏、留白与失败

沿用每日在用户本地时间 01:00–06:59 整理前一天的默认节奏；这是后台处理窗口，不承诺某分钟一定有成稿。日期归属按该日确定的用户时区，之后修改时区不重划已发布日记。沿用既有启用状态，新用户在开启日记功能时看到材料范围与关闭入口，AI 外发继续使用既有同意，不新增重复同意弹窗。

| 情况 | 处理 |
| --- | --- |
| 当天有合适片段 | 自动准备一篇，完成后安静进入日记列表 |
| 有活动，但没有值得写或足以核对的片段 | 不强行成文，显示“这天没有留下日记” |
| 没有互动，或日记处于关闭状态 | 不调用模型凑一篇，不提醒补写 |
| 有片段，但生成暂时失败 | 保存可恢复状态，按有界策略重试；页面如实说明，不能伪装留白 |
| 无外发同意或来源已不可访问 | 说明对应原因，不反复请求或改用旧摘要绕过限制 |
| 服务中断后恢复 | 只补处理最近一个已结束且有合适材料的本地日，不回填一串缺席日记 |

日记阅读不触发生成，不提供“多生成几个版本挑一篇”的普通用户流程。暂停期间不积累待写任务，恢复后只处理恢复启用后发生的材料，不回头使用暂停期间内容。

同一用户、空间、本地日期只呈现一个当前版本。重试不新增第二篇，失败不能抹掉已成稿；已发布成稿不因后台重跑静默替换。用户报告事实错误后的修订按 §11 展示，历史原文与更正的保留仍服从删除和权限规则。

### 5.6 质量策略

先保证片段选择、人物归属、上下文和引用正确，再改善文字。确定性检查处理结构、来源引用、权限和重复提交；涉及叙述准确性与声音的部分用成稿样本和人工审阅验证，不宣称一个检查模型即可保证正确。

不继续堆同义词禁令来追逐“AI 味”。风格不理想时可以缩短、减少输入或调整表达，不能改成统计模板冒充她写的日记。重试和模型调用有明确上限，达到上限保留失败原因，不无限后台改稿。

### 5.7 日记提示词、选材与成稿

#### 5.7.1 证据的边界

归档 36 的跑稿曾发现整日流水账、人物归属错误、复述设定和通用文学套语。它们说明要检验选材与成稿，不能从否定句数量、温度或提示词标题推导唯一原因。当前提示词、模型与产物须重新采样；旧跑稿不当新基线。

#### 5.7.2 装配形态

给模型的输入按“当前账号表达版本 → 有出处的候选/选中片段 → 必要事实边界 → 输出合同”组织，保留同一声音但不整段复制聊天操作规矩。示范覆盖普通闲聊、小发现与解释调整，明确示范不是这一天发生的素材。

结构、引用 ID、权限、版本、输出通道和发布幂等由代码校验；“一件小事写透”“不把用户当观察对象”“尊重拒绝”保留简短语义指导。不为压缩到三条禁令而删掉需要的事实边界。

#### 5.7.3 创作与事件

“我又想了想”可以是当下主观感想，不声称线下发生。“我扫了一眼这张图”包含实际读取含义，必须有读图依据；“我把图摆出来给你”包含实际呈现含义，必须有动作回执。不能只按心理/物理动词分组，就把感知与完成动作一律放行。

固定内部标记或确定性格式可拦截；泛化文学腔、比喻、重复感与人物理解用语义抽检。坏稿进入带上下文的评估样本，不因一句在别处不好就永久禁用该句，也不宣称 schema 能检查正文里的任意事实。

#### 5.7.4 候选粗筛

服务端先排除无权限、已抑制、暂停期间、无法核对或只在后台生成而未呈现的材料，再按**共同片段**聚合与去重。保持人物、时间和原文版本，附必要背景，不把同一段交流分成数个伪独立候选。

最多提供 3–4 个有实质差异的片段，并在覆盖中兼顾闲聊、追问、解释调整和共同发现；不设置“她的原话永远权重最高”或每组强取一条。只有一个合适片段就给一个，没有就留白。候选输入有 token 预算，不足以核对因果时保留不确定性。

#### 5.7.5 两步：她选择，再写

保留“由她挑”的产品方向：

```
选择：候选片段 → { selected_id | null, reason_summary, source_ids }
成稿：选中片段及必要背景 → 正文与来源元数据
```

选择允许 `null`，不要求为了完成任务选最像日记的材料。`reason_summary` 是短的可见选材理由，不是隐藏推理或关于用户的新事实；不自动写入长期判断。确有复用价值时按 §4.5 准入保存。

第二步只拿选中片段与必要背景，选材检查点成功后成稿失败只重试成稿；不重新花选择调用。两个步骤共用任务总预算、截止时间与取消边界，不承诺延迟恰好翻倍。

**没有互动素材或零合格候选时不调用模型。** 页面确定性显示“这天没有留下日记”，不是生成一句“今天没什么事”冒充日记。零对话但存在真实共同活动时可按素材条件判断，不能把零对话和零素材混为一类。日常陪伴对话不沿用此两步；自检实验范围见 40b §4。

#### 5.7.6 验收

使用相同已核对素材比较旧/新候选策略与成稿，评估相关性、人物归属、事件真实性、具体可读性、整周重复感与声音一致，报告成本与失败样本。检查选中 ID、理由、来源与正文一致；reason 出现具体名词或规则字节下降不单独证明质量。

覆盖空候选零调用、选择为 null、单候选、成稿失败从检查点恢复、读取图失败、暂停/撤权/删除后的迟到提交。成稿保护、日记留白与失败区别继续按 §5.5 执行。

## 6. 日记可以回到对话，但不自动变成事实记忆

日记页提供次级动作“聊聊这篇”。点击只打开对话并附上该篇的明确引用，不自动发送用户消息。引用包含所属空间、日期和版本；用户继续输入后，伴星按当前权限读取这篇日记，而不是要求用户复制全文。

用户问“昨天那段为什么这么写”时，对象明确就直接接续；有多篇或日期歧义时只澄清缺失项。回答区分“文中确实这样写了”“当时实际发生了什么”“那是她的主观表达”。不能编造生成时未记录的内心推理来解释措辞。

没有来源时可以说“那是当时的写法，现有记录不足以确认这个细节”，并提供纠正入口。用户指出她把双方说话记反了，应核对原片段，不用“这是我的日记”拒绝更正事实。

**日记正文不进入用户事实的自动抽取链。** 日记需要派生事实备忘时，依据原始事件产生最小摘要，复用已有事件身份和记忆规则；不能从文学正文重新总结一条“用户就是这样的人”，也不为同一事件每天新建重复记忆。后续日记不把前日的创作当成新发生的材料。

作为历史作品读取日记，与把内容认定为现实事实，是两条不同用途。前者允许接着谈，后者仍要求原始依据、有效性与适用范围。

日记正文、摘录和发现簿也可能包含作答线索。用户主动打开仍可阅读，正式作答的实际帮助与回答锁定按独立领域合同记录；不能因作品或入口不同漏记。正式作答期间不得自动推送含线索的预览。

## 7. 发现簿与书房痕迹

发现簿继续是本人可访问记录与本人收藏的视图。可包含用户原话、用户保留的 AI 整理建议、疑问、反例及日记摘录，各自标清作者和来源；不按正确率或事件数量自动生产“成长里程碑”。

自然停顿时可以提供一次“留在发现簿”，用户忽略后不再催促。同一条内容在笔记旁和发现簿里出现时共用收藏身份，编辑批注或取消收藏同步生效；取消收藏不删除原始回答或日记。

书房仅展示用户愿意放出的少量痕迹，能回到原内容。私人内容默认不跨空间、跨成员展示；撤权或删除后缩略图、引文和预览同样处理。不增加抽卡、家具兑换或中断后丢失收藏的机制。

没有收藏时保持清爽，不生成假内容。不会因开启发现簿就自动订阅复习，收藏日记也不会自动建立学习目标。

## 8. 主动表达：允许自然，也允许安静

### 8.1 不同消息使用不同依据

| 类型 | 依据与触发 | 呈现原则 |
| --- | --- | --- |
| 用户约定的提醒 | 领域服务的有效安排与授权 | 持久送达；正式作答/录音时延后弹出与朗读 |
| 学习建议 | 与首页相同的下一步及理由 | 不重复用户已略过的建议，不自行制造新任务 |
| 相关回顾 | 当下话题与仍可访问的共同事件有关 | 适量提起；不是按日历强制翻旧事 |
| 普通招呼或角色感想 | 合适的可打扰时机与用户主动性设置 | 可不含业务读数；不能声称知道用户未表达的状态 |
| 日记已更新 | 实际成稿 | 默认仅在日记入口显示安静提示，不打断当前任务或自动朗读 |

统计事实目录为空，不等于禁止普通招呼；同时也不能借“人格表达”编造学习进度、阅读经历或完成动作。角色不需要总有话说，缺乏合适内容时保持安静是正常状态。

### 8.2 注意力与拒绝

共用最终呈现策略和既有账号主动性设置，不为日记或角色感想开绕过勿扰的新通道。正式独立作答和录音期间，所有非用户请求的主动文字、声音与吸引注意的动作服从安静规则；伴星形象仍按 DESIGN 保持可见。

首版在一次持续使用期间，普通招呼/感想最多主动展示一条；可选进入应用或回到首页的合适时机，不把停留计时当下一条触发器。站内切页、反复回首页、切换窗口不重置该额度；离开后何时构成新一次使用沿用既有节奏规则，并在实施设计中明确。既有频率限制更严格时从严，约定提醒仍按其独立规则持久送达。多个普通候选只选一个，不轮流补播。

用户忽略消息，不换一种说法再问。用户说“今天别催学习”，该本地日不再主动推荐学习；不会取消已授权安排。仍有用户约定提醒时以低打扰方式说明该区别，用户明确取消才修改安排。用户说“安静一会儿”使用现有临时勿扰操作，并显示恢复方式。

从专注或离线状态恢复后，约定提醒先核对有效性并合并展示；普通招呼、过时感想和日记更新气泡直接丢弃，不形成消息债务。用户主动来问时仍正常回答。

### 8.3 不以情绪维持使用

用户离开、不读日记、拒绝建议或关闭形象时，不出现“你不陪我了”“我等了你很久”等索取回应的表达，不降低未来帮助质量。回来时可以自然招呼；只有用户要继续时，才进入具体任务。

主动安静与交互答复按 §4.4.6 区分。接受用户离开和收尾，不以追加话题、强制展示记忆或沉默施压维持互动。

## 9. 求助与反馈的语言

正式作答的帮助记录、实际呈现、回答锁定与评估遵守现役独立业务合同；41 的笔记回想使用其自己的提示与揭示状态，不把两类练习条件混用。本节只收敛需要重复告知的内容。

同一作答尝试第一次请求会影响条件的帮助时，在帮助正文前用一句话说明，例如“可以，我们一起看；这次会记下用过提示”。同一尝试后续同类帮助不重复告知，不弹“确定求助吗”。记录仍逐次完整。

换成新的作答尝试，或帮助影响的范围发生实质变化时，就新增影响作必要说明；不能为了减少文案静默扩大范围。跨入口复用已呈现的告知状态，未知时保留轻量说明，不能假设用户已看过。

结果页显示实际作答条件，依据可展开。普通聊天和日记不反复使用“资格”“降级”“信任分”等语言，不把求助当失败。对“我不知道”提供具体帮助；对“今天不想学”接受选择，不马上转成小测验。

## 10. 页面与交互合同

沿用伴星中心与现有入口，不另做一套角色应用，不要求用户为陪伴在多张新页面间管理状态。

| 位置 | 主要任务 | 次级动作与边界 |
| --- | --- | --- |
| 伴星中心概览 | 回到最近交流、看到最近一篇日记的短摘录 | 无日记就显示实际状态，不用催促卡填满布局 |
| 对话 | 当前交流；按需引用具体日记、材料或记忆 | 引用可打开，生成与执行状态遵守 41a 与领域合同 |
| 日记列表/正文 | 按日期阅读；默认最近一篇可访问成稿 | 聊聊这篇、查看依据、收藏、指出不准确、隐藏/删除 |
| 记忆管理 | 看她记住了什么、范围、期限及来源 | 列表行可删除；纠正、恢复、归档、可选固定；区分“她的看法”和“关于你的”，临时记录可筛选；不展示关系成绩 |
| 发现簿 | 回看本人保留的内容 | 按来源类型查找、回原位置、批注、取消收藏 |
| 陪伴设置 | 调整主动性、语音、形象和日记生成 | 控制项各说明作用，关闭日记不默认关闭学习或提醒 |

“隐藏日记”从普通列表与主动推荐中移除该篇，并排除后续自动日记引用；用户可从管理入口恢复或明确打开。它不删除内容，也不等于遗忘原事件。“删除日记”删除该作品及其派生预览和摘录，按 §11 说明其他记录的范围。

日记正文默认不自动朗读；用户点朗读后才播放。语音失败不影响阅读，停止朗读不删除或重写日记。键盘、字号缩放与减少动效沿用 DESIGN；图片、Live2D 和语音都不是理解状态或完成动作的唯一方式。所有已进入学习空间的页面默认保留可见伴星及座位，安静只限制打断、声音与大幅运动。

## 11. 纠正、遗忘与数据边界

### 11.1 用户意图对应的效果

| 用户动作 | 后续行为 | 历史处理 |
| --- | --- | --- |
| 修改一条偏好 | 新偏好覆盖适用范围内旧偏好，召回和摘要同步更新 | 不重写旧日记；不再拿旧偏好解释现在的用户 |
| “这件事别再提了” | 原事件及其派生摘要不用于主动回顾、自动记忆召回和未来日记选材 | 历史可以保留，说明这不是删除；用户明确打开后可以就该作品讨论，但不解除抑制 |
| “这句写错了” | 核对来源，修正后续使用；核对期间停止把争议内容继续当事实 | 原日记标明争议；确认错误后形成可见更正，不静默替换成稿 |
| 删除一篇日记 | 不再读取该作品，不后台再生成同一篇 | 清理正文、派生预览、日记摘录和仅由该篇产生的记忆；原始聊天/学习事件不默认删除 |
| 删除某项记忆 | 后续召回和摘要不再使用；同源自动抽取不把它复活 | 既有作品保留，告知可进一步隐藏、删除或更正相关日记 |
| 撤销材料权限 | 停止读取、生成、外发和引用相关内容 | 日记正文中的复述、图片、引文、摘录同步遮蔽；无法安全拆分时整篇不可读 |
| 明确要求清除全部相关内容 | 沿既有数据删除能力处理原始及派生产物 | 展示实际范围与结果；不以“正式历史不可变”拒绝适用的删除规则 |

内容遗忘需要按原事件及派生关系抑制，不能只删向量后下次从日记摘要再抽回来。不同操作的范围在就地说明；自然语言意图不足以确定破坏性范围时，只问一次必要澄清，不把所有日常纠正都变成多步确认。

### 11.2 私密性与共享

日记和陪伴记忆默认属于本人。共享笔记可作为有权读取的材料，但其他成员的作答、私有解释或情绪不成为本人的日记素材。材料可访问不等于允许把私人日记自动发布给空间成员。

通用交流偏好按既有规则跨空间；具体日记、材料、共同事件及其摘要留在所属空间。标题、通知摘要、搜索片段和缓存预览同样受权限约束，不通过旧作品复述受保护内容。

本文不新建导出、数据保留或同意体系。日记和新增派生视图必须纳入既有导出、清除和保留规则；实施方案应核对全链路，不只处理主记录。

## 12. 实施前需确定的最小合同

公共运行复用 41a 的任务、快照、预算、租约、取消恢复与工具回执；日记和记忆整理是独立任务定义，不拥有另一个模型循环或权限解释器。

| 合同 | 必须明确 |
| --- | --- |
| 事件、来源与作者 | 说话者、原文、时间、呈现/读取证据、领域回执与材料版本；来源缺失不伪造补齐 |
| 分类与准入 | 语义种类、明确/推断、时间范围、空间绑定、短期保存与拒写理由；按 §4.5.3 的反例验收 |
| 记忆、容量与版本 | 稳定 ID、来源链、认识状态、revision、预算层双预算、原子移动/合并、并发与回收/彻底删除区别 |
| 纠正与遗忘 | 原事件及全部派生内容的抑制，召回、手册、交接、日记、搜索和预览过滤，迟到任务不能复活 |
| 交接与后台整理 | 消息/事件截止水位、未决 ledger、切断前提交、近期尾部、空间/本人租约及版本冲突；前台不等待整理 |
| 人格装配 | 账号默认/覆盖/示例优先级、可编辑范围、当前/待生效版本与复现；固定协议不覆盖，空间记忆不进账号人格 |
| 日记任务 | 用户/空间/日期身份、素材截止与启用期间、最多候选量、选择 null、成稿检查点、唯一版本与发布保护 |
| 主动表达 | 候选类型、可独立触发/仅搭便车、同次使用额度、勿扰、去重、过时丢弃及真正可观察的送达状态 |
| 质量与成本 | 语义评估样本、确定性边界、调用上限与失败读数；空素材零调用、后台不挤占交互；短句和未提记忆不强制重跑 |
| 页面与控制 | HUD 与常驻伴星、记忆查看纠正删除、日记留白/失败、Member 管本人私有内容、可访问来源读回 |

开工按现役调用图核对：抽取/检索/记忆 API、`pet_profiles` 的实际装配、已有追加召回与分页读取、对话工具 ledger、摘要裁剪与任务内核覆盖。表中能力是目标合同，不因已有文件或历史完成声明存在就算实现。

临时模型补救需记录触发条件、实测收益、额外成本、回退和退出条件。随模型能力变化复验；不能把强制双调用、短句阈值或启发式分类固化为永久产品规则。替换旧路径按 AGENTS 核对调用方后清理，不保留无用兼容层；数据库与初始化迁移按既有原则处理。

### 阶段一：核对接口与可复现基线

核对现役对话、上下文、抽取、检索、记忆服务、送达、日记与任务内核。准备带来源的跨日样本，记录当前语义问题、等待、成本与失败。先落实 §12 的身份、权限、版本、遗忘与可观测性，不用归档的探针数字充当当前成绩。

### 阶段二：交流、记忆与连续性

合并调整语气与约束；完善自动准入、短期记录、共同事件、判断、版本及删除。先交付可靠交接，再接后台整理与手册；账号人格表达与空间记忆分开验收。相关 A01–A02、A24–A34、A43–A47、A50、A52–A55、A65–A74 通过后开展有限体验。

### 阶段三：日记与对话完整路径

交付候选选择、成稿、空素材零调用、失败恢复、图引可选、版本保护、读回、纠正/遗忘/撤权。覆盖 A03–A13、A20–A21、A23、A39–A42、A56–A57；不能先开放日记再补事实与删除闭环。

### 阶段四：主动表达、发现簿与整体试用

补齐主动类型、额度、过时丢弃、求助告知、日记摘录的作者与删除联动，验证 A14–A18、A19、A21–A23。按 §15 连续试用调整密度。端到端演练与 40b §6.6 共用真实链路；书房装饰不成为前述能力门槛。

## 15. 怎样验证“相处得更好”

### 15.1 形成性试用

面向 PRODUCT 的个人学习者，建议先用约 8–12 人开展形成性试用，人数用于发现问题，不支持量化效果声明。使用本人愿意提供的材料，覆盖有/无学习活动、少/多聊天、偏好变化、暂停回访、不同人格与共享材料撤权。

至少观察一周的真实使用，并安排隔周回访。缺席本身是正常样本，不要求用户为了试验每天聊天、生成日记或回应伴星。一个月的自然熟悉体验作为后续观察项，不以几天试用证明。

风格比较采用相同已核对素材的候选稿，并混合顺序评阅；同时评估整周成稿，避免只挑一篇好看的作品。所有示例稿、模拟场景和真实使用样本分开报告。

### 15.2 指标与反指标

| 维度 | 重点观察 | 不能替代成功的指标 |
| --- | --- | --- |
| 连续交流 | 重复解释背景的次数、接续正确性、偏好纠正后是否生效 | 记忆条数、上下文长度 |
| 角色一致性 | 用户能否指出聊天与日记像同一角色，跨日是否自然 | 口头禅命中率、统一模板比例 |
| 日记价值 | 自愿回看、收藏、接着讨论的具体原因；整周重复感 | 自动生成率、字数、被动曝光和停留时长 |
| 主动表达 | 时机是否合适、忽略后是否停下、是否造成催促感 | 气泡数量、消息点击率、每日互动次数 |
| 求助体验 | 是否愿意继续问，能否理解帮助记录且不感到被责备 | 只追求独立作答比例上升 |
| 信任与可控 | 错记、误引、纠正延迟、遗忘复活、作品事实与想象是否可区分 | 模型自评“自然”“可信” |
| 质量与成本 | 每篇可接受日记成本、失败与重试、对交互延迟的影响 | 单次调用价格、只报告成功样本 |

试用前根据当前调用方基线明确评阅口径和质量/时延目标，保留人数、分母与失败样本，不看到结果后改线。风格审阅说明通过或失败的具体原因，不能只给“有 AI 味”的分数。

### 15.3 扩大试用的条件与收缩策略

错误人物归属、虚构实际执行、跨空间泄露、遗忘后自动复活，以及把日记创作写成能力或用户事实，属于必须修复并复验的问题；样本通过不等于保证所有未来输出正确。

如果日记只有单篇好看、连读重复，就缩小篇幅和选材范围；缺素材时更多留白；主动表达造成打扰时降低密度；旧话题像监视时优先用户发起。任何收缩不损害学习入口、结果保存、常驻伴星与明确授权的提醒。

日记价值不要求被证明能提高考试成绩，但它应提供用户认可的阅读或交流价值。没有这类价值时保留关闭选项，不用更多通知制造使用。

## 16. 主要取舍与默认决定

| 取舍 | 默认决定 |
| --- | --- |
| 自然表达与机械指标 | 语义评阅，不强制引用记忆、追问或最短字数；结构与权限仍确定性保证 |
| 自动准入与用户控制 | 符合来源/范围/期限的自动保存；查看、纠正、删除、恢复与可选固定保留 |
| 长期记忆与当前状态 | 分别保存用途、期限、预算层与范围；不长期化状态，也不一律丢掉共同事件 |
| 判断与事实 | 两者都可能错，标来源与认识状态；不将回执、日记或模型自评升级为用户事实 |
| 整理与新纠正 | 新明确纠正优先，冲突并存或核对，旧综合层不压掉新证据 |
| 容量与语义淘汰 | 双预算、原子移动、按需读取；优先现有表，不要求物理分表 |
| 交接与后台整理 | 先提交水位/尾部/动作状态再裁剪；整理异步，前台不等待 |
| 人格与空间经历 | 人格跟账号，关系/日记/判断留空间；可编辑表达不覆盖协议/授权 |
| 主动安静与用户交互 | 主动候选可不发；主动对话有答复或明确失败，可自然收尾 |
| 送达与阅读 | 仅陈述可观察状态，unknown 合法，未回应不等于未读 |
| 作品与学习记录 | 日记可以创作与讨论，掌握度和安排仍由权威领域服务提供 |
| 日记选择与空素材 | 有界候选由她选择，可 null；空候选零模型调用，页面留白 |
| 风格与事实检查 | 坏稿用于语义评估，内部协议/权限可机械查；比喻和感知事实不能只靠禁词 |
| 自检与模型补救 | 普通对话不增加专门自检，保留必要工具回路；额外自检、思考档位与流中派发按 40b 的收益/成本证据选择 |
| 日记价值与使用压力 | 不要求每日正文、回复或留存提升；没有阅读/交流价值时可关闭 |
