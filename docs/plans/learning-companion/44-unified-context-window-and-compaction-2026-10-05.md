## 1. 目标与本次取舍

用户体验是：换入口、换话题或隔天回来，仍与同一个伴星合作；她能找回相关经历、接续正在进行的工作，并把真实反馈用到下一次任务。用户无需手动维护模型会话或清理上下文。

全系统共享持续身份、执行与上下文治理、按现行范围可用的记忆和方法。每次模型调用根据当前请求与对应目标独立装配工作上下文；后台任务保持自己的要求、材料版本、进度和回执。

本次撤换原 44 的下列设计，避免实施时沿用旧口径：

| 原设计或判断 | 本次修订 |
| --- | --- |
| contextWindowTokens 从未被生产代码读取 | provider 已读取并提供能力快照；缺口在完整请求的预算消费与超限控制 |
| 80,000 字符就是整轮上下文上限 | 当前只限制 system 部分；历史、当前输入、工具定义等必须一并计量 |
| 摘要、尾部与水位全部改成用户级滚动 | 保留会话/目标的工作边界，建立按范围可检索的历史与经验索引 |
| 预算先乘 0.8，再在该预算的 80% 压缩 | 明确硬上限、80% 触发线和压缩目标，避免重复折扣 |
| 摘要输入必须大于回放窗口 | 验收折叠区间的覆盖与恢复能力；允许有界分块 |
| 日记、尾部与短字段统一按窗口比例放大 | 按任务用途与实际质量调整，区分模型容量、选材、存储和显示限制 |
| 放大预算后再补遗漏表达 | 来源覆盖回执与取回入口随装配、压缩一起交付 |

Hermes 的借鉴点是会话压缩、跨会话记忆与历史检索、可复用技能和后台复盘之间的协作。其定时任务使用独立会话，可以加载指定技能。本项目沿用数据库、现有执行内核与空间权限，参考材料见 §10。

“越用越好”通过经验使用后的错误、返工和重复解释减少来验证；使用次数、记忆数量和模型自评不作为成长成绩。初期通过有条件的记忆与方法学习，不以在线训练模型参数为前提。

## 3. 上下文、记忆与历史各自的归属

### 3.1 持续身份与独立工作上下文

| 内容 | 归属与更新 | 使用方式 |
| --- | --- | --- |
| 持续身份、人格与允许的通用合作偏好 | 按账号及 PRODUCT / 40 的既有准入与版本规则 | 各入口使用当前有效配置 |
| 当前交流 | 当前用户、空间、会话及本轮交互 generation | 当前请求、相关尾部与话题索引 |
| 持续目标 | 当前用户、空间、runId、goal revision | 该目标的材料、计划、依赖、成果与真实回执 |
| 专业生成 | 对应领域作业/执行尝试及材料版本；有父目标时保留绑定 | 领域模板、必要原文和相关有效经验 |
| 历史事件与经历索引 | 保留原消息、运行、操作与产物身份及读取范围 | 按需检索、定位、补取原文 |
| 长期记忆与合作方法 | 复用现役记忆/Procedural 手册的范围、来源、版本与状态 | 先给相关目录，需要时读正文 |
| 后台整理与效果分析 | 自己的有限维护作业、来源快照和执行预算 | 返回有来源的候选或修订，不接管前台话题 |

人格与已允许的一般合作习惯连续。具体科目、目标、材料、对话、日记和私人经历仍按空间与本人范围读取；空间经验不能因贴上“通用技能”标签自动跨空间。

窗口占用是一次模型请求的容量读数。调用成本按 turn、目标、维护作业及账号治理累计。多个后台调用的 token 消耗不能累加成一个用户级窗口水位。

### 3.2 跨会话找回与跨入口接续

一次新回合先装配最新请求、必要协议/人格、相关尾部和必要目录。明确涉及已有任务时读取对应目标快照；提到过去的讲法、经历或方法时，通过同一执行驱动检索并补取相关来源。

跨会话连续性由可检索历史、有效记忆、方法与目标快照共同提供。会话摘要保留本来的来源身份，按相关性选用；新会话不默认回放该用户所有会话的最近 N 条。自然话题边界可以在内部组织分段，伴星身份和用户草稿不因模型上下文分段改变。

后台完成事件推进目标与送达状态。家常消息更新当前注意力，不能改后台原要求；后台摘要与旧任务结果也不能成为当前用户请求。

### 3.3 条目身份、水位与失效

扩展 42 的 ContextPlan。条目至少记录：稳定身份、用途与信任边界、来源引用及版本/哈希、用户/空间范围、对应会话或目标、读取时间与有效性、token 估算及估算方法。最终调用记录实际纳入/排除条目、原因、模型路由和快照哈希。

沿用各源流的局部序号；跨源覆盖记录 (sourceKind, sourceId, revision, seq/range, hash) 的清单。需要统一事件索引时，可建立有稳定源键的可检索投影，其游标只承担索引遍历。索引顺序不能充当目标执行顺序或材料版本。

压缩幂等键绑定工作上下文身份、来源区间/哈希、父摘要版本与压缩策略版本。不同会话的同号桶不能碰撞，相同区间重复触发只能产生同一次提交。

用户纠正、遗忘、删除、撤权、材料版本变化与过期沿来源关系传播到摘要、经验、索引、缓存和待提交作业。读取与提交均检查当前有效性，旧摘要不能恢复失效授权或被遗忘内容。

## 4. 完整模型请求预算

### 4.1 唯一预算解析与三条水位

从本次实际 provider/model/endpoint 的能力快照与生效参数解析预算。平台配置、已确认能力和 provider 限制共同约束有效窗口，变更来源可追溯。

~~~text
C       = 当前路由的有效 contextWindowTokens
O       = 本轮实际采用的输出预留（包含该路由计入输出的 reasoning）
I       = provider 独立的输入硬上限；未单独声明时视为无额外限制
M       = 未完全可计量的协议开销与估算误差余量
B_hard  = max(0, min(C - O, I) - M)
T       = floor(B_hard × 0.80)    // 默认压缩触发线
G       = floor(B_hard × 0.60)    // 初始压缩目标，按真实样本调整
P       = 最终完整请求的输入 token 计量/估算
~~~

80% 只作用于触发线，不再先对 B_hard 乘一次 0.8。G 是防止每轮再次压缩的目标，不代表必须删除无法折叠的必要内容；始终重新检查硬上限。

O 依据实际被 provider 执行的输出配置。请求的 maxTokens 被忽略或省略时，不能用该值假定输出很小，应采用已知默认或保守预留。现役 maxInputTokens 有的是由“窗口减最大输出”派生；接入时区分派生值与供应商独立硬限制，迁移前保留其保守约束，不能当作互不相关的三个数字重复扣减。

系统协议、人格与工具定义已计入 P，不能又作为固定 RESERVED_TOKENS 扣一遍。无法获知能力时使用经过登记的保守能力或已有 provider 默认；临时保留旧字符护栏也必须标注估算与未知项，80,000 字符本身不能证明适配小窗口模型。

### 4.2 计量范围与可信程度

P 包括实际序列化的 system/developer/user/assistant/tool 消息、工具 schema、调用参数与结果、provider 包装，以及图片等多模态输入。不能只测 system 或业务数据块。

优先使用适配当前模型的 tokenizer 或 provider 计数能力；可用相匹配请求的真实 usage 作为锚点，再计新增内容。锚点匹配模型路由、前缀内容、工具集与序列化版本；压缩、改写或模型切换后失效。缓存命中仍占窗口，已包含的 assistant 输出不重复计算。

无准确计数时使用保守估算并记录方法、误差与余量。中文/英文字符比例只是估算依据；provider 实际 prompt 用量用于校准。多模态或不透明载荷的未知成本不能记作零，也不为计量采集隐藏推理。

### 4.3 每次真实调用前检查

统一检查覆盖首步、每个工具回合、补取材料、后台继续、重试和备用模型调用。工具结果回来后重建/计量请求；不能只在 companion-dialogue 入口检查一次。

模型或 provider 变更遵守所在执行合同。允许变更的路径生成新能力与上下文快照，按新窗口重检；被冻结的执行不能静默更换模型。恢复同一已提交尝试沿用匹配快照，同时复查权限和取消屏障。

P >= T 时尝试有界压缩；压缩后重新装配并测量。保留当前已接受请求、明确操作、必要权限/协议和不能丢的事实引用。必要内容自身超过 B_hard 时，保留原请求并给出可行动的限制/分段方案，不能静默切掉问题尾部，也不能承诺任何输入都能继续成功。

### 4.4 字段上限按用途调整

回放尾部用于指代和交流连续性，摘要输入受摘要模型预算控制，日记选材重在相关经历，here-and-now 重在简洁定位。用户可见短文案、数据库字段和业务输入长度各自按合同处理。

逐项核对旧上限的用途与质量证据后调整，不能按主模型窗口同比放大所有字段。保持“上限是容量，实际装配按需要”的原则。

## 5. 可靠压缩：覆盖、恢复与提交

### 5.1 压缩对象与必须保留的内容

压缩当前工作上下文中的旧交流、冗长结果与已完成过程。目标状态、授权与正式产物仍由各自账本承担，摘要保留引用及理解所需的事实，不能替代完成核验。

同一来源流按“已有有效摘要/摘要节点 + 本次新增折叠区间 + 必须保留的工作引用”接续；较长历史可分块形成摘要与索引，再有界合并。跨来源材料保留各自区间清单，不能用一个 fromSeq/throughSeq 假装覆盖所有来源。

至少保留：

- 当前请求与最新修改、明确约束和用户纠正；区分本次例外与长期偏好。
- 当前涉及的对象、材料版本、关键术语/参数与事实引用，保留反例、不确定性和适用条件。
- 已完成操作与产物引用、未决依赖、待确认或 outcome_unknown 的真实状态。
- 覆盖区间、来源哈希、父摘要版本、未覆盖区间及原文取回入口。

工具调用与对应结果按完整记录处理，不能剪出孤立的 tool 消息或破坏 JSON。摘要保留可核对标识，表达语义由模型处理；没有读取的材料不能记成已阅读全文。

结构化覆盖只证明源区间关系，不证明语义完整。关键约束是否保留必须通过压缩后真实接续样本验证，不能用摘要短了或字段齐全替代。

### 5.2 摘要模型与尾部各自有预算

摘要调用使用自己的 provider 能力、输出预留与完整请求预算。主模型能容纳 100 万 token 不代表辅助摘要模型也能一次读取；按摘要模型预算分块，保留区间边界，禁止截掉半段后仍标记整段已覆盖。

摘要与回放从同一实际保留边界派生。覆盖、尾部和待补取区间要能核对，避免空档与不必要重放。摘要输入可以小于尾部，验收对象是累计折叠区间的覆盖和恢复能力。

不能只取最新一份局部摘要就丢掉更早索引。长期接续保留有效摘要节点及来源目录；合并时保存父子关系、覆盖和旧约束，避免重复概括逐步改变原意。超过预算的节点按需检索，不自动全部注入。

### 5.3 原子提交与并发

1. 短事务冻结来源清单、工作上下文 revision、父摘要版本和授权/取消屏障，取得有界租约。
2. 在事务外调用摘要模型。压缩费用归属触发它的 turn/目标或明确维护作业，同一次调用不重复计费。
3. 提交前重查租约、来源哈希、版本、失效状态与权限；以预期父摘要版本比较并提交。
4. 覆盖记录、摘要节点和工作指针在同一事务推进。旧后台结果不能覆盖新纠正或更新后的指针。
5. 重复请求使用已有有效结果；恢复检查点时再次核对来源。前台已转话题的结果只更新仍有效的原工作上下文，不抢回当前回复。

撤权、删除与用户纠正需检查摘要的传递来源，而不只检查直接父摘要。尚未提交的旧作业同样受失效影响。

### 5.4 有界等待、失败与防反复触发

优先在后台维护可用摘要，降低前台临界压缩的等待；压力闸在每次真实调用前兜底。模型等待在事务外，前台等待有明确时间预算。

一次实际请求默认最多进行一次压缩尝试；分块计划也有总调用、时间与费用上限。压完重新计量，仍高于目标但低于硬上限时可以带有效上下文继续，并记录未达目标原因。

超时或失败时保留原文、有效摘要与覆盖状态。利用已验证摘要、完整引用和按需展开收边；最终请求仍须符合 B_hard。必要内容无法容纳或无法可靠估量时给出真实限制，不能以“沿用旧摘要”直接发送超限请求。

按工作上下文、来源版本与模型路由记录失败冷却和无进展状态。同一失败输入不能每轮重新触发；provider 确认溢出时可做一次受总预算约束的恢复，不无限重发。晚到摘要也只能按 §5.3 提交。

### 5.5 遗漏回执与恢复入口

本轮纳入、折叠、排除、失效和读取失败分别记录。涉及当前回答所需材料而未完整注入时，模型能看到覆盖范围与可用取回入口；可直接恢复读取，不靠日志承担认知边界。

不把每个无关条目的排除都变成免责声明。对用户说明影响本次回答的实际阅读限制；正常回答不固定插入“你被截断了”。40c 的注入面缺口随本层一起补，不能因窗口放大后触发少而延期。

## 6. 后台任务参与同一成长闭环

### 6.1 应用经验与贡献经验双向接入

| 入口/作业 | 执行时读取 | 可以贡献的依据 |
| --- | --- | --- |
| 当前交流 | 当前请求、相关记忆与方法 | 明确长期要求、具体纠正、有来源的共同事件 |
| 持续目标与复合任务 | 该目标工作快照、相关方法与有效偏好 | 实际能力组合、成功/失败回执、有效替代及后续反馈 |
| 制卡、拓展、速看、演示等专业任务 | 冻结材料、领域合同和相关合作/生成经验 | 具体审核反馈、内容核验、失败条件与修订效果 |
| 学习反馈与练习相关任务 | 当前题目、真实作答和领域评价合同 | 可核对的错误与解释反馈；生成内容不能充当用户已掌握的证据 |
| 日记、主动表达与关系整理 | 按需读取允许的经历、偏好和表达经验 | 有来源的表达及具体用户反馈；角色感想不成为事实或独立成功证据 |
| 摘要、记忆重整与经验提炼 | 有效来源快照、已有经验版本及派生关系 | 来源整理、冲突与修订关系；自身摘要不算新的独立支持事件 |
| 解析、索引、embedding 与确定性维护 | 必要作用域、来源版本和资源治理 | 真实处理结果；不为接入 Agent 增加无必要的模型规划或反思 |

页面按钮与伴星调用使用同一经验体系，不要求用户先开聊天。领域模板、正式评分、候选审核和提交条件继续由领域承担；方法中的步骤不能扩大工具权限或复用旧授权。

### 6.2 从依据到后续效果

~~~text
真实运行结果 / 用户明确纠正 / 具体评价
    → 冻结来源与版本
    → 提炼有适用条件的经验或方法候选
    → 按 40 / 42 现役准入采用、修订或保留候选
    → 后续相关请求读取并实际采用
    → 关联真实结果与具体反馈
    → 保留、缩小范围、修订、停用或替代
~~~

明确长期要求按已有准入规则生效；模型推断仍保留其认识状态。沿用用户确认、固定、手动修订、拒绝和来源抑制规则，不新增每个后台任务都要用户批准经验读取的流程。

提炼不以每句话后强制反思为默认。由新有效来源、具体纠正、值得复用的过程或重复问题触发；幂等绑定来源版本和提炼策略，无新依据时不重复分析。后台提炼失败不阻塞当前交付。

方法记录标题、适用条件、有效步骤、参数选择依据、例外、失败原因与替代路径、能力版本、来源、版本和状态。现有按能力目录生成的方法步骤可作候选骨架，不能冒充已经提炼了这次真实做法。

失败运行也可能贡献可核对经验，不仅提炼 completed 的成功路径。临时供应商故障、未知结果和确定不适用分别表达，不能凭一次失败把能力永久判死。成功提交证明操作发生，质量与用户满意度需另有依据。

### 6.3 实际采用与效果归因

复用现役方法、版本和使用记录。区分目录被提供、正文被阅读、经验被实际用于步骤/参数/表达，以及后续效果；阅读次数不能直接记成采用或有帮助。

采用记录关联经验/方法 ID 与版本、turn/run/job/step、应用位置与当时来源。下次查询只读当前有效版本；已开始的调用保留固定快照，新纠正从下一次尚未开始的调用生效。

效果来自可核对的返工、失败、领域验证和具体用户评价。无回应、停留、点击、落库成功及模型自评不自动记作正反馈。语义判断可以辅助归因，但要保留依据、相反证据和评阅结果。

### 6.4 防止经验互相证明与覆盖新决定

保存完整派生关系，识别共同原始来源。摘要、日记、记忆候选和方法若源于同一次事件，只算同源依据；不得把模型重述或后台反思再次包装成独立佐证。

提炼和效果作业提交前检查原始来源及最新经验版本。用户控制或固定的条目不由后台擅自覆盖；冲突按现役合同并存、标争议或另提修订。纠正、遗忘和撤权传递到派生经验及其未来采用。

成长作业保持后台额度、租约、总执行上限和账号资源治理。属于特定目标的开销归入该目标；跨目标整理有自己的维护记录，不重复向多个目标记账，也不占满交互车道。

### 6.5 贯穿验收示例

用户指出：“这批卡把公式的适用条件删掉了。”系统关联反馈、对应材料与候选卡版本，形成“讲解/制卡涉及该类公式时保留原文适用条件”的有来源经验，避免泛化为所有输出都要更长。

下一次页面直接发起相关制卡也能读取并采用该经验；记录方法版本、实际应用与新卡来源。通过内容核验和具体反馈检查条件是否保留、返工是否减少。用户本次要求简短时仍保留必要条件；用户后续纠正或停用后，后续请求不再采用旧版本。

## 7. 工程落点与迁移

| 层 | 承担职责 |
| --- | --- |
| shared | 预算、计量可信程度、上下文快照、覆盖/来源、经验采用与效果的共同合同 |
| agent-core | 扩展现有 ContextPlan/composeAgentContext；纯预算解析、计量端口、完整记录准入、压缩计划与调用前校验 |
| agent-host | 现役来源解析、事件/经历索引、摘要覆盖、工作指针、租约与原子提交、方法/经验版本及失效传播 |
| worker / API 宿主 | 实际 provider 能力与序列化计量适配；模型调用、领域材料/任务上下文、队列和公共执行内核的组装 |
| renderer | 沿 42 的真实任务与成长视图展示来源、结果、纠正和停用；保留草稿与焦点，不向用户暴露上下文内部操作 |

预算权威采用通用 Agent 上下文职责，扩展现役模块；不另建一份仅伴星使用的 companion-context-budget，再让其他入口复制。core 不导入 provider、数据库、worker handler 或 UI；实际 tokenizer、usage 与存储通过端口注入。

覆盖所有实际模型调用面，包括 API 专业调用、worker 任务、编排与辅助压缩。复用 41a 的执行内核、检查点、有限重试与事务外调用，专业链路不为学习经验新增第二套模型循环。

保留 conversationId 及目标身份，不建立原 44 所提的单一用户滚动摘要表。按覆盖清单、父摘要、工作指针和来源索引的真实存储需求制定迁移；复用现役记忆、方法、回执与事实，避免无限复制私人正文。

历史摘要缺少可信覆盖或完整派生关系时，只作历史线索，不能补写成“全部覆盖”。历史回填按可访问原文核对；同一恢复尝试的已提交快照保持可验证。RLS、删除/撤权、导出和清理路径随新增派生关系一起迁移。

过渡读取与旧路径须有明确切换条件；确认无运行入口与有效依赖后按项目规则清理，不长期保留两份预算或摘要权威实现。

## 8. 验收：容量、接续、隔离与质量分别证明

### 8.1 完整请求与模型能力

- [ ] 相同材料在小/大窗口路由下得到对应预算；缺少平台配置时有明确能力回退和计量可信程度。
- [ ] system 很短但工具 schema、历史或单次工具结果很大时也能触发治理；多模态未知成本不记零。
- [ ] 硬上限、80% 触发线和压缩目标口径一致，无重复 0.8 或系统/工具开销重复扣减。
- [ ] 输出配置被省略/忽略、usage 缺失、缓存命中、补取材料、重试和允许的备用模型切换均有对应检查。
- [ ] 当前已接受请求、明确操作与关键引用保留；必要内容超限时如实给出可行动限制。

### 8.2 压缩覆盖与故障

- [ ] 多轮压缩后，更早的纠正、约束、对象、材料版本、待办与不确定性仍可恢复；使用真实模型接续验证。
- [ ] 摘要模型窗口更小时分块覆盖，无静默切片后宣称全段已读；尾部、摘要与取回区间可核对。
- [ ] 完整工具调用/结果关系与 JSON 保留；outcome_unknown 不被摘要改成完成或失败。
- [ ] 并发压缩、重复入队、超时、失租、迟到结果与重启恢复不覆盖新指针、不重复提交。
- [ ] 失败有界与冷却有效；降级仍检查完整请求，无法容纳时不无限重发或静默丢掉要求。
- [ ] 原始来源被纠正、删除、遗忘或撤权后，父子摘要、索引、经验与缓存同步失效。

### 8.3 跨会话与后台隔离

- [ ] 新会话能按需找到旧话题/方法并补取来源，两个会话的同号 seq/桶不碰撞。
- [ ] 任务 → 家常 → 任务按当前请求回应；后台保持原要求，查询进度不重新生成。
- [ ] 同一用户并发两个目标时，要求、材料、授权、预算和指针各自归属；迟到事件不抢前台。
- [ ] 换空间保留人格与允许的一般偏好，具体任务、经历和方法仍按现行范围隔离。

### 8.4 后台经验闭环

- [ ] 聊天和页面直接发起的相关专业任务都能采用同一有效经验，并保留实际使用版本与位置。
- [ ] 一次具体纠正可以追溯到原成果，后续采用有结果证据；“目录提供/阅读”不冒充采用或有用。
- [ ] 可核对失败与替代路径能够提炼；一次临时故障不形成无条件永久规则。
- [ ] 同源摘要、日记、候选和方法不增加独立佐证数；模型自评、沉默与提交成功不自动记质量正反馈。
- [ ] 修订、停用、遗忘与新要求从下一次未开始调用生效；后台作业不能复活被拒绝的经验。
- [ ] 维护故障不阻塞原交付，不扩大权限、不改正式评分、不占满交互容量。

### 8.5 质量、成本与工程验证

采用同批已核对任务做有/无相关经验对照，记录模型、路由、prompt/方法版本、材料、难度、来源、样本量和评阅标准。至少覆盖公式条件保留、讲解偏好及本次例外、新材料方法复用、失败替代和撤回。

分别报告内容错误、同类返工、重复解释、无效工具调用、压缩语义损失、等待与成本；维持可比的任务完成范围。冷启动对照与持续使用观察分开，样本与缺失用量公开，不能以记忆增多或输入变短宣称长期改善。

代码实施后执行受影响包的 npm run typecheck，至少覆盖 shared、agent-core、agent-host、api、desktop-client、ai-worker；选择相关单测、来源/RLS/并发/恢复实库测试和真实模型接续样本。需要全量回归先记基线，区分既有与新增失败。

窗口验证跨会话找回、前后台切换、长交付、来源/成长纠正与停用；界面验证、数据库验证和真实语义质量分别记录。本次文档修改不视为这些验收已经通过。

## 9. 实施顺序与阶段交付

| 阶段 | 交付内容 | 独立验收重点 |
| --- | --- | --- |
| 1：作用域与完整计量 | 确认所有调用入口；扩展通用合同、能力解析、完整请求计量与快照，保留现役状态边界 | 小/大窗口、未知用量、工具增长、输入保留、实际模型参数 |
| 2：可靠压缩与跨会话检索 | 来源清单/索引迁移、摘要接续与分块、原子指针、调用前压力闸、失败冷却、遗漏/取回闭合 | 压缩后接续、同号桶、并发、撤权、超时与恢复 |
| 3：后台经验应用与产出 | 专业任务读取相关经验，来源事件接入提炼，方法采用/效果关联，纠正与失效传播 | 页面入口与聊天同用经验、失败学习、同源去重、撤回 |
| 4：效果与交互验证 | 同输入对照、持续使用观察、成本/等待数据、现役任务和成长界面的真实窗口验证 | 质量与返工是否改善，当前意图、范围与权限是否保持 |

各阶段沿同一真实调用链交付，不能以纯函数通过代替调用面接线。预算与压缩先支撑当前交流、持续目标和专业生成，再逐类补齐其他后台作业；原业务生成保持可用，成长处理是可降级的独立工作。

43 的带路体验继续按原文接续 42；本次增加 44 的上下文与成长实施阶段，不把 43 的视觉交付当成 44 的完成证据，也不要求先完成视觉体验才治理现役上下文。
