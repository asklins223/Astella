# 51 · 拾星笔记 App 与小程序：随身伴星与便携书房

日期：2026-10-10。本文交付产品定位、能力范围、页面与交互、数据互通要求及验收方案；本次未实现移动客户端。

## 0. 已确认的产品决定

用户已经明确：

1. App 与小程序都以伴星为中心，界面精简，两端共用一套 UI 与逻辑代码。
2. 伴星承担产品中的操作，包括新增笔记、读取用户上传的文件、读取图片、修改笔记与讲解知识。
3. 移动端与桌面端的业务数据和伴星聊天数据互通，手机可以实时、方便地看和学。
4. 移动端是桌面客户端的便携版本，通过伴星完成实际操作，并提供适合手机情境的独属功能。
5. 预览与讲解是重要呈现方式；产品结构可以按移动情境重新设计。
6. 视觉参考用户提供的 Muse 玻璃面板与伴星居中布局，保留项目的色彩与身份，以实际可实现的组件构图。

本方案按完整 Agent 能力组织产品，精简导航与专门功能页。新增、上传、读图和修改属于核心交付，不能因没有完整桌面编辑器而推迟为只读版本。

以下页面布局、操作反馈与分阶段安排是本轮设计建议；具体框架与平台接入需工程验证。能力事实、权限、版本、保存和正式学习边界继续沿用现有领域合同。

## 1. 产品定位

**随身伴星：把同一位伴星、同一份交流与同一间书房带到手机上，随时问、随手递、随时看、接着学。**

用户可以让伴星找资料、看文件、读图片、解释知识、创建笔记、调整正文、准备学习内容，并接着追问。伴星读取真实材料、调用产品能力、交付真实成果；移动界面围绕当前交流和成果展开。

桌面端适合大空间阅读、编辑与多项工作；移动端适合临时发现一个问题、拍下一份材料、在短暂空闲中理解一小段，以及离开书桌后的继续学习。两者使用同一账号、空间、笔记、资料、图片、对话、任务和成果。

本方案建议围绕三种价值安排产品：

- **随手交给它**：拍照、传文件、说一句话，伴星完成读取与实际操作。
- **当下看懂**：对话、原文、图文与声音连贯，读不懂可以立即打断和追问。
- **回到哪里都能接上**：电脑上的交流和操作手机实时可见，手机产生的内容回到电脑继续使用。

以伴星为中心体现在操作入口、持续身份、交流与结果关系。见面时角色突出；交流时给连续对话让位；阅读和学习时给原文与讲解让位。角色始终可找到，不能为了始终显示大形象而把聊天和正文挤成小窗口。

“伴星操作一切”是产品内的统一操作入口：实际能力通过共享目录与领域服务接入，依用户意图、权限和真实可用状态执行。普通问答不自动保存笔记；讲解不自动算作掌握；学习卡和拓展候选仍按领域规则审核。

### 1.1 典型使用情境

| 用户说／做 | 伴星应完成 | 最终看见什么 |
| --- | --- | --- |
| “把刚聊的知识整理成一篇笔记” | 创建独立笔记、核对保存结果 | 新笔记正文、已保存回执、打开入口 |
| 递来 PDF：“读一下这份资料” | 上传、解析、按实际覆盖范围阅读 | 文件状态、内容预览、解释与出处 |
| 发一张图片：“这道题讲一下” | 读取图片实际内容、解释 | 原图、题目识别与解题讲解 |
| “把这篇笔记第二段改成一个表格” | 定位笔记和原段、修改、确认持久化 | 已修改的正文、变更摘要与对照 |
| “用简单的例子讲讲熵” | 根据问题回答，必要时使用已开放能力 | 可读／可听的知识讲解 |
| “找上周写的那篇，补一个例子” | 搜索 → 读取 → 修改 → 核对 | 原笔记的真实更新 |
| “这份资料整理成笔记，再讲一下重点” | 处理依赖，保存笔记后基于真实结果讲解 | 同一件事的进展、新笔记与讲解 |
| 换回桌面端 | 读取同一份业务数据 | 手机刚创建和修改的内容 |
| 电脑回复到一半，拿起手机 | 实时读取同一轮回复和操作进展 | 相同文字、内容块、任务与成果继续到达 |
| 拍下书上一张图并圈出一处 | 结合实际图片与圈选区域解释 | 原图、所指区域、讲解与后续笔记 |
| “先记住这个想法，晚上继续” | 按明确意图保存短记或待看项 | 手机和电脑都能找到、继续处理 |
| 在路上只想学一小段 | 从真实材料讲当前一处，允许主动暂停和复述 | 有来处的短讲解和可接续位置 |

### 1.2 成功体验

用户能说清要做什么或递来材料，随后知道伴星正在操作哪个对象、做到哪一步、结果是否保存，以及从哪里继续。移动端完成的操作和聊天可在桌面找到；桌面修改、消息与进展在移动端取得真实状态。

手机拿起来就能找到当前交流与手边内容；短暂使用也能完成有意义的一步；长内容可以认真阅读；回到桌面不需要复制粘贴、重讲背景或再导入材料。

精简不能牺牲成果可读性、必要的用户决定、暂停／停止、异常恢复或权限边界。

## 2. 能力范围与首批交付

### 2.1 核心能力必须完整闭环

| 能力 | 移动端要求 | 业务结果 |
| --- | --- | --- |
| 知识交流 | 文字、语音、追问、换种解释、举例；无材料也可聊天 | 同一份连续对话与回复 |
| 新增笔记 | 根据讨论、文件、图片或明确要求创建；支持标题、列表、表格、公式与代码 | 保存到当前空间，默认本人可见，真实笔记身份与来处 |
| 查找和读取 | 搜索实际可见笔记、资料与已有成果，按版本及真实范围读取 | 可核对的正文、出处和引用 |
| 上传文件 | 选择文件加入草稿，发送后上传、解析、读取；逐份表达成败 | 桌面可访问的共享资产与解析结果 |
| 读取图片 | 相册／文件图片，已有材料中的图片；拍照入口按实际能力接入 | 同一图片资产、识别与解释 |
| 修改笔记 | 追加、指定位置插入、替换、删除指定段落、整篇格式整理；可把文字改为表格／流程图 | 原笔记正文和搜索投影更新，真实持久化回执 |
| 图文与语音讲解 | 原句解释、整篇要点、图文、对照原文、朗读及主动打断 | 绑定真实材料／回复的讲解 |
| 任务和成果接续 | 查看进展、修改要求、暂停、继续、停止、打开结果 | 同一目标、任务及产物身份 |
| 跨端互通 | 两端直接使用统一服务端数据；操作无需桌面保持打开 | 桌面与移动读取同一对象和状态 |
| 实时聊天接续 | 同一账号／空间的同一条消息持续更新，工具进展与成果同步 | 电脑正在回复时手机可读，手机追问电脑可见 |
| 手机捕捉与学习 | 拍照圈问、语音随手记、边听边看、回到原处接着学 | 使用共享资产、笔记与记录的移动体验 |

新增笔记不要求先有一篇旧笔记；修改笔记不要求用户先打开完整编辑器。对象唯一且要求明确时，伴星直接执行。目标不明确才提供简短的对象选择。

### 2.2 产品的其他能力按同一机制接入

速看、思维导图、互动演示、知识拓展、学习卡、复习相关读取、日记、念想、人格／记忆及偏好等，继续复用全项目 Agent 与实际能力目录。移动端不以固定页面白名单裁掉可用能力。

需要用户审核、正式作答或选择的领域，打开相应的精简纸页：候选学习卡逐张决定，拓展笔记逐篇收下，练习由用户本人作答。伴星可组织流程、解释和执行已授权动作，不能把自己的答案写成用户的正式学习证据。

每项能力接入要同时具备请求、对象、真实执行、必要决定、成果阅读和失败恢复。已有领域 API 尚未成为 Agent 工具时补齐共享能力合同；不能仅显示聊天建议或宣称已完成。

### 2.3 精简界面的方法

首页不陈列完整来源库、笔记编辑器、学习卡后台、星图和设置菜单。用户通过伴星表达目标，通过内容纸页阅读和核对结果，通过必要的小控件做选择。

首批完整闭环为“上传／读取 → 讲解 → 新增笔记 → 修改笔记 → 桌面读取”。其他能力沿同一产品结构逐步接入，不另建另一套交互与数据。

公开分享、后台持续播放、整库离线同步等独立体验另行设计，不作为核心操作的前置条件。适合手机的功能先围绕拍照、声音和接续组织，不增加另一套独立知识库。

## 3. 信息架构

~~~mermaid
flowchart LR
    H["伴星主画面：说话／输入／递材料"] --> I["统一 Agent：理解目标与选择能力"]
    I --> T["实际操作与任务进展"]
    T --> D["交付纸：结果、保存回执与下一步"]
    D --> R["内容纸页：文件／图片／笔记／演示"]
    R --> H
    H --> C["选已有内容／上传"]
    H --> J["对话手记／交给我的事"]
    D --> J
    J --> H
~~~

用户始终围绕同一位伴星和同一份交流活动。纸页依用途展开，功能通过当前目标出现，不要求先选“聊天／学习／编辑模式”。

主画面拥有可展开、可回滚查看的连续交流区，不把所有聊天只藏进手记。材料纸签依附当前交流，点开获得完整纸页；收起后仍看得见与这份材料的对话。手记负责检索、旧记录、任务与完整过程。

主画面展示当前回复与正在查看的一件事。其他任务在“手边的事”和手记中可找到，不把全部后台工作叠在角色身旁。

材料、消息、任务、成果各有自己的身份。切话题不会默默取消任务；切纸页不改变已经提交的操作；收起不是停止。

![真实页面：材料处理、修改对照、小程序布局](assets/51-mobile-companion/09-layout-upload-edit-miniprogram.png)

用户指出前一轮玻璃不明显、角色又缩成图标，并要求避免常驻背景区侵占阅读。本轮以真实 HTML/CSS 交互稿取代生成式界面图：现有书房底图铺在整个界面下方，不单独占高度；120px 宽的伴星模型取帧居中可见，输入时收拢；聊天与操作面透出环境，长文使用更厚的磨砂底。以上是浏览器实际截图，消息、任务、保存与音频仍为本机样例。已检查 54 组屏幕／字号／状态及草稿保留、长文滚动、修改对照、发送、停止；真机键盘、Live2D、实时服务及账号互通尚待实现。详见 [交互稿与验证记录](assets/51-mobile-companion/README.md)。

### 4.1 伴星主画面

顶部菜单与手记之间是伴星入口：交流时角色宽 120px，姓名玻璃签位于角色下方；角色区共 132px，正文从其后正常布局。阅读时改成 94px 角色与侧边姓名签，顶部收为 100px；输入时角色宽 78px、顶部收为 76px。短屏键盘态进一步收拢，收起键盘后恢复。空间入口位于右侧，小程序宿主胶囊另行避让。环境为整个界面的底层静态图，不设置独立风景栏；“接着学”和当前材料明确来处，不把每条消息都强制绑定它。

主画面随用户正在做的事改变比例，不提供模式开关：

| 用户此刻的事 | 主要空间 | 伴星与控件 |
| --- | --- | --- |
| 打开、见面、没有长回复 | 角色、当前内容和接着看入口 | 可辨认的完整角色，自由输入直接可用；不先放一块风景 |
| 正在连续聊天 | 最新对话与足够的上文，向上可看更早记录 | 角色与姓名签居中，环境仅作底图，输入稳定 |
| 阅读资料、看图片或核对修改 | 可读纸面、来处、当前选择与结果 | 角色退到纸页上沿／页边，当前交流可就近展开 |
| 正在听讲解 | 当前讲解段落、相关图文与播放反馈 | 角色表达配合实际声音，暂停和提问可达 |
| 键盘展开或字体放大 | 输入、引用和正文 | 角色改为紧凑布局，短屏限制输入框增长；草稿可滚动 |

变化跟随最新意图，不重建会话、不清草稿，也不把角色收成只有导航按钮。

底部只有一份输入草稿，包含文字、麦克风和“＋”递材料入口。“＋”展开文件、图片及已有内容引用；拍照在宿主可用时加入。附件缩略图／文件签放在输入上方，可以查看、移除、替换。手边材料、事项和历史分别从菜单、手记及“＋”进入，取消常驻三个去处行。播放时同一区域换为音频控制，主动提问后接同一输入。

玻璃由有层次的背景、半透明底、亮边、内侧高光、轻阴影与局部模糊共同表达。聊天大面约七成白底，阅读大面约九成白底；交互稿使用静态模型取帧，避免同时运行角色动画和大量动态模糊。移动宿主再按性能选择模糊或更实的浅底，不能以滤镜支持为可读性的前提。软键盘打开时缩短角色区域，输入跟随实际键盘边界；顶栏、正文和底栏都占据正常布局空间，文字不从控件背后穿过。

“选内容”“对话手记”和“手边的事”保持轻量。首页没有完整功能网格或固定四栏导航。当前对话可以直接滚动查看；检索旧话或事项时再打开手记。空空间也能发文件、读图片、聊天和让伴星新增笔记。首次进入不自动开麦、发起任务或播放旧回复。

### 4.2 附件草稿与内容选择

文件签显示文件名、类型、大小与当前状态；图片显示完整可辨认的缩略图。选择附件只准备输入，不自动创建笔记或发布为共享资料。发送前用户可以配文字，也可围绕选定附件说话。

已有内容选择只承担查找和引用：当前空间、最近使用、笔记／资料类型、标题搜索。通过自然语言找得到唯一对象时，可直接读取，不强制先走选择页。

发送请求的材料身份固定。随后切空间或换内容不会把正在上传的附件静默挂到新空间。多份材料各有状态，失败项可单独重试；成功项不因某一份失败重复上传。

### 4.3 做事经过与任务纸签

操作发生后显示简短真实进展：“正在上传”“正在读取”“正在补写这段”等。只有真实工具调用才产生“做事经过”；正文与过程可同时到达。

持续任务有短目标、进展、已有成果与调整入口。暂停、继续和停止由状态及能力决定；完整要求、过程和旧成果在手记。百分比只用于有真实总量的传输，不能给未知生成进度编造百分比。

### 4.4 一次回复的交付纸

一轮回复共用一张交付纸，按内容显示可读正文、成果预览、目标入口与回执：

| 结果 | 直接显示 | 按需展开 |
| --- | --- | --- |
| 新增笔记 | 笔记标题、可读预览、真实“已保存”、打开笔记 | 关联材料、相关笔记与处理经过 |
| 修改笔记 | 实际改动摘要、修改后的内容、保存状态 | 修改前后对照、原版本、恢复路径 |
| 文件读取 | 文件名、实际读取范围、解释与原文入口 | 页码／段落、未读或解析失败部分 |
| 图片理解 | 原图与可读解释 | 放大、定位相关区域、识别不清的地方 |
| 学习产物 | 实际成果与待决定状态 | 完整阅读、审核或正式作答纸页 |
| 部分完成 | 已有成果和未完成部分分别表达 | 错误原因、核对、重试剩余步骤 |

保存标签只来自服务端持久化回执；伴星说“写好了”不能替代保存事实。文字回复失败时已经保存的笔记仍可打开，不能误报整件事全失败。

### 4.5 内容纸页与伴星编辑

内容纸页承担文件、图片、笔记与讲解的完整阅读。当前对象和来处清楚，目录、出处、大图和宽内容按需展开，阅读位置可恢复。

笔记纸页提供“让伴星改这段”和“继续补写”等就近入口，但用户在主画面说“改《某篇笔记》”也能直接操作。移动端不依赖完整格式工具栏；新正文、表格、公式、图片和代码由同一文档呈现。

“先给我看看怎么改”只产生可应用的草稿与对照，用户明确应用后写入。“把这段改成表格”已经交代实际修改，对象与范围确定时直接执行，不多加例行确认。

执行时在相应段落显示工作状态，保持其他内容可读。原文已变化则停止过期替换，保留改写内容，并提供读取最新版后重新调整的入口。

### 4.6 对话手记与必要设置

手记沿用连续记录、交给我的事与实际待决定项。回复、任务、成果和附件都能定位到真实对象。“接着聊”带入同一输入草稿；翻历史不自动发言或生成。

账号、空间、AI 同意、声音、动效与真实能力状态收在头像或空间胶囊后。人格、记忆等管理可以由伴星定位并打开必要内容，选择、纠正和撤回仍有明确的用户操作。

### 4.7 适合手机的独属功能

建议优先设计下面五项。它们都把材料、笔记和记录留在同一间书房；桌面能够读取结果，移动界面拥有更适合情境的发起方式。

| 功能 | 具体体验 | 与现有能力的关系／交付要求 |
| --- | --- | --- |
| **拍照圈问** | 拍书页、题目或图表，圈出“这一处”，直接问；原图与所指区域一起可核对 | 复用图片资产与读图，补区域引用；圈问不靠破坏原图替代 |
| **语音随手记** | 说“把这个想法记成笔记”，先保存忠实短记，之后让伴星整理或补充 | 实际创建笔记、桌面可见；短内容不能为凑篇幅虚构补写 |
| **边听边看** | 一边听伴星讲，一边看到当前段落和相关图片；随时说“这个地方再讲一下” | 语音分段和图文关联可靠后接入；当前提问带上实际所指内容 |
| **一小段学习** | 对一份材料选择“先讲这一点”“举个例子”“我来讲一遍”，每一步可以独立使用 | Agent 讲解、示例与复述反馈；保存真实练习内容，不冒充正式评分或掌握 |
| **接着学／手边待看** | 把一处内容留在手边，下一次或另一端继续；待看项可以聊、读、整理和移除 | 共享材料引用、用户私有待看与接力位置；不自动建立复习计划 |

首批把拍照／传图、语音记录、前台边听边看和接力纳入交互验证；小段学习与待看整理可以沿同一纸页逐步交付。入口出现在用户当下需要的位置，不另加五个常驻大按钮。

App 可以通过实际支持的系统分享或文件转入把网页、文件和图片递给伴星；小程序通过宿主实际支持的转入方式进入同一附件草稿。具体宿主能力需验证，接入后都走共享材料与任务链路，不创造第二份对话或来源。

产品默认优先保证前台的可读、可听、可打断。锁屏听课、定时提醒或主动推送可以后续设计，不能让“边听边看”的首版依赖后台常驻。

## 5. 上传文件与读图片的完整路径

### 5.1 文件：选择 → 上传 → 解析 → 读取 → 操作

1. 用户递来文件并提出要求，发送后出现与该文件绑定的上传状态。
2. 服务端接收并登记共享资产，返回真实身份；上传成功只代表文件已接收。
3. 解析任务提取正文、图片与可靠的页／段落定位，分别表达已解析、部分解析或失败。
4. 伴星按当前要求读取实际可用内容，长文件按任务需要续读，并保留覆盖信息。
5. 回答、讲解、生成笔记或修改已有笔记，均继续使用这份材料的真实引用。
6. 交付纸能打开原文件／解析预览及成果；桌面手记与对应材料入口能找到同一资产。

首批目标格式为文本、Markdown、代码、PDF 与 Word（.docx），具体格式、大小、加密文件和页数限制来自统一合同。旧格式和无法解析的文件明确说明原因与下一步，不静默丢弃或截断。

扫描 PDF、图片页与文字提取失败的页面要识别出来，再按可用图像理解能力处理并标明范围。未读完时不能声称“全文已读”；跨页表格与图文顺序需要样本验证。

### 5.2 图片：实际读图后再讲解

图片上传后使用现役资产身份和读图能力，图片、解释与后续笔记指向同一对象。不能只根据文件名或用户问题猜图里写了什么。

识别不清楚的区域明确指出，可让用户补图、换清晰原图或指定局部。图中的题目、公式、图表与截图可以继续解释；用户明确要求时再整理为笔记或插入已有笔记。

拍照圈问同时保留原图身份与区域位置；圈选和放大只改变所指范围，用户能取消或调整。后续“旁边这条曲线”需回到实际原图核对，不能只记住一张无来处的裁切图。

### 5.3 上传材料与正式资料区分

会话附件成为当前账号与空间内可核对的资产，可在桌面查看同一消息与附件；它不因上传就变成公开资料或新笔记。

“收录为资料”“根据这份文件创建笔记”等明确操作才产生相应来源／笔记业务对象，并保留附件、解析内容和成果之间的关系。会话文件读取与空间资料创建分别沿用实际权限；只读空间不能借上传绕过资料和笔记写入规则。

移除未发附件不会删除用户已有资料。重试沿同一提交身份核对资产、解析任务和后续写入，避免形成多份重复笔记。

## 6. 新增笔记与修改笔记

### 6.1 新增笔记

用户说“把刚聊的整理成一篇笔记”，伴星利用当前讨论和真实材料生成独立正文，按现有规则检索、读取相关笔记并附真实关联。没有相关内容时可以保存独立笔记。

新笔记保存到当前有权限的空间，默认本人可见。服务端确认后，交付纸直接提供新笔记正文和入口。无需用户进入笔记库按“新建”，也不要求为了保存再重复说一次同意。

任务重试返回同一已创建对象；后续“补个例子”修改这篇真实新笔记，不能每次创建一篇副本。用户只要求回复里的总结时，继续作为对话交付。

### 6.2 修改笔记

目标可以来自当前纸页、用户选择的内容、上一轮新笔记，或本轮实际搜索／读取的唯一笔记。目标和位置不用依赖某台桌面当前打开的页面。

读取当前版本 → 确定原段与用户范围 → 生成改动 → 核对原文和版本 → 通过已有协同文档服务写入 → 确认持久化 → 更新正文、搜索和交付纸。

局部修改绑定可靠段落和原文；全文格式整理依据整篇实际内容；追加不要求手机提供桌面光标。插入光标等位置存在时可沿用，但不能凭模型猜测坐标。

### 6.3 冲突、对照和撤回

桌面同时改了同一段时，过期替换停止，移动端保留拟改内容和最新原文，用户可继续要求合并。不得用整篇覆盖把另一端改动抹掉。

修改结果可以查看前后对照。撤回本次修改沿真实版本／补丁合同执行：先检查之后是否有新改动，再恢复相应内容，返回保存回执；不能为了撤回局部操作直接覆盖整篇最新版。实施时补齐这条恢复路径，提供的按钮必须有效。

“停止”只影响尚未完成的工作；已落盘的新增或修改仍保留，实际状态分别说明。写入结果未知时先查询和核对，不能自动再做一次。

## 7. 知识讲解、自由交流与复合目标

无材料的问题可以直接讲知识；有引用时按实际需要读取。用户可以从“讲讲这个概念”转到“写成笔记”“再改这段”，身份、交流、材料和成果连续。

讲解文字、图文与声音属于同一条回复。原句、查阅片段和联网来源按现行交付语义呈现；联网仍受账号开关与真实服务状态约束。

用户要求“读这个文件，整理成笔记，再给我讲重点”时：

- 上传与解析是阅读依赖，界面如实等待；
- 伴星读取材料后创建笔记，核对真实保存；
- 讲解使用刚保存的笔记／原材料，成果直接可打开；
- 任一步失败保留已完成部分，用户可继续剩余步骤；
- 不要求分三次发消息或切换三个功能模式。

用户“先别写了，我想问个问题”立即接当前意图；停止写入与转话题依明确要求处理。旧后台完成不能替换新回复、抢焦点或抢声道。

移动学习默认由用户选择当下需要的深度：一句话先懂、一段解释、展开完整纸页，或“我试着讲一遍”。伴星针对用户的实际复述给出具体反馈，再按明确要求继续讲、记笔记或安排已开放的学习动作。无需每次固定走“生成提纲 → 讲解 → 测验”。

声音不是把整篇正文机械播放一遍：当前讲解段落、相关图文与来处可以就近对照。用户选择边听边看时，实际语音分段能定位所讲内容；手动滚到其他部分不被持续强拉回来，提供轻量“跟着讲解”入口。

## 8. 交流、工作与语音状态

材料上传、解析、Agent 执行、本机播放、收音与纸页展示各自有状态，不能用一个“忙碌”同时锁住全部界面。

| 状态 | 用户看到什么 | 可做什么 |
| --- | --- | --- |
| 附件准备／上传 | 文件签或图片缩略图，真实状态与错误 | 移除未发项、重试失败项、保留文字 |
| 正在解析 | 该文件的解析状态，部分内容可用时明确范围 | 查看已得内容、取消未完成步骤、继续聊天 |
| 消息尚未接受 | 保留输入，显示发送中／未发出 | 核对后重试 |
| 已接受、正在执行 | 当前动作、真实进展和已有成果 | 改要求、看已有内容、明确停止 |
| 正在修改／保存 | 目标笔记和相关范围，等待真实保存 | 看其他内容、停止剩余工作 |
| 完成或部分完成 | 对象、成果、保存回执与未完成项 | 打开、追问、核对、重试剩余步骤 |
| 正文已有、声音准备中 | 文字先可读，声音入口表达等待 | 读文字、继续等、改用文字 |
| 正在朗读／暂停 | 实际播放状态与对应角色表达 | 暂停、继续、重听、我想问 |
| 正在收音 | 字幕及明确收音状态 | 说好了、暂停、结束、改用文字 |
| 结果未知／版本冲突 | 保留已有内容，不宣称失败回滚 | 查询、对照、重新定位 |
| 离线／失权 | 失败在对应位置，受限内容不继续展示 | 保留草稿、换材料、恢复后核对 |

暂停音频、停止任务和收起纸页是不同动作，名称和回执明确。收起不取消服务端已经接受的操作。

“我想问”立即停止本机旧声音与说话动作，进入新输入或收音；提交后按最新回合处理旧输出。旧内容留在手记，取消提问可主动继续原讲解。结束收音不发送未完成内容。

返回前台不自动开麦或播放旧回复。首版不依赖锁屏播放、后台常驻和推送完成操作；服务端接受的工作可以继续，重进查询真实状态。

已经取得原声的重听不重新生成正文。历史原声跨端访问需要接齐音频存放与权限；没有录音时保留文字，重新朗读须明确是新朗读。

## 9. 与桌面端的数据互通

### 9.1 同一套业务数据

~~~mermaid
flowchart LR
    D["桌面端"] --> S["统一身份、API、Agent 与领域服务"]
    A["App"] --> S
    M["小程序"] --> S
    S --> B["同一空间：笔记、资料、附件、图片、任务、成果与历史"]
    B --> D
    B --> A
    B --> M
~~~

同一账号与空间使用同一笔记、版本、协同文档、资料、图片资产、对话、任务、成果及允许的伴星身份与记忆。移动端创建或修改直接提交现有服务端事实，不通过导入导出或另一套手机数据库再“同步回去”。

**聊天互通是核心交付。** 同一账号、同一空间的桌面端、App 和小程序使用同一份连续聊天：相同消息身份、用户原话、伴星正文、引用、图片、工具经过、成果和实际决定。来源设备只用于识别宿主和事件归属，不另分一套“手机聊天”。

手机操作不要求桌面正在运行。文件解析和笔记写入需要能在共享服务链路独立完成；桌面上打开过的页面、光标或本机缓存不能成为移动端执行的隐藏前提。

### 9.2 哪些状态同步，哪些属于本机

| 共享事实与记录 | 本机呈现状态 |
| --- | --- |
| 笔记正文、版本、分享范围、来源与关联 | 当前展开的纸页与阅读位置 |
| 上传资产、解析状态、图片与内容引用 | 尚未发出的草稿与键盘焦点 |
| 对话、任务要求、进展、成果及实际决定 | 正在播放／收音与本机音量 |
| 持续身份、允许的一般习惯与空间经历 | 当前场景大小、性能与动效偏好 |
| 用户私有待看项及可主动接续的阅读／学习位置 | 当前是否跟随讲解、临时圈选和未发附件 |

另一端更新笔记时，按协同／版本合同更新内容与状态；原解释保留其依据，提示可以按新内容再讲。变化不自动把当前讲解切换到另一条任务。

另一端发消息或完成工作，实时更新所属交流、历史和成果。当用户正看当前交流末尾时直接接入同一消息；正在翻旧记录或读其他材料时给出轻量新内容提示，不抢阅读、声音和焦点。

换空间重新核对材料和权限；含引用草稿留在原空间，用户可明确只带走自己输入的文字。换账号清理旧展示、订阅、音频和待发引用。一般伴星身份可连续，具体材料与经历不能跨来源泄漏。

### 9.3 保存与重试

每次上传、解析、创建和修改都绑定稳定提交身份与真实对象。断线重试先核对是否已经接受或保存；已经创建的笔记直接返回同一对象，不能再造副本。

移动端显示“已保存”后，桌面重新查询必须取得相同对象及正文；协同场景中接入实际文档更新。桌面正在显示旧内容时明确版本状态，并有刷新／接续路径。

业务提交成功后回复失败，成果仍是成功成果；只有接收增量或动画结束都不足以显示“已保存”。

### 9.4 实时聊天如何接续

用户在电脑提问，手机打开当前交流后，可以看到本轮文字、工具状态、图片和成果逐步到达，无需等整轮结束或手动导入。手机接着追问，电脑同一记录中出现这条用户消息及回复。

断线重连先以持久消息与执行快照补齐，再接事件增量；同一内容不能重复追加，旧快照不能倒退当前状态。切空间后旧事件只更新其所属记录，不能污染新空间的主画面。

两端同时发问时，每条请求保持自己的身份与回执。现役并发限制需要核对并明确呈现；不能通过复制消息或静默覆盖草稿解决竞争。用户明确停止同一任务时，各端看到相同停止结果；本机麦克风和播放不会因另一端单纯查看而开启。

文字、图片与操作回执属于共享聊天。桌面已有的历史原声目前使用本机缓存，需要补齐受权限约束的共享音频路径才能承诺跨端播放原声；没有原声时同一文字仍可读，新的朗读明确标识。声音表达沿同一角色和实际回复，不另生成一份聊天正文。

### 9.5 接着学的产品行为

“接着学”读取当前材料、可靠的段落／页位置、所指解释及用户已经做过的一步，呈现一个可主动继续的入口。可以从手机回电脑、从电脑回手机，也可以只在手机继续。

接力位置和待看项是用户私有的接续信息，与资料身份及版本绑定；不是掌握标签、正式评分或复习计划。版本变化后核对锚点，无法可靠定位时保留原片段并让用户选择最新内容。

多个设备各自的当前视口独立。共享位置作为继续的候选，不强制另一端跳页或改写它正在使用的本机阅读位置。

## 10. 共用 UI 与逻辑代码

| 共用移动端实现 | 宿主适配 |
| --- | --- |
| 主画面、附件签、做事经过、交付纸、阅读与对照组件 | 顶部胶囊／导航、安全区与系统返回 |
| 草稿、材料引用、任务控制和成果打开 | 文件选择、相册、拍照和传输 |
| 操作／保存／冲突／重试状态规则 | 凭据存放、网络与生命周期 |
| 收音与播放的语义、互斥和打断 | 录音、播放、音频中断与权限 API |
| 伴星身份和表达状态 | 角色运行、资源加载、设备性能 |
| 内容块、领域决定与阅读行为 | 实际渲染容器、键盘、大图与宽内容查看 |

App 与小程序具有相同伴星定位与核心操作路径。App 作为常用的已安装入口，小程序作为便捷进入同一书房的入口；入口、授权和宿主资源条件可以适配，业务能力和事实不因外壳另分等级。

两种宿主运行同一组页面和控制逻辑，平台差异通过能力接口注入；不能各自写一套新增笔记、上传重试或修改合同。

服务端继续使用共享能力目录、统一 Agent、执行治理与领域事实。桌面与移动可以有不同布局，但不能有不同的保存语义、权限判据或成果身份。

目前桌面 DOM、Electron IPC 和本机解析器有宿主耦合，需要按真实依赖提取或改接服务。具体框架须用双端最小样例证明：角色、附件、纸页、中文输入、语音与真实接口都能接通，再做选型。

## 11. 原文、权限与领域边界

| 内容／动作 | 必须核对 | 对用户的表达 |
| --- | --- | --- |
| 文件和图片 | 实际资产、当前权限、读取覆盖与图像清晰度 | 读过哪些、哪些不可读、来处在哪里 |
| 笔记读取 | 实际正文、版本及可见性 | 原文、摘录和 AI 整理区分 |
| 笔记创建 | 当前空间写入权限、真实来源与保存结果 | 已创建对象直接打开 |
| 笔记修改 | 目标、原文、范围、版本和持久化 | 改了哪里、是否保存、冲突如何继续 |
| 学习卡与拓展 | 候选、审核与正式保存各自身份 | 待决定动作直接可见 |
| 正式练习 | 用户本人作答、真实评分与记录 | 伴星的解释不冒充用户答案 |
| 跨端接续 | 相同账号／空间、稳定任务与版本 | 继续已有工作，不重复生成 |
| 声音与动画 | 实际收音／播放／执行状态 | 表情只补充反馈，不替代回执 |

用户明确交代新增或修改，范围确定且权限允许时直接执行。只有对象歧义、超出已交代范围，或领域合同要求本人决定的动作才呈现必要选择。日常写入不增加层层批准纸页。

AI 同意、图片外发与联网开关沿用账号级规则；未授权时解释真实受限能力。上传、一般知识回答和业务写入的权限分别核对，不借“伴星能做”突破空间角色规则。

失权或删除的内容不因旧预览／旧附件继续展示。旧版本解释保留依据，无法定位时回到旧片段，不凭相似文字猜新位置。

## 12. 已核对的基础与需要补齐的链路

本次源码核对只证明以下入口存在；没有移动端运行或能力全面验收结论。

| 现有入口与事实 | 移动产品需要补齐 |
| --- | --- |
| agent-capability-catalog 与 companion-agent-registry 使用共享目录；工具依权限和政策过滤 | 移动宿主接入相同目录，领域能力和成果路径逐项覆盖 |
| companion_create_note 有真实创建、稳定身份与保存回执 | 移动请求、生成进展、新笔记直接阅读与桌面可见 |
| companion_edit_note 经 API 的协同文档服务写入并确认持久化 | 从对话搜索出的目标也能编辑；脱离桌面 page_context 依赖，可靠选择与冲突恢复 |
| companion_read_image 和伴星图片上传已有资产引用 | 移动上传／拍照、语音结合附件、清晰度与错误恢复 |
| companion_read_source 能续读并报告未解析状态与范围 | 用户新上传文件的统一解析、页／段定位及 Agent 读取 |
| 桌面 PDF／docx 导入包含本机解析；来源接口主要接收正文／URL | 建立双端可用的文件上传和解析链路，保留原文件及关联，不依赖桌面启动 |
| 当前回合输入为文字加可选单图，语音不携带图片块 | 扩展共享材料引用合同以支持文件、多材料和“对着图片说话”；三端共同理解 |
| 连续历史、工具事件、任务及丰富内容已有合同 | 移动订阅、断线恢复、多设备迟到事件隔离和领域成果打开 |
| 桌面实时语音及本机历史原声已有链路 | 前台边听边看、材料定位、共享原声策略与音频中断 |
| 原文版本与引用已有合同 | 拍照区域引用、短记、用户私有接力位置与待看项 |

不能把“服务端已经能读 source”当作“手机已经能传 PDF 并读全文”；不能把“有编辑工具”当作“任意对话目标已脱离页面约束可编辑”。这些接入差距属于本方案核心实施工作。

## 13. 首版交付顺序

| 阶段 | 具体交付 | 通过条件 |
| --- | --- | --- |
| 双宿主与共享链路验证 | 同一主画面、连续交流、附件签、纸页、现有账号、真实资料与文字请求 | App 和小程序运行共用组件与控制逻辑；电脑与手机看同一轮实时回复 |
| 核心实际操作闭环 | 文件／图片上传与读取、知识解释、创建笔记、修改笔记、交付回执 | 一轮能“读文件 → 新增 → 修改 → 桌面看见”，桌面关闭时仍可完成 |
| 语音与移动学习 | 语音结合材料、随手记、字幕、边听边看、暂停、重听、打断，角色随实际播放表达 | 连续真机多轮，旧音频不抢新问，附件与语音引用正确，当前段可核对 |
| 数据接续与领域覆盖 | 拍照圈问、接着学／待看、跨端更新、版本冲突、任务恢复、其他 Agent 能力与必要决定纸页 | 逐项核对能力目录；接力可用，没有假完成、丢失成果或被 UI 裁掉的操作 |

分阶段推进实现与验证，首版产品范围包括用户明确要求的写入和上传。第一阶段的最小样例只用于验证，不作为另一个只读产品发布口径。

每项能力同时交付可操作 UI、真实执行、成果与失败恢复。新能力加入共享目录和领域合同，再按用途复用交付纸与精简决定纸页。

## 14. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 打开与空空间 | 先见伴星；能聊天、递材料和要求新增；无自动开麦或发任务 |
| 新建笔记 | 明确要求即可创建；正文和保存回执可读，桌面可打开同一 noteId |
| 连续修改 | 对刚创建的笔记补写／替换，更新原对象，不重复建副本 |
| 搜索后修改 | “改上周那篇”能查找、读取和写入，不要求打开桌面编辑器 |
| 文件上传读取 | 上传／解析／读取分别表达，实际格式与覆盖清楚，桌面可访问同一材料 |
| 图片理解 | 使用真实资产读图，解释对应原图，不根据文件名猜图 |
| 语音问附件 | 问题、文件／图片、原文引用进入同一真实回合，不丢材料 |
| 多份材料失败 | 成功项保留，失败项单独重试，不重复上传或创建笔记 |
| 复合目标 | 上传、读取、保存和讲解按依赖接续，一轮完成或给出真实部分结果 |
| 改正文回执 | 通过同一文档服务保存，正文与搜索更新，已广播不冒充已持久化 |
| 冲突与撤回 | 两端改同段时不覆盖新改动；对照、重新调整与撤回有真实结果 |
| 停止／结果未知 | 已保存成果保留，未知先核对，不因重试再写一遍 |
| 权限与 AI 同意 | 账号、空间和外发规则一致，受限动作可解释，无越权写入 |
| 学习事实 | 候选审核和正式作答由本人决定，预览讲解不自动算掌握 |
| 讲解与打断 | 暂停接续实际声音，打断立即停旧播放，旧回执不抢新回复 |
| 收起与后台 | 收起不取消任务；回来可恢复；不自动收音或重播 |
| 跨端数据 | 手机写入桌面取得；桌面改动手机取得；同一版本／权限／任务事实 |
| 实时共享聊天 | 两端读取同一消息；正文、工具过程及成果逐步同步，重连不重复、不倒退 |
| 多设备交流 | 共用历史，当前焦点、未发草稿和声道不被另一端强制切换 |
| 手机随手使用 | 拍照圈选指向原图，语音短记真实保存，一小段学习可随时结束 |
| 接着学 | 主动恢复真实材料与位置；改版有核对；不误记掌握或正式成绩 |
| 连续交流与构图 | 聊天不藏在历史入口里；角色随任务让出空间，长回复和键盘下仍可读 |
| 移动独立执行 | 桌面进程全部关闭时仍能上传、读取、创建和修改 |
| 触摸与无障碍 | 键盘、字体放大、减少动态、快速操作下正文与关键操作可达 |

主验收旅程：电脑与伴星讨论到一半 → 手机实时看到同一段交流 → 上传一份含图 PDF → 让伴星解释一个知识点 → 说“整理成笔记” → 再说“把第二段改成表格” → 打开真实修改结果 → 桌面找到同一笔记、材料与聊天 → 桌面修改一段后手机继续问它 → 核对冲突、版本和任务恢复。

第二条移动旅程：拍下书页 → 圈出一处问伴星 → 边听边看 → 中途提问 → 语音说“把刚才这点记下来” → 留一个接着学位置 → 下一次在手机或桌面主动继续。核对单手可达、短时间使用的完整性和实际保存结果。

同时用真实图片题目、长文本、Word、部分解析文件、只读空间和弱网络核对。质量以是否完成真实操作、依据是否正确、用户是否知道保存结果为准，不用关系等级或功能按钮数量替代。
