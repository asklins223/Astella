> 日期：2026-09-27；修订：2026-09-30。本文定义目标运行合同，实际覆盖度按当前调用图与验证结果核对。

> 范围：约束归属、运行/供给/表达分层、失败状态、工具派发与恢复、调用预算、账号人格装配、诊断回放及层边界守卫。

## 1. 约束的分层与审计

### 1.1 从实际合同盘点

盘点现役人格、任务、日记、抽取、摘要与工具提示，记录版本、来源和装配位置。字节数、否定句数与重复要求只作复杂度诊断，不设“人格否定句必须归零”的验收。

CortiSoulmate `ORIENTATION.md` 明确包含 Never claim、Do not expose 等否定规则；它的 `CORE.md` 可由模型工具读取，不能描述成只给开发者看的文档。Cormini 与 Soulmate 的文本、权限和记忆协议不同，也不能用一份种子长度概括全部 Bot。

### 1.2 表达问题是待验证假设

过度限制长度、堆重复禁令或只给教学示例可能损害回应，但“18 条禁令导致嘿嘿”“关闭思考只能模式匹配”都不能由源码确定。使用相同输入、模型与配置比较改动，保留失败样本；模型档位、输入供给、上下文、工具路径和提示词都是变量。

审计的目的在于消除冲突、重复与职责错位，不把字数下降当自然度提高，也不把第一人称当连续性的证明。

### 1.3 约束该在哪一层

| 合同 | 主要保障 | 模型仍需知道什么 |
| --- | --- | --- |
| 登录、账号同意、数据范围、业务写权限 | 公共上下文/工具边界与领域服务复查 | 当前可用范围、拒绝原因及替代动作 |
| 参数、协议形状、调用预算、版本与幂等 | schema、任务内核、ledger 与领域提交 | 如何正确调用、状态是否确定 |
| 来源引用与实际完成 | 输入身份、引用解析与真实回执 | 不把引用材料当新指令，不把未知说成完成 |
| 秘密、隐私与文本索取 | 不提供越权能力、限制输出、必要语义指导与评估 | 不索取凭据、不披露私人内容；缺工具不能单独保证文本合规 |
| 尊重拒绝、不施压、表达相关 | 简短提示、正确上下文、语义评阅 | 正向默认与具体场景示例 |
| 任务专属格式 | 任务输出合同 | 在该通道采用的格式；不与宿主展示协议互相覆盖 |

不存在“所有约束都归 persona”的通则。安全授权和业务条件不能随风格覆盖改变，语义约束也不能因为难写正则就删掉。

### 1.4 六项审计动作

1. **登记每条要求。** 标目的、适用任务、来源版本、保障位置与可检验证据；行号仅作定位，不能成为稳定合同身份。
2. **迁移已有机械保障的重复叮嘱。** 先证明工具/服务真实覆盖该边界再删；没有取回工具仍可能用文字索取密码，不能按工具缺席宣称已经保障。
3. **给语义边界正向默认。** 不施压对应“用户拒绝或离开时接受选择”；不确定事实对应“查来源或说明不确定”，不强制所有失败都说不认识用户。
4. **消解跨任务冲突。** `HOST_PROTOCOL` 与 `GROUNDED_TUTOR` 等按实际展示通道说明格式差异；协议形状由 schema 管，角色风格不另写相反规则。
5. **集中可编辑文本与版本。** 日记、抽取等任务提示按职责登记，不混成一份人格；本轮实际装配版本可复现。
6. **守住职责而非词数。** 用权限、工具路由、格式和提示装配契约的测试防回退；新增约束需有理由与样本，但不以否定句或闸的数量只减不增阻止必要修复。

### 1.5 模型补救的退出条件

短句重跑、额外自检、启发式分类等若用于当前模型，必须记录适用配置、触发条件、实际质量收益、成本、回退与退出条件。模型或 provider 改变后复验，收益不足时删除，不叠成永久规则。

权限、隔离、版本、防重复提交等产品不变量不随模型增强取消。借鉴 Cortico `PHILOSOPHY.md` 的“当前妥协作为 fallback”，而非用它消除安全边界。

## 2. 运行、供给与表达三层

### 2.1 统一底座的目标

公共底座处理一次任务能否可靠、可控地执行；伴星领域决定本轮有哪些背景、怎样回应及何种记忆可用。底座改善可能降低空响应和恢复错误，表达改善仍需单独验证；不能宣称统一底座必然改善或必然不影响体验。

### 2.2 各层职责与模型配置

| 层 | 负责 | 当前复用点与核对要求 |
| --- | --- | --- |
| 公共运行 | 任务身份、模型传输、预算、输出解析、取消恢复、来源权限、工具登记与回执 | 41a 与 `ai-task-kernel.ts`；逐调用方核对覆盖，不沿用历史完成数 |
| 领域供给/提交 | 材料、笔记/选区版本、真实事件、记忆来源与期限、动作授权和业务幂等 | 现役上下文装配、领域服务与工具 ledger；提交前复查 |
| 表达与陪伴 | 人格、文风、相关记忆使用、日记选材、主动表达 | 40；不能拥有最终权限或学习事实写入权 |

模型/思考配置按任务选择。交互记录端到端等待与首个有效反馈，后台记录准确性、成本和排队影响；共用总预算但可分队列，后台不能挤占交互资源。思考开关不等于判断能力开关，开启也不保证质量。

在当前 provider 上验证流式/非流式正文、结构输出、超时、用量与不透明恢复句柄，再比较可用档位。旧“非流式开思考会空正文”的记录只作待复验故障线索，不自动当永久禁令。没有证据时保留现役可用配置；有明确收益后再调整。

### 2.3 确定性边界与语义评估

代码可验证参数、来源 ID、权限、回执存在与协议状态，无法单靠正则保证全文没有虚构，或两个汉字重合就表示记忆正确。事实内容与自然度需要语义评阅和失败样本。

不因普通回复短、无问句、开头相同或未提召回记忆自动增加调用。真正截断、无效输出可按 41a 有界处理；尊重拒绝、人物理解和相关性问题不能靠无限重跑掩盖。

### 2.4 公共权限与 persona 的分界

1. 人格、记忆目录、表达手册与声音在领域侧；公共层只装配有身份和版本的任务输入，不携带具体角色常量。
2. 不同任务可声明不同工具子集，同一工具的行为与权限契约不随人格改变。模型可选择建议，不可自行授权。
3. 来源访问、账号同意、工具参数、权限复查、幂等与执行回执属于公共基础和业务服务。persona 的提示说明这些事实，但不能替换检查、更改权限档或扩大记忆可见范围。

### 2.5 主动触发与真实依赖

| 项目 | 真实依赖 |
| --- | --- |
| 文风与语义评估 | 实际提示词装配与固定协议，不等待所有调用方统一 |
| 记忆自动准入/判断/手册 | 来源、期限、本人范围、现役工具服务与版本提交 |
| 交接/后台整理 | 水位快照、ledger、租约与 revision；不等待周期重整 |
| 失败与送达状态 | 运行结果与交付服务的真实信号，不要求平台具备真正已读 |
| 层边界守卫 | 当前被抽出的公共接口及调用方，随迁移同步维护扫描范围 |

区分可独立触发的授权提醒/用户操作，和只可搭便车的普通念头、表达经验或日记结论。`surface` 结论和 ordinary thought 不因生成/到期就启动新对话；需要有效的可打扰触发再注入。用户已明确约定的提醒仍按自己的调度与送达合同执行，不能误归搭便车而漏送。

当前静默时段、预算、反馈等量限制继续生效。是否存在类型限制须按现役调用图核对；空闲检查可按收益退避，不为了维持心跳产生模型调用或消息。

## 3. 缺失与失败表达

### 3.1 可借鉴的机制

Cortico 为折叠、超预算、缺回执、未执行、重启与流中断提供明确标记，截断时修复调用/回执配对。本项目借鉴状态完整性，不要求照搬英文文本或向用户展示内部标记。

回放和交接保留相关应答边界及真实执行状态；隐藏推理不因参考实现保留而纳入本产品采集。

### 3.2 状态合同

| 状态 | 含义与下一步 |
| --- | --- |
| folded / omitted | 内容因预算未注入，保留来源与可按需读取入口，不能假称完整阅读 |
| not_executed | 从未开始执行，含权限拒绝、参数无效、屏障或取消原因 |
| unavailable | 所需资源或能力不可用，指出实际影响及可用替代 |
| pending | 已开始且未完成，给运行身份和查询方式，不冒充成功或安全重试 |
| outcome_unknown | 可能有副作用但未取得确定回执；先查账/核对，禁止盲目重复 |
| failed / completed | 有确定失败或业务完成回执，只宣称对应范围 |

使用稳定结构化类别与安全摘要；模型可见的标记在上下文中，页面用确定性文案和恢复入口，二者对应同一运行身份。普通后台过程无需逐步弹给用户，但不能把失败伪装成留白或完成。

折叠阈值按输入、工具结果和素材类型分别声明，并记录实际 token/字节占用。权限/同意读取失败不能用旧摘要或默认风格绕过；可选图片/TTS 失败可保留文字与来源明确的正文。

失败状态包含时间、范围、已完成部分和可恢复条件；后续模型据此接续。区分读取暂时失败与记录本来不足，不制造“我不认识你”的假记忆缺失。

### 3.3 验收

覆盖全部状态与页面/模型的一致性。权限撤销、取消与未知副作用不得落 completed；不重复已有完成动作。文本失败有即时状态，TTS 失败不抹掉文本，日记失败与空素材明确区分。对可选能力持续不可用时准确调整可用入口，不伪造替身或完成。

## 4. 延迟、工具派发与可选自检

### 4.1 先测关键路径，再选择优化

记录排队、装配、模型首个有效输出、完整模型步、工具执行、提交、交付与 TTS 的分段时间，报告 p50/p95、失败/取消样本和实际用量。重叠、子步骤截止、减少不必要工作都可按证据选择，不存在必须按固定顺序完成的通则。

**（1）流中提前派发：先只读，满足合同再考虑写。**

Cortico `EagerDispatch` 按 `output_index` 处理完成项、校验完整参数、串行调用 handler、按 call id 配对，并由 `barrierAfter` 挡住后续调用。闭合参数不等于所有业务前置成立。本项目启用前必须满足：

- provider 有可识别的完成事件且参数完整合法；不能从流式 JSON 片段、猜测调用名或越过输出序号缺口执行。
- 工具先登记到持久 ledger，校验 schema、任务范围与执行时授权，记稳定操作身份及参数指纹；已有 `(run_id, tool_call_id)` 与领域幂等能力优先复用。
- 顺序、屏障、确认、取消、租约和输入版本照常生效。需要用户确认的工具不能提前执行；确认门之后的调用不得越过。
- 重试即使 provider 给新 call id，也不能重复已提交业务操作；业务操作身份跨 attempt 保持，不能只靠 call id 去重。
- 回执落存与调用配对；流中断保留已经执行的结果，未开始写 not_executed，可能执行但不确定写 outcome_unknown。重启先核对 ledger/业务结果再决定续跑。

第一批仅对无业务副作用、可取消的读取工具测收益。写工具只有在上述生命周期与故障用例通过后开放；提前派发本身不免授权或确认。所获收益取决于生成/工具重叠时间，并非工具越多必然收益越大。

**（2）子步骤截止：可选读取降级，写入核对实际结果。**

Cortico 的 3 秒是 World 延迟渲染等待，不是所有业务工具的期限。保留现有任务、租约和总预算，再给实际慢步骤设独立截止，向下传播 abort。

可选召回/图片读取失败可在来源明确的前提下继续，必要输入不足则准确失败。写操作超时不能假造 fallback 成功；需确认 aborted 且未提交，或记录 pending/outcome_unknown 并核对。迟到结果在提交前复查取消、租约、权限和内容版本；已经发生的外部副作用不能假称回滚。

**（3）减少重复与不必要调用。**

空素材零调用、选择/成稿各自检查点、有效状态可查询、已完成工具可复用，都是减少等待和成本的路径。恢复从已保存状态继续，而不是重发所有事件。检查点必须匹配任务/提示词版本、输入快照和权限；用缓存不能延续已撤销的授权或过期页面状态。

### 4.2 Cortico 的起草-确认为何存在

QQ World 的 `qq_draft` 先准备外部发送，屏障后让模型读期间新到的 QQ 事件，`qq_confirm` 再发送或取消；未确认草稿在轮次结束后丢弃。这解决外部 IM 与动态事件下的发送决定，不证明普通请求式聊天每条回复都需要第二次推理。

本项目**默认不为最终文本额外增加自检调用**。已有工具对话循环与“草稿再评一次”是不同机制。保留自检为可验证实验能力，不作为首发必做或人格存在的证明，也不取代权限和业务确认。

### 4.3 如需实验，明确收益与成本

仅对已观察到、单次响应难以改善的特定问题比较单次与自检策略，使用相同素材、模型和任务版本。预先声明语义质量、端到端 p95、成本、取消率和故障目标，使用盲评与完整失败样本。

自检最多新增一次有预算的调用，无收益或等待不合格就撤回。自查模型也可能错；首句更长、问句更多不算质量提升。与思考配置和流中派发分别改变，避免同时改多个变量后无法判断归因。

### 4.4 实验作用域与草稿生命周期

| 场景 | 默认策略 |
| --- | --- |
| 日常陪伴对话 | 不增加专门自检调用；按 40 回应意图、允许收尾 |
| 日记 | 选择 → 成稿两步及发布检查点，无额外强制自检 |
| 念头/后台整理 | 独立任务预算，可无表达；不因生成结束唤醒对话 |
| 教学/正式作答 | 按 41 与独立作答合同，非人格自检门接管 |
| 记忆与业务工具 | 参数、来源、授权、确认、幂等、revision 与回执，不能靠自检代替 |

开启实验时草稿有任务/输入/人格版本和截止时间，保持不可见、未送达；只有确认后的最终版本进入对话/TTS。期间新输入、取消、权限或材料改版需重新核对，陈旧草稿不得发送；废弃草稿不变成对外发言或后续日记素材。错误有确定性状态，不再增加一次模型调用解释失败。

### 4.5 验收

验证开启/关闭路径、额外调用上限、陈旧/未确认草稿不交付、TTS 仅对应最终版本。报告有无实质质量收益及其延迟/成本；未达到预先目标保持默认关闭。流中派发分别覆盖序号缺口、无效参数、屏障、确认、流中断、重启、授权撤销、取消和重复提交。

## 5. 账号人格装配与可编辑范围

### 5.1 已有能力与目标能力

现役 `packages/shared/src/companion-persona.ts` 提供默认文本，`pet_profiles` 已有名字、风格与示例等配置；完整自由文本编辑与版本装配是目标能力，不能概括为“用户现在只能改代码”。

Cortico 的 module → bot → deployment 同名模板替换适合本地部署。多人共用服务时 deployment 属部署实例，不等于用户账号；不能把私有人格写入共享部署目录。

### 5.2 装配优先级与隔离

| 部分 | 归属与装配 |
| --- | --- |
| 固定协议/身份事实/安全与来源规则 | 随代码发布、有版本；账号编辑或模型修订不可替换 |
| 默认角色表达 | 随代码发布，可被账号表达文本整体替换 |
| 账号表达覆盖与 examples | 私有账号持久化，经本人设置入口编辑；跨空间一致，按 40 优先于默认风格 |
| 空间关系、判断、记忆、日记与任务状态 | 按 `(workspace_id, user_id)` 和当前任务权限装配，不能写入账号表达覆盖 |
| 当前用户意图 | 本轮生效；优先于适用表达偏好，不能自行改变产品权限 |

“整份替换”只作用于可编辑表达模块，不作用于最终合成 system prompt。固定协议由装配器分开持有并保持边界；自由文本中的越权声明不产生真实工具权限。示范用于风格，不作为当前用户经历或授权来源。

恢复默认撤销账号表达覆盖并采用当前发布的默认版本，保留必要修订身份供本人核对；不把空文本当有效覆盖。只恢复声明的表达项，不误清名字、开关或空间记忆。

### 5.3 版本、审计与生效

1. 账号覆盖含 `profile_revision`、作者、时间、适用模块与当前/待生效状态，旧版本按既有保留/删除规则保存。用户可查看自己那份及恢复。
2. 每次调用绑定固定协议版本、默认表达版本、账号 revision、示例 revision 与任务提示版本。模型自改下一会话生效；用户明确编辑可在下一轮未开始调用生效，详见 40 §4.8.4。
3. 共享运行日志记录装配版本身份与安全元数据，不写私有文本。必要的内容指纹与原文只能留在受本人权限保护的版本/回放存储，不对外导出可识别私有内容的材料；不因“私有”取消版本元数据。
4. 稳定协议/人格前缀可按版本复用缓存；当前请求、页面、权限、撤权与订正是动态输入，缓存不能冻结这些变化。先满足正确性，再验证缓存收益。
5. 默认或表达版本不可用时使用有版本的可运行默认并显示实际情况；同意/权限失败按公共授权边界拒绝，不回退放行。

### 5.4 验收

两账号共用部署互不影响；本人换空间使用同一账号表达，空间判断和材料不串入。能查看当前/待生效文本，恢复默认与版本来源可辨；固定协议和工具权限不被覆盖。已发生调用可按合法保留的版本复现装配，普通日志和对外诊断不泄漏私有正文。删除/撤权规则同时作用于旧版本和缓存，不以可复现为由无限保留。

## 6. 可观测、诊断与回放

### 6.1 常驻诊断入口

提供 runs、log/timeline、turn、doctor 和受控 bundle 的查询能力，复用当前 run/job/conversation/tool ledger 与交付身份，不另建一套业务日志真相。支持按本人/空间/任务筛选，数据访问与保留按既有规则执行。

doctor 只读核对任务状态、租约、可用工具、配额、失败类别与链路缺口，输出简短 Markdown 和定位身份。大日志按行流式读取与有界尾部缓冲，单轮展开有大小和时间预算。

### 6.2 层边界守卫

Cortico 的公开专有词表可作简单补充；本项目优先验证公共层不导入人格/业务模块、公共接口不暴露私有人格/领域写入口、注册范围和授权契约正确。静态词表不能证明这些事实，注释命中也不一定是违规。

新增/拆出公共模块时同步维护扫描范围；依据契约覆盖其全部承载文件，不因搬文件让守卫读少了或测试空断言。正反样本证明能抓真实违规，也能接受合法抽象。测试放 `__tests__/`，不以专有词数或否定句数量的 ratchet 代替层边界。

### 6.3 私有回放与对外诊断分开

| 用途 | 可包含的内容 |
| --- | --- |
| 本人有权限的私有 turn 回放 | 输入来源/版本、实际注入片段、assistant 产物、工具调用与安全回执、任务/交付/TTS 时间线及用量；按同意与保留规则访问 |
| 对外 issue / bundle | 默认元数据、失败类别、用量与去标识的最小复现；不含聊天、笔记、日记、判断、私有人格、原始工具参数或凭据 |

跨文字/TTS 回放用于区分“文本未生成”“已生成未交付”“TTS 未启动/失败/未播放”，不把 displayed 解释成已读。

**Cortico 的 `logq` 不构成可安全外发的证据。** 所检查 `turn` 会输出正文、推理与工具参数/结果，`bundle` 复制 runs 目录；配置的 `redactSecrets` 只覆盖特定键，不能去掉自由文本隐私。本项目不原样复制这类输出。

不采集隐藏思维链。provider 必需的不透明恢复句柄只按现有受控存储使用，不解码、显示或放进导出；选材理由等可见简短结论按普通产物处理。对外导出采用允许字段清单而非仅扫密钥词，检查嵌套回执、异常与文件名，预览实际包内容；不得宣称自由文本经过一次脱敏就能安全分享。

### 6.4 可选观察者与业务持久化分界

调试监听、统计与 UI 订阅异常隔离、限流并有健康状态，不让观测回调毁掉业务。可选日志失败可以丢弃并报警，不能假装所有诊断正常。

任务状态、业务回执、来源、版本与工具 ledger 是可靠执行合同，不能用 `try/catch` 吞掉写入失败后报告成功。区分“可选观察者失败不影响业务”和“业务必须保存的状态失败导致动作未确认”，禁止把 fail-closed 解释成静默成功。

### 6.5 连续失败跨重启

记录失败段的开始/最近时间、类别、次数、任务身份与恢复时间，跨重启保留有界状态，避免重启把趋势归零。首次恢复可在诊断中报告该失败段，用户侧只说明当前确需知道的影响，不重复播报历史故障。

失败状态不存无必要私人正文；用户删除、保留上限与去标识规则同样生效。趋势区分传输、输出、工具、交付与 TTS，不把全部计成“人格失败”。

### 6.6 全链路演练

按真实调用图串联用户请求、工具、记忆写入/召回、交接、后台整理、日记发布、主动消息、对话读回与文字/TTS。预算内仅替换外部模型/语音传输，可复现核心时序，不能把每层 mock 后宣称接线通过。

覆盖取消、重启、权限撤销、来源改版、双窗口去重、删除后迟到提交以及失败状态。必要隔离数据库测试验证事务与权限；实际桌面窗口检查 HUD、常驻伴星、长内容、空态/失败、缩放与键盘。真实模型样本补充语义评估，测试成绩不证明全部自然语言正确。

演练由相应业务调用方与 41a 公共边界共同承担，本文直接规定需要的样本，不将工作推回已失效的 39d，也不以历史集成测试数量作充分性结论。

### 6.7 验收

诊断能定位一轮失败及其实际完成范围；私有回放只向合法本人开放，对外包只有允许的最小字段。层边界守卫正反样本真实检验，观察者异常不毁业务，关键 ledger 持久化失败不假成功；连续失败段跨重启但服从删除/保留规则。

## 7. 实施顺序与退出条件

### 7.1 核对真实前置

列出现役模型调用、工具服务、任务与提示装配；复用 kernel、ledger、领域授权与 delivery。先修缺失的权限/状态/恢复合同，守卫随抽取公共职责一起做，不等待一个名为“统一完成”的阶段。

### 7.2 基础合同与可观测性

| 编号 | 工作 | 前置与验证 |

| R1 | 失败/执行状态与确定性呈现（§3） | 运行身份、业务回执；覆盖未执行、pending、未知和确定完成 |
| R2 | turn/doctor、观察者隔离与失败段（§6） | 现役运行记录、访问/保留规则；私有/对外输出分开 |

### 7.3 完善恢复与有证据的延迟优化

| 编号 | 工作 | 前置与验证 |
| --- | --- | --- |
| R5 | 检查点与恢复核对（§4.1） | R1；已执行工具不重做，取消/权限/版本变化不提交 |

| R8 | 写工具提前派发（有收益才做） | R7 全生命周期合同和领域幂等/确认/提交保障，不越过用户确认 |

### 7.4 按实验决定的可选项

| 编号 | 工作 | 退出条件 |

R10/R11 不要求所有提前派发都完成才可评估，也不能因低峰就自动全开。层边界与端到端演练贯穿 R1–R11，机制改变后重采受影响基线。报告实际接口与验证，不沿用旧台账的“已完成”。
