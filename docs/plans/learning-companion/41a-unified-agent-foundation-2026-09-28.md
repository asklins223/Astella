# 41a｜统一 Agent 基础：独立保留的技术方案

> 日期：2026-09-28  
> 状态：当前技术方向；实现覆盖度按调用图和测试核对  
> 来源：从已废弃的 39 §15.5 提取并重述。保留的是**公共运行能力与领域分工**，不是 39 的学习路线、页面、卡片优先级或未完成任务表。  
> 对应产品：[41 笔记与伴星学习体验](./41-note-companion-learning-experience-2026-09-28.md)。

## 1. 保留的目标

伴星、笔记解释、动态教具、制卡与开放回答评估不应各养一套模型调用、重试、任务恢复和审计逻辑。先从真实调用方抽出最小公共能力；不建设通用插件市场、任意工作流解释器或无限递归的多 Agent 平台。

统一的是**一次 AI 任务如何可靠、可控地执行**，不是把伴星的人格、笔记教学方法和评分标准混成一个提示词。每个任务仍要说明自己需要什么材料、能用哪些工具、怎样才算完成。

## 2. 公共层与业务层

| 公共基础负责 | 业务功能自己负责 |
| --- | --- |
| 模型适配与路由、调用预算、超时、有限重试、结构化输出解析 | 讲解的教学目标、伴星语气、制卡范围、评估依据 |
| 任务身份、尝试、检查点、取消与恢复、运行事件及用量 | “保存笔记”“接受拓展关系”“评估作答”等业务提交 |
| 上下文来源身份与权限检查、工具登记、参数校验、执行回执及防重复提交 | 当前笔记选区、教学材料、用户已授权的具体动作 |
| 失败类别与可追溯运行结果 | 在纸面、伴星对话、Live2D、语音、审核页上的表达 |

任务定义至少有 `id/version`、输入快照引用、所需上下文与权限、工具范围、输出合同、预算、完成条件。任务只拿必要材料，不把聊天全文、原始回答和所有笔记塞进同一份无限增长的上下文。模型结果只是**候选产物**；保存新笔记、改变排期、写入关系必须有对应领域服务的明确回执，不能由模型文字宣布成功。

## 3. 运行边界

- 准备与保存用短事务；模型和工具等待在事务外。提交失败不重复花一次模型调用；取消、租约失效、权限撤销或内容版本变化后不能继续写入。
- 同一任务按身份、版本和输入快照命中检查点；提示词或输出合同变了要升版本，旧产物可回放但不能悄悄当成新结果。
- 可重试与不可重试原因有一处权威分类：传输、超时和可修复的结构错误才考虑有界重试；权限、输入版本、实质质量问题不靠无止境重试掩盖。
- 交互对话、作答反馈、后台制卡可共用语义，但须分配额或执行队列；批量任务不能占满用户正在等待的反馈。
- 工具行为在服务端执行并复查授权。伴星或其他任务可以提出动作，但只有业务服务提交成功才上屏“已完成”；撤销与重复提交需可辨认。
- 公共层不承载人格、关系记忆、语音风格或产品文案。伴星的存在感与注意力边界由独立陪伴方案和 41 的页面协作负责。

## 4. 对当前代码的使用方式

`packages/shared/src/ai-task-kernel.ts` 已有任务定义、预算、失败分类、检查点和事务外执行合同；笔记教学及动态产物、制卡等位置已有调用。`jobs`、租约、模型传输、隔离产物呈现及部分领域事件也已有实现。**这不等于所有调用方已统一。** 开工先列出现役模型调用图，逐个核实伴星对话、笔记讲解/动态教具、制卡生成/检查和开放回答评估是否真正经过公共边界，以及失败、取消、迟到提交的测试覆盖。

复用现有内核与任务表时以代码实际行为为准；只把确属公共的职责迁入。保留领域内有用的持久化和权限判断；迁完一个调用方就删除其无人使用的专属执行循环、兼容分支和测试，避免新旧双轨。实施新的选区批注、拓展笔记及整份 AI HTML/SVG 时，业务保存和产物隔离仍分别由领域服务与安全宿主负责，不能让统一 Agent 变成万能写库入口。

## 5. 验收

用至少三类真实调用方证明公共层：一类生成/检查任务、一类开放回答评估、一类伴星工具对话；笔记自由形态教具也要经过同一预算和恢复边界。逐一覆盖成功、超时、输出无效、权限撤销、内容改版、取消、迟到结果、重试与重复提交。核对交互反馈时延不因后台批量任务变差；报告实际读数与样本量，不沿用旧 39 台账的完成声明。
