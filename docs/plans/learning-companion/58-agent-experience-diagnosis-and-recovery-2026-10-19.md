## 1. 三项验收目标

| 目标 | 用户需要的结果 | 必须覆盖的改造与验收 |
| --- | --- | --- |
| **速度** | 尽快得到有效回答和成果；等待期间及时知道在做什么、推进到哪里。 | 同时缩短实际耗时和感知等待：减少无效模型往返与执行绕路；及时呈现真实进度；已完成成果立即可用。分别记录首个明确反馈、有效正文首字、首份成果、完整交付耗时及不明原因的空等区间。 |
| **质量** | 回答当前问题，正确、完整，符合要求；让它做的事真实完成。 | 核对话题与对象、事实依据、数量、篇幅、内容完整性和真实产物。模型正常返回、格式正确和工具调用成功，都只是其中一部分证据。 |
| **稳定性** | 多次使用、长时间使用和异常情况下都可依赖。 | 常见请求重复执行不频繁报错；停止、重试、断线恢复、后台完成和切换话题行为一致；不重复写入，不丢已完成成果，不把未知结果宣称为成功。 |

三项同时验收。提速不能靠减少用户要求的内容或降低正确性；提高成功率也不能靠拒绝原本支持的常见请求。每次增加分类、审查或重试调用，都需要证明对这三项的收益和代价。

## 3. 速度：实际提速与感知提速一起做

### 3.1 缩短真实执行与交付时间

- 在已知任务的具体操作生成之前，准备相应的已授权能力。修复“要求创建笔记，候选操作为空，生成完再因缺工具被拒”的绕路；自由表达仍保留授权范围内的能力发现。
- 拆分统计分类、上下文装配、模型生成、工具执行、协议修复、结果核对和末尾总结的耗时，针对真正昂贵的步骤修改。不得将所有慢都归给模型或数据库。
- 已保存的笔记立即提供真实标题与打开入口，后续任务继续执行；完整成果可用后，不被额外总结步骤继续阻塞。
- 清理重复内部纠正和不相关任务背景，记录上下文各部分的必要性与体积。样本输入约从23,000增长到38,500 token，值得实测比较，但不能据此直接认定某次答错的原因。
- 模型、思考档位、传输方式和任务编排都是被测变量。使用同样请求、资料、输出要求和负载比较，分别报告时间、质量与失败；不预设当前模型一定足够，也不预设换模型必然改善。
- 后台反思、主动参与考虑、嵌入和语音等工作与前台请求核对资源争用，避免后台负载拖住正在等待的用户。

### 3.2 用真实反馈减少感知等待

**进度展示属于速度目标的必要部分，优先级与执行优化并列。** 用户应及时得到确认，持续理解实际推进，尽早使用已完成的部分。

| Before | After | Why |
| --- | --- | --- |
| 泛化的“正在执行工具”长期不变。 | 显示真实对象、阶段、已用时间和最近确认进展，例如“正在写唐朝笔记，已保存1篇”。 | 用户能够理解等待对应的工作与推进。 |
| 过程和步骤两层默认折叠。 | 当前过程与可读工作说明默认展开，历史查阅可直接读到关键过程；保留用户手动选择。 | 不需要逐层点击才能知道它在做什么。 |
| 等最终模型总结才看到全部成果。 | 每份已保存成果立即出现真实链接，余下部分继续推进。 | 用户更早获得可使用的结果。 |
| 延迟、重试和失败都像同一种转圈。 | 依据真实信号区分生成中、等待服务、正在恢复、失败和结果待核对。 | 降低不确定性，让用户知道是否需要操作。 |

输入后立即产生操作反馈；服务端接受请求后呈现明确的真实处理状态。阶段更新及时出现，文字与成果保持可读，避免跳动、自动折回或强行滚动打断用户。

进展暂时没有变化时，显示最近已知活动及持续时间。可先以10秒提示间隔、30秒明确说明延迟作为界面试验值；它们是展示策略，不是强制结束任务的时限。只在确有重试、切换或完成时显示对应状态，不编造阶段、百分比或预计剩余时间。

工作说明帮助理解目的、方法和依据，工具回执证明实际读写。沿用已有可展示信息，不为进度额外采集隐藏推理。长技术参数可以作为次级详情，但当前步骤、工作说明、错误、待确认事项和成果必须可直接阅读。停止和恢复操作始终可达。

**速度验收分开记录并共同判断：**

- 实际速度：有效正文首字、首份真实成果、完整交付耗时，按任务类型报告中位数和尾部等待。
- 感知速度：操作反馈是否及时、首个明确工作反馈何时出现、最长不明原因空等区间、阶段变化是否可理解、成果是否及时可用；结合真实窗口连续操作评价，不能只凭有一条状态事件判定通过。

## 4. 质量：以满足当前要求为准

- 保留唯一权威的当前请求、材料与版本引用；转交、内部纠正、压缩、恢复和换话题都不能把旧问题变成当前问题。
- 现有工作区已包含纠正消息去重、新建笔记路由与分类器候选修复，实施时保留这些改动，再验证实际入口闭环。[此前调查](../../testing/learning-artifacts-live-probe-2026-10-19.md)记录过内部重附用户原话导致“你重复说了几遍”的误判，以及后台目标只交付摘要、实际没有创建笔记的问题；本轮没有重新独立复现这些生产事件，不能把已有修复记录当作部署后验收。
- 内部纠正必须保留宿主身份。现有带标记的重附件仍使用 `user` 角色，需要验证模型是否稳定地区分真实用户发言与内部修复。
- 固定检查当前对象、问题各点、篇数、近似篇幅、结尾完整性、事实依据和实际保存结果。大幅不符合要求的回答即使格式正确，也算质量失败。
- 解释、创作与执行分别评价。教学不能遗漏关键条件；故事不能只有开头；创建笔记不能仅在总结里写“已完成”。人格和语气服务内容，主动补充不承担原本应在本轮完成的后半段回答。
- 使用真实口吻、多轮指代、否定、混合要求、只读权限等样本验证路由。分类器黄金集只能提供部分证据，还需完整阅读请求、回答及产物。
- 必要时针对确实不完整的结果接续修复，不给所有聊天一律追加阻塞式审稿模型；新增调用必须有质量收益与等待代价的比较。

## 5. 稳定性：让恢复基于真实状态

- 分开处理网络故障、非法工具协议、参数错误、缺失工具组、资料过期和写入结果未知；避免同一错误在多层重试机制中反复绕行。
- 每类失败明确恢复归属，沿用同一运行、检查点与操作身份。重试前记录改变了什么；成功部分保留，未完成部分继续。
- 写入结果未知时先查回执和业务状态，再决定重试；已经保存的笔记不能因后续模型失败而丢失或被重复创建。
- 单独评估交互请求首输出与无活动超时，不直接沿用15分钟通用超时处理所有场景。取消必须传播到实际模型与工具，最终状态持久化；单纯慢不等于应中断正常长任务。
- 保留此前不按任意步骤数、工具数或模型调用数截断任务的决定。完成、明确停止、真实故障和没有推进的证据决定后续处理。
- 停止后新请求可正常继续；断线或重启恢复同一任务；旧回复和后台完成不覆盖当前话题、输入、焦点或声道。
- 后台目标只有在取得所需真实成果后才可宣称完成；任务列表关闭时，完成结果也能按既有参与与通知规则送达。
- 备用模型、重试与断点恢复必须在实际配置下测试。短样本成功和单元测试全绿，不等于持续使用稳定。

## 6. 实施顺序：每次交付都检查三项

| 顺序 | 实施范围 | 可核对的结果 |
| --- | --- | --- |
| **第一批：修通现有高频失败，并同步给出进度** | 用“创建三篇历史笔记”贯通正确能力、真实进度、逐篇保存与即时链接、格式错误恢复、停止和部分重试。验证并保留已有局部修复。 | 同一真实窗口完成客户端→API→队列→worker→权威保存→事件→客户端；既减少绕路，也能清楚看到推进；三篇内容符合要求，重试不重复创建。 |
| **第二批：实测比较提速与质量优化** | 对高耗时模型步骤、重复生成、上下文和最终交付逐项改造；比较模型及思考配置，补充请求完整性评价。 | 同样请求和输出要求的前后对照，同时给实际耗时、感知等待、内容评价和失败记录；回答变短不能算提速。 |
| **第三批：连续使用与版本验收** | 长对话、后台负载、断网重连、服务重启、未知写入结果、换话题与迟到消息。 | 实际构建客户端和运行服务的版本可核对；多次重复与长会话通过；保留负面样本，再由真实体验确认。 |

不以整体框架重写或独立展示样机作为前置。过程界面与真实执行共用现有运行身份和事件流，避免新增另一套任务状态机。

## 7. 验收方法与初步目标

以下是建议目标，尚未实测达成。先建立固定请求、输出要求、版本与后台负载的基线，再校准阈值。

| 目标 | 初步验收要求 |
| --- | --- |
| 实际速度 | 普通聊天有效正文首字p50≤2秒、p95≤5秒；固定的三篇短笔记样例首篇保存≤30秒、完整交付p95≤90秒。长材料研究和大型交互产物单独分组，不混算。 |
| 感知速度（速度的一部分） | 反馈及时，当前步骤和工作说明无需展开；阶段、延迟、恢复和已完成成果连续可读；不让用户长时间面对含义不明、没有解释的静止状态。用真实窗口与连续操作核验。 |
| 质量 | 代表性常规请求完整达成率以≥95%为初步目标，公开分母和失败样本；验收集内不允许假保存、假完成、明显答非所问或遗漏关键要求。 |
| 稳定性 | 正常请求重复与长会话验证；异常注入下无重复写入、已成结果丢失、错误对象修改和旧回复覆盖；停止、恢复与后台完成状态一致。技术失败率和恢复成功率单列统计。 |

保留用户实际失败作为固定案例：新建笔记、换说法重试、约400字完整故事、故事续讲、笔记解释、聊天→任务→聊天、内部纠正不虚构用户重复。加入长笔记、资料版本变化、未装载工具组、非法模型输出、流中断、一篇保存后失败、未知写回执，以及关闭任务列表后的完成送达。

每类正常样本重复运行，并做持续多轮会话。尾部耗时需要足够样本，不能用几次成功证明稳定p95。超时、取消、被新请求接替和无正文运行保留在结果表中；有效完成时间与未完成比例一起报告，避免只统计成功的快速样本。

学习卡测试按方案57的新笔记归属合同接入，不恢复已删除的旧复习、旧制卡或学习轮次作为前置。本方案也保留方案56默认主动参与能力，不借可靠性整改改变这项产品决定。

## 9. OpenDesign Cloud：伴星与手记的完整交互设计任务

### 9.1 设计目的与产品环境

用户在同一次需求卡中确认：**跨平台、一个核心流程、精致产品界面**。由 OpenDesign Cloud 设计一套可点击、可连续操作的精致产品原型，围绕“伴星接下任务→查看进度→随时预览→成果跳转→返回手记原位置”这一个核心流程，覆盖正常、历史回看与失败恢复等分支。将操作逻辑、信息层级、空间布局、视觉和动效作为同一项设计工作，不把它拆成互不接续的独立截图。

桌面对应现有 Electron 学习书房，界面使用中文。暖纸、柔和薄荷与桃色、圆润但克制的物件感延续现有识别；正文和学习成果占阅读重心，Live2D 伴星有稳定座位。设计可重新组织现有结构，不要求复制当前折叠层级、浮窗堆叠或固定列数。手机对应现有 SwiftUI / Compose 原生产品，以中性色、白/浅灰表面和单一系统蓝适配同一核心流程，不将桌面暖木/薄荷纸张直接铺满手机。此次交付浏览器可操作的跨平台设计原型，不宣称已完成两端原生实现；不新增无关模块。

持续保持三项目标：快速开始且进展可理解，回答及成果完整可核对，多次操作和中断恢复稳定。预览和回看读取已有内容，不为打开界面重新发起模型生成。

### 9.3 连在一起设计的界面

| 界面 | 主要职责 | 必须保留的接续关系 |
| --- | --- | --- |
| 伴星身边的轻聊、任务提示与快捷操作 | 发起交流；看当前在做什么；停止、修改要求；进入预览或完整记录。 | 收起只改变展示，已接受工作继续；手记入口定位到对应交流或任务。 |
| 当前任务与过程 | 完整要求、真实步骤、工作说明、资料与阶段成果；部分失败和恢复操作。 | 当前过程默认可读；切换查看对象不改变任务；成功成果在后续失败时仍可打开。 |
| 就地预览 | 看引用材料、可用草稿、已保存笔记、图解、图片和互动成果；必要时展开阅读。 | 不离开当前交流即可查看；切换与关闭后恢复原对象和阅读位置。 |
| 对话手记 | 连续阅读消息和过程，定位某次交流、任务、动作或成果；查阅更早内容。 | 历史不按“最近一条”猜关联，不因新消息覆盖正在阅读的记录。 |
| 正式笔记、资料与成果页 | 完整阅读、按权限继续编辑，定位到真实来源或产物版本。 | 显式跳转，并可返回原手记/任务及其滚动锚点；返回无需重新查找。 |
| 待确认、失败与结果待核对 | 就地理解影响范围，作出决定，继续未完成部分。 | 确认对象与版本清楚；未知写入先核对；重试不重复已完成操作。 |

声音、消息回放、传图、建议问题与跟进输入也纳入操作布局，不能被任务状态或预览遮住。仅为已有可用能力设计操作；不能用原型中的按钮假定后台已实现新能力。

### 9.4 随时预览、可回看、可跳转的具体含义

**随时预览：**在伴星身边与手记的相应条目上都能进入，当前消息、引用来源、任务步骤和成果保持明确关联。任务未完成时也能看已具备的资料或可读部分，并明确标注“生成中草稿”“已保存成果”或“仍在准备、暂未产生可读内容”。可打开查看不代表每个阶段都必须已经有产物，不制造假内容或假完成。

**可回看：**即时纸签收起或离开书房后，手记仍有同一份记录、来源与成果入口。进入历史不重新发起执行。已生成内容、修改后的新版本和当时的记录有清楚关系；必要时分别提供“查看当时成果”与“打开当前笔记”。历史版本若未保留，如实说明，不把当前内容伪装成当时内容。

**可跳转：**“预览”“打开笔记/成果”“查看原文”“在手记中查看”“返回刚才位置”有各自清楚含义，避免用一个泛化的“查看”承担所有动作。预览先留在原交流；显式打开才去正式页面。来源能定位到有权访问的原文段落时提供精确定位，只有篇级身份时就明确为打开该篇。

**可接回：**从手记→成果→来源→返回，接回消息或任务、选中的成果、阅读锚点、已展开内容和未发送草稿。预览正在读旧版本时，新内容到达先提示更新，不强制跳到最新。退出账号或切换空间按数据范围清除旧上下文。

人工打开的阅读面板在阅读期间保持，不用倒计时催促用户；正在进行和需要处理的状态有持久入口。用户没有在查看时，轻提示可以收回到简短标记，完整内容仍能主动找回。

### 9.5 操作语义与异常状态

- 明确区分关闭预览、收起伴星、关闭手记、停止当前工作和修改要求；关闭展示不暗中取消执行。
- 停止只作用于实际指定任务；已保存成果保留。暂停、继续等能力按现有执行合同呈现，不对无法暂停的在途操作承诺即时暂停。
- 修改要求接到所属任务与新要求版本，已完成部分可辨认，不悄悄把旧成果当作新要求的交付。
- 用户明确要求“打开某篇”时正常执行授权导航；普通完成事件与主动发言不抢导航、焦点或当前话题。
- 加载、无可读草稿、部分完成、待确认、正在恢复、已停止、失败、结果待核对分别有解释与下一步。未取得确定结果时不显示“重新生成全部”作为默认动作。
- 对目标已删除、权限变化、版本不可用、离线和加载失败给出准确状态；保留原记录和返回入口，不让用户陷入空白页。
- 窄窗口、放大文字、多份成果与长标题下，停止、返回、关闭和主要阅读操作仍然可达；重要入口不依赖悬停。

### 9.6 布局与视觉设计要求

要求 OpenDesign Cloud 对真实信息量作出布局判断：伴星轻提示简洁可读，完整手记有足够行宽与纵向空间，预览按需借用空间，不用多张悬浮纸同时挤压正文。导航、阅读与预览层级明确，避免过程区域再套小滚动窗。

保持暖纸书房身份，但正文、过程说明、状态和可操作入口有足够对比度。重要说明不能缩成灰色截断小字；长内容按阅读节奏分段，技术详情可以次级展开。图标须有可理解的标签与状态，颜色不单独承担含义。

重点核对1440×810、1280×720以及125% / 150% / 200%缩放。内容不足时保持自然留白，内容增加时按阅读任务重排，不强制所有场景使用同一列数。

### 9.7 动效与中断设计

动效在操作逻辑设计阶段一并确定，用于按压反馈、空间来源、状态变化和阅读层级。复用项目有效的纸面弹簧与动效偏好，不新增相互争抢同一属性的动画系统。

| 场景 | 动作与空间关系 | 中断与功能要求 |
| --- | --- | --- |
| 点击伴星入口/操作按钮 | 立即按压反馈，随后相应内容出现。 | 操作与焦点立即生效，不等待动画结束；高频操作力度轻。 |
| 轻聊→手记 | 从当前交流接到相应记录，保留可理解的层级关系。 | 快速开→关→开从当前画面接续，不闪回初始状态，也不丢输入。 |
| 条目→预览→关闭 | 预览的来处明确，关闭返回原条目。 | 切换对象不叠加多个离场/入场，不改变旧阅读位置；Esc按当前层级退回并恢复焦点。 |
| 新进度和成果到达 | 对真实阶段变化和新成果做短促、局部反馈。 | 不逐字触发布局动画，不移动用户正在阅读的旧段落，不自动切换预览对象。 |
| 跳转到成果/原文并返回 | 用轻量过渡说明页面层级和返回方向。 | 导航先响应，重复点击不产生重复跳转或排队动画。 |
| 失败、停止、恢复、完成 | 原位置切换状态与可操作入口。 | 错误和操作立即可读，迟到事件不能把终态改回执行中。 |

原型中说明关键曲线/弹簧、入场与离场关系，并给出完整、轻量、关闭与系统减少动态的对应行为。频繁操作的反馈可更轻；键盘也可提供有用的空间提示，但功能和焦点不等待动效。避免整页弹跳、持续呼吸式进度装饰或把读取中的文字反复淡出。具体节奏通过原型连续操作与正式窗口复验落定，不把技能的一刀切时长当作项目规则。

### 9.8 同一核心流程必须走通的状态与分支

1. 发起创建几篇历史笔记→看见真实阶段→随时打开已有材料/草稿→首篇保存后就地预览→后续继续完成。
2. 从伴星提示打开相应手记→回看完整要求与过程→切换多份成果→打开一篇笔记→定位来源→返回原手记位置与预览内容。
3. 一份成果已保存、后续生成失败→已成部分仍可预览/打开→只继续未完成部分→同一任务记录更新。
4. 阅读旧消息/旧成果时新进度到达→原阅读与预览不被接管→用户主动返回最新→未发送草稿保留。
5. 打开预览后连续切换对象、收起/重开手记、停止工作并改聊其他话题→无错位、失焦、重复操作或旧结果覆盖。

用独立标明的演示数据展示进行中、等待、部分完成、失败、已停止、待确认、结果未知和完成状态。场景切换仅是原型演示工具，不混入拟交付的正常产品流程。按钮应有真实原型行为；没有后端的执行以演示身份明确表示，不伪造应用已实施。

### 9.9 设计交付与落地验收

OpenDesign Cloud 需交付：可点击且有动效的关联流程原型；布局与视觉层级；入口/返回关系；状态与操作清单；关键动效及降级规则；可映射到现有客户端的实现说明。设计评阅沿完整用户路径进行，不以截图数量或页面数量验收。

设计生成流程沿同一次需求确认继续，使用同一项目与运行，不重复发起相同任务。生成开始后跟进到终态，取得可用预览/设计链接并打开核对。需求确认、账户状态或额度若需要用户操作，准确说明所处边界，不把“已打开需求卡”说成“设计已生成”。
