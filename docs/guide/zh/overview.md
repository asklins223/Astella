## 它解决什么问题

个人学习里最常见的失效不是"资料没存下来"，而是"学了但不知道是否真的懂了"。收藏夹越满，越没人能回答：这条理解凭什么成立、上次练到哪儿、下次从哪里接着来。

拾星笔记的做法是把资料变成**有出处、可验证、可复习的理解**：每条讲解能追溯到原文片段，每次练习留下按笔记版本与原文保留的记录，正式作答的证据与"我说过我会"的自述分开记账。无法可靠检验时，系统保留"练过、未证明"，不把它写成掌握。

产品身份的另一半是书房本身：暖纸、册本、便签、印章式的物件语言，加上坐在纸面旁边的 Live2D 伴星。这不是装饰层——它决定了页面怎么组织内容、动效怎么给触感，见 [DESIGN.md](../../../DESIGN.md) 的方向与 Layout 两节。

## 当前主线

现在这条链路是：

**来源 → 可编辑笔记 → 在同一篇笔记里按需「速看 / 回想 / 往外学 / 学习记录」，选中一句还能「写批注 / 发给伴星 / 原句解读」→ 需要时制卡或加入长期复习。**

三点需要说明清楚：

- 来源是不可编辑的材料；写笔记的动作从「开始写笔记」发生，此后一篇笔记就是自然入口，不再要求回到来源。
- 页首那四张书签——速看（读懂重点）、回想（想起一点）、往外学（发现关联）与学习记录——各自独立，可以只做其中一件，不串成固定一轮，也不要求先做完 A 才能碰 B。
- **学习卡是用户主动选择的独立能力，不是笔记学习的前置条件。** 历史方案里"卡片优先、固定学习顺序"的写法已作废。

页面长什么样，比描述更直接。首页是一间固定镜头的书房，四个区域（书桌、书架、星窗、休息角）承载真实入口：

![书房首页：房间物件、今日复习纸签与常驻伴星](../assets/home-room.jpg)

进入产品先是一张登录纸：品牌、雨夜书桌，外加一句明确的说明——账号与密码不会被伴星读取、记录或发送给任何模型。

![登录页：品牌、雨夜书桌与凭据不外发的说明](../assets/login-gate.jpg)

进来之后，来源库把采集到的材料按处理状态摊开，一张纸一份来源，就绪状态与「已生成几篇笔记」同屏可见；今日学习是接续点，三站路线、卡在半路的事项与这一天的学习记录排在同一张纸上。

笔记册页是学习的重心，页首的「正文／速看／回想／往外学／记录」保持稳定位置，结果回到当时选中的原文旁边；这一屏的构成与调用链见 [桌面客户端](./desktop-client.md)。

## 能力清单

| 分组 | 今天真实存在的东西 | 状态 |
| --- | --- | --- |
| 采集与来源 | 文本、Markdown、代码、URL 四种来源的采集与解析；重复材料给"打开已有 / 再采一次 / 返回修改"；从笔记回来源接续原阅读位置 | 可用 |
| 笔记与版本 | Milkdown 编辑（`@milkdown/kit` `^7.22.1`）、自动保存、不可变版本记录；正文写入走 Yjs 这份唯一内核；阅读页用 KaTeX 排版公式，源码保留 TeX | 可用 |
| 学习与验证 | 理解练习与练习结果两屏（页面 16 / 17，LearningRun 统一入口；练的时候屏内说的是"旅程 / 这一轮"）；笔记页首的速看、回想、往外学与学习记录 | 练习与结果链路可用；四张书签的页面、流程与状态都已在代码里，[PRODUCT.md](../../../PRODUCT.md) 记为实施中、真实窗口验收未通过 |
| 复习与记录 | 间隔复习计划与到期队列；学习记录按笔记版本与原文保留，改版后旧记录不重定位 | 可用 |
| 学习卡 | 从笔记生成带证据对齐的学习卡，V2 带候选审核与 Agent 活动流；重新生成、停止与逐张决定有独立合同 | 可用 |
| 检索与理解星图 | 全文搜索、来源追踪、理解关系图；星图以整片可漫游夜空承载真实知识关系，查找用于定位，目标筛选保留相关笔记与证据 | 可用 |
| 伴星 | 窗口内 Live2D 形象（唯一形态）、语音（服务端 TTS + 本机 ASR）、对话手记、记忆、日记 | 仍在打磨：[PRODUCT.md](../../../PRODUCT.md) 把它列为"正在打磨的第二差异化"，标注测试中、持续迭代 |
| 工作区与成员 | 个人 / 协作工作区，Owner / Member 角色；邀请码注册与加入 | 可用 |
| AI 数据同意 | 账号级 AI 使用同意与数据外发政策（`PUT /me/ai-consent`，存于 `user_ai_settings`） | 可用 |

伴星是这套能力里唯一还在明显变动的一块。伴星中心承载近况、对话、日记、记忆、发现簿、动态、人格七个入口，其中对话页只做历史展示与查询；日常交流走伴星身边的轻聊与「我们的对话手记」（全部对话 / 伴星念想 / 交给我的事 / 待确认四个入口）。她是什么、能替你做到哪一步，见 [伴星体验（产品设计）](./companion-experience.md)。

## 运行形态

**只有 Electron 桌面客户端，没有浏览器产品。** 覆盖 macOS / Windows / Linux；`apps/` 下只有 `api` 与 `desktop-client` 两个应用，仓库里不存在对外的 Web 前端构建入口。

后端不是多租户服务。API（Fastify 5 + Drizzle ORM + PostgreSQL 16）与 AI Worker（Node.js + TypeScript 独立进程）在本机通过 Docker Compose 起一组容器：本机开发用 `docker-compose.dev.yml`（`make up`，源码挂载 + 热重载），宿主机默认只回环映射 `127.0.0.1:4000`。`docker-compose.yml` 是生产配置，用于镜像构建与扫描，不绑定任何本地 Makefile 目标。

桌面客户端通过 `DESKTOP_API_ORIGIN`（默认 `http://127.0.0.1:4000`）连本机 API，凭据只存在于主进程，渲染进程拿到的是会话快照。可选的对象存储 MinIO 位于 `storage` profile，`make up` 与 `make storage` 都会带上它。

> **说明：** "个人本机跑一组容器"与"云端多用户服务"是两种运维模型。本页只描述前者；仓库里有生产 Compose、角色分离与备份脚本，但不存在把这套栈当 SaaS 运营的产品承诺。

## 工作区与权限

| 工作区 | 角色 | 对工作区数据 | 私有动作 |
| --- | --- | --- | --- |
| 个人（Personal） | 创建者即 Owner | 全部读写 | — |
| 协作 | Owner | 增删改 | — |
| 协作 | Member | 只读 | 验证、复习、查看理解状态等用户私有操作照旧可用 |

Member 界面明确标注权限边界，不伪装操作入口。

AI 使用同意挂在**账号**上，与空间完全隔离：签了就在哪个空间都算同意，没签就在哪个空间都发不出去；换空间不重签，Owner 也不能替别人签。空间不追加第二道外发政策。

## 它刻意不是什么

| 不做 | 现行决定 |
| --- | --- |
| 每人自带 Key / 个人模型或供应商配置界面 | 仓库中没有用户级模型选择或 BYOK UI；模型与供应商由 Worker 的平台配置决定，属未来产品决定 |
| 自由相机、鼠标视差、场景级 3D | 固定镜头的 2.5D 注册图层；PixiJS 只合成已注册的 D0–D4 图层 |
| 独立透明置顶桌宠窗口 | 该链路已整体失效并在代码中不存在；主进程只有一个 `BrowserWindow` |
| 自助找回密码 | 没有邮件通道与重置令牌，登录页刻意不提供「忘记密码」入口；只有 Owner 代用户初始化密码的管理端接口 |
| 光球（orb）形态与形态选择 | 2026-09-16 裁决移除；Live2D 不可用时隐藏形象并就地给一句可关闭的说明，不回退替身立绘 |
| 精灵图（Sprite Level A）伴星 | 只有共享合同，没有资产与渲染实现，不写成现有能力 |

## 现状与边界

- **项目尚未上线。** 下面的版本号是仓库内的版本记录，不是发布物。
- **两条版本线。** 服务端栈 `0.5.0`（`release/version.json`）与桌面客户端 `0.1.0`（`release/desktop-version.json`）各自独立，别把两者混成一个"产品版本"。
- **许可尚未声明。** 仓库根没有 `LICENSE` 文件；[PRODUCT.md](../../../PRODUCT.md) 的品牌承诺写的是 MIT 意图，但在文件落下之前不能把本项目当作已授权。第三方组件、模型与素材的许可与再分发限制集中在 [THIRD_PARTY_NOTICES.md](../../../THIRD_PARTY_NOTICES.md)。
- **CI 不再构建与扫描生产镜像**（2026-10-06 起 CI 只跑与本地基线 `make verify` 一致的测试）。生产镜像需要本地手动构建验证。
- **学习房间素材仍标记 `reviewOnly / IN_REVIEW`**，授权与发布验收完成前不作为生产素材宣称。
- **伴星带路已经实现。** 右上角房间控制岛里的「伴星带路」打开一本 7 个主题的目录册，按当前空间的真实内容带看，可跳过、暂停、重看（`components/hud/HudRoomControl.tsx:365-370`、`components/companion/guidance/guide-definitions.ts`）。没验过的是两件事：新账号的全程走查，以及签署同意之后的语音那一段——两者都从未在真实窗口里跑过。
- **上下文治理（方案 44）代码已接线，验收证据仍是缺口**：§8 尚无一条真实模型、实库或窗口证据，迁移 0382–0389 从未在实库上跑过。方案 42 已按 2026-10-05 本轮验收，但 §14.6 记录：没有严格同负载的 p95 或长期试用效果证明，未知 stream 用量不当作零，长期效果不能由闭环通过推导。进度与验收状态以 [方案索引](../../plans/learning-companion/README.md) 的合同表为准。
