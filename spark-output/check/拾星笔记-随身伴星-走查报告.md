## 一、先回答「卖点」这件事

§1 现在写的三条价值，逐条对到 2026 年的通用 agent 现状：

| §1 的价值 | 通用 agent 是否已具备 | 证据 |
| --- | --- | --- |
| 随手交给它（拍照、传文件、说一句话） | 已具备 | ChatGPT 移动端照片提问 + 高亮图片局部 + 语音模式随时打断 + 项目内文件上传 |
| 当下看懂（对话、原文、图文、声音连贯） | 已具备 | 同上；Canvas 提供就地改写 |
| 回到哪里都能接上（跨端同一轮回复） | 已具备 | 同一账号网页/桌面/手机同一会话续写；Gemini 2026-03 起还能一键导入 ChatGPT/Claude 的记忆与聊天记录接着写 |

所以「通用 agent 都能搞」这个判断成立，而且 §9.1 把「聊天互通是核心交付」写成主打，恰好把最没有差异化的部分放在最大篇幅。

代码里真实存在、通用 agent 复制不出的是这四层：

1. **产物归属**：`companion_create_note` 落的是 noteId + 不可变 `noteVersions` + Hocuspocus/Yjs 协同文档服务（`apps/api/src/modules/note/collaboration.ts:279`）+ 来源块级锚点（`modules/source/source-note-blocks.ts`）。通用 agent 的产物停在聊天里，改一次是一段文本；这里改一次是一个有版本、有出处、能被搜索投影到的对象。
2. **学习判定合同**：候选逐张审核（`card-generation-v2/candidate-review-service.ts`）、间隔复习排期（`modules/review/`）、正式作答与 `trusted_mastery` 分表记账（migration 0040），浏览/求助/自述/作答互不冒充。通用 agent 承担不了「我到底会不会」的证据。
3. **权限与可见性的唯一判据**：`modules/note/visibility.ts` 全仓一份、API 与 Worker 共用，Owner/Member 角色（`workspace-membership-service.ts:173`）。这是「手机替你写进对的地方」的前提。
4. **数据主权**：原声从不落服务端（migration 0088 的 `CHECK (raw_audio_persisted = false)` + 测试断言）、私有可见性默认、模型自选与可自部署。方案 51 一字未提，而这恰恰是家长、学生和版权材料场景最硬的一条。

移动端真正独占的动作是**捕捉 → 归位**：路上拍一页、随口说一句，回来已经在对的空间、对的笔记版本上，她还记得讲到哪一句。建议 §1 按这个重写，把跨端实时互通降级为基本要求。

## 二、Findings（按严重度）

### 🔴 Blocker

1. **主链路在手机端是断的**（flow-continuity｜51-...md:72, 337, 423-431）
   §2.1 把上传文件列为 P0、§9.1 承诺不要求桌面运行，但服务端上传只有图片四条路（`upload/routes.ts:114/191/248/312` → `note_image_assets`），来源登记只收正文/URL（`source/routes.ts:33`），PDF/Word 解析全在 Electron 渲染进程（`source-pdf.ts`/`source-docx.ts`/`source-intake.ts`），api 与 ai-worker 里没有任何 pdf/docx 解析。
   → 把「对象存储 + 上传 API + 服务端解析 worker + 页/段定位」单列成移动端前置工程，给出体积/耗时/存储成本；在它落地前首版闭环改成「图片 + 已有资料」，PDF/Word 归第二批。

2. **小程序被当作同级首版宿主，但框架尚未选定**（responsive｜51-...md:9, 381-398, 488）
   玻璃（backdrop-filter）、Live2D 资源体积、文件选择（小程序只能从会话取文件）、后台与中断音频、中文输入，每一项在小程序侧都有硬限制，方案没有降级分支。§10「两种宿主运行同一组页面和控制逻辑」是先承诺后验证。
   → 先做 2-3 天证伪样例（真机跑 玻璃 + 角色帧 + 录音 + 中文输入 + 文件转入），出一页结论表；不成立就把「共用一套 UI」降级为「共享逻辑与语义、外壳各自实现」。

3. **没有分发与合规这一节**（brief-consistency｜51-...md 全文缺失）
   AI 对话/生成式内容类小程序与 App 在国内上架涉及主体资质与生成式 AI、深度合成相关备案，个人主体通常走不通 AI 问答类目；而伴星的每个核心交互都是生成式能力。这直接决定「小程序」这一端是否存在。
   → 补「分发与合规前提」：主体形态、类目、备案路径与替代方案（H5/PWA、企业主体、先 App 后小程序）。确认前别把小程序写进首版承诺。

4. **首屏英雄位压着一个没有数据源、也没有空态的模块**（ia｜51-...md:138, 347, 373-379 / layout.js:183-196）
   「接着学」卡片是首页第一视觉，但它依赖的 待看项/接力位置/阅读位置 全仓 grep 零命中（`companion_context_handoff_snapshots` 是每 run 的页面上下文快照，语义不同），而 §13 把它排在最后一个阶段。
   → 要么把接续数据（表 + API + 版本锚点）提到阶段1，要么首屏换成已有事实（最近一条真实交流/最近打开的笔记）。

### 🟠 Major

5. **§9.4「两端同时发问每条请求保持身份与回执」与真实合同不符**（brief-consistency｜51-...md:369）
   实际每会话至多 1 个 active run，后来者 409 `RUN_ALREADY_ACTIVE`，必须带匹配的 `supersedesGeneration` 抢占（`turn-service.ts:421-460`）。多端是抢占式接力，且文档没定义被抢占那一端看到什么。
   → 按真实合同改写，补抢占提示文案与取消通道；要真并发就写成需要改的运行模型与成本。

6. **共享原声被写成「缺口」，其实是在悄悄推翻一条隐私决定**（brief-consistency｜51-...md:316, 371）
   `raw_audio_persisted = false` 是带 CHECK 约束和测试断言的刻意设计。
   → 摆上决策台二选一：A 保持原声本机（则「手机重听电脑原声」明确不做）；B 上传原声（说清存放、权限、保留期与约束变更）。默认建议 A。

7. **语音带图在合同层是非法的，却进了首批**（flow-continuity｜51-...md:209, 431, 444 / contracts:426-464）
   blocks 1-2、首块必须 text、第二块只能是用户图、`voice_transcript` 带图直接判非法；§14 却有「语音问附件」验收，§13 把语音结合材料排到阶段3。
   → 多材料合同提到阶段2，或把该验收项移到第二批，别让验收跑在合同前面。

8. **§4.1 的界面描述与实现和评审记录对不上**（brief-consistency｜51-...md:128,132 / README:9,27,71,75 / DESIGN.md:31）
   文档 120/132/94/78/100/76px，实际 CSS 是顶栏 154→86px、短屏再让 22px，100 与 76 两个数在代码里不存在；文档说复用书房底图，README 与 DESIGN 已改判为 CSS 画天空海面；54 组 vs 63 组；DESIGN 写宽 132px、51 写宽 120px。
   → §4.1 不复述像素，引用唯一来源（README 几何表 + layout-verification JSON）；同一指标只允许一个源。

9. **键盘态读不到上文**（visual-hierarchy｜08 截图 02 屏 / README:71,75）
   README 自报最坏 320×640 键盘态正文只剩 168px，截图里键盘上方是空的渐变带，输入时看不到正在回复哪一句，直接违背 §4.1「最新对话与足够的上文」。
   → 键盘态顶栏压到一行、输入时锚定上一条回复首行；把「键盘态可见上文行数」写进判据。

10. **状态覆盖几乎为空**（edge-states｜layout.js:74,231,246-257,517 / 51-...md:296-308）
    demo grep 离线|失败|加载|empty 零命中；§8 的 11 行状态只有 4 行有界面；§14 要求的 权限与 AI 同意、只读空间、弱网、结果未知、多份材料失败 全部没有界面。
    → 按 §8 逐行补最小呈现（一句文案 + 一个可行动作），把四态列为交互稿交付项。

11. **AI 同意未签时的移动首屏没定义**（edge-states｜51-...md:415,467 / PRODUCT.md:95,97）
    未签同意消息发不出去，而移动端整个首屏就是「和伴星说点什么」，用户会在发送后才撞上失败。
    → 定义未同意首屏：伴星在场不发言、输入可用、首次发送前一次同意说明与就地签署，拒绝后保留只读书房。

12. **导航职责重叠且与自己正文冲突**（ia｜51-...md:146,150,191-195 / README:86）
    正文仍写「取消常驻三个去处行」「没有固定四栏导航」，demo 已是常驻三段；改判只落到 assets README，`docs/design/mobile/2026-10-10/README.md:19` 也是旧句。「对话」标签与主画面重复；任务既在「手边的事」又在「手记」；菜单/＋/手边/手记 四处都能找历史与材料。
    → 先回写三处文档统一口径，再做一次归位：手记=记录检索、手边=此刻事项与待看、菜单=空间设置、＋=只放材料；任务只留一处。

13. **首版范围实际没有裁剪**（brief-consistency｜51-...md:65-79, 440-449, 453-478）
    11 项能力全列 P0、24 条验收无分级、四阶段只排序不砍项，同时 §15 承认几乎所有前提待验证。没有「明确不做」清单。
    → 压成 3 条真闭环，其余标「接入路径已定、不承诺时间」；验收逐条标 P0/P1，单列「首版明确不做」。

14. **阶段1 把两个高风险未知捆绑**（flow-continuity｜51-...md:442）
    跨端框架未选 + 实时互通验证捆在同一阶段，任一失败整阶段作废。
    → 插阶段0 证伪闸门（只验宿主能力）；实时互通已有 SSE + Last-Event-ID 补发底座，单独一天验移动端订阅即可。

15. **一屏多个主操作、卡片套卡片、高饱和实心成片**（components｜08 的 01/03 屏、09 的 05 屏）
    「继续看」大绿按钮 + 拍一张问问 + 传文件 同屏三个主操作；接着学卡内再嵌按钮；「修改后/原文」切换与「听伴星讲这篇」用同一饱和绿实心块，在阅读器里与正文抢重心。也踩中项目自己定的雷区（默认控件、饱和底色、框套框）。
    → 每屏只留一个实心主操作，其余降为文字链/描边；接着学改成无边框接续行；播放入口用行内小控件。

16. **撤回被当成按钮而不是功能**（feedback｜51-...md:268,465 / layout.js:643-647）
    §6.3 自己承认恢复路径待补，demo 撤回只改演示文本，§14 却把冲突与撤回列入验收。基于版本的局部 revert 要先检查其后新改动，是新的服务端能力。
    → 要么单列为一条工程交付（含回执与失败口径），要么首版只提供「对照 + 重新调整」。

17. **定位缺竞品对照**（brief-consistency｜51-...md:22-33, 335）
    全文没有一句「为什么不用 ChatGPT」，而三条价值全部对标已具备能力。
    → 按第一节重写 §1，并补一小节与 ChatGPT / NotebookLM / ima 的对照表。

### 🟡 Minor
