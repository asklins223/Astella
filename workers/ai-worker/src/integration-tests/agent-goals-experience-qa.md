# 统一 Agent 阶段 0：实现与体验验证

日期：2026-10-04。对应 [方案 42](../../../../docs/plans/learning-companion/42-unified-agent-and-companion-experience-2026-10-04.md)。本文记录已实现和实际验证的范围，不能替代后续阶段的验收。

## 实现范围与归属

| 层 | 本次实现 | 状态所有者 |
| --- | --- | --- |
| shared | run、revision、operation、事件、冻结材料与真实产物引用；能力 schema 派生模型参数 | 权威协议 |
| agent-core | 公共执行驱动、持久步骤端口、模型边界、纯回执归并 | 宿主通过端口持有状态；core 不导入 API、数据库或 renderer |
| agent-host | 创建、修改、暂停、继续、停止；检查点、事件消费、持久唤醒、作用域与租约检查 | PostgreSQL 事务与领域回执 |
| API | 身份初始化、认证和参数校验、目标接口 | 当前登录用户与空间 |
| worker | 动态选择读取、速看、演示；目标恢复、共同预算；持续人格与已确认偏好的使用 | 后台目标与专业生成任务 |
| renderer | 一份目标控制器供轻气泡、手记与通知使用；操作等待实际回执；打开指定产物 | 当前空间的投影与局部交互状态 |

交流与目标执行共用执行驱动和模型治理边界。目标不占住下一轮聊天；历史要求、弱页面线索不作为新的行动授权。专业速看与演示仍由原领域生成链负责存储、引用、校验和提交。

目标与子任务共同计数，最多 16 次模型调用；子任务保留一次最终交付调用额度。恢复已保存的模型响应不再次计费；同一冻结材料、能力与目标 revision 不因 provider tool-call ID 改变而重复生成。失败后继续可复用兼容的已完成成果。已有成果保留，修改要求产生新 revision；停止后的迟到提交被挡住。

当前空间最多同时保有 5 个活动目标，暂停也占用名额。创建、重新修改旧目标、恢复失败目标使用同一个事务锁与计数；暂停后恢复同一目标不再占一个名额。

迁移 `0368_unified_agent_runs.sql` 建立独立目标、操作、步骤和事件表，启用强制行级隔离。worker 的插入、取消和恢复使用有限权限，不靠扩大所有 jobs 或账号表写权限完成。

## 轻气泡与对话手记

撤掉初版大任务纸。默认任务气泡沿用现役暖黄、薄荷绿、圆润边缘与角色旁的停靠方式，首屏只给状态、简短目标、已完成成果与下一步。宽度优先 310 CSS px；内容区高度受窗口约束，展开操作和编辑不会变成独立小窗口。

- 气泡内可修改要求、暂停、继续、停止、切换目标、打开真实成果。重复提交在回执到达前被禁止；失败保留修改草稿。其他窗口的要求更新不会清空编辑器，用户核对后可按最新 revision 重新提交。
- 多篇笔记的成果按需展开，使用笔记顺序区分，不丢弃第四个以后的入口。旧 revision 的全部成果留在手记。
- “去手记看完整记录”进入现役“我们的对话手记”的任务页；长要求、成果、交付说明与处理过程按层级组织，过程默认折叠。
- 交付说明复用现役 Markdown 渲染器，粗体、列表、行内代码按结构显示；没有另建一份解析器。
- 手记中的目标记录从顶部开始；聊天的跟随末尾滚动不控制任务页。任务页发送新消息后回到对话，能够看到真实回复。
- 收起界面不停止后台目标；完成通知不自动切页、不抢焦点，也不触发朗读。通知在角色附近避开既有操作入口。
- 正在看的目标完成后仍保留在气泡里，不会自动换成另一件运行中的目标；主动切换目标时焦点跟随标题。
- Esc 先收起调整，再关闭气泡并把焦点还给入口。即使等待操作使焦点暂时离开按钮，也不会误触书房导航。

产物打开携带真实生成任务和产物 ID，读取指定保存结果，独立于列表的第一页和当前最新生成。等待或读取失败不会替换成其他结果；“重新读取”不启动新生成。返回正文、切换学习页、重新生成时解除旧选择；互动演示直接进入产物页。

## 真实窗口与模型链路

在本机 Electron 开发窗口、Personal Beta 空间，使用已有的“欧姆定律生成验收”笔记 v5 验证。窗口截图为 2880×1620 像素，对应 1440×810 的逻辑窗口。本次真实窗口验证限于这组尺寸。

1. 提出“速看 + 电压/电阻两滑块演示”的开放目标，要求保存结果并保持页面。目标 `49d3a27f-6e28-49dd-91bb-3949598ec5f5` 实际完成，两个操作均成功，保有两个可打开产物，合计 8/16 次模型调用。
2. 后台生成期间转谈午饭。伴星回答新话题，该轮没有工具调用；原目标继续执行，没有重新生成或切换页面。再问刚才任务进展，实际查询目标状态，按真实结果答复。
3. 从气泡和手记打开保存的速看，呈现公式、重点和原文入口。打开此次互动演示，实际 HTML 产物载入；电压由 5 V 增至 6 V、电阻保持 10 Ω，电流从 0.50 A 变为 0.60 A。旧任务保留的演示也能打开并操作。
4. 控制验收目标 `c9273aaa-55cb-4d0c-9eb7-b6a79856c9f3` 从暂停状态修改要求，获得 revision 2 的实际回执，再暂停、继续、停止。最终数据库状态 cancelled，未完成部分没有继续生成。
5. 真实窗口检查了气泡开合、成果跳转、手记从顶部阅读、返回正文、编辑与键盘 Esc。发现 Esc 导航串扰后修复，再实测第一下收起调整、第二下关闭气泡，笔记页面保持。

早期目标 `b77205f4-63ce-4b57-80ec-4ea661e6763c` 曾因预算用尽结束为 failed，已生成的成果仍保留。它没有被改成成功以代替后续验证；重复读取材料、失败继续复用和交付调用额度是在后续实际链路检查中修正的。

## 保留的范围与后续验收

- 当前只把读取、速看与互动演示接入独立复合目标。制卡、拓展、正式评估及其他现役 AI 调用尚未全部迁移；阶段 1–4 仍按方案推进。
- 已有共同人格和受作用域约束的已确认偏好使用；完整合作规则的确认/纠正/撤回 UI、方法经验、自主归纳和长期效果仍待后续交付。
- 跨空间稳定身份和空间偏好隔离经过真实数据库验证；完整 GT-03 的跨空间窗口操作尚未验收。
- 目标列表当前读取最近 20 件；更早目标的分页、完整要求修订史和每轮交付历史尚未提供。已有目标全部产物仍由持久记录保留。
- 新气泡的窗口验收尚未覆盖全部缩放、1280×720、日夜、Off 和系统减少动态组合。现有关闭动效路径与 CSS 减少动态规则有实现，不能代替这些窗口实测。
- 模型能自主选择最小能力组合，但开放目标的语义完成质量仍依赖真实样本持续评估；测试通过不代表任意目标都可完成。
