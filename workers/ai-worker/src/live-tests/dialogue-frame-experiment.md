# 对话用途、阶段与发布前范围核对实验（2026-10-07）

用户要的是普通多轮聊天中的改善。测试输入不添加“不要建议”“不要反问”或“陪我说一句”，也不向模型提供理想答案。编码 agent 读完实际回复后选择下一句；这仍是合成测试，不是人类用户研究。

## 实现与启用状态

`COMPANION_DIALOGUE_FRAME_V1` 和 `COMPANION_DIALOGUE_REVIEW_V1` 均仅在值为 `true` 时启用，默认关闭。当前实测不足以默认采用。正式平台、模型路由与冻结的人格版本没有因本次实验而更换。

用途与状态接入已有的意图解释调用，正常仍是解释、生成两次调用。开启后先完成解释，再生成；不能复用尚未收到用途与状态的投机首步。分类输出额度为 4000，关闭时仍为 900。这是结构化分类任务的明确输出预算，不是对聊天正文的字符裁剪。

解释材料中的 `userRecords` 最多选择最近十条用户消息，保持每条完整原文和原索引，不使用助手回复作为用户自述。现有五条摘要式分类窗口仍在；完整用户证据是单独字段，正文生成的原生历史不因此改短。每项状态最多引用 320 字的连续原话，程序检查原话、用户角色与索引，并绑定完整来源消息的 SHA-256。该限制属于结构化引文合同，不截断来源消息、当前问题或生成正文。

`dialogueFrame` 包含当前用途及有来源的用户自述解读：分享、吐槽、求助、纠正等；话题下的进展、时间、偏好、决定分别保存。工作完成和交付完成分别更新。当旧原话同时支持两个阶段、其中一个被新原话替代时，旧项不再携带已被替代的阶段。来源绑定保证“这段引文出自哪条原话”，不保证模型对否定、完成范围、话题别名和用途的解读正确，也不是外部事实核验。

实验生成仍保留当前人格。明确纠正，或前景中的进展与时间，需要核对时请求模型默认思考档、温度 0.3；旧进展仅作背景时维持闲聊请求关闭思考、温度 0.9。档位是否能关闭仍由模型档案决定，不把请求参数当成真实用量。

范围核对仅处理已绑定用途的无工具分享、吐槽或纠正。草稿缓冲，另用一次模型调用逐段决定保留或删除：不能改写或增加正文。所有非空原段必须恰好判定一次；错误索引、重复、漏检、额外正文、全部删空、工具调用或不完整输出均拒绝发布。保留段落保持原字符与换行，没有长度裁剪。模型的合法删除计划不能证明判断正确。

核对调用经过同一调用预算、租约、来源围栏与模型任务入口。封装后的完整核对数据没有历史 seq 映射，不能套用原对话的位置压缩；遇到软压力只消费一次尝试并保持原数据，硬溢出仍拒绝。检查器 JSON 和草稿不会进入可见流。失败只保存诚实的 `kind=error` 状态，明确未发布，不以“没听清”“走神”解释后台失败；已送达的正文继续保留。普通失败兜底也已改为如实描述回复失败，这项不依赖实验开关。

## 验证入口

在一次性数据库中运行 `natural-dialogue-probe.ts`，分别设置上述开关和唯一的 `LIVE_NATURAL_SUFFIX`；输入普通话语，读取真实回复再继续。它覆盖生产历史 SQL、读取时钟、解释、循环、治理、调用计数和交付；读取上下文使用夹具，绕过完整 HTTP、turn-service 与 UI。`ok` 只表示交付成功。

`dialogue-review-probe.ts` 是允许改写的早期只读诊断，未作为正式发布链。`dialogue-removal-replay.ts` 使用当前只删除原段的合同，重放已知失败草稿；可用 `LIVE_MODEL_ID` 比较同平台已声明模型，`LIVE_REVIEW_REPLAY_SUFFIX` 分开记录。两者都不写应用数据，不修改正式路由，不提供参考答案。重放核对请求根据记录重建，不能算同一请求的严格重复，也不能当作新话题验收。

`natural-dialogue-probe.ts` 可以额外保存本合成夹具的最终核对 JSON；不保存模型明文推理。原始用户输入、完整可见答复、实际发送 instructions、哈希、wire 用量与数据库计数都保留在各会话产物中。

本次 12 场普通接话共 41 轮，40 轮交付，1 轮初版内部合同拒绝；91 次真实出网调用。成功轮数据库计数共 88，与其 wire 数相同。另有早期改写诊断 3 次、两个模型的删除计划重放各 3 次，总计 100 次出网调用。不能把这 100 次算作 100 轮用户聊天，也不能把“40 轮交付”说成自然度通过。

完整人工核对、等待成本与未确认范围见 `outputs/audits/2026-10-07-live/frame-dialogue-report.md`。既有失败和中间方案保留，不覆盖成全绿结果。
