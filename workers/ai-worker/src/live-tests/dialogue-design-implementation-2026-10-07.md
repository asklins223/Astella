# 方案 46 第一阶段实施与证据

2026-10-07，Asia/Shanghai。用户明确要求开始实施后完成；对应 [方案 46](../../../../docs/plans/learning-companion/46-companion-natural-conversation-research-and-design-2026-10-07.md)。

本阶段交付了隔离话题材料、受控表达入口、请求与出网快照、匿名评阅材料，并修复一处 embedding 输入静默截断。120 次真实表达调用仍复现擅自安排与无依据自述，尚未得到可以采用的自然对话候选。正式人格、模型路由、用途/阶段实验和发布前检查的默认值没有改变。

## 实现范围

| 实现 | 作用与边界 |
| --- | --- |
| [dialogue-cases](dialogue-cases.ts) | 10 个设计话题、20 个话题隔离的后续核对组，涵盖分享、吐槽、纠正、转题、结束和真正求助。判据允许多种合理表达，生成模型看不到判据和标准答案 |
| [dialogue-experiment](dialogue-experiment.ts) | 复用生产人格/首步构造，固定原生历史、发送时间、意图、权限与参数；完整/相关装配只改变声明的合成背景。简洁身份另作多变量诊断 |
| [dialogue-matrix](dialogue-matrix.ts) | 现役/候选 × 完整/相关装配，每组两次，顺序轮换；最多 80 次实际请求，无自动质量重试 |
| [dialogue-persona-ablation](dialogue-persona-ablation.ts) | 示例有/无的单变量对照；另外提供无示例现役人格/简洁身份的能力诊断，每批最多 20 次 |
| [评阅材料](dialogue-review-packet.ts)、[离线导出](dialogue-export-review.ts) | 打乱回复顺序，隐藏模型、条件、等待与哈希，映射单独保存；评阅字段为空，目前没有独立人工评分 |
| [出网记录](acceptance-common.ts)、[连续聊天入口](natural-dialogue-probe.ts) | 合成夹具保存出网文本、参数与用量；不保存凭据、请求头和私有推理回放。连续入口本轮只补证据能力，未新跑数据库/HTTP/UI 验收 |

评测入口保留完整原生消息；快照采用允许分数温度的稳定 JSON 哈希。出网白名单若省略字段，记录数量；工具后续轮包含私有推理回放、不能保存快照时，明确记录省略原因，不改变真实调用。

| 批次 | 采样范围 | 实际请求 | 结构有效 |
| --- | --- | ---: | ---: |
| [模型与输入矩阵](../../../../outputs/audits/2026-10-07-live/dialogue-matrix-design-v1.json) | 10 组 × 4 条件 × 2 次 | 80 | 80 |
| [人格示例移除](../../../../outputs/audits/2026-10-07-live/dialogue-persona-ablation-examples-v1.json) | 5 组 × 2 条件 × 2 次 | 20 | 20 |

结构有效只表示正常结束、未要求工具、正文校验有效。120 条回复是固定前缀的表达诊断，不是 120 段连续聊天，也不是完整生产链路通过。

[完整性回执](../../../../outputs/audits/2026-10-07-live/dialogue-integrity-design-v1.json) 核对了产物、请求及出网哈希，原生历史/当前话语逐字相同，指令与参数在 HTTP 出口相符，各条件两次采样的请求哈希相同，矩阵上下文对照没有同时改变其他请求字段。每条回复对应一次实际调用，没有补采样覆盖失败。

第一版矩阵的 `answer` 尚含语音控制标签，匿名评阅导出使用生产正文校验投影剥掉标签，原始产物不重写。入口随后修正为同时保存原始与干净正文。第一版 `firstTextMs` 可能只是标签，不能当首个有效正文或用户等待；后续入口另记 `firstVisibleTextMs`，旧产物没有补造这个值。第一版白名单快照没有后加的省略计数字段，不声称历史产物已有该字段。

## 结果与采用判断

评阅者是编码 Agent，知道条件，以下是诊断观察；没有独立人类盲评偏好、总体胜率或最终自然度认证。

### 分享仍被接成安排

“简历改完了，还没投出去，看得我眼睛疼。”在矩阵四条件各两次中均出现休息、再次检查或投递时机安排。现役相关装配说“先放着吧，等眼睛缓过来再投也不迟”；候选完整装配说“先放着吧，脑子也得有个下班点”。练琴分享同样出现“先别急着再弹一遍”“先瘫一会儿吧”。用户输入没有附加“不建议/不反问”约束，问题是回复擅自安排接下来做什么。

单独移除账号 examples 后，简历样本仍出现“挑两三家最想去的先丢出去”。简洁身份诊断仍说“还没投就先别投”“先别急着碰下一段。歇会儿吧”。这几种改动都不足以作为修复；简洁诊断同时改变多个提示条件，不能归因于某一段。

### 示例影响措辞，但不是已证实的唯一原因

候选多次复用“脑子也得有个下班点”，但移除示例没有稳定改变安排倾向。固定协议和运行政策在简洁诊断中仍保留，也不能据此宣称已隔离出模型本体或能力极限。

### 无依据自述仍存在

候选对简历说“这个症状我熟”；对只有文字描述的鸭子视频说“我看完都有点想帮它在底下鼓掌了”。现役在结束解释时说“我这边也正好到饭点了”。这些回复没有相应见闻或现实生活记录。观点、想象和比喻需逐句区分，不能因出现“我”就一律扣分。

### 局部场景已经能正确处理

封面纠正组的八条矩阵回复都采用“封面已改、正文未改”的范围；歌曲转题组都接上歌曲，没有恢复组装椅子的安排。真正求助组提供具体练法，证明测试没有通过统一禁止建议抹掉帮助能力。不过其中还有无充分信息就断言卡壳原因的表达，不能把整组标为知识质量通过。

这些局部结果不抵消分享与自述失败。20 个隔离话题尚未生成回复，匿名 [评阅表](../../../../outputs/audits/2026-10-07-live/dialogue-review-design-v1.json) 仍未评分；没有选出候选时不消耗后续验收组来继续调提示。

## 思考、用量与等待

现役 `deepseek-v4.1-flash` 声明窗口 1,000,000 tokens；候选 `muse-spark-1.3-contributor` 声明窗口 1,048,576 tokens。两者声明最大输出 131,072 tokens，本轮出网额度相符。这些是配置声明，本批输入仅 1,617–3,112 tokens，不能证明百万窗口的实际容量。

| 实际出网档位 | 次数 | 返回推理 token |
| --- | ---: | --- |
| DeepSeek 普通聊天 `none` | 68 | 全部为 0 |
| Muse 普通聊天 `minimal` | 36 | 54–514 |
| DeepSeek 明确求助 `high` | 12 | 494–1,709 |
| Muse 明确求助 `high` | 4 | 1,622–2,442 |

本批证明已测试的 DeepSeek 关闭档没有报告推理用量；Muse 最低为 minimal，不能称为关闭。固定意图入口没有验证真实分类器在任意交流中是否选对档位，也没有证明强思考让聊天更自然。

| 矩阵条件 | 完整回复中位数 | 最大值 |
| --- | ---: | ---: |
| 现役/完整 | 2.682 s | 9.133 s |
| 现役/相关 | 2.534 s | 9.508 s |
| 候选/完整 | 4.269 s | 18.353 s |
| 候选/相关 | 4.014 s | 23.569 s |

时间来自单次表达执行器，混合普通聊天和高思考求助，不含分类、HTTP/数据库和 UI 交付。120 次用量合计输入 315,160、输出 34,458、其中报告推理 24,483 tokens；推理不另与输出相加估算账单。本轮未取得货币费用证据。

候选等待较长且仍有同类问题，尚无采用依据；正式路由不替换，不默认开启额外审校调用。

## 验证与剩余范围

- 相关对话/流式/思考回归 121 项通过；后续新增简洁身份合同测试通过。
- provider、流式、治理、记忆检索与实验入口相关组合 83 项通过，包含本轮新增的两条 embedding 回归。
- `workers/ai-worker` 的 `npm run typecheck` 通过。
- 120 次真实表达请求及对应快照核对完成，生成模型没有接收评阅判据，失败原文保留。
- 没有新的完整 HTTP、数据库持久化或当前代码桌面窗口验收，也没有独立人类评分；运行中的桌面程序来自其他工作树。

本阶段保留确定的工程修复，拒绝把失败候选设为默认值。输入去噪、删除示例和简洁身份均未提供足够收益；后续表达模型/可训练模型适配需要新的候选证据，不能继续以熟悉样本上的提示修改替代采用验证。
