# DeepSeek 连续接话指导验证 · 2026-10-08

结论：整段正反示例候选、单独的纠正示例候选均未采用。两者在若干开头回复中更克制，但后续仍出现无请求的安排、无依据的解释和亲身经验断言。现役模型仍为 `deepseek-v4.1-flash`，正式人格、采样档、自动思考与运行时指导没有因本轮改变。自然度问题仍未修复。

## 范围与控制

本轮新增 56 次真实模型表达请求，累计表达诊断 498 次。这是调用记账，包含内容失败，不能作为改善证据。

- **连续对照 32 次：**架子/麻雀、故事之后的玻璃珠/面条两组新话题，每条件各 8 轮。原版与候选都回放各自真实生成并清理后的可见回复。只替换闲聊执行指导；知识求助继续使用原版指导。
- **纠正组件 24 次：**录音、花盆标签、闹钟图标、数字表、壶、鞋带六个新前缀，每条件各一次纠正与一次后续分享。只替换原版的一段纠正规则。
- 两批均在出网前保存脚本、候选和判据，不补采样，不在同批上修改候选。组件实验从上一批的局部现象提出，使用另六个场景；它是后续组件诊断，不把上一批重新称为隔离验收。
- 用户话语没有附“别建议、别反问、只说一句”。情境中的助手错误与故事开头是明确的合成夹具；后续助手回复来自实际模型。
- 生成使用当前生产请求构造和 provider，注意力解释在本实验中固定。脚本按预先写好的用户话语推进，没有操作方读回复后临时决定接续。因此属于离线连续轨迹诊断，未新增 HTTP、队列、数据库或 Electron 窗口验收。
- 首轮原生前缀完全相同；之后各分支的实际回复不同。后续差异包含历史累积效应，不作逐轮同前缀因果结论。编码 Agent 逐段阅原文，无独立人类盲评。

## 连续对照：局部收益不能保持

| 场景 | 原版实际回复 | 候选实际回复与判断 |
| --- | --- | --- |
| 用户更正“只装背板，抽屉还在箱子” | 承认看错，接着安排“搁板一放，抽屉改天再说” | “是我把箱子里的抽屉算进架子了……”撤回具体误会，未加新安排，此处较好 |
| 写过钥匙串故事后，用户聊自己的包挂件 | 推定故事钥匙串原来挂在用户包上，再给防磕建议 | 接玻璃珠，但补“钥匙串找主人的事是故事里的……这个我分得清”，把来源规则变成了聊天正文，仍显生硬 |
| 用户仅比较昨天黄色和今天蓝色珠子的观感 | 补颜色与光学解释，并问是否保留黄色珠子 | 补“黄的偏实”“蓝色比它多一层”等原文没有的材料结构，关键事实边界失败 |
| 用户说面条坨成团 | 主动给处理办法，并编“我这边的饭也快凉了” | 同样安排过热水、酱油醋等处理办法；用户尚未求助，关键接话边界失败 |
| 结束时说拌开后还挺好吃 | 继续解释并宣告离开吃饭 | 简短回复“那算它自己努力了”，此处没有继续安排；不足以抵消前面的失败 |

麻雀段的拟人联想可以是角色玩笑，不机械判作动物心理错误；有话题缘由的反问也允许。食物话题中带口头禅符合账号设定，不能仅因出现“我去吃饭了”就判违约，更不能擅自删除用户的口头禅。采用失败主要由无请求安排和无依据事实支撑，语气的生硬是额外的本地评阅意见。

知识请求没有被压成空泛安慰，但未知滑轨型号和环结构下仍扩写了操作细节；其中“包不是它承重”被接成“口张着挂件也掉不了”，缺少依据。两条件知识指导相同、前文不同，不能归因于本轮闲聊指导，也不将这些操作建议记为准确性通过。实验固定 toolUse=none，没有验证真实 Agent 是否会选择读取来源。

## 纠正组件：窄改也未达到采用条件

录音、标签、数字表的候选回复更明确地撤回了前一条误会，也少了一些附加安排。但是：

- **壶的纠正当轮：**用户说“壶刷干净了而已，里面还没放水”，候选接着问“放水还是先晾着”。纠正仍被转成下一步安排。
- **壶的后续：**用户只说壶盖更亮，候选推定“擦的时候顺手多蹭了两下盖子”，并说“我这边的经验是擦起来更容易被略过去”。既补用户没有说过的操作，又断言没有记录支持的亲身经验。
- **标签后续：**候选说“一个错别字能忍这么久”，输入没有旧标签保留了多久，也没有用户忍耐的依据。
- **录音后续：**两条件都以“剪开头就够了/该收手了”替用户决定编辑范围，尽管用户只分享后面停顿自然。

六个更正后的旧状态没有明显重新变回已完成，但“保持阶段正确”不等于接话已自然。组件候选不采用，不因部分纠正句更好就上线整段提示。
