# 伴星 AI 接入与上下文修复记录

2026-10-07。对应本次平台/模型、自动思考、硬截断与人格审计。工作区原有的语音、界面及其他改动继续保留，没有提交 Git。

## 已修复

- 闲聊预生成首步按推进后的步号消费，在选择流式或缓冲路径之前统一复用。分类尚未结束时，快速流式生成也不能提前返回；取消/超时后晚到的放行不再吐字。
- 流式请求透传 `disableThinking`。纯闲聊关闭，提问/任务使用模型默认档；未提供工具的请求可以走流式，不要求 provider 解析工具增量。
- 当前合法问题完整保留，近期 20 条消息保留完整原文，短确认不再连同用户问题被删除。更早的消息继续由摘要与原文补读承接。
- 笔记与来源读取支持 `startOrdinal + startOffset`，返回 `nextStartOrdinal + nextStartOffset`。超长段落能在块内续读，UTF-16 游标不会把代理字符对拆开。持续目标的 `note_read` 同步接入。
- 工具结果在结构化取材阶段分页；不再对编码后的 JSON 进行截尾，转义字符、正文与游标完整保留。
- 上游 `finishReason=length` 不再把半截答案结为成功；已有正文保留为失败部分，不继续派发动作，不自动重投同一份截断请求。对话失败回执区分输出上限与传输错误。
- 摘要折叠只删除校验过的 `[fromSeq, throughSeq]` 覆盖区间，缺失/非法起点不折。超过输入硬预算但还有压缩路径时先压缩，重测仍超限才拒绝。
- 分类器的历史摘要保留首尾并标明省略，能够看见长回复结尾的邀请；正式生成仍使用完整历史。
- 主链、兜底都经过目标模型的预算与压缩端口；终答和等待确认分支保存最后一次发送的压力读数，分类器的小 JSON 预算不会覆盖它。系统装配容量与回执统一为 100,000 字符。
- OpenCode 工厂接入真实 conversationId，同会话跨轮保持 session 稳定。兜底请求使用目标模型的输出预算；OpenAI-compatible 的 chat、stream、agent 出口按模型档案限制输出，移除固定 65,536 上限。
- 当前本机 GLM 9B 配置补入 32,768 窗口与 8,192 输出预留，并启用请求输出上限。32K 是依据原模型配置采用的保守值，未宣称已压测确认 SiliconFlow 的完整服务边界。主模型百万窗口保持原配置。
- 交互与主动念头使用同一套完整人格解析；默认大肥鱼保留慵懒、贪吃与幽默，减少固定吃饭梗与例行追问。v8 区分角色表达和实际事件，保留事实/工具/关系边界。历史 v7 常量不改写，预设版本升为 3。已有有效自定义档案不被新默认预设覆盖。
- 主动念头候选与表达采用关闭思考的短 JSON 请求，完整加入说话风格、标签、例子与行为边界。日记已有完整人格取材，继续使用更新后的共享预设。

## 真实窗口样本

在 `companion-probe` 开发工作区，通过 Electron 输入框发送了三轮测试消息，全部成功落库，prompt_version 为 `companion-persona-v8`：

1. “嗨，我回来了。今天先随便聊聊。” → 正常寒暄，没有续讲旧的熵/星图任务。此轮严格分类后丢弃了猜测生成，因此共 3 次模型调用。
2. “就想歇会儿，不用问我问题。” → “好，那就歇着。我趴这儿，不吵你。” 没有继续追问，共 2 次调用。
3. “嗨。” → 正常短回复；日志明确保留预生成，约 2.35 秒完成，共 2 次调用。流式 `textDelta` 与最终保存正文逐字相同，没有 `stream_full_text_diverged`。

第三轮还带出了白饭梗，因此继续删掉了默认寒暄示例里的白饭句，让吃饭偏好主要由相关话题触发。人格自然程度仍需更多真实连续对话判断；这三个样本只能证明当前链路成功与明确收尾要求生效。

随后完成的真实模型大上下文、识图、嵌入、思考开关与连续对话验收，见 [真实验收报告](/Users/asklins/Documents/asklins_workspace/study/outputs/audits/2026-10-07-live/acceptance-report.md)。其中发现的 ASCII token 低估已进一步接入官方 tokenizer 修复；知识长答错误与自述模板重复仍保留为内容质量问题，未被结构测试的绿灯掩盖。

## 2026-10-08：原文从窗口到模型的补齐

前端喂给事件、session 和 API 选区合同统一为显式 20,000 字校验，超限不裁正文。气泡与手记校验发生在清理草稿前，Enter 和发送按钮均不能绕过；贴回批注仍遵循单独的 2,000 字锚点合同。长标题和回想问题也不在事件总线上二次截尾。

实际窗口的 2499 字笔记选区第一次暴露 worker 的 2400 字必需块上限，尚未出网却重试三次。移除 selection 与 continuation 的局部上限，保留系统 100,000 字符和全请求 token 预算；`AgentContextError` 保存失败、发布真实 error + character.cue，不重试确定性溢出。受限角色完整 handler 新增 20K 原文成功和 110K 必需来源零调用失败用例。修复后再次从窗口发送，原文尾部更正完整进入模型快照、历史和展开引用，SSE 与保存正文逐字一致。

日记实际 collector 的 SQL 不再把对话、标题、念头、提醒和记忆裁到 120/60/40 字；实库测试验证完整原文进入候选请求。实际成稿先聚焦所选完整来源，不经过旧的非聚焦渲染预算分支。存量长记忆召回、读取与 resident 装配保留正文，短目录标签和新写入字段校验独立处理。

最终 Worker 单元 1480 项、三组实库 99 + 150 + 9 = 258 项、桌面 73 项、shared 合同 28 项通过，五包 `npm run typecheck` 与桌面构建通过。目标批次与全量有重叠，不累加。最新实际回合从创建到终态 7.283 秒、分类 2.011 秒，不能抹去此前 75/93 秒等待；普通聊天仍有多余建议和无来源补写，自然度未通过。

## 2026-10-08：停止与直接文本创作

真实窗口复现新轮尚未输出就停止，HUD 把上一轮太阳回复冒充中止正文。现从会话层 interrupted 读取本轮文本，空轮只显示停止，不宣称已经留档。本地停止、SSE 取消和轮询先读到 cancelled 消息都按中止收尾。

真实长故事在流式中止后只有事件、没有历史消息。API 取消/接替事务现按 appendFrom 原样还原已提交正文并保存一次，空正文不造消息；移除 worker 在迟到完整生成返回后写 cancelled 消息的旧分支，避免补写未交付正文。受限数据库两项修复前失败、修复后通过；桌面相关 90、Worker 1481 和数据库 261 项回归通过。

纯故事曾被解释为 task/act，人物对白触发无来源引文纠正，再切备用小窗口档而超限。分类 v7 区分直接文本创作 task/none 和保存/生成项目对象；无读取来源的直接回复允许没有来源声明的引号，明确用户/笔记/教材原话以及资料读取仍核对。实际分类六项中三项创作均 task/none，保存未指明正文时仍 uncertain。不是关闭所有来源核查，也不是拟人化已通过。完整证据见 [本轮验证记录](../../live-tests/companion-integration-and-final-validation-2026-10-08.md)。
