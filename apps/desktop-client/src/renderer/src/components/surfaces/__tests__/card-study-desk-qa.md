# 学习卡详情、答题、结果的书桌验收

2026-10-03。用户最后明确范围为「学习卡详情 → 答题 → 结果」，制卡和候选卡审核不属于本轮收尾范围。窗口优先检查正常尺寸，没有继续扩展缩放适配。

## 设计与实现

- `card-study-scene.css` 持有这三页的书桌场景。日夜背景均为实际绘制的 PNG；图片不嵌入 UI，纸面、文字、控件和 Live2D 仍由代码独立渲染。图片和完整生成提示词见 `public/assets/card-study/README.md`。
- 详情页由知识点和启动操作构成卡片正面。练习说明、学习足迹、出处与原文可展开；无原文依据的提醒留在出处里，必须核对的状态仍保留相应操作。
- 最近一轮与旧练习次数来自不同记录：存在最近结果时显示「已有学习记录」，不让旧计数的 0 覆盖真实完成的作答。页面可读快照使用同一文案。
- 答题页沿用相同的圆角、纸边、厚度和投影，左侧读题，右侧写回答。保存状态和提交操作留在纸内；其他题型仍使用真实编辑器，没有用文字输入替代选项、配对或排序。
- 结果页先显示判定、已经证明的部分和缺口。回答对照、逐条判定与详细报告默认折叠；底部操作在长内容滚动时仍可使用。复习安排未改变时如实说明，不能把「记录保存成功」说成「已经安排复习」。
- 没有返回真实缺口的练习结果不渲染「还差什么」，也不把「继续正式挑战」冒充缺口。学习卡结果以「回到学习卡」为主按钮，学习空间为次要出口。
- `validation-surface.tsx` 从 TaskSurface 中承接退出逻辑。卸载 Player 后仍经过主进程确认；结果直接回同一张卡，不插入首页。返回等待期间保留最新的侧栏目标，只发起一次释放；工作区变化后旧目标不能落到新空间。
- 开始作答退首页的根因在 API 写路径：限流返回值判断反了，正常请求没有进入处理过程并返回空合同。五条写路径已修正；业务合同错误的会话复核也不再清空当前卡片。

## 真实 Electron 窗口

真实输入与提交验收构建为 `out-chain-v8`；结果主操作与回卡验收构建为 `out-chain-v10`，独立 QA 应用和 profile。正常内容区 1440 × 810、zoom 1；Retina 截图 2880 × 1620。

使用本任务创建的公开学习方法笔记「学习卡书房体验验收 · 2026-10-03」，不以用户私人笔记作为输入夹具。

- 从对应卡包进入详情，知识点、开始操作、三行可展开支持内容与上次记录均可完整阅读；右侧伴星没有遮住卡片。夜间背景使用真实灯光版，不是单色遮罩。
- 从详情开始练习进入真实文字题，中文输入 59 字，状态从「有未保存修改」变为「草稿已保存」，提交按钮可用。
- 暂停后显示「已暂停」；继续后仍为同一题、同一份 59 字回答和已保存状态。提交经过真实评估后进入结果页，判定为 `practice_completed`；已暴露参考答案的练习没有被当成正式掌握或推进复习安排。
- 日间结果与详细报告的滚动此前已在真实正式作答中核对，实际判定为达标；没有因为复习安排未推进而显示已安排复习。
- 夜间练习结果的首屏可完整看到真实收获、下一步、折叠报告和两个出口，右侧伴星未遮挡纸面。v10 主按钮为「回到学习卡」，点击后直接显示同一知识点与上次结果，没有落到首页。
