# 首次进入 AI 协议体验验证

2026-10-07。用户要求协议签署先于首次引导播放，本轮把原来的「先让伴星能出声 → 去设置 → 回来继续」改为独立协议纸页，确认本人签署成功后直接进入五站带路。

用户随后要求更大胆的连续动画。当前协议正文直接呈现，读取时使用中性核对状态，签署后播放连续影片，伴星临时固定右下角。最新验证以 [影片体验记录](./guide-film-experience.md) 为准；下面保留前一轮逐站与折叠全文的历史验证。

## 当前行为

- 未确认本人同意前不挂载 `GuidanceScene`、`GuidanceNarration` 或路线快捷跳转；读取失败留在协议页重新读取。
- 纸页说明使用内容、外发范围和账号范围，提供当前版本全文。勾选默认关闭，主动勾选后才能签署；设置页复用同一正文。
- 直接使用既有 `workspace.updateAiConsent`，签署回执必须带当前 `AI_CONSENT_VERSION`。2026-10-08 修正：签署同时开启外发总开关，保留图片、检测与审计选择；重复点击只发一次请求。
- 签署失败保留勾选和阅读位置，原处可重试。暂不签署或 Esc 保存暂停进度，右上角带路目录可继续；明确暂停后重挂不自动展开。
- 已签署用户直接进入实际章节。暂停在历史 `voice` 前置位置时，继续会把进度记为真正的第一站 `room`。
- 账号或部署变化时丢弃旧回执；身份消失时清空上一位用户的带路。会话纪元更新不重开整段体验。

## 原生 Electron 窗口

用实际组件、控制器、全局样式与 Live2D 创建隔离窗口；`getAiSettings` 与 `updateAiConsent` 只操作内存。未向真实账号提交协议。窗口检查通过 CUA 原生点击、键盘和截图完成，截图只用于当次检查。

| 检查 | 观察到的结果 |
| --- | --- |
| 首次未签署 | 展开协议纸页，无演示、路线或讲解；未勾选时主按钮不可用 |
| 展开全文 | 当前版本与四段正文可阅读，正文独立滚动，页脚不随正文离开 |
| 勾选与签署 | 按钮立即可用，提交期间显示确认状态并避免重复提交；完成后聚焦书房第一站 |
| 首次签署失败 | 原处显示失败，勾选保留；第二次提交进入第一站 |
| 读取失败 | 禁用同意勾选，提供重新读取；重试后恢复正常协议入口 |
| 暂不签署与继续 | 关闭协议、交还书房；从继续入口重开，重新主动勾选 |
| 键盘 | 初始焦点落在标题；Tab 与 Shift+Tab 在协议内循环，Esc 暂停；全文可用 Page Down 阅读 |
| 窗口与缩放 | 1440×810、960×640、760×540；150% 与 200% 下正文仍可滚动，页脚操作保持可见 |
| 角色与纸面 | 宽窗口按真实角色位置避让，遮罩给角色保留清晰区；紧凑窗口优先分配阅读空间 |
| 关闭动效、减少动态 | 通过隔离窗口传入现有动效偏好验证，勾选与签署即时可用，成功后仍进入第一站 |

另在实际桌面当前已签署账号中，从岛内「跟我完整走一遍」进入「认识书房 · 1/5」，没有重复要求签署；讲解按钮变为「暂停语音讲解」，显示「边看，边听我讲」。检查后暂停带路并收起控制。

## 未覆盖的边界

本轮没有为真实新账号签署协议，因而没有验证「真实新账号刚签署 → 服务端 TTS」的完整链路。旧实施记录中的该链路失败不能由本轮内存签署或既有已签署账号的正常播放推定已修复。操作系统的减少动态设置没有修改；本轮验证使用应用现有 reducedMotion 状态。跨设备、Member 实窗与网络断开期间提交未实跑。
