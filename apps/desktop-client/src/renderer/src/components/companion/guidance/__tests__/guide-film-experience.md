# 书房开场动画体验验证

2026-10-07。用户进一步明确：引导要更大胆，做成连贯播放的动画，伴星可以固定在右下角。本轮以这个决定替代逐站点击、全屏箭头和多张操作纸的方案。

## 当前体验

协议先独立确认，正文直接可读。服务端确认签署成功后，影片从书房、资料到笔记、原句解释、伴星提纲一路自动接续到开始学习。同一张纸保持 DOM 身份，几何、镜头、圈选与候选出现接续当前呈现；静音版的基准为 60 秒。旁白尚未完成时停留在本幕，避免切章截断朗读。

协议和影片使用临时的右下角角色座位，不改写用户摆位。电影画面、字幕和轻量播放条占主位；可以暂停、继续、重播当前片段、定位某幕、跳过或打开真实入口。影片结束保留开始学习的邀请，自动播放不自动创建内容或导航。打开真实页面后收起影片，保留返回与接续的短纸签。

暂停同时停住影片时钟、CSS/GSAP 动画和旁白。语音保留已解码段落及音频时钟偏移，恢复不重新合成，也不从头念。窗口失焦/隐藏时保存当前位置；回到窗口后沿原来的播放选择继续。回复、录音、静音与账号关闭声音仍按原声道规则处理。Off、Lite 与减少动态使用相应的静态或轻量呈现，功能与焦点不等待动效。

读取期间呈现中性的核对状态，未读出同意前不覆盖原来的恢复章节。手动结束首次引导同时收尾首次空间进度；跳到后面的章节没有伪造学习事实。旧箭头、锚点扫描与对应事件链已清理。

## 验证证据

13 个相关测试文件、212 项通过，覆盖协议前置、首次进度、播放器自动衔接与暂停、后台保持、真实入口接续、音频偏移恢复和快速反向、伴星座位几何、岛内入口、设置以及样式守卫。desktop-client 的 node/web 类型检查通过。设置测试保留已有 jsdom `HTMLMediaElement.pause` 未实现日志，测试仍通过。

日志在 `apps/desktop-client/outputs/ai-consent-entry-20261007/film-tests.log`、`film-typecheck.log`。同目录的 `stable-build.log` 记录固定预览构建成功；这不是整套桌面打包验收。

在实际桌面已签署账号中，从「伴星带路 → 播放书房介绍」进入影片，确认自动衔接到第二幕、真实旁白开始、角色固定在右下角。按暂停后，按钮变为播放，旁白状态变为「播放已暂停」。测试过程没有替真实用户签署协议。

工作区其它页面的开发热更新会整页重载，因此完整连播另用固定构建的独立 Electron 窗口检查，载入实际组件、全局样式与 Live2D，协议和进度服务仅操作内存，语音关闭。观察到不点击下一步也会进入第五幕，最终停留在学习邀请；窗口与缩放、暂停/重播/章节定位、Off 和减少动态在该隔离环境检查。操作使用原生点击和键盘，截图只用于当次核对。

## 边界

真实新账号「刚签署 → 服务端 TTS」尚未实测，旧记录中的合成拒绝不能由本轮既有签署账号的正常播放推定已修复。固定预览没有验证真实后台写入、跨设备进度或完整 Electron 打包；系统减少动态开关没有修改，检查使用应用现有 reducedMotion 状态。其它并行改动不属于本轮交付。
