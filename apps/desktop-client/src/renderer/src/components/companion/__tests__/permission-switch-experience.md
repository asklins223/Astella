# 助理权限切换不重建书房（2026-10-09）

用户报告：在消息气泡切换「仅可读取 / 分步确认 / 自动执行」后，出现「正在恢复上次登录」，随后回到首页。

## 调用链与修复

原入口在读取和保存前都通过 `requireWorkspaceEpoch()` 重新读取会话。保存完成又广播无载荷的账号变更，伴星、设置与带路分别重新读取账号，其中伴星还会再次读取会话。权限偏好因此额外进入会话复核链；任何边界错误都可能触发门禁并清空当前任务位置。

现在权限入口使用门禁已验证的纪元，保存回执携带完整账号状态并同步到所有监听者。成功切换只需保存请求，不再因该通知读取会话、人格、账号或带路进度。没有已验证纪元时仍按原鉴权路径处理；服务端和主进程继续校验请求边界，保存失败保留原处错误并重读账号。

另修复 `GatewayTransport.loadSession()` 的顺序：先接纳服务端纪元，再组装工作区。独立窗口曾读到同一会话回执的 `session.workspaceEpoch=6`、`workspace.workspaceEpoch=1`，这会被门禁判为需要重新同步。修复后首次恢复、纪元推进和旧服务端值均保持两个字段一致。

## 验证

- 相关五个测试文件共 148 个用例通过，含门禁、主进程伴星开关、账号权限、多入口同步和带路回归。
- 桌面端 `npm run typecheck`、`npm run build` 及房间素材守卫通过。
- 独立 Electron 窗口连续切换：自动执行 → 仅可读取 → 分步确认 → 自动执行。三次保存使用纪元 7，revision 5 → 6 → 7，输入草稿保留，气泡与手记显示相同档位。
- 设置中心的伴星设置将自动执行切到分步确认后显示「伴星设置已保存」，继续留在原分区；保存使用 revision 8。
- 切换期间门禁新增次数为 0。窗口验证使用本机 IPC 账号/会话测试桩，不修改远端偏好；不能据此宣称原安装包已更新或联网持久化已验收。

窗口记录：`outputs/permission-switch-20261009/window-result.json`。原安装版的普通切换在独立会话中未稳定重现用户报告的每次跳回；已确认并消除了上述重复读取与回执版本不一致，用户原运行会话的具体错误仍未捕获。
