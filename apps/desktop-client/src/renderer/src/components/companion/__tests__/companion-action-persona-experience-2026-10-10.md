# 动作回执与人格阅读体验（2026-10-10）

用户反馈：动作结果一次堆出多张过期卡片；人格页把长描述、编辑框和改名配置同时铺开，阅读与操作都不顺手。

## 实现

- 历史提案读取先进入 loading，旧浮层将这些 ID 当成新动作缓存，读完后逐项显示过期回执。浮层现在只接纳当前回复引用的动作或真正待处理的 ready 状态，旧终态和历史读取失败留在手记里。
- 多项动作使用一张确认纸和前后切换，决定仍提交当前真实 proposalId。终态合成一张短回执，显示各结果数量；单项保留标题，失败保留最近的失败说明和记录入口。执行中不会按普通回执计时消失；失败等待用户收起。普通回执在阅读、手记或待决定动作占位时暂停计时，关闭后不因重新渲染复活。
- 浮层按实际内容高度落在伴星附近，短回执不再占用整条阅读走廊。退出中的按钮即时不可操作，Off 和系统减少动态即时收起。
- 人格页以短身份封面和完整正文呈现名字、自我描述、表达方式。改名和描述编辑按需展开，具备保存、取消、Esc 和焦点返回；保存失败保留草稿。人格预设默认折叠，选择后展示保留或覆盖的字段，再沿原接口提交。
- 待生效人格展示实际变化的字段，包括只改自我描述的情况，原内容可展开核对；作者、理由、生效条件和原激活接口保留。
- 记忆视图保持一行。窄纸面的方法和长期目标用详情替代索引，先显示正文标题和返回；返回接回同一条目，长期目标的未发送要求与笔记选择在本次页面会话中保留。

## 验证

相关 Vitest 覆盖 11 个文件、128 项测试，全部通过：动作卡片、历史隔离、翻页与真实决定 ID、过期计时、执行与失败、关闭和焦点延续；浮层摆位和时钟；人格编辑、失败草稿、预设保留与可读视图、待生效差异；方法及长期目标原有调用与返回草稿。

桌面包 `npm run typecheck` 通过，分别检查 `tsconfig.node.json` 与 `tsconfig.web.json`；`git diff --check` 通过。

`scripts/probe-companion-action-persona-ui.mjs` 连接正在运行的 Electron 开发窗口，19 项检查通过。真实数据用于人格阅读、编辑开合、Esc、连续开合、历史往返和方法选择返回。三项动作、混合终态和失败使用真实生产组件加临时本地状态验证，不确认真实动作、不保存真实人格。探针结束后移除临时组件，恢复动效和视口。

正常窗口的混合结果回执为 300 × 130 CSS px。另用 CDP 模拟 1280 × 720 与 720 × 405 CSS 视口检查重排、横向溢出和窄页详情首屏。截图与报告保存到 `apps/desktop-client/outputs/companion-action-persona-ui/`，属于工作材料。

本轮只调整桌面渲染体验，没有修改共享类型、API 或动作执行器。没有做完整项目回归、安装包检查或原生 Windows 窗口验证；模拟视口不等于操作系统缩放验证。
