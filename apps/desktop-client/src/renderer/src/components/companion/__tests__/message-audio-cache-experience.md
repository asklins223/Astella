# 历史消息的本机音频 · 2026-10-07

实时回复的 `speakSegment` 在主进程取得 MP3 后，按部署、账号、空间与 run 身份保存当时的原字节和实际音色。一个 run 对应一条伴星回复，各段按 ordinal 保存并回放，不拼接 MP3、不重新合成。账号在本机跨空间合计保留最近 100 条有音频的消息，补到的分段和回听不会提升旧消息的顺序。念想和带路各自的既有 64 条缓存保持独立。

手记的消息组件与伴星中心的对话历史共用 `CompanionMessageAudioButton`。仅录音存在时显示播放入口，准备与播放时可以立即停止，切换消息取代旧音源，离开页面和切空间释放播放。音频继续使用同一 `HomeV2AudioController` 的解码、AudioContext 和嘴型通道。静音、录音、不可见与正式作答规则继续生效。

当前空间的历史清除会删除对应本机录音；清除前已发出的请求不能写回。缓存损坏、磁盘不可写和会话变化独立处理，磁盘失败不阻断当前回复，损坏的历史录音不会触发补合成。原文、账号和空间身份不进文件名；缓存接口只接受类型化的 run 与 ordinal，不接受任意路径。

## 验证

shared、api、desktop-client 和 ai-worker 的 `npm run typecheck` 均通过。桌面相关的 14 个测试文件合计 197 项通过，共享语音合同另有 2 项通过。覆盖跨进程读取、多段排序、并发写入、跨空间共用 100 条额度、回听不改变淘汰顺序、过期轮次迟到、清除栅栏、损坏文件与未提交文件清理、IPC 路径和数量拒绝、过期空间、快速切换和停止、两个页面的入口以及离页清理。

`node scripts/verify-companion-message-audio.mjs` 使用独立 Electron 窗口与临时 userData，通过真实 preload、主进程缓存和音频图验证。消息和 `/voice/tts` 响应使用明确的固定样本及仓库已有的 MP3，不调用模型、不改服务端对话或 AI 同意。已核对两个入口的开始、停止、快速重复点击，伴星中心 1440×810 与 125% / 150% / 200% 缩放下的按钮到达，以及重启 Electron 后同一 MP3 的本机读取。首次进程仅有两次样本音频响应，回放没有合成请求；新进程的合成请求为零。原生窗口截图与结果保存在 `outputs/companion-message-audio/`。验收脚本会删除自己的临时 profile。

重启验收曾遇到现有认证恢复提示「学习空间已更新」，通过「再试一次」同步后继续；本轮没有修改认证恢复链路。窗口音源与录音读取已验证，未声称完成真人麦克风多轮对话或扬声器听感验收。旧消息未曾存下的音频不补生成；本次主进程与 preload 改动需要重启客户端后开始保存新回复。
